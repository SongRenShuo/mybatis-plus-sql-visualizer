## 4. dev↔master 分叉现状与合流风险点

1. **两条大集成线并行且互不包含**：t-sql-insight（⊃dev，486 patch）与 t-branch-merge-route（⊃security+hiddenbug+domestic，120 patch）。route → insight 缺 120 patch、insight → route 缺 security/hiddenbug/domestic 全部实质 patch。**合流前必须先定一条主合流线**，否则双向重放工作量翻倍。
2. **重叠文件冲突面**：两线都动过设置面板/守卫账本/CHANGELOG/索引（route 有 `ce8fbd03b` 对齐笔，insight 有同名对账笔）——合流时守卫计数与 BannedApiScan 豁免表是首撞面（route `e8d2a635d` 已实证过一次合并修正）。
3. **t-perfsweep31 是独立新线**（route 缺 33、insight 缺 32），基于较新 master（behind=4），合流代价最小，可最先收。
4. **在途线三个**（rollback-preexec、hd-absorb、perfsweep31 的 32 精简）都已 CI 全绿，合流顺序上宜「小线先收、大线对齐后一次合」。
