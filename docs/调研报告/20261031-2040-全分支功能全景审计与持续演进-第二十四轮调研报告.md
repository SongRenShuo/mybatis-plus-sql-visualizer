## 四、优势（重估：护城河收缩为三条）

1. **14 方言渲染器 + 7 家信创数据库**：全场唯一。CHP 的方言面停在 MySQL/PG/Oracle/H2，新入场的 SQL 预览插件 EXPLAIN 面最多 5 方言。**竞品要补需 7 套方言 × 真机对照，短期不可能。**

3. **跨 ORM 覆盖**：MyBatis-Plus Wrapper/Lambda、JPA/QueryDSL/EasyQuery/Xbatis/MDS、JdbcTemplate、注解 SQL、HQL/JPQL 全在一个预览引擎里；竞品全部单框架。
4. **工程纪律仍是硬优势**：59 件守卫测试、4 处 TODO、双语零缺口、巨文件五件终于收到 2000 红线内（第六次登记后兑现）、AGENTS.md 四条纪律落档。

1. **【头号】328 笔成品积压 + 189 笔纯本地提交**：dev 8 笔、insight 131 笔、k2j 50 笔无远端副本；`t-settings-converge` 整条分支从未推送。第二十三轮「先留底再合流」的红线**又一次被并行推进会打破**——留底不是一次性动作，是持续动作。

6. **【老·最痛】真实功能缺口两条**：①代码生成——`generator/` 只出 CRUD **SQL** 文本，不出 Java 代码；②编辑器内 Inspection——master **0 个**（dev 刚有第一个）。竞品的红波浪线才是被动流量入口。

| 「demo 里出现了很多 SQL 预览图标」 | **噪音** | gutter 分组显隐 |
| `[SqlVisAgent]` 输出太多 | **噪音** | 默认静默，仅 debug 输出 |
| GaussDB/达梦/瀚高/海量预览恒降级 | **静默失败** | PSI 方言配对修复 |
| MCP 261 过滤器契约不兼容 | **共存破坏** | 契约探测兼容层 |

五条里**没有一条是「缺功能」**——全是「装进真实环境后添乱或悄悄坏掉」。用户环境不是干净沙箱：装了三五个同类插件、几千个 mapper、多数据源、不同 IDE 版本。所以本轮 UX 判断修订为：

1. **共存是第一优先级**（图标让位、快捷键让位、菜单不抢、MCP 端口不抢）；
2. **噪音治理高于功能扩张**（图标密度、控制台输出、通知频次）；
3. **降级必须响亮**（方言判不出、驱动未识别、数据源不可用，都要有可见出口而不是静默回落）；
4. 上一轮的「能力可见性」仍然成立，但它是**第二优先级**——用户先要「不烦我」，才谈「你还有什么」。

新增一条具体缺口：合流后设置页会同时出现两个「导出报告」入口（`DiagnosticReportFormatter` 面向提工单、`EnvironmentCheckReport` 面向自查），**文案必须区分**，否则用户分不清点哪个。

**贯穿三条线的不变项**：留底（持续动作，不是一次性）、真机验证债攒批、评价资产（W1/N-24）、k2j 跟版策略重定、共存与噪音治理。

## 十一、结论

与第二十三轮相比三点最大变化：

1. **合流债从「三棒 279 笔」变成「两棒 328 笔、零文本冲突」，但多了一个顺序陷阱**（insight 缺 dev 设置收敛 5 笔，绕过 dev 静默丢功能）。第二十三轮计划的 S1-2/S1-3 两棒已被并行会话在 dev 上预先完成，只剩 S1-4 一棒——**执行面比计划更简单，验证面比计划更重**（insight 自 `bef08646` 起无全量读数）。
2. **第二十三轮开出的处方 100% 兑现，兑现率与变现率的剪刀差拉到头**：D201/D202/R45/UX/NEW-18/NEW-19/设置收敛/FR-0045/magpie 全在 dev 上，master 一件没有。这既证明工程执行力，也证明**「做完」和「交到用户手里」之间还隔着一整条发行链**。
3. **竞品格局第一次出现真实反转**：CHP 用 MCP + Java Agent 压上了我方两根柱子，「能预览 SQL」已商品化。护城河收缩为三条（14 方言/信创、EXPLAIN 解读、跨 ORM），真实缺口两条（代码生成、Inspection）。**继续按「功能数量领先」自我叙事是危险的**——该换成「信创 + 诊断深度 + 稳定性」三条具体叙事。

瓶颈排序：**留底与合流两棒（328 笔变现 + 189 笔本地单点）＞ insight 全量门禁复跑 ＞ Inspection 体系（被动触达）＞ 信创兼容体检（护城河变现）＞ 评价资产（第 21 轮零稿）**。
