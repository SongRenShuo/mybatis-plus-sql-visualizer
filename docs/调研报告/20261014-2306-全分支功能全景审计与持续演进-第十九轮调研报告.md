3. **跨平台 MCP 路径**：`mcp/McpFilePathResolver.kt:39-57` 只把 Windows 盘符认作绝对路径；POSIX `/home/...` 落入 `mcp/McpRenderInput.kt:74-79` 的项目相对路径分支，前导 `/` 被剥离，可能错找/拒绝项目内绝对路径。未实测 macOS/Linux，需带符号链接与项目外路径负例作 fail-closed 回归，不能仅「让它工作」却打开越界读。
4. **门禁的空绿范围**：`src/test/kotlin/cn/song/mybatisplus/visualizer/xml/fidelity/RealEngineFidelityTest.kt:33-60` 真引擎对照只覆盖既有语料，不等于面板/参数/多数据源端到端；`sql/verify/DialectDockerVerificationTest.kt:51-66` Docker 缺省禁用/无 daemon 跳过，`buildSrc/src/main/kotlin/mpv-testing.gradle.kts:1043-1056` 默认测试排除部分 DB 集成类，须单独记录 `testDatabase` 真跑与否。项目越大，越要给「未被验证」显式标记。


能力覆盖的盲区不只是「不认某个 API」：有入口但 SQL 语义不对、产生了 SQL 却绑定错方言/库、第一次点击失败没有反馈、已捕获却丢源码位置，都会让用户失去信任。故未来的对照矩阵应按「入口可达 / 产物与真引擎一致 / 失败可诊断 / 交互可完成 / 冷热态性能」五列逐项记实，而不是只数已注册的图标、工具或方言。

## 三、用户痛点与优劣势

### 可延续的优势

1. 产品覆盖编码前（静态预览）、编码中（mapper 编辑器辅助）、运行中（捕获、回溯）与运行后（历史、对比、EXPLAIN、回滚），有条件把零散工具串成闭环；具体能力与分支状态见 §二。不能把「功能入口多」直接说成所有场景都比竞品强。
2. 保守失败策略已经有基础：不能解析时显式降级，写入/执行有安全闸，agent 与控制台可按条件回落；`docs/规范/设计规范-弹窗克制红线.md:68-88` 已明确拒绝主动营销弹窗、后台失败不改模态弹窗。
3. 真实缺陷记录不仅列现象，还记录触发、根因及反向测试。`docs/开发计划/20261013-0910-T-SqlTemplateUx-SQL快捷模板三动作的失败反馈与库归属口径-开发计划.md:125-149` 曾在修好「气泡带操作」后通过真机重录发现「晚到错误根本没有进入回调」，证明从按钮到宿主回调的端到端判据不可省。

### 需要先解决的劣势

1. **可信度有时低于功能广度**。真实用户碰到过 `@Embedded` 列前缀丢失、MPJ ON 的右列别名取错、JPA 参数链错位、字符串拼接/方法返回 SQL 无法认领；`CHANGELOG.md:67-68,79-81,148-149` 登记了修复。它们不是「多支持一种语法」的营销问题，而是预览与真实 SQL 不一致或定位不到的正确性问题。新支持面必须附正反两种真语料对照。
2. **同一失败在不同入口给出的能力不一致**。快捷模板曾只给纯文本告警，预览面板则能定位和复制；改完快捷模板又曾被无宿主回调门控吞掉晚到错误，详见上述 T-SqlTemplateUx `:55-68,125-149`。一处复用底层执行器不等于用户体验已复用。
3. **多项目、多模块、多库的「默认智能」尚未闭环**。`docs/开发计划/20261014-1252-T-PreviewDialectAutoInferMultiModule-SQL预览多项目多模块Maven自动方言推断-开发计划.md:12-21,25-40` 已实证项目级推断取第一 URL、私有预览文件映射 MySQL、日志条目 URL 未带入预览；该计划截至开工时仍标「待实施」。错误方言可能改变可执行 SQL，不可用「开关已叫自动识别」代替上下文证明。执行数据源应与渲染方言另行交叉验证。
4. **真机体验债会逃过代码门禁**。2026-09-20 走查曾记录首开降级、窄窗口元信息被整个挤没和不具备所需 agent 会话导致的未验项（`docs/验收文档/20260920-真机走查记录-验收问题修复.md:35-71`）；这些是当时环境的历史案例，不能据此断言现行版本仍有相同缺陷，但足以说明 GUI 与宿主状态要单独验。
5. **发行证据与旧文档随时间分离**。第十八轮 `:23-43,116-122` 记载的「未打 10.13 tag / 149 笔推送债 / 官网 update 404 影响现有用户」都是 10 月 11 日时点；当前 tag 和主干都已前进，网站路径的影响面也被实际更新检查源证伪，不能抄旧结论。dev 仍有功能库存，但只对当前具体符号按 §一重核。
6. **有图标/有测试但真实链路不能用**。`psi/WrapperLocator.kt:93-113` 的 Kotlin 识别结果无实体表、`ui/SqlPreviewService.kt:267-291` 非服务链直接返回 null；多链场景的锚点变量并未参与选链。首先修复或诚实隐藏不可用入口，而非新增一批 detector 单测。
7. **安全与隐私文字不能写大于代码**。执行超时 30s 的 `execute/ExecutionTimeoutGuard.kt:16-24` 仅覆盖 MCP 而非 IDE 内嵌控制台；设置关闭 SQL 日志文件自动保存不等于应用级预览历史和参数预设都不落盘（`history/SqlHistoryManager.kt:12-27`、`ui/ParamHistoryCache.kt:7-12`）。同意/关闭、存储域与清理动作要逐项说清，不能靠一句「不上传」替代本地持久化告知。
8. **跨版本/跨系统边界需要单测之外的验证**。MCP POSIX 绝对路径被相对化、旧 IDE 的外部工具过滤 EP 缺席、Oracle/SQL Server EXPLAIN 面与模板动作硬编码 LIMIT 都不是多登记一种方言能解决的；详见 §二证据与配套计划负例。

## 六、长期迭代机制与停止条件

1. 建「场景样本」而不是把大量纯单测当作体验覆盖：每条包含原始源码/工程依赖/运行时 SQL/目标库、期望预览、失败反馈、截图/日志锚点、脱敏判据；至少留有静态正确、静态不可判、跨模块歧义、执行目标冲突四类反例。新 ORM 以真实用户使用率及误产出风险开工；`docs/架构设计/其他ORM官方API覆盖矩阵.md:3-9` 明确矩阵是调研基座，不代表全部立项或上线。
2. 每月留一张五行的产品账：首用成功路径、预览对照不一致、高价值来源跳转、执行误触/被阻止、反馈闭环。数值只从用户同意的本地诊断或主动反馈与复现样本收集；**默认不新增后台遥测、上传 SQL 或主动评分弹窗**。先收基线，再设目标；不得拿下载量、0 评论或自测样本冒充用户留存。
3. 功能进入稳定版需四级门：真实语料的正反对照与反向验证；定向测试；单路统一全量与跨平台适用门（大改或发版按项目纪律跑 verifyGate）；真机/真库端到端及发行物回读。没有真库的方言/驱动只能写「文法/静态验证，真库待验」。文档写「已发布」只对发行物，不对未合支线。
4. 每季度重评机会成本：如果新增功能让首开更慢、配置更难懂、分支合流更久，则先把现有链路化繁为简；如果主路径稳定且访谈有明确需求，才扩大框架或 AI 工作流。竞品的新特性不是自动立项理由。

### 待验证前提（可推翻本轮建议）

- 「预览正确率」能否以真实运行时 SQL 为真值，且不把参数化/数据库驱动改写误报为解析错误？设计双向规范化与人工复核样本后再定指标。

## 七、本轮结论与引用
