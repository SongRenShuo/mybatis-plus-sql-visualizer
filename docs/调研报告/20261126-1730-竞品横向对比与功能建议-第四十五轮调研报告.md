## 六、交叉研判（综合结论）

1. **真正的威胁换了人**：r41~r44 一直把 zMyBatis 1.0 当作头号盯防对象，本轮证据显示它零产品增量、零外部用户、卡在作者自己的验收清单上；而 CHP 在 11-23/11-24 连发 3.7.0/3.7.1，功能面与我方正面重叠且在打磨。**盯防重心应从 zMyBatis 移到 CHP**。D240（zMyBatis 发版扳机预案）可保留但降级；**新增 CHP 盯防条目**是本轮最该立的项。

2. **改名的收益是真的，但只到了「被搜到」这一步**：`mybatis sql` +104 名、`goldendb` 首次命中、`mybatis` +166 名——可见度工程成功。但 6.65 天日增 30.2 与 r43 的 29/天几乎持平，**说明可见度没转化成下载**。转化断点在「搜到了点不点」——而搜索列表卡片上我方**零评分**，CHP 4.96、JPA Buddy 4.94、MyBatisX 4.73 都带星级。**评分是当前最便宜、最直接的转化杠杆**（车道 B：SQLite Lens 2 票即能在列表端拿到星级）。

3. **我方最强的叙事资产已被第三方验证，但没被自己用好**：locdd 跟帖里有人原样复述「日志方案在新增 IDEA 会失效，改成 JDBC 层挂 agent」——**这是社区替我们写好的文案**。而 Log 类差评主题（兼容断裂/参数错配/覆盖缺口）与 agent 采集的优势面严格同向。W1 文稿的弹药面从未如此充足，发射仍待用户令。

4. **D223 EXPLAIN 是唯一「需求被验证、供给侧全行业冻结」的窗口**：DBX 冻 48 天、32766 停更 4.5 个月、postgres-explain-visualizer 2 年未更新却拿 23,697 下载 4.60 分。我方已有全部弹药（`ExplainJsonPlanTree` / 计划 Diff / 计划历史 / 索引建议，竞品全无），**只差把结构化渲染从实验开关转正**。这是投入产出比最高的一项，且不需要新建能力。

5. **我方空白面里，Mapper XML 格式化是唯一「高频 + 竞品刚做 + 我方弹药已备」的**：CHP 3.7.0 重做、3.7.1 立刻修细节，说明是它认定的高频场景；我方 `SqlFormatter.kt`（1157 行）+ `SecureXml.kt` + `SqlNode` 树三件套齐备，落地成本主要在校验（格式化前后渲染出的 SQL 必须一致）。

6. **合流债继续恶化，但已被绕过而非化解**：dev 冲突 16、insight 31、route 7（r43 口径 10/19，第 78 版 11/28/5，本轮 16/31/7，只涨不跌）。11-22 后八支全部停推，master 成唯一活跃面，团队选择「不合流、在 master 上重做」。D220 的「不裁决」成本已可量化，但既然新功能都在 master 上直接落地，**合流的边际收益在下降**——这条应作为 D220 重新评估的输入，而非重复催促。
