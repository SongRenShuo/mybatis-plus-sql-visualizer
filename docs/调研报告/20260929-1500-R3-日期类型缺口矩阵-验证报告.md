## 二、缺口矩阵（dbx 真库逐格实测，2026-09-29）

探针形态：对 `SYSDATE`/`NOW()`/`now()`（各库等价当前时间）比较「我方会渲染出的字面量」；A~E 为我方产出形态，C 为候选修复形态。

| 字面量形态 | Oracle 23 Free | Oracle 11g XE | 达梦 DM8 | 金仓 KingbaseES V8 | MySQL 8.4 | MySQL 5.7 | PostgreSQL 16 | openGauss 5.0 |
|---|---|---|---|---|---|---|---|---|
| **A** `'2024-01-01 10:00:00.0'`（Timestamp/Date 标注） | ✗ ORA-01861 | ✗ ORA-01861 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| **B** `'2024-01-01'`（LocalDate 标注） | ✗ ORA-01861 | —（同族不重复） | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| **D** `'10:15:30'`（LocalTime 标注，对 datetime 列） | ✗ ORA-01843 | — | ✓ | ✗ invalid input | ✗ ERROR 1525 | — | — | — |
| **E** `'2024-01-01T10:15:30'`（LocalDateTime ISO-T） | ✗ ORA-01861 | — | ✗ 非法的时间日期类型(22015) | ✓ | ✓ | ✓ | ✓ | ✓ |
| **C1** ANSI `DATE '2024-01-01'` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| **C2** ANSI `TIMESTAMP '2024-01-01 10:00:00.0'` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 补充：ANSI `TIMESTAMP '2024-01-01 10:15'`（缺秒） | ✗ ORA-01861 | — | — | — | — | — | — | — |
| 补充：ANSI `TIMESTAMP '…30.123456789'`（9 位小数） | ✓ | — | — | — | — | — | — | — |
| 补充：`DATE '2024-1-1'`（不补零） | ✓ | — | — | — | — | — | — | — |

**结论**：
1. **缺口坐实且只在 Oracle 族爆发**（两代版本 11g/23 同读数）：我方 A/B/D/E 四种形态对日期列隐式转换恒败（ORA-01861/01843）——与竞品差评同款形态；MySQL/PG/金仓/openGauss/达梦对 A/B/E 全宽容（达梦仅 E 的 ISO-'T' 形态报 22015）。
2. **ANSI 类型字面量（DATE/TIMESTAMP '…'）在全部实测引擎通用**——修复**不需要方言分支**，一个映射表即可全引擎正确，这是本矩阵最重要的工程结论。
3. **D（LocalTime）语义取决于目标列类型**（对 TIME 列各库皆可、对 datetime 列各库表现分裂），且 Oracle 不支持 ANSI `TIME` 字面量——**不包装**，登记边界。
4. **缺秒形态必须归一**：ANSI 字面量不接受省略秒（Oracle 实测 ORA-01861），`LocalDateTime.toString()` 恰好省略零秒——包装前须补 `:00`。

**环境受限未实测（如实登记）**：Oracle 18c/19c/21c（19c 容器停机 listener 拒连，其余未逐一打点——ANSI 字面量为 ANSI SQL 标准特性，11g/23 两代已实测两端，代码可判）、MariaDB（连接拒）、虚谷 XuguDB（DBX 驱动未装）、SQL Server/SQLite/H2（无连接）。此八格不作为修复依据。

## 三、修复设计（随本分支实施）

**只改还原链一处**（`LogSqlRestorer.renderParam`），三通道自动生效；面板参数行手输回填链不动（见 §四决策点）。

- 新增日期族映射：类型标注（简单名归一，兼容全限定名与 JDBC 类型名）→
  - `LocalDate` / `DATE` / `Date`（值匹配 `yyyy-MM-dd`）→ `DATE '…'`；
  - `Timestamp` / `LocalDateTime` / `TIMESTAMP` / `DATETIME` / `Date`（值匹配 `yyyy-MM-dd[ T]HH:mm[:ss][.f…]`）→ `TIMESTAMP '…'`（'T' 归一空格、缺秒补 `:00`）；
  - **不匹配即回落既有引号行为**（如 `java.util.Date` 的非 ISO toString）——包装永不产生非法字面量。
- **维持不包装**（边界登记）：`LocalTime`/`Time`（列类型相关）、`OffsetDateTime`/带时区值（ANSI TIMESTAMP 不收时区后缀，需方言级 TO_TIMESTAMP_TZ，超出小件）、**无类型标注**（启发式无法区分日期串与字符串列的日期值，误包装会改变字符串列语义）。
- 契约变更（显式登记，循 T-01 先例）：六处测试文件的日期族期望值由裸引号串改为 ANSI 字面量（`LogSqlRestorerTest`/`ParamEdgeCaseRegressionTest`/`HibernateLogParserTest`/`HibernateLogParserDualCopyTest`/`JdbcTemplateLogParserTest`/`SqlLogCaptureRealtimeScenarioTest`）。

## 四、决策点（带回，不阻塞本件）

| # | 决策点 | 推荐 |
|---|---|---|
| D1 | 面板参数行手输回填链（`toHint`/`renderSingleValue`）是否同步 ANSI 化 | **A=暂不动**（用户手输值自动加前缀属 UI 行为变更，宜真机走查后定）；B=同步 ANSI 化 |
| D2 | 无类型标注的日期形串（如 `2025-01-01 12:00:00`）是否启发式包装 | **A=维持引号**（字符串列 `WHERE code='2025-01-01'` 误包装会破坏语义）；B=正则启发式包装 |
| D3 | 带时区值（OffsetDateTime）方言级包装（Oracle TO_TIMESTAMP_TZ） | A=登记不做；B=随方言基建任务立项 |

> **D1 后续定案（2026-11-07，T-DateLiteralBackfill）**：Oracle 真机预览执行
> `UPDATE_TIME = '2026-11-07T13:20:14.417'` 报 ORA-01843（错误位置正落在该字面量开引号），
> 把 D1 定为 **B=同步 ANSI 化**。面板参数行 / `ParameterReplacer` / `AgentEventAdapter` / 模型链
> 统一走 `SqlDateLiteral`；SQL Server / SQLite 因不支持 ANSI 类型字面量方言门禁回落引号。
> 详见 `docs/开发计划/20261107-1333-T-DateLiteralBackfill-日期族参数回填未用ANSI字面量致Oracle执行失败-开发计划.md`。
