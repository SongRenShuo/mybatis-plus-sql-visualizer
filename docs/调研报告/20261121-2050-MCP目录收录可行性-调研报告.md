# MCP 目录收录可行性探测报告（D249-④）

- 读取日期：2026-11-21（当日各站实测，时点敏感读数以文中标注 URL 为准）
- 调研对象：五个 MCP 目录站点（glama.ai / smithery.ai / mcp.so / pulsemcp.com / punkpeye/awesome-mcp-servers）对本插件 MCP 形态的收录可行性；顺带探明官方 MCP Registry（registry.modelcontextprotocol.io）对嵌入式形态的口径
- 本插件 MCP 形态：非独立 npm 包、非常驻独立进程；11 个 `sqlv_*` 只读工具注册在 IntelliJ IDEA 2025.2+ 内置 MCP Server（`com.intellij.mcpServer`）上，agent 经 IDE 本地端点调用，插件只随 Marketplace 安装分发
- 数据来源：各站公开页面与 FAQ（curl 经本地代理抓取）、GitHub API（awesome 清单仓库数据、modelcontextprotocol/registry 仓库文档，经 `.local/github-token.json` 令牌）、WebSearch（美国区）、Web Archive（smithery 历史快照）
- 性质：只读外部调研。未注册任何账号、未提交任何表单/PR/issue、未外发任何内容；一切「提交后会怎样」的读数均为站点文档口径与静态探测结论，非实测

## 1. 结论摘要

1. 五个目录对「IDE 内嵌本地形态」的可行性分两档。**可直接走「提交 GitHub 仓库 URL + 审核」的有两个**：mcp.so（免费审核上列，提交页明说接受「MCP servers (with their GitHub repository)」这类仓库形态）与 punkpeye/awesome-mcp-servers（PR 改 README，且清单里已有同类 IntelliJ 插件形态先例条目）。**当前物理上不可行的有两个**：smithery（2026-10-31 关停连接管理服务，转「精选制」，发布 CLI 已弃用、提交入口 404）与 PulseMCP（2026-09-03 起暂停一切收录与变更，官方建议先发官方 MCP Registry 等恢复后自动抓取）。glama 介于两者之间：开源 server 目录按「能从源码跑起来的 GitHub 仓库」索引，插件形态大概率过不了健康检查（同类 IDE 插件仓在 glama 均 404），但其先例 JetBrains/mcpProxy 的条目页恰好示范了「安装方式＝装一个 Marketplace 插件」的呈现形态。
2. **官方 MCP Registry 是本次探测最大的增量发现**：generic server.json 格式显式支持「嵌入式 MCP」——文档原文 "For MCP servers that follow a custom installation path or are embedded in applications without standalone packages, use the `websiteUrl` field to direct users to setup documentation"，示例就是一个 "MCP server embedded in a Desktop app"，不带 packages 也不带 remotes。本插件形态正中此例。PulseMCP 恢复后从官方 registry 自动抓取，glama 每小时同步官方 registry 的 Streamable HTTP 端点（connector 面）——发布官方 registry 是多个渠道的上游母本。
3. 曝光量级实测（均为当日读数）：awesome-mcp-servers 98,342 star / 20,558 fork、60 分类 4,982 条目、2026-11-17 仍在活跃合并；glama 注册表 124,772 个开源 server（页面标题实测）；mcp.so 自报 DR 74、12 个月 2.2M 独立访客 / 6M PV、266K MAU（自报，未独立核验）；smithery 与 PulseMCP 独立流量读数未取得。
4. 推荐主攻两个：**awesome-mcp-servers PR**（零账号成本、先例齐、社区面最大）＋ **mcp.so 免费提交**（仓库形态明确接受、自报曝光最高）；**并行做官方 MCP Registry 发布**（websiteUrl 形态 server.json，`io.github.SongRenShuo/*` 命名空间）作为 PulseMCP 恢复后的被动入口与「官方在册」背书。glama 可顺手试一次 Add MCP Server（若被拒零损失）；smithery / PulseMCP 列为观察项。

## 2. 各目录逐个探测

### 2.1 glama.ai

**收录形态**（来源 https://glama.ai/mcp/faq ，2026-11-21 实测抓取）：

- 两套并存。①**开源 server 目录** `/mcp/servers`：条目按 GitHub owner/repo 键（如 `glama.ai/mcp/servers/JetBrains/mcpProxy`），页面标题实测 "Open-Source MCP Servers – 124,772 in the Glama Registry"。FAQ 口径："Submit open-source MCP servers to the Glama registry straight from a GitHub repository. On the servers page, click Add MCP Server and fill in: The GitHub repository URL for your server, A display name and short description. Glama runs automated quality checks (license detection, security scan, health test) during indexing. Most submissions pass automatically within minutes… Servers that run from source must be on GitHub today; for other sources, reach out on Discord."
- ②**Connectors**（远程端点目录）："Connectors are remote MCP servers you've already deployed somewhere with a public endpoint… The server URL – must be HTTPS and speak the streamable-http transport… Submissions are reviewed." 通过后邮件发 claim 链接；claim 支持端点文件、域名（`_glama-claim.<domain>` TXT 或 `/.well-known/glama.json`）、GitHub 三种验证。
- 维护：收录后 Admin → Listing 改展示信息，Admin → Dockerfile 管构建规格；仓根放 `glama.json` 可声明维护者名单。FAQ 另说："No separate Glama submission is needed if you publish to the official MCP Registry. Glama syncs published Streamable HTTP endpoints on an hourly schedule, without manual review."（注意：同步的是 streamable-http 端点，即 connector 面；本地形态不在该口径内。）

**对本形态的判定证据**（2026-11-21 逐仓实测）：

- 本仓 `glama.ai/mcp/servers/SongRenShuo/mybatis-plus-sql-visualizer` → 404，未被自动爬到。
- 同类 IDE 插件仓 `hechtcarmel/jetbrains-index-mcp-plugin`、`hechtcarmel/jetbrains-debugger-mcp-plugin`（在 awesome 清单在列的 IntelliJ 插件形态 MCP）→ 均在 glama 404，未收录。
- 对照组 `JetBrains/mcpProxy`（官方 npm 代理包，可从源码运行）→ 在列：页面类别 Developer Tools / App Automation / Coding Agents，标 Official、JavaScript、Local；页内明示 "This server does not currently have a deployable release on Glama. Follow the repository's setup instructions to install and configure it"，且页面直接以 "Install MCP Server plugin: https://plugins.jetbrains.com/plugin/26071-mcp-server" 作为安装说明；页面同时标注 Deprecated："The core functionality has been integrated into all IntelliJ-based IDEs since version 2025.2. The built-in functionality works with SSE and JVM-based proxy (for STDIO) so this NPM package is no longer required."（来源 https://glama.ai/mcp/servers/JetBrains/mcpProxy ）

**流程**：servers 页 Add MCP Server → 填 GitHub 仓库 URL＋名称＋简介 → 自动质量检查（license / security scan / health test）→ 多数几分钟自动通过 → claim 后可编辑。健康检查要求 server 能从源码跑起来——这是插件形态的硬缺口。

**曝光价值**：124,772 条目大盘，带 score 徽章体系（`/badges/score.svg`），awesome 清单大量条目直接挂 glama 徽章，两者联动是真实流量面。独立流量读数未取得。

**可行性判定：存疑、偏低。** 目录面按「可从源码运行的仓库」设计，插件不可独立运行，自动健康检查大概率不过（hechtcarmel 两仓未被收录是旁证）；connector 面要求公网 HTTPS + streamable-http，本地 IDE 端点不适用。存在的一个正向可能：mcpProxy 条目证明「无 deployable release 也能挂条目、安装说明可以直接指向 Marketplace 插件」——如果提交被接受，我们的条目形态已有先例可抄。代价是一次表单提交，被拒零损失，可在用户授权后单次试探。

### 2.2 smithery.ai

**现状（重大变化）**：站点横幅与 /future 页实测（2026-11-21）："Smithery's MCP Proxy and managed identity shut down on October 31"——2026 年 10 月 31 日起关停连接管理服务，Smithery 保留为 "a public (non-proxied) MCP registry"，由 Arcade.dev 驱动，目录改为 "A curated set of verified servers"；同时停用 Smithery API / Connect / Toolbox / 账号与 API key / CLI 与 SDK（CLI 标记 deprecated）。（来源 https://smithery.ai/future ）

**提交通道实测**：`smithery.ai/new` → 404；`registry.smithery.ai/servers?q=...` API → 500 "An unexpected error occurred"；现行站检索页为客户端渲染、静态抓取无结果。发布文档仍挂在 Mintlify（https://smithery.mintlify.app/docs/build/publish.md ）：URL 型（公网 HTTPS + streamable-http，扫猫 SmitheryBot）与本地 MCPB bundle 型（`server.mcpb` 经 CLI `smithery mcp publish ./server.mcpb` 分发）两种——但 CLI 已弃用、发布入口 404，文档与主站脱节。

**对非 npm 形态**：文档层面 MCPB bundle 让「无 npm 包的本地 server」有理论通道（MCPB 需是一个可执行的 stdio 服务器包，插件本身不是；包一层 stdio→IDE 端点的代理如 JetBrains mcpProxy 可凑），但实际通道已关。

**先例**：旧版 Smithery 曾收录 `@jetbrains/mcp-proxy`（Web Archive 2025-03-02 快照 200：http://web.archive.org/web/20250302123447/https://smithery.ai/server/@jetbrains/mcp-proxy ）；现行站同路径 404。hechtcarmel 插件仓与本仓均 404。

**曝光价值**：转型期，首页只放少量 featured 精选位；独立流量读数未取得。

**可行性判定：当前不可行。** 无开放提交通道，目录转精选制；列为观察项，待其转型结束（精选准入方式公开）再评估。

### 2.3 mcp.so

**收录形态**（来源 https://mcp.so/submit ，2026-11-21 实测文本）："You can list MCP servers (with their GitHub repository), remote MCP servers (a hosted endpoint URL), MCP clients, AI products, CLI tools, Agent Skills and Loops." 表单字段即 **Repository URL**（placeholder `https://github.com/owner/repository`）＋ Name。首页 FAQ："Use the Submit button in the top navigation (mcp.so/submit). Enter your repository or server URL and we fetch the details; you can then review the name, description, config and tools before submitting. **Listings go live after review.**"

**流程**：免费通道＝填仓库 URL → 站方抓取详情 → 人工审核后上列。付费通道＝一次性 $39：免审即发、verified badge、featured/priority 位、dofollow 外链（本次调研不涉及付费，默认走免费审核）。

**先例**（2026-11-21 实测）：`https://mcp.so/server/jetbrains` 在列——"JetBrains MCP Proxy Server"，@JetBrains，分类 Developer Tools，transport stdio，最近更新 2026-11-11，带 Claim 按钮 / Repository / Homepage 链接。即「IDE 周边的 MCP server 以仓库为条目」有官方在列先例。`hechtcarmel/*` 两仓与我们的仓均 404（mcp.so 靠热门仓库自动爬＋主动提交补齐，小仓库需提交才会出现）。

**曝光价值**（提交页自报，未独立核验）：Domain Rating 74、backlinks 144.21K（88% dofollow）、ref. domains 4.1K、**12 个月独立访客 2.2M、pageview 6M、月活 266K（↑11.2%/月）**；"Each listing gets its own page with setup instructions and ready-to-copy configs for MCP clients such as Claude, Cursor and VS Code."

**可行性判定：可行、直接。** 五个目录里唯一一个把「GitHub 仓库（不要求 npm 包、不要求可独立运行的 server 进程）」写进收录口径的；对「插件即 server」的表述最宽容；自报曝光量在五者中最高。审核通过率未知（免费通道走人工 review）。

### 2.4 PulseMCP（pulsemcp.com）

**现状**（来源 https://www.pulsemcp.com/submit ，2026-11-21 实测，需浏览器 UA 否则 403）：

> "Apologies, submissions and changes are temporarily paused. We are not accepting new MCP server or client submissions right now, and we are not making changes to existing listings… Last updated: September 3, 2026. In the meantime, if you have a server to share, **publish it to the Official MCP Registry. That is the best first step even when we are not paused, and we will pick it up automatically once we are back.**"

**机制（恢复后口径）**：提交页仍存在（表单结构在，横幅盖住），历史上是表单提交＋人工审核；收录面含 servers 与 clients。恢复时间未承诺（"rather than promise another date we will simply reopen this page the moment we are ready"）。

**曝光价值**：独立流量读数未取得；其 `/statistics` 页是生态级指标（全互联网 MCP server 流量估算），不是自身流量读数。

**可行性判定：当前不可行、恢复后被动可行。** 收录动作做不了；但若先发布官方 MCP Registry，恢复后会被其自动抓取——不需要单独盯防，属于「官方 registry 发布后的顺带收益」。

### 2.5 punkpeye/awesome-mcp-servers

**基本盘**（GitHub API 2026-11-21 实测）：98,342 star / 20,558 fork，main 分支 2026-11-17 仍有提交；README 实测 60 个分类、4,982 条目。

**PR 收录要求**（来源 https://github.com/punkpeye/awesome-mcp-servers CONTRIBUTING.md ，2026-11-21 实测）：

- Scope："This list is for **servers with a public GitHub repository — something you install and run yourself**. If your server is remote-only (just a hosted URL, no installable package), it belongs in awesome-remote-mcp-servers instead."
- 格式：server 名字链接到仓库、一句话功能描述、归入合适分类（分类内字母序）、一行一条。流程：fork → branch → 改 README → PR → 维护者审核。
- 专门给自动化 agent 开了快速通道："If you are an automated agent, we have a streamlined process for merging agent PRs. Just add the robot emoji to the end of the PR title to opt-in. Merging your PR will be fast-tracked."

**同类先例条目**（README 实测原文，均在 "Developer Tools" 分类）：

- `- [hechtcarmel/jetbrains-debugger-mcp-plugin] … ☕ 🏠 - JetBrains IDE plugin giving coding agents programmatic control of the debugger.`
- `- [hechtcarmel/jetbrains-index-mcp-plugin] … ☕ 🏠 - JetBrains IDE plugin exposing indexing and refactoring features: rename, safe delete, find references, call and type hierarchy, diagnostics and more.`
- `- [jetbrains/mcpProxy] … 🎖️ 📇 🏠 - Work with JetBrains IDEs such as IntelliJ, PyCharm, WebStorm and Android Studio.`
- 桌面应用插件形态同类还有 `mrexodia/ida-pro-mcp`（IDA Pro 插件）、`13bm/GhidraMCP`（Ghidra 插件）等。

图标语义（README Legend 实测）：☕ Java 代码库、🏠 Local Service、🎖️ official implementation、📇 TypeScript。本插件两项可对齐：☕（Java/Kotlin）、🏠（本地）。

**曝光价值**：MCP 生态 GitHub 上头部清单（近 10 万 star），条目随仓库获得长期曝光；PR 被合并的同时仓库获得一个高质量外链；与 GitHub star 积累互喂。

**可行性判定：可行、低门槛。** 本仓是公开 GitHub 仓库、插件经 Marketplace 一键安装，「installable」语义成立；IntelliJ 插件形态已有两条在列先例（hechtcarmel 系），审核面风险低。本仓当前不在清单中（README grep SongRenShuo / mybatis 零命中，2026-11-21 实测）。

### 2.6 官方 MCP Registry（顺带主干发现，非任务清单内但影响全部结论）

**对嵌入式形态的官方口径**（来源 modelcontextprotocol/registry 仓库文档，GitHub API 2026-11-21 实测）：

- generic-server-json.md "Server with Custom Installation Path" 节原文："For MCP servers that follow a custom installation path or are embedded in applications without standalone packages, use the `websiteUrl` field to direct users to setup documentation"，示例 server.json 只含 name/description/websiteUrl/version，无 packages 无 remotes，描述即 "MCP server embedded in a Desktop app"（docs/reference/server-json/generic-server-json.md）。
- 另有 "Embedded MCP inside a CLI tool" 节（借 packages 指向宿主 CLI 包）与 MCPB 包类型（GitHub/GitLab release 托管、stdio transport、须含 fileSha256，identifier 须含 "mcp" 字样）——前者不适用（无独立 CLI），后者不适用（插件不是 stdio 进程）。
- 发布流程：`mcp-publisher` CLI，命名空间用 GitHub 认证（`io.github.<用户名>/<服务器名>`，本仓对应 `io.github.SongRenShuo/…`）或 DNS/HTTP 域名认证；registry 处于 preview（官方明示可能有 breaking changes 与数据重置）。（docs/modelcontextprotocol-io/faq.mdx 、docs/server-json/official-registry-requirements.md ）

**为什么它是主干**：PulseMCP 恢复后自动从官方 registry 抓取（官方声明见 2.4）；glama FAQ 称每小时同步官方 registry 的 streamable-http 端点（2.1）；smithery 转型后的自我定位也是 "public (non-proxied) MCP registry"。官方在册是目录生态里最强的「上游事实」。

**未验证点**：websiteUrl-only server.json（无 packages/remotes）能否通过官方 registry 发布验证，本次只读探测未实测（未提交）。generic 文档把该形态写成示例，但 official-registry-requirements.md 的校验规则以 packages/remotes 为主，风险登记在第 5 节。

## 3. 可行性排序与推荐

| 排序 | 通道 | 判定 | 理由 |
| --- | --- | --- | --- |
| 1 | awesome-mcp-servers PR | 可行、低门槛 | 同类 IntelliJ 插件先例两条在列；98k star 社区面；零账号成本；scope 明确收「可安装运行的公开仓库」 |
| 2 | mcp.so 免费提交 | 可行、直接 | 收录口径明说接受「带 GitHub 仓库的 MCP server」；自报 12 个月 2.2M 访客为五者最高；官方 JetBrains 代理先例在列 |
| 3 | 官方 MCP Registry（websiteUrl 形态） | 可行、待验证放行 | 文档明写嵌入式形态；是 PulseMCP 恢复后的被动入口与官方背书；发布前需确认 websiteUrl-only 条目可过验证 |
| 4 | glama Add MCP Server | 存疑、偏低 | 健康检查按「可从源码运行」设计；hechtcarmel 同类仓未收录；但 mcpProxy 条目证明「无 deployable release＋安装说明指向 Marketplace 插件」的条目可存在，可单次试探 |
| 5 | PulseMCP | 暂停中 | 2026-09-03 起停收；发官方 registry 后被动等待抓取即可 |
| 6 | smithery | 关闭 | 2026-10-31 关停提交通道转精选制；转型结束后再评估 |

推荐主攻：**awesome-mcp-servers ＋ mcp.so 两个**。理由：两者都明确接受仓库形态、都只花一次提交成本、都不需要注册新账号体系（awesome 走 GitHub 账号＝现有；mcp.so 提交无需账号，见其表单无登录门槛）。官方 registry 作为并行动作一并做掉（发布物是一个 server.json＋CLI 调用，成本最低、收益面覆盖 PulseMCP）。glama 顺手试探一次（表单一次，被拒零损失）；smithery 与 PulseMCP 不投入，登记观察即可。
