# agent-desktop 桌面自动化选型调研报告

> 日期：2026-11-14
> 调研问题：`vercel-labs/agent-desktop`（AI 桌面控制 CLI）能否提升本插件 **UI 验收**（`ide-ui-acceptance`）与**演示动图录制**（`ide-demo-gif`）两条作业线的效率。
> 结论先行：**不能用作主链**。它依赖 OS 辅助功能树（Windows 上是 UI Automation），而 IntelliJ IDEA 的 Swing 内容树在 UIA 上**零暴露**——本轮在 262 录制沙盒（2026.2.1）实测复核，与 skill 坑表在册先例一致。仅窗口管理/截图等外围能力有零星收编价值。

## 1. 项目核实

| 项 | 实测值 |
|---|---|
| 仓库 | github.com/vercel-labs/agent-desktop（23.4k star，Apache-2.0） |
| 本机安装 | `npm install -g agent-desktop` → v1.3.1，原生二进制（agent-desktop-win32-x64.exe），Node 22 正常 |
| 机制 | 读 OS 辅助功能树返回 JSON（元素带 `@ref`），agent 对 ref 做 click/set-value 等语义操作，再 snapshot 验证。**不是**截图/像素匹配，工具本身不含模型 |
| Windows API | UI Automation；要求 Win10 1809+，须运行在交互桌面会话 |
| 无头模式 | 默认 strict headless：语义操作不动指针、不抢焦点；`--headed` 才允许物理输入/焦点副作用 |
| 其他 | 每命令输出统一 JSON envelope；`agent-desktop mcp` 可暴露为 MCP 工具；ref 唯一性约束严格（同窗口同身份双胞胎 → AMBIGUOUS_TARGET） |

## 2. 实测结果（2026-11-14，本机 Win11 26200）

### 2.1 基线：非 Java 应用可用

- **记事本（WinUI3）**：snapshot 完整（22 refs，中文元素名正常）；语义点击闭环成功——点「设置」→ 快照验证设置面板出现（refs 22→30）→ 点「返回」→ 快照验证编辑器恢复。全程无头、未抢前台。
- **ZCode 宿主（Electron）**：snapshot 3s/15s 均超时（TIMEOUT）。个别应用的 UIA provider 也会拖死它，并非普适。

### 2.2 关键实证：IntelliJ 2026.2.1 沙盒（录制/验收目标环境）

以 `./gradlew runIde -PgifRecord=true --args=<demo>` 拉起 262 录制沙盒，agent-desktop 实测：

| 探测 | 结果 |
|---|---|
| 主窗口 snapshot | `ref_count=5`，全部是窗口装饰（系统菜单/最小化/最大化/关闭），**编辑器、工程树、菜单、工具窗口内容零暴露** |
| `find --text "Project"` | 0 命中（该文本在截图中肉眼可见） |
| Trust Project 对话框 | 同样空树，语义点击无落点 |
| screenshot（PrintWindow） | 可用，甚至能拍到**被遮挡窗口**的内容 |
| 物理点击（`--headed mouse-click --xy`） | 可用，但就是普通坐标点击——被其他窗口遮挡时会点进别人的窗口（本轮三次点击落进了记事本，幸而只是移动光标）；且必须先 `focus-window` 抢前台 |

**判定：UIA 路线对 IntelliJ 不可用，与 `.agents/skills/ide-demo-gif/SKILL.md` 坑表在册结论一致**（「Windows UIA 路线已实测否决：UIA 只看得到 Swing 顶层 `SunAwtFrame`、children=0，`jabswitch` 已开亦然」）。本轮用另一独立实现（agent-desktop 的 UIA 客户端）复核，结论相同，可判**平台级定案**而非工具实现缺陷：Swing 的辅助功能走 Java Access Bridge（MSAA/IA2），不映射为原生 UIA 元素树，UIA 客户端拿不到内容。

### 2.3 对两条作业线的逐项评估

| 环节 | 现行方案 | agent-desktop 能否替代/提速 | 判定 |
|---|---|---|---|
| 验收：IDE 内交互（菜单/编辑器/弹层） | robot-server + 图像锚点/像素带 | UIA 无 IDE 内容，语义点击不可用 | **不可用** |
| 录制：IDE 内操作重放 | pyautogui 脚本重放 | 同上，`--headed` 坐标点击不比 pyautogui 强 | **不可用** |
| 窗口管理（等窗口出现/聚焦/尺寸归一） | pyautogui + 窗口探测 | `launch`/`wait --window`/`focus-window`/`resize-window` 有 JSON envelope，比自拼 win32 稍稳 | 可选收编，收益小 |
| 拍被遮挡窗口截图 | 需抢前台再拍 | `screenshot` 直接拍（PrintWindow 路线） | 可选收编，偶有用 |
| 验收/录制的非 IDE 环节（浏览器、文件管理器等） | browser-use / 手工 | 非 Java 应用上确实好用 | 与主线无关 |

## 3. 结论与建议

1. **不引入为验收/录制主链**。核心瓶颈（IDE 内容树不可达）是平台层限制，换工具无解；现行 robot-server + 图像锚点路线继续。
2. **低价值收编项（可做可不做）**：`focus-window`/`wait --window`（窗口就绪等待）、`screenshot`（拍被遮挡窗口）。若收编，建议只在这两个 skill 的辅助脚本里以子进程调用，不进主链。
3. **复评触发条件**：JetBrains 官方落地原生 UIA 支持（而非 JAB 桥接）、或本项目验收目标迁到 Electron/WinUI 系工具时，再重测。届时只需重跑本报告 §2.2 的两条探测命令。
4. 本机已装 v1.3.1（npm 全局），保留不卸载；登记表已注销，沙盒 IDE 已关。
