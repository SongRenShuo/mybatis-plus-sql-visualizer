## 一、结论速览

**9 种方言全部消除假设性标注**。本机可验证的部分（H2 六种兼容模式 + SQLite 原生引擎 +
官方文档黄金断言）共 **29 个验证用例全部通过**，插件各方言渲染出的 SQL（分页/引用/UPSERT/
保留字全量扫描）在对应引擎上**零语法错误**。验证过程发现并修正了 **4 类真实兼容性缺陷**
（原实现按"假设性标注"运行时会生成语法错误的 SQL）：

| # | 缺陷 | 严重度 | 证据来源 | 修正 |
|---|------|--------|----------|------|
| 1 | **H2 方言 UPSERT 输出 `ON CONFLICT (k) DO UPDATE SET col = EXCLUDED.col`，在 H2 任何模式（含 PostgreSQL 兼容模式）均为语法错误**——H2 2.3.232 引擎实证 `ON CONFLICT` 仅支持 PG 模式下的 `DO NOTHING`（无冲突目标、无 DO UPDATE） | 🔴 高（UPSERT 功能整体不可用） | H2 2.3.232 引擎实测（全部 5 种模式） | H2 原生 upsert 为整语句 `MERGE INTO t (cols) KEY (conflict) VALUES (...)`——新增 SPI `renderUpsertStatement`（整语句形态优先于 INSERT+后缀），H2 实现之 |
| 2 | **H2 方言保留字用 PG 集合近似，漏包 20+ 词**：`key`/`value`/`values`/`day`/`year`/`interval`/`row`/`if`/`minus`/`qualify`/`rownum`/`top`/`unknown`/`uescape` 等在 H2 裸用作列名直接语法错误 | 🔴 高（漏包 → 语法错误） | H2 引擎逐词实测（89 个裸用被拒词清单） | 新增 [H2_RESERVED]（官方关键字表全量 + 引擎实测核对） |
| 3 | **DM（达梦）保留字用 Oracle 集合近似，双向错误**：DM 额外保留 `top`/`section`/`domain`/`identity`/`int`/`index`/`array` 等（漏包）；Oracle 保留的 `number`/`size`/`level`/`raw` 等 DM 仅关键字——错包后双引号大小写敏感（CASE_SENSITIVE=Y）反而易失配 | 🔴 高 + 🟡 中 | 达梦官方附录 1 逐词核对 | 新增 [DM_RESERVED]（官方附录 1「带 \* 系统保留字」全量 254 词） |
| 4 | **KingBase 保留字用 PG 集合近似，漏包**：金仓额外保留 `auto_increment`/`binary`/`collation`/`ilike`/`minus`/`nvl`/`online`/`rowid`/`rownum`/`synonym`/`top` 等 20+ 词 | 🔴 高（漏包 → 语法错误） | 金仓官方 V9 手册《SQL保留字和关键字》逐词核对 | 新增 [KINGBASE_RESERVED]（官方「保留」分类全量） |
| 5 | MariaDB 保留字 = MySQL 集合近似，漏包：`except`/`intersect`/`binary`/`offset`/`returning`/`row_number` 等 23 词为 MariaDB 保留而 MySQL 8.0 非保留 | 🟡 中 | MariaDB 官方保留字表逐词核对 | 新增 [MARIA_RESERVED] = MySQL 基线 + 官方差量 |
| 6 | PG 集合漏掉官方「reserved (can be function or type name)」类别：`authorization`/`binary`/`concurrently`/`freeze`/`isnull`/`notnull`/`similar` 7 词裸用作列名在真 PG 语法错误 | 🟡 中 | PG 官方关键字附录 + 金仓官方表交叉验证 | [PG_RESERVED] 补齐 7 词 |

SQLite 方言经真实引擎（sqlite-jdbc 内嵌 SQLite 3.50.3）全量验证**无任何缺陷**，MySQL/
Oracle/SQL Server 方言的语法形态在 H2 对应兼容模式全部验证通过（保留字集合本就取官方全量）。

**2026-08-29 Tier 2 真机执行补全**：MySQL（8.4.6/5.7.42）、PostgreSQL（16.14/14.23/17.4）、
Oracle（26ai Free 23.26.2 + 19c/21c/18c/11g）、DM8、KingbaseES V9R1C10 七个家族在 DBX 测试
服务器上执行插件渲染 TC 套件与保留字探针，**零缺陷**（详见第十节）；PG 的
`ON CONFLICT DO UPDATE`、DM 的 `LIMIT 1, 2`、达梦/金仓官方保留字集合等此前只有 H2/文档级
证据的形态全部获得真机实证。

## 二、验证策略与证据分级

```
Tier 1  H2 2.3.232 嵌入式（REGULAR + MODE=MySQL/MariaDB/PostgreSQL/Oracle/MSSQLServer）
        → 语法形态级证据：分页形态 / 引用符号 / UPSERT 形态 / 保留字包裹执行
Tier 1+ SQLite 3.50.3 原生引擎（sqlite-jdbc 内嵌，零外部依赖）
        → 100% 真实证据：SQLite 方言全量
Tier 2  真实引擎（2026-08-29 经 DBX 测试服务器真机执行，见第十节；Testcontainers 路径保留）
        → MySQL 8.4/5.7、PostgreSQL 16/14/17、Oracle 26ai/19c/21c/18c/11g、DM8、KingBase V9
Tier 3  DM / KingBase 官方文档逐词核对（无公开自动化镜像）
        → 黄金断言测试固化文档结论，防回归
```

**核心原则**：被执行的 SQL 一律由插件渲染链路产生（`SqlGenerator.generate` /
`BatchModel.renderSql` 按方言渲染），**不手写 SQL**——验证的是插件真实输出在目标引擎上的
可执行性。`?` 占位符经 PreparedStatement 绑定执行（对齐面板「参数回填后执行」的真实使用形态）。

## 四、保留字全量扫描结果

对每个方言保留字集合**逐词**构造「插件渲染 SELECT + INSERT 模板 + UPDATE + UPSERT（含
保留字列进 EXCLUDED./VALUES()/MERGE KEY 路径）」在对应引擎上执行——「宁可多包」策略的
全量合法性证明：

| 方言 | 保留字词数 | 扫描引擎 | 结果 |
|------|-----------:|----------|------|
| MySQL | 262 | H2 MODE=MySQL | ✅ 0 失败 |
| MariaDB | 285 | H2 MODE=MariaDB | ✅ 0 失败 |
| PostgreSQL | 84 | H2 MODE=PostgreSQL | ✅ 0 失败（UPSERT 步按 SKIP 跳过） |
| Oracle | 109 | H2 MODE=Oracle | ✅ 0 失败 |
| SQL Server | 180 | H2 MODE=MSSQLServer | ✅ 0 失败 |
| H2 | 100 | H2 REGULAR | ✅ 0 失败 |
| SQLite | 147 | SQLite 3.50.3 原生 | ✅ 0 失败 |
| DM | 254 | —（无引擎） | 黄金清单对齐 ✅（词表 = 官方附录 1） |
| KingBase | 117 | —（无引擎） | 黄金清单对齐 ✅（词表 = 官方 V9 手册） |

**反向覆盖探测（漏包检测）**：把各方言集合全集 + 其他方言集合 + 常见业务列名
（name/status/value/key/domain/section/password/text/image/page 等）逐词**裸用**建列+查询，
引擎拒绝的词必须已在插件集合内：

- H2 REGULAR：引擎拒绝 89 词 → 全部 ∈ H2_RESERVED ✅（另 11 个上下文敏感词
  `grant`/`groups`/`ilike`/`leading`/`over`/`partition`/`range`/`regexp`/`rows`/`trailing`/`both`
  裸用可接受，保留在集合中=保守多包，无害）
- SQLite 3.50.3：引擎拒绝 8 词（order/group/limit/index/table/check/transaction/returning）→
  全部 ∈ SQLITE_RESERVED ✅

### 10.2 保留字探针方法说明

真机探针采用「批量建列」法：把方言保留字集合全量作为引用列名建会话级临时表（MySQL 262 列、
DM 254 列、KingBase 117 列、Oracle 109 列、PG 84 列），再以全列 SELECT 与全列 UPDATE 验证
每个引用标识符在真实引擎可解析——等价覆盖原逐词扫描的「引用后可执行」层；逐词
INSERT/UPSERT 路径已由 TC 套件（order/table 保留字列）与 Tier 1/3 覆盖。另：DM 探针中
rowid/rownum/versions 等官方 FAQ 标注「加引号亦不可用」的词，实测以小写引用列名可建可查
（5.1 节的保守标注仍保留，插件不应依赖该行为）。

### 10.3 观察项（无需改动）

- MySQL 8.0.20+ 将 `VALUES(col)` 标记弃用（警告 1287），8.4 实测仍正确执行；5.7/MariaDB 无此
  警告、且不支持 8.4 的别名替代形态——插件维持 `VALUES()` 形态是跨版本兼容的正确选择，待
  MySQL 未来版本真正移除时再跟进。
- DBX MCP 对持久 DDL 有高风险拦截，本次验证全部经临时表完成，无残留对象。

   为准并已在 H2Dialect KDoc 注明。
