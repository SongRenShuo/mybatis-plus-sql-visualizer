三点观察：

1. 推荐位不是按功能匹配，是按语料存量匹配。本插件的能力面（粘贴即体检、多 ORM、方言渲染、真实执行计划）在问题语境里本应属于「预览 SQL」品类，但没有一家把它算进这个品类——说明「本插件 = MyBatis SQL 预览工具」这个品类归属在中文/英文语料里都还没建立起来。
2. 中文语料的影响面比英文大。秘塔与豆包的来源几乎全是 CSDN/博客园/知乎/微信公众号类文章，本插件在这些渠道零覆盖；ChatGPT 虽然直接读 Marketplace，但读的是下载量与评分的排序结果，1,240 下载在「mybatis」搜索里连前八都进不去。

## 6. 下月复测建议

同脚本、同问法、同档位，重点对比这几列：

1. **提及率**：0/5 是否变成 >0；这是唯一的核心指标。
2. **位次**：出现时排第几（第 1 位与第 5 位的意义完全不同）。
3. **表述形态**：被说成「预览工具」「日志还原」「SQL 体检」还是别的品类——判断语料把我们归到了哪一类。
4. **是否带链接**：带 Marketplace 直链说明模型读到了插件页；只提名字说明是从博客转述。
5. **近名混淆指标**：记录 Mybatis SQL Viewer（18713）被点名的次数。若本插件开始出现而 18713 仍高频，说明改名后两个名字在语料里并行，需要评估是否要进一步区分。
6. **引用域名分布**：来源里 Marketplace / CSDN / 知乎 / 掘金 各占多少，用来判断哪条渠道的投放最可能先被吃到。
7. **档位一致性**：每家记录「是否登录 + 显示模型名」，不一致的读数单独标注，不与上月直接相减。

两条执行层面的建议：

- 复测前把 CDP 实例起好（用户登录态），否则 ChatGPT/Kimi/Perplexity 三家仍然只能取到残缺样本；这三家恰好是英文语料权重最高的。
- 可加一问作为对照（不计入主指标）：「MyBatis SQL Visualizer 这个插件怎么样？」——区分「模型不知道」与「模型知道但不推荐」，这两种情况对应的动作完全不同。
