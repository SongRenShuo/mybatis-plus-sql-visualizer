### 3.2 竞品差评痛点（超越机会，均注明出处）

1. **参数还原的类型正确性**（MyBatis Log Free 17898，2025-04-17）：LocalDate 参数还原成裸字面量导致 `ORA-01722: invalid number`，用户自己给出需 `DATE '...'` 包裹的期望——**我方 14 方言渲染底座可做「类型感知字面量还原」，竞品无人做**。
2. **Map/@Param 复杂参数解析误报**（MyBatisX 10119，2026-04-08 / 2026-08-31 / GitHub baomidou#116 2026-10-28 三条同域）：`@Param("map") Map<String,Object>` 的 `map.key` 写法被判「无法解析符号」、`<sql>` 公共片段 `@Param` 误标——**静态解析正确性正是我方 Inspection 环可以正面碾压的面**。
3. **Result type not match 误报**（MyBatisX，2026-02-24）：select 泛型推断误报——我方方言匹配链已有「误报归因三分」经验（262 读锁一役），同类误报的防腐经验可复用。
4. **工具窗不可常驻**（MyBatis Log Free，2026-01-21）：「为什么不能固定在页面上随项目启动，每次 debug 到一半才发现没开」——低成本高感知补齐项。
5. **JPA SQL 不支持还原**（MyBatis Log Free，2025-10-16「如果能支持jpa就好了」）——我方预览环已含 HQL，捕获/还原环向 JPA SQL 延伸是差异化空位。
6. **shardingsphere 等代理层日志格式**（MyBatis Log 13905，2023-05，三年无应答）——还原环的格式扩展位。
7. **付费信任**（MyBatis Log 13905，2023-04「买了也激活了为什么不能用」+「没地方退款」）——反衬我方完全免费的定位主张，文案可直接引用。
8. **补全回归无人管**（CHP 14522，2024-10~2025-03 三条 if test/param 提示丢失无回复）——「用户报障→根因→修复→当日上架」的响应闭环（我方 v2026.11.2/v2026.11.3 两次实证）本身就是竞品做不到的差异。

### 3.3 MyBatis-Plus 社区通用 SQL 调试痛点（来源：[baomidou 官方 p6spy 指南](https://baomidou.com/guides/p6spy)、CSDN/知乎/博客园多篇方案文）
