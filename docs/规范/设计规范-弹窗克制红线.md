## 允许类

默认放行，不需要额外论证，但仍须登记进触点清单。

1. 用户操作反馈：点击按钮后的结果、错误、「未找到」类提示（含跳转失败提示）。
2. 用户操作确认：破坏性操作（清空历史等）的 YesNo 确认、轻量输入框。
3. 含开关的一次性通知：默认关或可永久忽略（现状基准即更新通知的模式），同一触点每会话至多一次。

## 禁止类

一律不做，Code Review 按此驳回。

1. 无开关的插件主动弹窗、导流弹窗。导流只走设置页与 README。
2. 营销/评分引导弹窗。评分引导只进 README 与更新通知正文链接。
3. 频率超限的任何主动触点，超出「每会话一次」即违规。
4. 后台失败转弹窗。维持性能红线结论：主链失败面板内报错或静默降级。

边界判断：「用户点击直接引发」是允许类的客观判据。拿不准的触发路径（如异步回调里弹提示）按禁止类处理，
宁紧勿松。

## 准入五问

新增主动触点前逐问自检，全部通过才准合入：

1. 是否用户点击直接引发？
2. 面板内或通知形态是否确实不够用？
3. 是否带开关或一次性？
4. 频率上限是多少？
5. 是否已在本文触点清单登记？
