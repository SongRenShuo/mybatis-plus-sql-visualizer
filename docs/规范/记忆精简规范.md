# 记忆精简规范

> 规范本地记忆文件（`~/.zcode/cli/memories/.../memory/`）的管理，防止无限增长导致上下文膨胀。
> **适用**：每次完成功能开发或修复后，主动判断记忆去向。

---

## 1. 三类记忆与去向

| 类型 | 特征 | 去向 |
|------|------|------|
| **核心知识** | 架构、模型、约定、活跃功能（未完成/待实施） | 保留在项目 memory |
| **已完成记录** | 已交付的功能、已修复的 bug、已解决的踩坑 | 移入 `docs/memory-archive/` |
| **通用经验** | 平台陷阱、方法论、用户偏好（跨项目复用） | 移入 `~/.zcode/cli/memories/global/` |

### 保留标准（全部满足才保留）

- 下次开发**仍需参考**（如架构决策、注册表映射）
- 处于**活跃状态**（功能待实施、问题未彻底解决）
- **仅本项目独有**（否则归 global）

### 归档标准（满足任一即归档）

- 功能已交付且发行
- Bug 已修复且测试全绿
- 踩坑已解决且不会以相同形态复现
- 开发计划执行完毕

### 全局标准（满足任一即归 global）

- IntelliJ 平台通用陷阱（非本项目特有）
- 多智能体协调方法论
- 用户偏好/环境配置

---

## 2. 归档目录结构

```
docs/memory-archive/
├── README.md                          # 归档索引（导航清单）
├── bug-fixes/                         # 已修复 bug / 已完成功能
├── pitfalls/                          # 已解决踩坑
├── methodology/                       # 智能体方法论（备用）
└── user-context/                      # 用户环境/工具
```

### 归档索引维护

每次归档新增文件后，同步更新 `README.md` 中对应分类表格：新增一行（文件名 + 一句话摘要）+ 更新底部统计。

---

## 3. 操作流程

### 归档操作（每次完成功能/修复后）

1. **判断**：按 §1 标准确定去向（保留 / 归档 / 全局）
2. **移动**：`mv` 文件到对应归档子目录
3. **更新归档索引**：`docs/memory-archive/README.md` 新增条目
4. **更新项目索引**：从项目 `MEMORY.md` 删除已移出条目
5. **更新 docs 索引**：`docs/MEMORY.md` 变更记录追加一行（日期倒序）
6. **提交**：`git add` 归档文件 + 索引，`git commit`

### 定期审视（每 2~4 周或记忆增长 20%+ 时）

1. 列出项目 memory 全部文件
2. 逐文件按 §1 标准重新分类
3. 批量移动 + 更新索引

---

## 4. 全局记忆维护

全局记忆（`~/.zcode/cli/memories/global/`）不受 ZCode 自动加载，但作为完整备份。

- 新项目启动时，按需从 `global/` 复制到项目 memory
- 全局经验精炼摘要写在 `~/.zcode/AGENTS.md`（自动加载）
- `global/README.md` 维护全局索引

---

## 5. 数量基线

| 位置 | 基线 | 预警线 |
|------|------|--------|
| 项目 memory（含 MEMORY.md） | ~15 | >25 |
| 归档 archive | 持续增长（历史记录） | — |
| 全局 global | ~40 | >60 |

超过预警线时触发定期审视。

---

## 6. 索引更新格式

### 项目 MEMORY.md

```markdown
## 归档记忆（`docs/memory-archive/`）

> 已修复 bug（X个）+ 已解决踩坑（Y个）+ 用户环境（Z个）= N 个文件。
> 索引见 [docs/memory-archive/README.md](../memory-archive/README.md)。
```

### docs/MEMORY.md 变更记录

```markdown
| 2026-08-26 | 记忆第N精简（A→B）：新增 X 个归档（...）；archive 增至 Y 个文件 |
```

变更记录**必须日期倒序**（最新一行在表格顶部）。

---

## 7. 示例

### 归档一个已修复 bug

```bash
# 1. 移动
mv ~/.zcode/cli/memories/projects/.../memory/project-xxx-bugfix.md \
   docs/memory-archive/bug-fixes/

# 2. 更新归档索引（docs/memory-archive/README.md 表格新增一行）
# 3. 更新项目索引（MEMORY.md 删除该条目）
# 4. 更新 docs 索引（docs/MEMORY.md 变更记录追加一行）

# 5. 提交
git add docs/memory-archive/ docs/MEMORY.md
git commit -m "chore: 归档 project-xxx-bugfix"
```

### 归档一个平台陷阱

```bash
# 1. 复制到全局
cp ~/.zcode/cli/memories/projects/.../memory/pitfall-xxx.md \
   ~/.zcode/cli/memories/global/

# 2. 从项目 memory 删除
rm ~/.zcode/cli/memories/projects/.../memory/pitfall-xxx.md

# 3. 更新 global/README.md
# 4. 更新项目 MEMORY.md
```

---

> **原则**：记忆是开发过程的副产品，不是纪念品。已完成的记录就该归档，让活跃知识保持精简。
