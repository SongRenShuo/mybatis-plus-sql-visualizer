### 增强捕获心跳与重连（T-AgentHeartbeat，2026-09-21 立项）

**改动文件**：SenderLoop.java（agent）/ AgentProtocol / AgentManager / SqlLogManager / SqlLogPanel / CaptureDiagnostics

> **背景**：T-RA-01（2026-09-18）落地在线窗口后，会话在建立后**恰好 30 秒**被摘除——agent 侧心跳实际
> 60.6 秒一发（`idleMs` 记的是假定耗时，每轮 +200ms，而每轮真实耗时约 1200ms），首条心跳永远赶不上 30 秒窗口；
> 且摘除后无法重连（premain 通道只 accept 一次就关监听 socket）。沙盒日志四轮运行全部命中，
> 用户侧表现是「一条都捕不到」。本组用例是修完后必须逐项确认的真机行为，**headless 单测覆盖不到**。

- [ ] 启动应用后**不碰面板**静等 2 分钟以上，`idea.log` 内 `增强捕获在线态切换: true -> false` **0 条**（修复前：30 秒处必有一条）
- [ ] 上述期间设置页「增强捕获」状态行持续显示「已挂载 pid=…」，**不得**出现任何心跳类回落文案
- [ ] 应用刚启动的那几秒，状态行**不得**报心跳停摆、更不得出现「进程可能已卡死」这类因果断言（⚠️ 独立复核订正口径：T-01 修复后 agent 连上即发心跳，**「等待中」这一态在真机上几乎不可复现**——唯一可复现路径是旧版 agent jar 仍在运行的宿主 JVM；该态本身由 `AgentHeartbeatWindowTest` 单测覆盖，真机这一条只需确认**不误报停摆**）
- [ ] 应用真正停摆（或手工 kill 会话）后，状态行才报心跳类回落，文案形如「已 30 秒未收到应用侧心跳，已回落控制台捕获」——**秒数应取在线窗口值**（改了窗口应跟着变），且不含因果断言
- [ ] 英文界面下同两态文案可读且带秒数（headless 下 `MpSqlVisualizerBundle` 兜底中文，英文侧只由键集合/占位符守卫覆盖，必须在真机看一眼）
- [ ] 手工制造一次掉线（停应用再启、或临时 kill 会话）→ 增强通道**自行恢复**，无需重启 IDE、无需重新点捕捉
- [ ] 连续跑两次应用（起→停→起），`premainChannels` 不随运行次数增长，日志无通道堆积告警（`MAX_PREMAIN_CHANNELS = 4` 不应被撞到）
- [ ] IDE 退出无 "Memory leak detected"（accept 线程与 socket 已挂进 disposable 树）
- [ ] 空态诊断行三行完整可见、提示语**不被右边界截断**；工具窗拉到最窄再截一次确认换行仍生效
- [ ] 捕获到 SQL 后诊断行消失、条目正常进列表（增强通道确实能捕到 SQL——本轮唯一未验的前提）

> **真机/沙盒操作配方（2026-09-21 N7 验收实测沉淀）**
>
> 1. **冻结应用进程模拟「停摆」**：`kill -STOP <pid>` 在 Git Bash 里对**原生 Windows PID 不可用**（报 `No such process`）。
>    改用 ntdll：`OpenProcess(0x0800)` + `NtSuspendProcess` / `NtResumeProcess`（PowerShell `Add-Type` P/Invoke，脚本见
>    `%TEMP%/proc.ps1`）。判定冻结成功的标志：端口仍在 LISTENING 但接口请求无响应（curl 返回 `000`）。
> 2. **冻结会让 HikariCP 打 `Thread starvation or clock leap detected`**——预期副作用，不是缺陷。
> 3. **收工必须确认沙盒 IDE 进程真的退出**：强停 gradle 任务**不会**带走 IDE 的 JBR `java.exe` 与 `fsnotifier.exe`；
>    残留进程会锁住 `~/.gradle/caches/9.7.0/transforms/<hash>`，让下一次 `runIde` 直接 `BUILD FAILED`
>    （`Unable to delete directory …`，连带 `:plainFjpfJar`/`:patchPluginXml`/`:compileMcpStubKotlin` 失败）。
>    清理清单是**三样**：IDE 的 JBR `java.exe` + `fsnotifier.exe` + **IDE 启动的应用 JVM**——第三样最容易漏，
   而它恰恰是关键：应用 JVM 会加载 IDE transform 目录里的 `libasyncProfiler.dll`，Windows 锁住已加载的 DLL，
   于是整个 transform 目录删不掉（手动删除时报 `对路径"libasyncProfiler.dll"的访问被拒绝`）。
   只清前两个仍会 `BUILD FAILED`。定位配方：遍历各进程模块找 `libasyncProfiler.dll` 拿到 pid → `Stop-Process -Force`
   → 手动 `Remove-Item -Recurse -Force` 验证解锁。
>
> 6. **优雅退出是两个确认框，不是一步**：关窗 → ① `Confirm Exit`（Are you sure you want to exit?）→
>    ② `Process 'X' Is Running`（Do you want to terminate the process?）→ 必须点 **Terminate** 才继续退出。
>    只点第①步的 Exit，IDE 会停在第②步等输入（表现为「点了退出却没退」）。若先手动杀掉应用进程，则只需第①步。
> 4. **GUI 驱动路线**：沙盒 IDE 的 a11y 树只有窗口级元素（7 个），坐标点击需要有效的 CUA frame 且 frame 易过期；
>    实测可行组合是 **PowerShell 全屏 `CopyFromScreen` 取图 + 裁剪放大读像素 + CUA 键盘**。键盘发送前**必须先用一次
>    点击把 IDE 置前**，否则报 `frontmost_pid_mismatch`。工具窗口菜单只能键盘导航（View → Tool Windows 子菜单里
>    `SQL Visualizer` 是第 13 项 → `Down×12 + Return`）。
> 5. **面板「移除重复的 SQL」默认勾选**：窗口内重复 SQL 会被**丢弃**、只把丢弃数记到已有条目的 `×N` 徽标上
>    （`SqlLogEntryBuffer.addEntry`）。验「一次请求一条条目」时**必须先取消勾选**，否则重复请求本就不该出现新条目。

### 热替换本地验证（T-DynUpdate，不依赖 Gitee/市场）

标准流程只有两步：

1. **构建新版包**（版本号必须高于 gradle.properties 的当前版本）：

       ./gradlew buildPlugin -Pversion=2026.9.12-beta.1

2. **点「Run IDE (Local Manifest)」**，然后沙盒里：设置 → SQL Visualizer → 更新分区 → 检查更新 → 下载并安装。

其余全自动：

- 本地清单服务随任务生命周期自动起停——任务启动时自动拉起 `dev-support/hotswap-local-server.py`
  （扫描 build/distributions 最新的 `mybatis-plus-sql-visualizer-*.zip`，自动在该目录生成
  `update.json`，端口 8919）；端口被占（用户手动起过）则复用不接管；IDE 关闭/崩溃/任务失败
  都由 `hotswapServerStop` 按 pid 文件停服务，只杀自有进程。服务日志：`build/hotswap-server.log`。
- `update.json` 每次服务启动时自动重生成——**先构建新包、再点 Run 配置**（服务是任务启动时
  才拉起的，天然满足顺序）；点完再构建新包的话，重启一次服务即指向新包。
- 全局 `runIde` 与 `runIdeHotSwap` 两任务都挂了同一套起停，点到哪个配置都能跑通；
  `runIdeHotSwap` 关闭了 autoReload（防平台自动重载器与热替换竞态），结果更干净。

判定免重启成功：通知「已更新并立即生效」（而非「重启 IDE 生效」）；沙盒 idea.log 搜
`dynamic install succeeded — plugin hot-reloaded`；设置页当前版本即时变化；更新后立刻开
预览/日志窗口功能正常。失败定位：idea.log 搜 `dynamic install not applicable — falling
back to restart script:`，原因字段写明卡在哪一环。

重置：直接重跑 Run 配置（prepareSandbox 每次覆盖沙盒插件目录，测试状态自动归零）。

注意：「从磁盘安装」（Install from Disk）测不出免重启——平台该流程不卸载已加载旧版，必提示重启（F0 反编译实证），不能据此判断功能无效。
