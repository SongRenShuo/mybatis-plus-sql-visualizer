**W1 与 N-24 是同一件事的两半：W1 是「写」（备料），N-24 是「发」（发射）。** 竞品报告里反复出现「W1 三件文案 + N-24 发射」，但定义散在多份计划里，20261026 用户追问「W1 三件文案 + N-24 是什么」时才逐处查清。

**W1 文案备料三件双语**（权威出处 `docs/开发计划/20261001-1141-竞品对比第十九轮落地对账与发行窗口增量-开发计划.md` §W1，标题原文「W1 N-24 文案备料（P0 的半边，零开发成本）」）：

1. **首评引导帖**
2. **评分引导话术**
3. **Gitee 内测用户邀请清单**

要求双语，落 `docs/发行说明/` 同级的 N-24 备料文件。**验收**＝三件成稿双语齐、用户过目记录在案、合规自查对照 **V47** 留痕。V47（同计划 §待验证前提）＝引导文案合规边界：**只邀请真实内测用户自愿留评、不代写内容、不承诺回报**（对照 Marketplace 政策自查 + 用户把关）。

**N-24 破零三件套**（出处 `docs/开发计划/20260930-1712-竞品对比近轮汇总-建议收敛与落地排期-开发计划.md` P0-1）：**首评引导 + 评分引导 + Gitee 内测用户 Marketplace 留评**。更早的原始定义在竞品第七轮记忆档：N-24（画像重发+边界声明+首评，**市场动作不立计划**）。

**两条硬约束**：

- **零弹窗**——`docs/设计规范-弹窗克制红线.md` 禁止类第 2 条明写「营销/评分引导弹窗。评分引导只进 README 与更新通知正文链接」。⇒ 这件事**不能做成插件里弹「给个好评吧」**，只能走人工件。
- **不催审、不盯梢**。

**判据**：`33633 comments ≥ 1` 或 `rating votes ≥ 1`（即「破零」）。`docs/发行说明/T-ReleaseChecklist-发行检查清单.md` §八 的执行节奏也把它写进正常发行链：`§二 → §三 → §四（第一档收口）→ N-24 破零三件套`。

**为什么卡了十六轮**：W1 是**纯人工件**（零开发成本但需人写三件双语文案，无自动化可替）；N-24 是**市场动作**（按惯例不立计划、随发行窗口执行）。两者都落在「只有用户能做」那一栏。

**20261026 为什么更值得做**：①67 天 0 评 0 票；②全市场 45 家 25 家零票、有票的 20 家票数中位仅 9 ⇒ 品类评价资产极度稀疏，「拿到前 10 票」的相对可见度收益可能高于成熟品类；③上架已完成但下载日增仅 +4、八词位次基本未动 ⇒ **上架解决「能被搜到」，解决不了「被搜到之后为什么选你」**，后者抓手正是评价资产。

## 20261026 用户裁决与两件展开

**第三件（Gitee 内测用户邀请清单）用户明确不做**（原话「第三个明确不做」）。与既有定案一致：该件的**机制件**（issue 模板/名单/投票贴）在 R41 那轮已被用户裁定废弃，理由四条——池内无人（0 评 0 票第 49 天，无参与者可池）、前置倒置（原建议「破零后启动」，D39 定案取了后半句）、瓶颈在分发侧（先修管道再谈收集）、零码≠零成本（名单/答复/投票贴是持续人力）。当时只保留「内测邀请清单」为纯文案件，现一并明确不做。

**首评引导帖 vs 评分引导话术 的区别**（目标同一＝破零，门���不同）：

- **首评引导帖**＝长文稿，面向愿意花时间写点东西的用户。要解决的心理门槛：用户看到 0 条评论会觉得「没人用过、没人认可」，不愿当第一个；文稿要替用户跨过它——说明为什么值得留、留什么（「你用它解决过什么具体问题」比「很好用」有用得多）、怎么留。文档给的投放渠道只写「更新通知 + README」。
- **评分引导话术**＝短措辞模板，面向顺手就能点一下的用户。**已有硬规格**：`T-ReleaseChecklist` §1.2「末尾补一行 **≤60 字** Marketplace 评分引导（中性措辞，如「好用的话，欢迎到 Marketplace 页评分留言（搜 SQL Visualizer）」，**无激励、无模板评语**）」。**现状**＝这句话已存在但只有一处：`update/preview.update.json` 的 changeNotes 末行（自 2026.10.16 起）；**README 里没有**（grep「评分/留言/好评」零命中），README 第 166 行「更新与诊断」节也没提。⇒ W1 这件要补的是把它扩成**分场景的双语模板**并落到 README 与发行说明。

**两条合规红线**（写稿时同时过）：①弹窗克制红线禁止类第 2 条——只进 README 与更新通知正文链接，不做弹窗；②Marketplace 评价准则——中性措辞、无激励、无模板评语，不能写「给五星好评」、不能承诺回报。

**待用户定的一个点**：首评引导帖的「帖」落在哪。文档只写「更新通知+README」，但竞品第七轮还提过「势头数据转 Gitee 发行说明置顶」，而插件内**已有交流群入口**（`log.community.action`「加入交流群」，扫码加微信群，在 SQL 日志面板）。三渠道性质不同：更新通知+README 合规最稳但只触达「正在更新/看文档」的人；Gitee 发行说明置顶触达内测群（自己人，破零价值低）；交流群触达最精准（已加群的是真用户）但属「主动触达」，是否越线须用户拍。
