# 沙盒 GUI 点击不落点的四类真因（2026-11-01 一次踩齐）

同一轮里把「点执行计划没反应」误判过两次，最后发现是四个独立原因叠加。**每次都要按序排除，别急着怀疑插件。**

## ① 对话框工具栏坐标每会话漂移（最坑）

同一对话框、同一分辨率，两次会话工具栏 y 相差 **25~27px**（175→165 的窗口位置差 + 布局差异）。复用上一轮的坐标 = 整行点空。
**判据**：不要靠目测整屏截图估算，**裁剪放大目标区域**（`ImageGrab.crop(...).resize(2x)`）再读像素位置；或直接悬停到候选点，看按钮是否出现 hover 高亮——**悬停自证**是最便宜的对位法。
本轮实测值：对话框 `(365,165,1190,702)` 时，工具栏按钮中心在 **y≈226**（不是 209），「执行计划」x≈**1305**（不是 1342）。两个都偏 15~40px。

## ② 探针里的 `front()` 会把主窗提到对话框之上

自己的探针若在点击前统一 `front()`（把 IDE 主窗置前），会把**模态对话框压到后面**，点击落在主窗的编辑器上——现象和「按钮不响应」完全一样。
**修法**：点击对话框内的控件时，用 `EnumWindows` 按 rect 命中该对话框 HWND，`SetWindowPos(HWND_TOP)` + `SetForegroundWindow` 置前，**不要**置前主窗。置前成功要读回 `GetForegroundWindow()==hwnd` 自证。

## ③ 阳性对照必须选「点了一定会变」的按钮

本轮第一次用「格式化」做对照——但 SQL 本来就已格式化，点了没变化，于是把「点击没落上」误读成「整行不可达」。第二次用「压缩」也没变（因为压缩同样是切换态，当前已在压缩态）。
**判据**：对照要选**幂等性差**的操作（会改文本/弹窗/切页签的），或者干脆用「悬停高亮」这种零副作用的判据。

## ④ 插件自绘工具栏/列表对 robot-server 完全不可见

`//*` 全量查询里，插件自绘的工具窗/对话框内部组件**一个都不出现**（只有平台壳组件）。所以「robot 查不到按钮」不能推出「按钮不存在」，只能推出「这条路走不通，改用像素/悬停」。
判据：查询结果里若只剩 `JBPanel`/`NonOpaquePanel`/`SquareStripeButton` 这类平台壳，就别再在组件树上耗时间。

## 通用纪律

- **先疑探针，再疑插件**：本轮四次「不响应」全部是探针问题，插件一次没错。
- **每次点击后立刻取一次日志**（`grep <该动作的固定日志前缀>`）作为「是否真的触发」的硬判据，比看界面变化可靠——界面变化可能被遮挡、可能是切换态。
- 动作入口若在对话框内，**先确认对话框在前台**（`GetForegroundWindow` 读回自证），再点。
