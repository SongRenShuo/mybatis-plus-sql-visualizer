# 表格内并排图片「大小不一」的根因在渲染器，不在图片

## 症状

同一篇 Markdown 里，两张 220×220 的二维码用两列表格并排，渲染后一张 178px、一张 163px（差 15px，肉眼明显）。

## 已排除：不是图片本身

实测两张原图均为 220×220，内容包围盒分别 195×194 与 197×198，几乎对称——差异不足以解释 15px。

## 受控实验（决定性证据）

在 Chromium 里造最小复现页：表格 + `<img width="180" height="180">`，两张渲出来**等大**；换成两张独立段落同样等大。所以「表格 + width」在标准浏览器里是好的。

**但用户的实际预览器（IDE 内置 Markdown 预览）渲染成 178 vs 163。** 结论：那类渲染器**忽略表格单元格内图片的 `width`/`height`**，改按列宽各自缩放，两列文字长度不同就出现大小差。

## 修法（按优先级）

1. **改成行内并排，不走表格布局**（用户最终采纳）：
   ```html
   <img src="a.png" width="200" alt="A"/> <img src="b.png" width="200" alt="B"/>
   ```
   行内图片不受列宽约束，两码等大。用途区分改用**正文一句话**说明（「左边是 A…；右边是 B…」），不要依赖表头。
2. 若必须并排且要求绝对等大，可**离线合成单张图**：两图各裁到内容包围盒 → 统一缩放到同一内容尺寸（如 200×200，顺带消掉 195 vs 197 这点原始差异）→ 四周补 10~12px 白边作安静区（保证扫码可识别）→ 拼接并在下方打标签。代价是二维码过期时要重跑合成，不如方案 1 好维护。
3. **不要靠「再加一个 width 属性」修**——属性本来就没生效，加了也没用。

## 验证做法

- 渲染后截图，量两张图亮区的包围盒（`numpy` 取 `>200` 的像素范围），直接比宽度/高度。
- 图片要「码里带码」时（二维码），合成/缩放后用 `cv2.QRCodeDetector().detectAndDecodeMulti` 或分半 `detectAndDecode` 解码自证——缩到 200px 加白边后仍能扫出原始链接才算可用。绿色码在二值化后更易解出，黑色码原图即解。

## 同族场景

任何「表格内并排图」都适用：联系二维码、功能前后对照图、并排卡片式说明。**判据：只要两张图在同一个表格行里，尺寸就不可靠。**
