# 文档约定

## 命名规范（docs/文档命名规范-说明文档.md）

- `docs/开发计划/{YYYYMMDD-HHMM}-{功能名}-开发计划.md`（**时分制**，不是序号！例如 `20260820-1752-多租户拦截器-开发计划.md`；同分钟冲突用 `-N` 后缀区分）
- `docs/需求文档/{...}-{功能名}-需求文档.md`、`docs/发行说明/{...}-{功能名}-发行说明.md`（段数**严格两段**：8 位日期 + 4 位时分）
- **⚠️ 日期段写成 10 位（`2026101009`）是本仓实测的惯犯缺陷（20261008 用户两次点名修）**：`2026101009-0000-…`/`2026101007-0000-…` 两个发行说明文件名日期段 10 位（疑似把 `YYYYMMDD` 当 `YYYYMM` 后接 `DD`），正名 `20261009-0000-…`/`20261007-0000-…`。**修法**：`git mv` 改名 → 全仓引用同步（本例 5 处：MEMORY.md 索引 2 行、变更记录 2 行、调研报告 1 行）→ 残留扫 0 → 目标存在性核。**扫描判据可复用**（python `os.walk` + 正则 `^(\d+)-(\d+)-`，判 `len(日期)!=8 or len(时分)!=4`）：本仓 docs/ 下只有这两个中招；`.workbuddy*/memory/2026-09-12.md` 这类代理笔记用 `YYYY-MM-DD` 是**另一套约定，勿动**。
- **⚠️ override-only API 违规（`@ApiStatus.OverrideOnly` 被调用）也会进 verifyGate 报数**——20261008 实测三目标各 2 条，修法与 javap 核验路径见 [[project-release-workflow]]（把列表抽成自有单一来源，别调 `DefaultActionGroup.getChildren`）。
- `docs/调研报告/{...}-{主题}-调研报告.md`（2026-09-12 起独立目录，竞品分析/可行性分析/技术验证归此；调研立项计划仍归开发计划）
- 发行说明内链接用绝对路径（Gitee 仓库 URL），开发计划内用相对路径

## docs/ 结构定案（20261031 收口，`#22` 全部执行完毕）

**根级只剩 3 个 md，各有留存理由**：`MEMORY.md`（索引入口）、`变更记录.md`（唯一权威总册）、`LESSONS.md`（活跃教训账本，收口高频追加）。其余约定类全部在 `docs/规范/`。

**判据（已写进规范第 6 条）**：**「稳定规则/约定」进 `docs/规范/`；「活跃账本 / 索引入口 / 权威总册」留根**。据此 `code-standards.md` 于 20261031 移入 `docs/规范/编码与验收标准-规范.md`（git mv 保历史 + 10 处引用同步：AGENTS.md 1、LESSONS 8、MEMORY 1、开发流程/夜间复盘协议 4）。

**规范后缀扩为四种**：`-规范.md`（约定）／`-清单.md`（可勾选验收项）／`-红线.md`（禁止项）／`-说明文档.md`（长期说明：机制/指南/协议）。原文只列前三种，与实际不符（`文档命名规范-说明文档.md`、`代码编辑规范-grep优先读取.md`、`task-queue任务队列-说明文档.md` 无处归类）。

**存量豁免**：命名规范**只约束新增文件**。存量文件不因命名不符合而重命名——`docs/` 下的路径被文档站链接、`docs/索引/` 索引行与若干守卫测试的路径字面量引用（路径本身是契约，参见 [[pitfall-doc-sample-path-is-test-contract]]），改名会静默打断它们。仍有个别无后缀者（`PSI跨线程读取协议.md`）按豁免处理。

**方案里此前已完成的（别重复做）**：`docs/调研/`→`调研报告/`、`docs/验收报告/`→`验收文档/` 两处合流已完成（目录已不存在）；`变更记录/` 已拆 `全量-YYYY-MM[-上半月|下半月].md` + `发行-YYYY-MM.md`；开发计划不按月分目录（明确不做，611 件命名 100% 合规 + 已有全量索引）。

**⚠️ 2026-11-04 实测：我自己把 `docs/验收报告/` 复活了（用户当场点名「你不应该独立一个目录」）**——写 262 沙盒验收材料时凭手感建了 `docs/验收报告/` + `-验收报告.md` 后缀，而该目录已于 2026-10-28 合流进 `docs/验收文档/` 并删除、后缀统一为 `-验收文档.md`。**判据链（三条互证）**：`docs/索引/索引变更记录.md` 2026-10-28 行明写「两个空目录删除」；`docs/MEMORY.md` §验收文档 写「含原 `docs/验收报告/` 并入的两篇」；主仓 master 只有 `docs/验收文档/`。

## 发行流程与 CHANGELOG/changeNotes 约定（2026-08-14 定稿）

- 发行说明文档：`docs/发行说明/{YYYYMMDD-HHMM}-{功能名}-发行说明.md`（示例：`20260813-1511-首发-...`、`20260814-1538-官方API全覆盖与批量增强-...`）；链接一律 Gitee 绝对路径；发布时打 tag `v{版本号}` + 附件 zip `mybatis-plus-sql-visualizer-{版本号}.zip`
- **CHANGELOG.md 版本化结构**：每版本一个 `## [{版本号}] - {YYYY-MM-DD}` 分区（最新在上），分区内子标题**每版本唯一**（### Added/Changed/Removed/Fixed 各至多一个——重复子标题正是 M18.2 changeNotes 解析取错分区的根因）；条目按用户视角简明汇总，全量技术细节进 `docs/变更记录.md` 总册
- **changeNotes 单一来源**：`build.gradle.kts` patchPluginXml 显式配置（勿依赖 changelog 插件自动注入）；结构为每版本一个 `<h2>v{版本号}</h2>` 标题块 + `<ul>` 高亮条目，**保留全部版本标题**（v2026.8.20 起不再局限最新两个版本，全部版本按倒序保留）；验证用 `./gradlew patchPluginXml` 后查 `build/tmp/patchPluginXml/plugin.xml`
- **⚠️ changeNotes 条目只保留标题（2026-08-20 用户反馈）**：changeNotes 每条 `<li>` 只写**标题式短语**（如「参数导入交互体验升级（手动输入弹窗 + 驼峰/下划线自动匹配 + 清除按钮）」），**不要带长详情段**（括号注水 / 完整技术说明去掉）——近几次版本曾写成详情段落被用户要求收敛为标题；CHANGELOG.md 保留完整详情，changeNotes 走精炼标题
- 发布日流程：gradle.properties 版本号 → 当日日期（一日一版）→ 构建 → 打 tag → Gitee 发行版粘贴发行说明
- ⚠️ 首发（v2026.8.13）漏做 CHANGELOG `[Unreleased]` 关闭（版本号规范 §7 要求改名），2026-08-14 补回填为 `[2026.8.13] - 2026-08-13`
- ⚠️ CHANGELOG.md 换行实测（2026-09-04 python 检测 LF count=635、CRLF=0；docs/变更记录.md 同样全 LF）——git autocrlf 警告「LF will be replaced by CRLF」仅是仓库触碰时行为，**当前工作区文件是 LF**，脚本编辑按 LF 处理勿再转（历史记忆写 CRLF 已过时）
- ⚠️ 换行实况已再变（2026-09-08）：dev worktree 的 CHANGELOG.md 实测**全 CRLF**（680 行全 \r\n，疑某次合并重写所致），docs/变更记录.md 仍全 LF——python 锚点编辑前先探测实际换行符、按现状写入（锚点带 `\n` 不带 `\r` 会 assert 失败）
