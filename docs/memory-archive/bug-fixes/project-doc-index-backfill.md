`docs/索引/开发计划.md` 是 `docs/开发计划/` 的完整清单（时间倒序表格，列＝文档/用途/状态）。索引漂移在本仓是反复出现的治理债（竞品第三十二轮记「缺口 14→23」并立 D195 项，验收判据 V220＝缺口归零）。

**对账判据（20261029 实测口径）**
- 缺口 = 目录内 `.md` 文件数 − 索引已登记 `.md` 行数；**反向孤儿必须为 0**（索引里有行、磁盘无文件＝另一类债）。
- 非计划件不入册：本次唯一未登记项是 `20260816-1600-三处图标统一优化-预览.png`（图标预览图），剔除后 615/615 全覆盖。
- 状态列按各册「§实施记录」实测回填：已实施写提交号+关键读数；仅分析/待拍板/待录制如实标注；决策已被后轮刷新取代的写「未执行即作废，历史留档」。

**工具链坑**：Git Bash 的 `comm` 在 CRLF 混合行尾 + cygheap fork 失败下给出「零交集」假结果（曾误判 616 条全缺）。改用
`grep -oP '\[\K[^/]+\.md(?=\])' 索引 | sort -u` 取已登记集合，再 `grep -vFxf idx dir` 求差集——文本模式不吃 collation 与行尾。详见 [[pitfall-msys-comm-zero-overlap]]。

**插入手法**：先 `grep -n -oP '^\| \[\K[0-9]{8}-[0-9]{4}'` 列出现有行日期，按时间倒序找到相邻锚点行，逐批 Edit 插在锚点前（一次编辑一个锚点，锚点互不重叠）。

**Why**: 索引是「存在性记忆」的机械兜底；缺口不会自己收敛，且每次新增计划册都会扩大它。回填是一次性劳动，但判据与工具坑会重复遇到。

**How to apply**: 用户说「索引也要维护」时：①先算缺口与反向孤儿并报数；②按时间倒序补；③补完复算到「md 全命中 + 仅非计划件未登记」；④与代码提交分开单独一笔（`docs(索引): …`）。相关：[[project-doc-conventions]]、[[project-perf-review-round5-20261029]]。
