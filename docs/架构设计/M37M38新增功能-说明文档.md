## 二、分功能使用说明

### 2.1 gutter 图标左右键交互

MP Wrapper 链锚点图标（`new QueryWrapper<>()...` 所在行左侧）的点击行为改为：

- **左键单击**：直接弹出该锚点的 SQL 预览，一键路径最短；
- **右键单击**：弹出菜单，两项可选——「预览 SQL」（同左键）和「最近执行记录」。

其他预览图标（注解 SQL、XML、JPA/HQL 等）行为不变，仍是单击直接预览。

### 2.2 从源码反查最近执行记录

调试时常见反向诉求：看着 Wrapper 链源码，想知道它最近一次实际执行长什么样。在锚点图标上右键选「最近执行记录」，插件从本次会话捕获的日志条目里反查这个位置附近的执行记录（同文件优先、行号 ±30 行内的排前面），选中一条即打开带参数的完整 SQL 预览。

前置条件：日志捕获处于开启状态且已经捕获过该位置的执行。没捕获到时菜单项为空，属正常。

### 2.3 真实 EXPLAIN 执行计划

**入口**：预览面板按钮行的「执行计划」按钮（v2026.9.10 起中文文案由「EXPLAIN」汉化，英文界面保留术语；导入/对比/分享等低频按钮已折叠进「更多」菜单）。

**用法**：先在预览面板看到 SQL，选中数据源后点「EXPLAIN」，插件按当前方言把 SQL 包装成 EXPLAIN 语句提交原生数据库控制台执行，真实执行计划与面板顶部的静态性能规则标注同屏对照。EXPLAIN 属免确认类操作，不会有 DML 二次确认弹窗。

> **后续演进（2026-10-24 起，T-ExplainConsoleFirst / T-DialectInferPollution）**：行为方向不变，但通道与取源已收口——①执行计划默认在**预览窗内嵌原生控制台**里出结果（结果区换入平台控制台文档，不替换预览编辑器），独立的原计划弹窗 `showExplainRawResultDialog` 已退役；②取源改为「模块学习归属 → 上次使用（与模块学习冲突不猜）→ 表归属路由」，插件不再枚举/筛选数据源，换源完全交给平台原生 Data Sources 菜单；③带索引建议与计划 Diff 的结构化渲染是 `explainStructuredRender`（**默认关**）之后的实验形态，推荐只提示一次。详见 02 篇 §2.8。

方言支持情况：

| 方言 | 渲染形态 | 验证方式 |
|------|----------|----------|
| MySQL / MariaDB | `EXPLAIN <sql>`（裸 EXPLAIN，对齐原生行为——平台结果网格不消费 JSON；早期 `EXPLAIN FORMAT=JSON` 为自创形态，T-ExplainFirstNative 起弃用） | 引擎级单测 + 真机走查 |
| PostgreSQL | `EXPLAIN (FORMAT JSON, VERBOSE) <sql>` | 真机通过 |
| 人大金仓 KingBase | `EXPLAIN (FORMAT JSON) <sql>` | 真机通过 |
| 达梦 DM | `EXPLAIN <sql>` | 真机通过 |
| H2 | `EXPLAIN PLAN FOR <sql>` | 引擎级单测 |
| SQLite | `EXPLAIN QUERY PLAN <sql>` | 引擎级单测 |
| Oracle / SQL Server | 不支持，点击后提示降级 | 结构性不支持 |

注意：「执行 SQL」能力依赖数据源（Ultimate 的 Database 工具窗），没配数据源时执行链会报错提示，先配置数据源再使用。

### 2.4 生成测试资产（已下线）

> **下线注记（双线一致）**：dev 主线于 2026-09-07 下线该功能（静态 SQL 文本 + 占位断言骨架，不感知项目测试栈、断言需手工补齐，实际使用价值不足）；本分支曾在 N-9（T-TestAssertReal）以数据源 schema 分档增强（B 档：NOT NULL 列清单注释 + SELECT 校验骨架 + count 前后对比占位），2026-09-10 经用户复核生成产物后确认价值仍不足——测试的难点在测试栈接线（Spring/数据源/前置数据/断言语义）而非 SQL 字符串行，分档弥补不了「生成的是待补骨架」这一本质，遂跟随 dev 双线一致下线。面板按钮与 `src/test/resources/sql-visualizer/` 落盘链路整体移除；`DatabaseSchemaResolver` 的 notNull 列元数据保留（schema 层能力，JOIN 富化/补全共用）。git 历史可找回；如需可执行用例生成（感知测试栈、生成即可跑）待重新立项。

### 2.5 首条 SQL 自动展开日志工具窗

捕获到第一条 SQL 时自动展开日志工具窗（60 秒防抖，展开不抢编辑器焦点）。默认开启，对应设置页「SQL 日志」分组里的「发现 SQL 时自动打开日志窗口」开关；升级前手动关过该开关的老用户保持关闭，不受影响。

前置条件：展开只随 SQL 捕获发生——开关开着但从未开始捕捉（「启动时自动捕捉」也关着）时不会弹；点「停止捕捉」后自动展开一并失效，重新开始捕捉才恢复。若嫌窗口打扰，手动关掉即可：关闭后本次会话内不再自动展开（设置开关重新开启或重启 IDE 后恢复），不会出现「关了又弹回」。

### 2.6 多模块源根跳转容错

日志条目「跳转源码」在标准 `src/main/java` 直拼失败时，改为按模块 content root 逐个匹配定位。多模块项目、源码根不在常规位置的项目里，跳转成功率明显提升。无新入口，原日志面板跳转行为自动受益。

## 三、顺带修复的预览问题

以下问题在竞品对比和回归矩阵建设过程中复现并修复，使用者直接受益，无需操作：

| 问题 | 修复后行为 |
|------|-----------|
| `ne` 渲染成 `!=` | 对齐 MP 官方语义，渲染 `<>` |
| `or(w -> w.eq(2).eq(3))` 嵌套条件连接词颠倒 | 组内恒 AND，外层按 or 表达 |
| 负数字面量（`-1`、`-5L`）被误判为运行时占位符 | 正确识别为常量 |
| `set(condition=false, 列, 值)` 仍拼接 SET 子句 | 与 MP 运行时一致，整段不拼接 |
| `last("LIMIT 5 OFFSET 10")` 的 OFFSET 丢失 | 完整保留 |
| `having(String)` 字符串版被静默丢弃 | 原生片段透传渲染 |
| JdbcTemplate 日志 `parameter value [null]` 渲染成 `'null'` | 正确渲染为 NULL |
| `new Helper().lambdaQuery()` 撞名工厂调用被误标锚点图标 | 不再误报 |
| 普通类里的 `findByXxx` 方法名被误标 JPA 图标 | 仅 Repository 接口内标锚 |
| 竞品翻车场景防御性验证（N-8） | Map 参数 `#{map.xxx}` 与多模块同名实体进金样矩阵，行为锁定 |

## 四、本次合并自 master 吸收的能力

2026-09-04 已将 master（v2026.9.4）合并进本分支，以下 master 侧新能力本分支同样具备：

- **JOIN 图原生框架渲染**：预览含 JOIN 的 SQL 时切到「JOIN 图」标签页即可；默认走 IDE 原生 Diagrams 引擎（缩放/自动布局/折叠/导出全框架托管），Diagrams 插件缺席自动回退自绘渲染。设置页「使用 IDE 原生图框架渲染 JOIN 图」可切换。
- **JdbcTemplate SQL 字符串预览**：`jdbcTemplate.queryForList(...)` 等方法的字符串 SQL 实参行显示预览图标。
- **@NamedQuery 实体级预览**：实体上的 `@NamedQuery`/`@NamedQueries` 注解处显示预览图标。
- **预览快捷键贯通**：默认快捷键 `Alt+Shift+Q` 现在覆盖 HQL/JPQL 运行时、自定义 DAO HQL、JdbcTemplate、`@NamedQuery`（此前仅 Wrapper/JPA/注解三类）。
- **历史读回剥除分号**：自动保存的历史 SQL 读回时统一去掉结束符，耗时展示不受干扰。

## 五、已知边界

- Oracle / SQL Server 不支持 EXPLAIN（点击提示，不影响其他功能）。
- 字符串版 `QueryWrapper` 服务链消费：本节原记录「`service.remove(w)` 输出 DELETE 缺 WHERE 条件（消费分支按 Lambda 解析，待后续版本支持）」与实测不符，勘误如下。立项前 14 形态探针实测表明，字符串条件本身在消费分支并不丢失——显式类型声明（`QueryWrapper<Device> w = new QueryWrapper<Device>().eq("id", 3L)`）与内联形态的 `eq`/`apply`/`inSql` 等条件均正常收集进 WHERE。真实缺陷是三处，已随 T-StrWrapperDeleteWhere（O-8，2026-09-06）修复：一是 `var` 声明 + 工厂形态（`var w = Wrappers.<Device>query()...; service.remove(w)`）消费语义整体丢失、删除意图被渲染成查询，现走变量路径按 DELETE 渲染；二是 `service.query()` 字符串服务链实体无法解析时预览静默为 null——现实体经服务接口泛型实参解析（`DeviceService extends IService<Device>`），仍无法解析时返回「无法推断实体表」降级警示而非无响应；三是 DELETE 消费丢失 `last()` 尾段，现按方言渲染——MySQL 语法族（MySQL/MariaDB/DM）输出 `DELETE ... LIMIT n`，不支持 DELETE LIMIT 的方言（PostgreSQL/Oracle/SQL Server 等）静默省略。
- MyBatis-Flex 支持经调研暂缓（结构性差异 + 同名锚点冲突），重启条件见 [Flex 调研报告](../开发计划/20260902-0120-MyBatis-Flex支持可行性-调研报告.md)。
