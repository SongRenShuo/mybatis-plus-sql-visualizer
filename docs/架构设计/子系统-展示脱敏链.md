## 三个脱敏开关的关系（S1-4③，2026-10-31 逐处 grep 核实）

设置里与「脱敏」沾边的字段有三个，**作用面互不相同**——三者不是同一开关的不同名字，
任意两者同时开启也不互相覆盖（各管自己那一段）。

| 开关 | 作用面 | 取值与默认 | 谁读它 | 与另两者的关系 |
|---|---|---|---|---|
| `displayMaskMode`（`String`，新三档 OFF/MASK/WARN/BLOCK） | **屏显面全语义** + **离开 IDE 面从严归一 MASK**。屏显：日志列表渲染、历史页、单击预览浮层、停靠预览（WARN 原文＋警示行；BLOCK 阻断占位）；离开产品面：导出/Replay 脚本/浮层复制/优化留痕（mode≠OFF 一律按 MASK 打码） | 出厂空串=「未迁移」哨兵；显式值按串解析，非法串回落 MASK。默认识别为 OFF | `PluginSettings.displayMaskMode()`（屏显消费点：`LogEntryFiltering.textFor`、`SqlDockedPreview`、`RailCellRendererBase`）；`PluginSettings.displayMaskExportOn()` = `displayMaskMode() != OFF`（出口消费点：`HistorySqlLogPanel.exportEntries`、`SqlLogPanelActions.exportVisibleEntries`、`SqlPreviewPanelExecution`（可移植/回放两条）、`TraceDocExport`、`SqlPreviewPanelParamPanel` 的 ShardingSphere Actual 段） | **优先级最高、覆盖面最大**。是唯一同时管「屏显」和「离开产品」的字段；下面两个都不影响它 |
| `displayMaskEnabled`（`Boolean`，旧布尔） | **仅迁移源**，不直接参与任何业务判定 | 默认 false。旧 XML 缺 `displayMaskMode` 时，`loadState` 按 true→MASK / false→OFF 归一写入 `displayMaskMode`；`displayMaskMode()` 在空哨兵时也按同一张真值表推导 | 只有 `PluginSettings.loadState` 的迁移归一与 `displayMaskMode()` 的空哨兵兜底读它；设置页不呈现它（`displayMaskEnabled` 被面板 apply 顺带同步写 = `mode != OFF`，仅为旧版本插件读新 XML 时观感一致） | **被 `displayMaskMode` 覆盖**。一旦 `displayMaskMode` 落了显式值，本布尔永不再被业务读取；改它不会改变任何脱敏行为（唯一例外：显式条件不满足时—即新装无 XML、`displayMaskMode` 仍是空串、`loadState` 未跑—回落到本布尔推导） |
| `enhancedCaptureDesensitize`（`Boolean`） | **agent 采集侧**：数据在应用 JVM 内就被打码，**数据怎么进来** | 默认 false（T-M56-08 用户定案：默认采集真实参数值） | `log/agent/AgentManager`（`pushDesensitize`、监听开关联动时下发）、`log/agent/AgentSessionSupport.sendConfig` 拼 CONFIG 帧 | **与展示侧完全解耦、互不覆盖**，也不被 `displayMaskMode` 影响。左者关、右者开：采集真实值 → 展示/导出口打码；左者开、右者 OFF：采集即脱敏，展示层就是已处理文本 |

**谁覆盖谁（一句话）**：`displayMaskEnabled` 只在「`displayMaskMode` 还是空哨兵」时被读；
`displayMaskMode` 一旦有显式值就完全接管屏显与出口两面，与 `displayMaskEnabled` 无关；
`enhancedCaptureDesensitize` 走 agent 通道，与上述两者在任何方向上都不覆盖。

**旧布尔何时被读（两处，逐处核对）**：
1. `PluginSettings.loadState`（`State.displayMaskMode.isBlank()` 分支）：旧 XML 反序列化后新字段为空 → 翻译成显式值；
2. `PluginSettings.displayMaskMode()` 的空串分支：新装无 XML（`loadState` 未跑）时直接按旧布尔推导。

这两处用的是**同一张真值表**（true→MASK、false→OFF），所以「迁移归一后」与「未迁移直接读」
结果一致；不存在「面板写一个值、访问器读另一个值」的分叉。

## 关键约束

- **双侧同步纪律（收窄后）**：同步范围=KEYWORDS 与形态规则本体；分级/白名单/计数是展示侧有意差异，agent 不跟进（无 UI 无状态）。
- **屏显面与出口面分开**：WARN/BLOCK 的原文语义不外流——导出/复制/MCP 一律归一 MASK 后渲染。
- **提示不回显原值**：警示行与 BLOCK 占位只含类别与次数（bundle `log.preview.maskWarn`/`maskBlocked`）。
- **缓存键带 mode**：渲染缓存（`cachedListLineFragmentsMasked` 等）以 MaskMode 串为键，防不同档结果串缓存。
- **插值对位**：INSERT VALUES 按列清单与值序列位置对位取 hint（UI-021），白名单豁免后计数为 0 的 BLOCK 按 OFF 原样。

## 失败与兼容行为

- `displayMaskMode` 旧值兼容：空串哨兵按 `displayMaskEnabled` 推导（true→MASK / false→OFF）；非法串回落 MASK。
- 引擎异常 fail-closed：`MaskMode.OFF` 不进兜底（不扫描=引擎不参与）；其余档异常一律落 `log.preview.maskFailed`。
- `settings.display.mask` 键复用为模式下拉的行标签与搜索身份（不新增幽灵条目，`SettingsPanelSearchableGuardTest` 钉住）。
