## 1. 产品定位

**MyBatis SQL Visualizer**（2026-11-23 起启用现名，T-D244 B1；此前名 SQL Visualizer / MyBatis-Plus SQL Visualizer，插件 ID 不变）是一款 IntelliJ IDEA 插件（Kotlin 为主源码），围绕 MyBatis-Plus / MyBatis-Plus-Join（MPJ）/ Hibernate / JPA 提供双向能力：

- **正向**：把代码里的 `LambdaQueryWrapper` 等 Wrapper 调用链、其他 ORM 链（xbatis / Easy-Query / MyBatis Dynamic SQL / Querydsl，M44）、XML / 注解动态 SQL、**iBatis 2.x `<sqlMap>` 语句与 Java DAO 调用行（T-Ibatis2Support，20 形态官方引擎黄金对照 + 双向跳转 + 交互式参数）**、**MBG Example 语句按调用点还原条件（T-MbgExamplePreview）**、Spring Data JPA 派生方法（findByXxx）、JPQL/@Query、CriteriaBuilder、HQL（含自定义 DAO 与 hbm.xml 命名查询）、JdbcTemplate / 自研 DAO 字符串 SQL 实时**转换为可读、可复制的 SQL**，支持参数回填、动态条件勾选、15 种方言（默认**智能推断**：按运行应用 agent 捕获的连接 URL 优先、IDE 数据源 URL 次之，T-DialectAutoInfer）、逻辑删除 / 乐观锁 / 分页注入。**Mapper 接口方法行亦可直接预览（T-MapperMethodSqlPreview）**：方法行 gutter 两枚图标——左预览、右跳转（顺序由独立 provider 注册位钉死，T-MapperPreviewOrder），`Alt+Shift+Q` 同一入口，渲染链与 XML 语句行逐字节一致。
- **反向**：把选中/粘贴的 **SQL 文本转换回 MP Java 代码**（QueryWrapper / LambdaQueryWrapper / Wrappers 工厂 / MPJ 等形态）。
- **CRUD SQL 生成（T-CrudSql）**：实体类（编辑器 / 项目视图右键）与 Database 工具窗表节点一键生成 INSERT / UPDATE / SELECT / DELETE 模板（主键 / 逻辑删除 / `@Version` 感知），候选经原生浮层选择后进统一预览窗口。
- **附属能力**：运行日志捕获还原（控制台解析 + **字节码增强 agent 双通道**，M56——增强捕获默认开启，开关即授权、不再弹注入确认；agent 接管期免注入拦截器即得源码位置/耗时/影响行数/请求标签；**四条静默丢弃路径与嵌套门禁状态全部上到常驻状态栏，含「门禁陈旧 N」确诊读数（T-PanweiInsertCapture / T-NestGateObserve）与深度泄漏根治（T-NestGateFix）**；主侧边栏 4 常驻 tab（日志 / 日志→SQL / SQL→Java / 历史）+ 可选第 5 tab 独立预览工作台，方法级/请求级聚焦页签、SQL 执行报错同列、排序方式选择器、疑似 N+1 红徽章（同线程 60s 滑窗、阈值 ≥5，T-HdAbsorb D216；点徽章可聚合看全，D235），参数随历史条目持久化并支持免占位符字面量恢复，参数预设/参数历史按声明方法隔离；**发现 SQL 自动开窗时让位给正在使用的面板（T-AutoShowYield，`12b84ae03`）**——同侧栏已有别的工具窗在显示就不展开，条目照常入缓冲，设置页 SQL 日志组新增子开关「自动展开时让位给正在使用的面板」默认开）+ SQL 历史、**独立 SQL **分层要点**：

- **③④⑤ 三层为纯函数/纯逻辑**（`model` / `converter` / `sql` / `xml` / `reverse` / `util` 及其子包），不依赖 PSI 与 IDE —— 这是大量纯 JUnit 测试类零 IDE fixture 的基础，也是核心算法可独立验证的关键。
- **③ 模型层是正反向共用的桥梁**：反向解析器（SqlReverseParser）产出的 `Condition` 与正向生成器（SqlGenerator）消费的是同一模型（round-trip 自洽），这是「SQL 能转回代码、代码能再转回 SQL」的根基。
- **② 编排层收敛所有入口**：所有 UI 触发（gutter/Action/面板）都汇入 `SqlPreviewService` 与 `SqlToJavaConverter` 两个编排点，避免 Action 与面板行为漂移（详见第 5 节设计决策）。JPA/Hibernate 六种 gutter 也统一进 `SqlPreviewService`（`previewDerivedQuery` / `previewJpql` / `previewCriteriaQuery` / `previewHql` 等方法族），JdbcTemplate / hbm 命名查询 / @NamedQuery 各有对应 `previewXxx` 入口。
- **日志捕捉是双通道汇入同一缓冲**：控制台解析链（consoleFilterProvider EP 主通道 + 反射桥轮询兜底 → 三族 parser 线程分桶 → 还原）与 M56 增强捕获链（`log/agent` 事件 → `AgentEventAdapter` 纯函数适配）都汇入 `SqlLogEntryBuffer`，`dedupeKey` 两通道同口径——接管/回落切换期两通道并存不双记（详见 02 篇 §6 / §6.5）。
- **M44 其他 ORM 双轨接入**：xbatis 以 `XBATIS` 类型走 `ConverterRegistry` SPI；Easy-Query / MyBatis Dynamic SQL / Querydsl 三家不进 SPI，由 `SqlPreviewService` 按 entry + receiver 启发**前置派发**给直解析转换器（见 §5.1），锚点判定分别挂在 `WrapperAnchorDetector`（EQ 入口方法集）与 `WrapperLocator`（xbatis 工厂族）。
- **CRUD SQL 生成是 L5 旁路**：不进 WrapperConverter SPI——`CrudSqlGenerator` 直接消费表规格（实体 PSI 自省或 Database 自省元数据经 `DbTableSpecAdapter` 适配），产出模板 SQL 走既有预览弹窗展示。
- **mcp 包是协议适配层**：十一个 toolset 类不自带业务逻辑，全部委托既有编排/生成/执行层（图中 E5 → S1 一类边），自身只做 MCP 协议适配、SELECT-only 守卫与门控；宿主插件缺席时整层不加载。

### 3.1 引擎导出子项目（`sub-projects/engine-jar`，T-OpenIDEAPort T0-0，2026-11-25）

把主仓的**纯逻辑**（`model` / `sql` / `xml`（含 `ibatis`）/ `reverse` / `generator` / `psource` / `util` / `log` / `execute` 中零平台渗透的部分）打成 `mpsv-engine-<engineVersion>.jar`，供非 IntelliJ 宿主（OpenIDEA / Rust 侧）经 JSON 门面消费。三条硬约束：

- **不改生产源码**：源集不是手抄副本，而是构建期由 `prepareEngineSources` 任务从 `../../src/main/kotlin` **机械裁剪**生成——按「剥注释后的代码文本」判平台引用（`com.intellij` 及 Gson/Baomidou/Spring/kotlinx 等平台自带库、JDK 桌面面 AWT/Swing/ImageIO），再按「引用闭包收敛」迭代剔除（同包同名不需 import，文本扫描看得见）；另有 5 处**投影**处理整体不可用但只差一条缝的文件（`sql/Dialect.kt` 截断平台成员、`log/LogSqlModels.kt` 删 UI 渲染缓存字段、`log/SqlSourceMarker.kt` 只留计数标记、`util/MpSqlVisualizerBundle.kt` 换本地等价语言/去注解、`xml/SecureXml.kt` warn 换 no-op），投影后仍带平台引用即构建失败。
- **依赖面只有 jsqlparser + Kotlin stdlib**，另为 P5 真连库 EXPLAIN 自包含 PG / SQL Server 官方驱动（`META-INF/services/java.sql.Driver` 改为合并声明，两份驱动各自那份会被 `duplicatesStrategy=EXCLUDE` 吞掉一份）。
- **零平台渗透由 `verifyNoPlatformImports` 逐 class 常量池扫描守住**：解包产物 jar 的每个 `.class` 在字节里查 `com/intellij` / `com.intellij` / `org/intellij`（覆盖常量池的 UTF-8 全限定名、内部名、字符串字面量三种形态；源码级扫描看不见同包全限定名与常量折叠出的类名字符串）。命中即构建失败，另断言 `mpsv/engine/EngineApi.class` 真的在产物里，防「扫了个空 jar 全绿」。

门面 `EngineApi`（`sub-projects/engine-jar/src/main/kotlin/mpsv/engine/`）七个入口，入参出参一律 JSON 字符串（跨进程/跨语言边界只需字符串协议，JSON 手写零新增依赖）：`renderLogs`（MyBatis/Hibernate/JdbcTemplate/ShardingSphere 日志还原）/ `checkSql`（语句数 + 逐条类型 + 无界写七规则）/ `perfAdvice`（性能规则静态分析）/ `render(kind, text, dialect)`（wrapper / xml / annotation / jpa / jdbcTemplate 等渲染）/ `explain` / `explainExecute`（真连库）/ `schema`。`StdioMain` 作 manifest `Main-Class`，`java -jar` 即可逐行收发 `{"protocol":1,"kind":"…","id":…}` 请求（P5 sidecar 分发面）。产物 `mpsv-engine-<ver>.jar` + `.sha256`，**当前不进插件 zip**（发行说明明示为未来 sidecar 基础设施）。

## 5. 关键设计决策

### 5.1 ConverterRegistry SPI —— 新增 Wrapper 类型零 UI 改动

```mermaid
flowchart LR
    S["SqlPreviewService"] --> R["ConverterRegistry.convert(chain, table)"]
    R -->|"firstOrNull{ wrapperType ∈ supportedTypes }"| C1["LambdaQueryConverter"]
    R --> C2["LambdaUpdateConverter"]
    R --> C3["MpjLambdaConverter"]
    R --> C4["…共 11 个"]
    C1 -->|"SqlStatement"| G["SqlGenerator"]
```

`WrapperConverter` 接口 = `supportedTypes` + `convert(chain, table)`。新增一种 Wrapper 只需实现接口并追加进 `ConverterRegistry.converters` 列表，UI 层（SqlPreviewService）零改动（F-20 可扩展性要求）。当前注册 11 个：LambdaQuery / LambdaUpdate / LambdaDelete / MpjLambda / MpjQuery / MpjLambdaQuery / QueryWrapper / UpdateWrapper / UpdateJoin / DeleteJoin / Xbatis（xbatis QueryChain/UpdateChain/DeleteChain，M44）。

M44 其他 ORM 三家走的是**平行直解析通道**，不进 SPI：`EasyQueryConverter`（Easy-Query proxy 链）、`MdsConverter`（MyBatis Dynamic SQL SqlTable 链）、`QuerydslConverter`（Querydsl 表达式树）都是 object，由 `SqlPreviewService` 在常规 Wrapper 流程前按 entry + receiver 启发认领（普通类同名方法不命中，带负例守卫）。锚点判定侧，Easy-Query 入口方法集挂在 `WrapperAnchorDetector.ENTRY_METHODS`，xbatis 工厂族（`QueryChain.of/create` 等，qualifier 前缀 `cn.xbatis.` / `cn.mybatis.mp.`）挂在 `WrapperLocator`。

JPA/Hibernate 侧是平行的一族（`converter/jpa`，不进 WrapperConverter SPI）：`DerivedQueryConverter`（findByXxx 派生方法经 `PartTreeParser` 解析条件树）、`JpqlConverter`（JPQL/@Query，含 IN 子句参数识别）、`HqlConverter`（HQL/JPQL 文本 → 原生 SQL，SELECT 裸别名展开为实体列清单）、`CriteriaQueryConverter`（CriteriaBuilder 调用链）、`SpecificationQueryConverter` / `QueryByExampleConverter` / `JpaCrudOperationConverter`（Specification / Example / JPA 仓储方法族）。实体解析由 `psi/jpa/JpaEntityResolver`（@Entity/@Table/@Column/@ManyToOne 注解）与 `HbmXmlEntityResolver`（Hibernate XML 映射）承担，与 MP 侧 `EntityResolver` 独立。

### 5.2 共享编排防漂移

项目反复踩过「Action 与面板各写一套逻辑导致行为不一致」的坑，因此：

- **正向**：`SqlPreviewService`（project 服务）是唯一编排点；`showResult` 统一弹窗（Action、gutter、日志面板共用），`previewAsync` 统一后台 ReadAction + EDT 回调（2025.3+ 慢操作守卫）。
- **反向**：`SqlToJavaConverter`（object）被 `ConvertSqlToJavaAction` 与 `SqlToJavaPanel` 双入口复用——parse/generateCode 纯函数、findCandidates 须后台 ReadAction。
- **展示**：`SqlPreviewPanel.renderSql` 统一处理三种渲染源（正向模型 / 批量模型 / XML 模型），面板勾选后按模型级重生成。

### 5.3 WrapperCache 双维度失效

解析结果按 `(PsiFile, 锚点偏移, 替换占位符开关, 配置签名)` 缓存（源码字段名 `resolveVariables`）；配置签名由 `TableConfigSignature` 六项设置（推断策略/忽略字段/添加与移除前后缀）拼上**方言判定结果**（`decision.status / dialectName / source / dataSourceIds`）组成：

- 文件内容变更（modificationStamp）失效；
- **表配置签名**变更失效——修复「改设置后预览不生效」；方言判定变化（切方言、源变化）同样不命中旧结果；
- 命中缓存时还校验**实体文件**戳（@TableName/@TableField 注解来源），实体变更重算。

gutter 锚点判定走 `WrapperAnchorDetector.anchorElement` 的 O(1) 纯语法快速路径（不 resolve），满足编辑器行图标性能红线。

### 5.5 其他决策

- **i18n 自管理**：`util/MpSqlVisualizerBundle` 自管 zh/en bundle（默认中文），语言设置独立于 IDE 界面语言（zh/en/AUTO）；平台组件文案（如 cancelAction）须 bundle 显式覆盖。

- **预览首开不推工程进 dumb（T-PreviewNoReindex / T-PreviewExecWriteDefer）**：exec 文件带方言映射，内容重写会触发平台语言替换重算并把工程短暂推进 dumb（`PushedFilePropertiesUpdater` → dumb + EDT 慢操作 SEVERE）。三道切断：方言映射统一落**父目录**（平台按层级继承，文件重写不再动映射）；方言映射写入加**本地备忘**（探测不可用且上一轮确实写成过目标方言就不再重复写）；打开预览默认**不准备执行控制台**（`ui/PreviewConsoleEager` 三档 LAZY/LAZY_SILENT/EAGER，默认 LAZY，设置页「执行控制台」可切，`sqlvis.preview.eagerConsole` 回退；惰性档在状态行补常驻「显示执行控制台」入口）。
- **表名反查索引与补全缓存（T-StartupReadLockFreeze 性能轮）**：表名反查从「打开预览每次全项目重扫」改 `EntityClassFinder` **一次扫描建全表索引**，候选源走平台 `JavaAnnotationIndex` 注解索引（大工程 16804 类 → 812 候选、重建 4737ms → 187ms），按 ORM 分源（`TableNameAnnotations`：MP `@TableName` + JPA `@Table`，未命中回补全项目推断）；EDT 只派发不等待（非 EDT 至多有界等 800ms），失败/撤销 10s 冷却防空转。补全侧实体解析按类名键缓存、**内容指纹**（实体文本 hashCode）判失效；联表候选缓存 TTL 2 分钟、缓存优先不上点击链。
- **更新链两件加固（T-HotUpdateSettingsGuard / T-LocalDirPersist）**：热更新前 `update/HotUpdateSettingsGuard`（订阅 `beforePluginUnload` isUpdate=true）关闭陈旧设置窗口并气泡提示重启——旧 classloader 卸载后点设置「确定」无反应的 CNFE 根因不再无声；本地安装包目录值写穿持久化（见 §5.5「本地安装包目录」）。
