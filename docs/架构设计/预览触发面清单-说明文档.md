> **创建日期**：2026-09-02
> **来源**：M38.4 / P-立项-06 A4——Mybatis-Flex-Helper 的迭代史教训：SQL 预览入口从「只支持 QueryWrapper」被用户追加需求拖着走了 4 个版本（1.4.4→1.4.7 链式/变量/测试场景）。本清单把本插件已覆盖的触发面显式化，**新增入口时按此表登记**，避免触发面成为隐性知识。

## 一之二、MBG Example 条件还原（provider 3 的形态扩展，T-MbgExamplePreview / T-PreviewOpenPerfM2）

2026-11-12 交付。**不是新的触发面**——走既有 provider 3（XmlSqlGutterLineMarkerProvider）与 `XmlPreviewService` 管线，登记在此防隐性知识：

- **命中门**：语句标签 `parameterType` 以 `Example` 结尾（`resolveExampleProfile` 判档：distinct / orderByClause 不展开、集合按 1 项；解析不到一律 null，行为与升级前一致）。普通 mapper SQL 完全不进这条链。
- **条件来源**：`ui/MbgExampleCallResolver` 从 mapper 方法**调用点**反推——`ReferencesSearch` 用 `forEach` 首个命中即止（`findFirst()` 在真机大工程恒空，L44），命中落在实现声明处 / 方法引用上跳过继续找（D6）；同一方法体定位 example 变量，逐个解析 `andXxx` / `orXxx` 的 `addCriterion` 常量，`${criterion.condition}` 从占位符变真实列名与操作符。dumb mode（索引未就绪）**跳过检索**退回占位骨架 `{{criterion.condition}}`，热态或下次打开由缓存补齐。
- **预取**：gutter 渲染期只对 **`select`** 且 parameterType 以 `Example` 结尾的语句后台预取一次（`prefetchMbgExample`——countByExample / deleteByExample 多数没有调用点，实测 6 秒内同一语句重跑 4 轮纯属白烧）；失败记忆 + 单条在途两道护栏。
- **负例边界**：非 `select` 标签不预取；parameterType 缺失或不是 `*Example` 不解析；无调用点的语句保留占位骨架并给「本轮未展开」灰字（不静默、不报错）。

主测试：`MbgExamplePreviewTest`（条件解析与骨架）、`MbgExampleCallCacheTest`（缓存与预取）、`MbgExampleRootMatchTest`（根匹配）、`MbgParamRowLabelTest`（左栏标签列宽）。

## 二、Wrapper 链入口形态细分（provider 1）

| 形态 | 示例 | 锚点落点 |
|------|------|----------|
| 链式内联 new | `new LambdaQueryWrapper<X>().eq(...)` | `new` 关键字（与变量声明同行时去重标变量） |
| 分步变量 | `LambdaQueryWrapper<X> w = new ...; w.eq(...)` | 变量名 |
| 抽象基类型降级 | `Wrapper<X> w = new LambdaQueryWrapper<X>()...` | 变量名（仅 Wrapper/AbstractWrapper 基类型 + 链首为具体 wrapper） |
| Wrappers 工厂 | `Wrappers.<X>lambdaQuery()...` | `lambdaQuery` 方法名 |
| 服务链 | `service.lambdaQuery()...` / `this.lambdaQuery()...` | 服务链方法名（qualifier 为 new 表达式的撞名调用**不标**，M38.1） |
| 批量调用 | `service.updateBatchById(list)` 等 | 批量方法名（与链方法撞名的 selectAll 有去重守卫） |
| 空 Wrapper 写族（T-WriteFamily） | `mapper.delete(null)` / `service.remove(null)` / `mapper.update(entity, null)` | 方法名 identifier（仅空 Wrapper 精确形态 + MP receiver；非空 Wrapper 仍归链） |
| JPA 撞名写方法（T-JpaDeleteAnchor） | `repository.delete(entity)` / `ht.delete(entity)` / `ht.update(entity)` | 方法名 identifier（receiver 属 JPA 家族；`JoinWrappers.delete/update` 仍归工厂） |
| Kotlin | `ktQuery<X>().eq(...)` | 行文本级匹配（F-4 MVP——注释/字符串按元素全文天然排除） |
| 结果变量 | `long total = service.lambdaQuery()...count()` | 服务链方法名（变量不标） |

## 三、负例边界（M38.1 锁定，改动判定前必读）

- import 语句、注释、字符串字面量内的链文本：**零图标**。
- 泛型实参位（`List<LambdaQueryWrapper<X>>`）：零图标。
- 非 Wrappers/ChainWrappers qualifier 的撞名调用（`new Helper().lambdaQuery()`）：零图标（M38.1 修复）。
- 普通类里 PartTree 形态方法名（`findByXxx`）：零图标——派生查询仅限接口 extends *Repository（M38.1 修复）。
- 抽象基类型变量 + 非 wrapper 初始化（`Wrapper<X> w = build();`）：零图标。
- lambda 参数（`and(o -> ...)` 的 o）：零图标（T-M23.12）。
- 非 MP receiver 的同名写方法（`redisTemplate.delete(null)` / `cache.delete(null)` / `list.remove(null)` / `list.remove(0)`）：零图标（T-WriteFamily receiver 守卫）。
- 非空 Wrapper 实参的 `delete` / `update` / `remove` 调用行：零图标——锚点由实参链/变量行承载（T-GutterDupFreeze + T-WriteFamily 形态门）。
- **iBatis 形态（T-Ibatis2Support 券 A，2026-11-09）**：
  - 父标签不是 `<sqlMap>` 的语句同名标签（`<mapper>` / `<pages>` / 任意自定义根下的 `<select>` 等）：iBatis provider **零图标**，仍由原通道（mapper / pages / hbm / 通用兜底）认领——iBatis 判定只看结构（标签名 + 父标签），不看文件名与内容首词。
  - `<sqlMap>` 直接子级的语句标签：**通用兜底通道必须零认领**（`XmlInlineSqlDetector.isClaimedByKnownStructure` 的让位分支与接管方共用同一判定函数），否则同一标签双图标。
  - `<sqlMap>` 下的**非语句标签**（`<sql>` 片段 / `<selectKey>` / `<parameterMap>` / `<resultMap>` 等）：不在接管集合里，也**不在让位集合里**——`<sql>` 片段照旧由通用兜底通道认领（让位集合 ≡ 接管集合，防「让位了但没人接管」的图标空洞）。
  - `ibatisXmlEnabled = false` 或 `mapperXml` 组关闭时：iBatis 语句整体零图标（含动态子标签形态）。
- **iBatis DAO 调用行（T-IbatisCallPreview，2026-11-11）**：
  - 方法名不在 `STATEMENT_ENTRY_METHODS`（`selectOne` 等）、首参不是 String 字面量、或首参不是 `id`/`ns.id` 标识符形态（真正的 JDBC SQL 文本）→ **零 iBatis 图标**，JDBC 通道照常认领。
  - 目标语句在项目内不存在 → **跳转箭头与预览图标都不出**（两枚同生共死，共用同一份 `resolveStatementAnchors`）；快捷键/MCP 形状命中但目标缺失 → 可见失败（「语句未找到」/ `SOURCE_NOT_FOUND`），**不回落 JDBC**（标识符形态首参本来就不是 SQL）。
  - `ibatisXmlEnabled = false` **只灭预览图标**，跳转箭头保留；`mapperXml` 组关闭或总闸关闭两枚同灭。快捷键与 MCP **不受** `ibatisXmlEnabled` 约束（显式动作＝用户意图；与 XML 语句行快捷键现状一致）。

回归集：`psi/WrapperAnchorDetectorNegativeTest`（判定器矩阵）+ `ui/gutter/GutterProvidersNegativeTest`（公共负例哨兵，当前覆盖 9 个 provider——`providers` 清单里 Java 侧可锚定的 9 个；XML 族与 JdbcTemplate 族靠各自 provider 测试里的负例，新增 provider 时按需登记进去；iBatis 族的负例在 `ui/gutter/IbatisXmlGutterLineMarkerProviderTest`，含「同一元素恰一个通道认领」的双图标断言）。

## 三之二、配对跳转图标（非新的预览入口）

2026-10-22（`6b6b56e3`）补了 `MpvsIcons.MapperMethod`（红头）与 `MpvsIcons.MapperStatement`（青头）两张 16×16 图标，分别用于 Mapper 接口方法侧与 Mapper XML 语句侧的配对跳转标记。这两个是既有跳转能力的图标补全，**不新增触发面**——它们复用 `MapperXmlLocator` 已有的定位逻辑（日志条目直跳 mapper XML，T-M55-01），不引入新的 gutter provider。所以本文件第一节的入口矩阵不需要加行；登记的是 `log/ToolbarIconSemanticsTest` 的图标加载清单。

## 四、登记约定

新增/调整 gutter 入口时：
1. 本表加一行（provider、锚定元素、形态）；
2. 在 `WrapperAnchorDetectorNegativeTest` 或对应 provider 负例中补该形态的误报边界用例；
3. 正例至少一条端到端（真实源码 → preview → SQL 快照，参照 `sql/spec/SqlPreviewSpecMatrixTest`）。
