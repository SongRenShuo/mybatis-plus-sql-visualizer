## 四、t-perfsweep31 分支深查（本期主菜）

### 4.1 SqlMapConfigAliasIndex：第三个自定义标量索引（合规，登记一条成本边界）

形态与前两索引对称：`ScalarIndexExtension<String>`、`DefaultFileTypeSpecificInputFilter(XmlFileType.INSTANCE)` 专属、`dependsOnFileContent=true`、`getVersion()=1`（新增装载即建，升级一次性重索引，纯文本扫描无 PSI）、键两族（`cfg` 文件级标记 + `ta:<alias>` 别名）、`getContainingFiles` 出候选后 PSI 侧精确匹配（rootTag == sqlMapConfig + alias 属性相等）——索引多收由 PSI 否掉，只少收不误收。提取内核纯函数（`keysForText`/`aliasEntriesFromText`），索引不建 PSI。plugin.xml 以 `<fileBasedIndex>` 注册，与前两索引同形态。消费方唯一：IbatisParameterClassResolver:104。

登记一条成本边界（不是问题，防误判）：`keysForText` 对每个 XmlFileType 文件先跑两次全文根锚正则（`<sqlMapConfig` 与 `<sqlMap` 谁先出现），命中 config 后再全文 findAll 提别名；虽有 `contains("alias")` 早退，但根锚扫描在前——**百万字节级 mapper XML 每次保存也付 2 次全文扫描**。量级为 BGT 索引期、相对平台 XML PSI 解析可忽略；若日后要抠，可把根锚判定收进头窗（config 文件惯例 KB 级）。分支对同类问题（MapperNamespaceIndex `#config` 头窗化）已给出语料级否证（`<properties>` 超窗 67085 字节），头窗化不是无代价方向。

### 4.2 DumbMode 六闸与 previewAsync 重试（合规）

六处新判定（比计划的四处多两处，覆盖面更全）：resolveClass 入口闸前移、resolveInterfaceMethod 补闸、EntityClassResolver 入口早退、EntityClassFinder 三处（find 入口 / requestLibrarySweep 投递前 / runLibrarySweepNow 返 −1 触顶语义允许 smart 后重投）。previewAsync 对 IndexNotReadyException 单独分流：`DumbService.runWhenSmart` 重试恰一次，仍 dumb 时走 `notifyIndexNotReady` 平台 WARNING 通知（`action.indexNotReady.message` 双语键）+ onResult(null)——dumb 窗点击预览从「点了没反应」变为「可见归因」。重试分支的 result/stillDumb 跨闭包可变捕获逻辑正确、可读性一般，不构成问题。
