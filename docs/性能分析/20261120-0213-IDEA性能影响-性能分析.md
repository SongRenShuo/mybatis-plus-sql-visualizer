## 四、master 本体新面（52 笔增量）

### 4.1 P2：独立预览弹窗链 EDT 解析（本期唯一）

SqlPreviewDialog 两条入口在 EDT 直跑解析：

- 贴入自动识别：pasteReparseTimer 稳定 2 拍后在 **EDT Timer 回调里同步跑** `StandaloneSqlSourceResolver.resolve(text)`（SqlPreviewDialog.kt:166，reparseDraftFromEditor 内）；
- 从文件载入：`ReadAction.compute` 内 `VfsUtilCore.loadText` 读整个文件（:194-199，EDT IO），随后 `reparseText`（:216）同样 EDT 直跑解析。

`StandaloneSqlSourceResolver.resolve` 是纯文本链（XmlFlavorDetector 计分 + 双链择优各最多 4 候选串 + SqlPerfAnalyzer），grep 全文零 PSI/ReadAction 引用，输入上限 100k 字符（:42）；工作台页签同链已池线程化（SqlStandalonePreviewPanel.kt:303-311）。证据上这条链在 BGT 是安全的——工作台形态就是证明。大 XML 片段 + 风味证据不足时最坏 8 次 DOM 解析，EDT 停顿数百毫秒级。修法照工作台形态搬即可（见开发计划 T-PerfSweep33 券01），与 hiddenbug 分支零重叠。

### 4.2 P3：windowStamps 无显式上限

D216 第二刀引入的 `windowStamps: HashMap<String, ArrayDeque<WindowStamp>>`（SqlLogEntryBuffer.kt:96）只有三个出口：读取时修剪（windowSuspectKeys :906-930，面板每刷新拍调一次）、clear（:942）、以及 KDoc :80-95 如实登记的「逐条出队不摘戳、窗龄自愈」近似（:615 淘汰循环确实不碰戳）。若捕获开启且面板长时间不打开，戳按捕获速率单调累积（单枚约 32B，量级微；形态属本系列盯防的无界累积族）。总帽兜底即可，见券02。

### 4.3 P3：pasteReparseTimer 弹窗待命轮询

javax.swing.Timer 400ms repeats（SqlPreviewDialog.kt:131-134，间隔常量 :292），仅在 autoParseOnPaste=true 的弹窗武装（唯一入口 SqlPreviewService.kt:2096 openDialogWith），每拍 `draftTextProvider()` 整份 String 复制 + 比较，稳定 2 拍即停（PASTE_REPARSE_STABLE_TICKS，:149/:297），命中/销毁即停。单拍成本微秒级；用户不贴内容则弹窗整个生命周期空转。登记观察，可选降频，不建议动语义。

### 4.4 登记：MCP 壳类机制（D238/D239）成本收敛

全新机制面逐文件过完：注册（McpToolsetDynamicRegistrar.kt:91 registerOnce，@Synchronized + AtomicBoolean 全应用一次）含每壳 declaredMethods 反射扫（:314）、注解读值（:320-332）、kotlin.Metadata 复制（:437-440）、TinyClassFileWriter 纯内存字节码 + ShellClassLoader define（:453）。清单重算共 3 次（注册完成后 1 次 :157 + 3s/12s 延迟兜底 2 次 :161-170，AppExecutorUtil 单发 schedule 非周期），每次先摘平台反射 provider 缓存再 requestUpdate（:252-258），跑在平台协程非 EDT。自检诊断（EP 回读 :104-111、逐壳 asTools 强制展开 :129-154）一次性 INFO。每工具调用 = 壳方法 `new 目标类 + invokevirtual` 转发（TinyClassFileWriter.kt:140-166），零反射。驻留：11 壳 Class + ShellClassLoader（KB 级不可回收）+ 三本台账 ≤11 条 + 过滤 EP 一个 Proxy。结论：无周期、无每调用成本、容器有界，登记即结。
