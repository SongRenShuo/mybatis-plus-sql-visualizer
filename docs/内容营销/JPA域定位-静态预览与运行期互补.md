## 两个问题，两件工具

写 JPA / Hibernate 的人每天面对两类时刻：

- **写代码时**：刚写完一个 `findByNameAndStatus`、一段 JPQL、一条 Criteria 链，想知道它到底翻成什么 SQL。这时候应用没起、数据库没连，日志里什么都没有。
- **调试运行时**：断点停下来、会话跑着，想看此刻真实执行的语句、有没有 N+1。

这两个时刻需要的工具不一样。本插件回答第一类：静态写前预览。IDEA 官方的 Hibernate Debugger 回答第二类：运行期调试。它们不互斥，也不互相替代——这是本稿所有表述的基准。

## 与官方 Hibernate Debugger 的关系

先摆事实（读数截至 2026-09-30，来源=第十八轮）：

| | Hibernate Debugger（JetBrains 官方） | SQL Visualizer（本插件） |
|---|---|---|
| 所处阶段 | 运行期：debugger 会话内查看语句 | 写前：编码期静态预览 |
| 前置条件 | 启动应用、进入 debugger 会话 | 不启动应用、不连数据库 |
| 兼容区间 | 263.5701.*（仅 2026.3，当前为 EAP） | 243 无上限（2024.3~2026.x） |
| 代表能力 | 会话内语句可见、实时 N+1 检测、重放控制台、调用栈超链接 | 派生方法 / JPQL / Criteria / HQL / NamedQuery / Specification / QBE 预览；免库 mock 填参（空参三态）；嵌入段列名精确（@Embedded / @AttributeOverride 展平，真机闭环已上架）；14 方言 EXPLAIN（含达梦 / 人大金仓 / OceanBase / openGauss / GaussDB / 瀚高 / 海量信创场景） |

再表态（主张，明示）：官方做运行期是对的，那是平台默认答案该站的位置；我们做静态也是对的，写前场景在结构上就轮不到会话工具——应用没跑起来，会话无从谈起。两件都装也完全成立：写代码时看我们的预览，断点调试时用官方的会话视图。

红线自我约束：官方产品是 JetBrains 自己的，对外表述永远用「互补」「分工」，不出现「不如」「取代」类字样；也不说「官方没有」——它有，只是版本线不同、所处阶段不同。JPA Buddy（679.7 万下载量级的 JPA 域大户，截至 2026-09-30）同样只在 263 单线，本稿只陈述这一兼容事实，不作它评。

## 兼容面事实

- 官方两条 JPA 相关产品线（Hibernate Debugger、JPA Buddy）兼容区间均为 263.5701.*，即仅 2026.3（截至 2026-09-30）。2026.3 尚在 EAP，正式版预计 11 月。
- 本插件 since-build 243 无上限，IDEA 2024.3~2026.x 全线可装（verifyGate 三目标 243/253/262 每次发行实测，读数随批次落验收文档）。
- 含义（主张）：在 2024.3~2026.2 构成的存量装机面上，静态 JPA 预览目前只有本插件一条供给；官方 2026.3 铺开后，这个装机面依然不受影响——铺开改变的是 2026.3 用户的运行期体验，不动存量版本的静态场景。
