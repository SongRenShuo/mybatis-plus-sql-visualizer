## 二、掘金稿全文

> 发布形态：掘金技术专栏。标题候选两个，摘要一段，正文约 3200 字。

### 标题候选

1. 改完 Wrapper 先重启服务再翻日志？现在写完代码就能看到最终 SQL
2. 服务未启，SQL 先知：一个把 Wrapper、mapper XML、JPA 都渲染成可读 SQL 的 IDEA 插件

（更名生效后候选二可替换为：MyBatis SQL Visualizer：把 Wrapper、mapper XML、JPA 都渲染成可读 SQL 的 IDEA 插件）

### 摘要

不启动服务就能看到 MyBatis-Plus Wrapper、mapper XML、JPA 派生方法最终拼出的 SQL；应用跑起来后，真实参数、耗时、影响行数与调用栈自动入列，N+1 循环单查一眼露馅。免费开源，IDEA 2024.3 以上可装。

### 正文

#### 一、先说场景

改一个查询条件：

```java
queryWrapper.eq(StringUtils.isNotBlank(query.getUsername()), User::getUsername, query.getUsername());
```

改完盯着屏幕想：这条语句最后拼出来是什么样？username 进没进去？deleted = 0 有没有被逻辑删除插件补上？

接下来的动作大家都熟：重启服务、发一次请求、翻控制台日志，先找 `Preparing: SELECT ... WHERE username = ?`，再到下一行 `Parameters: tom(String)` 逐位对回去。参数一多，肉眼对位就是体力活。一天来十几次，「写代码」和「看日志」两种状态来回切。

还有些时刻连日志都没有：代码刚写完服务还没跑；review 同事提交的 Wrapper 链，想知道他这条链最后改的是哪张表；接手一个 JPA 老项目，想看 findByUsernameAndStatus 到底翻成什么 SQL。

我的解法是把这件事交给 IDE。装了 SQL Visualizer，一个免费开源（Apache-2.0）的 IDEA 插件：写代码时静态算出最终 SQL，应用跑起来后捕获真实执行，看懂了还能反向转回 Java。插件不发任何使用数据、无账号无激活，要求 IDEA 2024.3 及以上。

#### 二、写代码时：不启动服务的静态预览

光标放在 Wrapper 链上按 Alt+Shift+Q，或者点行首的 gutter 图标：

![Wrapper 预览：左侧勾选动态条件、填参数，右侧实时出 SQL](https://sql-visualizer.jvtools.cn/demo/perf-advice.gif)

面板把 `.eq(condition, ...)` 的布尔首参变成了复选框，勾上取消，右侧 SQL 实时重渲染；参数按类型填值，LIKE 自动补 `%`，没填的保留 `?`。整个过程不启动 Spring 容器，不连数据库。

覆盖面比名字大：MyBatis-Plus 各类 Wrapper 与服务链、MPJ 联表、mapper XML 动态标签、注解 SQL、JdbcTemplate 字符串 SQL，还有 xbatis、Easy-Query、Querydsl 这类链式框架。JPA / Hibernate 是同一个入口同一块面板，派生方法、`@Query`、Criteria、Specification、HQL 都能预览：

![JPA 派生查询：方法名直接预览成 SELECT / ORDER BY / LIMIT](https://sql-visualizer.jvtools.cn/demo/jpa-preview.gif)

老项目里还在用 iBatis 2.x 的也能管：`<sqlMap>` 语句的 `#name#` 占位与动态条件标签可勾选、可填值，DAO 调用行与 XML 语句双向跳转，渲染口径对照的是官方 2.3.4.726 引擎。

![iBatis sqlMap 预览：占位与动态条件可交互](https://sql-visualizer.jvtools.cn/demo/ib1_ibatis_preview.gif)

2026.11.21 这版还把预览做成了独立工作台：主侧边栏新增「SQL 预览」页签，粘贴一段 SQL 或 mapper XML 片段就能格式化、填值、复制可执行 SQL，解析成功后自动跑一遍静态性能检查，`SELECT *`、缺 WHERE 这类问题直接标出来。从日志里捡出来的语句、群里同事发来的 XML 片段，都往这里贴。

#### 三、跑起来之后：增强捕获

静态预览管「写之前」，真正排查要看「跑起来」。日志还原类工具的思路是解析控制台文本，日志里没有的就看不到：参数被日志级别挡掉就没有，耗时靠正则抠，影响行数拿不到。

这个插件走的是另一条路：给本机应用 JVM 挂一个轻量 agent，直接在 JDBC 层采集。拿到的是真实参数、毫秒耗时、影响行数、报错原文，外加调用栈。默认开启、勾选即授权，启动期的 SQL 也能抓到。

![增强捕获：真实参数、毫秒耗时、目标库角标、源码位置一并入列](https://sql-visualizer.jvtools.cn/demo/enhanced-capture.gif)

列表按慢查询阈值三档着色，可以一键只看慢查询。更省时间的是同结构聚类：形状相同的语句归到一处，循环里单查一张表的模式一眼露馅。最新版还加了「疑似 N+1」红色徽章——同一线程 60 秒窗口内同一参数化模板累计 5 条就标红，并发请求各自查一条的情况不会误报。

![同结构聚类：循环单查同一张表，合并挂徽章](https://sql-visualizer.jvtools.cn/demo/n1-badge.gif)

找到可疑语句，右键「跳转到 Java」，直达执行这条 SQL 的代码行，位置取自真实调用栈，不用配置；鼠标停在调用栈上展开 Frames 风格列表，点哪一帧跳哪一帧。

![调用栈弹层：点 Controller 帧直接跳到对应源码行](https://sql-visualizer.jvtools.cn/demo/sql-log-stack-jump.gif)

#### 四、找到了慢 SQL，然后呢

点「执行计划」，插件按当前方言把 SQL 包成对应语句，提交给 IDEA 原生数据库控制台，真实执行计划和静态性能建议同屏对照。15 种方言里 14 种提供计划入口（GoldenDB 暂不支持），各库的验证程度在文档里如实分档标注，不做超出实测的表述。

![EXPLAIN：真实执行计划与静态性能建议同屏](https://sql-visualizer.jvtools.cn/demo/explain-plan.gif)

UPDATE / DELETE 的「更多」菜单里有「预估影响行数」：把 WHERE 改写成等价的只读 `COUNT(*)` 走只读旁路试算，不进共享控制台，也不替换你正在看的语句。JOIN 多表写、无 WHERE 等六种形态它明确拒绝试算。

![影响面预演：顶部横幅给出预估影响行数](https://sql-visualizer.jvtools.cn/demo/dml-impact.gif)

缺有效过滤的写语句，确认弹窗会升级为无界写警示，列出命中的特征：无 WHERE、恒真条件、纯通配 LIKE 等。按钮不变，仍是一步确认。

![无界写警示：弹窗指出语句将作用于全表](https://sql-visualizer.jvtools.cn/demo/danger-warning.gif)

方言支持顺带列一下：MySQL、PostgreSQL、Oracle、SQL Server 之外，达梦、人大金仓、GaussDB、OceanBase、GoldenDB、openGauss、瀚高、海量 Vastbase 也在内置的 15 种方言里，信创环境的预览与格式化走同一套。

#### 五、看懂了，还得能改回来

排查完想落回代码：选中 SQL 按 Alt+Shift+J，或在「SQL → Java」页签粘贴，生成 MyBatis-Plus Wrapper 链。支持增删改查、JOIN、子查询、GROUP BY、HAVING、DISTINCT，输出形态五选一。映射不了的结构降级成 `apply()` 透传并说明原因，不冒充完整支持。

![SQL → Java：生成 Wrapper 链，选调用类与返回类型](https://sql-visualizer.jvtools.cn/demo/sql-to-java.gif)

实体类或 Database 表节点右键「生成 CRUD SQL」：自增主键默认不勾选，`@Version` 乐观锁列自动进 WHERE，`@TableLogic` 字段额外给一个逻辑删除变体。INSERT 能推逆向 DELETE；UPDATE / DELETE 不凭空编恢复语句——插件没有执行前的原值，给的是先查快照、结果自动填入生成回滚 SQL。

![CRUD 生成：实体右键选语句类型，进预览可勾列](https://sql-visualizer.jvtools.cn/demo/crud-sql.gif)

#### 六、给 AI 一副看得见 SQL 的手

AI 写 SQL 的毛病不是不会写，是没有事实：不知道你库里的真实列名，也不知道这条语句渲染出来是什么，于是给你一段看起来很像的 SQL，复制出去跑就报 Unknown column。

插件向 IDEA 内置 MCP Server 注册了 11 个只读工具，Claude Code、Cursor、AI Assistant 这类客户端可以直接调用：渲染真实 SQL、还原日志、查表结构、拿执行计划、检查写风险、生成回滚预案、检索本地历史。工具只声明它能证明的事，没覆盖到的余量留给人判断。

![MCP：agent 经 IDE 内置 MCP 调用工具并给出结论](https://sql-visualizer.jvtools.cn/demo/mcp-agent.gif)

#### 七、它不做什么

工具的可信度一半在能做什么，一半在不假装能做什么：

- 不是 APM，只做本机 JVM 的采集与预览，没有链路追踪和聚合大盘。
- 静态预览不等于运行结果：静态常量会被内联，分页字面量会直接算出 `LIMIT 0, 10`，语义等价、文本不同。
- Kotlin Wrapper 还不能可靠还原，不显示预览图标，也不生成猜测 SQL。
- 执行 SQL 与 EXPLAIN 需要 Ultimate + Database Tools，Community 版相关入口降级，静态预览、日志、代码转换不受影响。
- MCP 工具面需要 IDEA 2025.2+，没这个环境其余功能照常。

#### 八、安装与门槛

Settings → Plugins → Marketplace 搜 SQL Visualizer，或从[插件市场页面](https://plugins.jetbrains.com/plugin/33633-mybatis-sql-visualizer)装。IDEA 2024.3 及以上，免费无广告，Apache-2.0，不发使用数据。

三个快捷键记一下：Alt+Shift+Q 预览，Alt+Shift+J 转 Java，Ctrl+Enter 执行。文档在[官网](https://sql-visualizer.jvtools.cn)，遇到问题去[需求池](https://sql-visualizer.jvtools.cn/about/feedback)说一声——你踩到的坑，多半别人也会踩到。

### 回答正文

先交代身份：我是 SQL Visualizer 的作者，下面关于自家插件的信息如实、文档可查，其他插件只按我自己项目里的用法归类，不做拉踩。

按日常开发流程里碰到的场景盘点：

一、Mapper 接口和 XML 之间来回跳、生成基础 CRUD。MyBatisX（baomidou 官方）是很多人装的一个，跳转和代码生成都覆盖。

二、控制台日志里的 Preparing / Parameters 两行对不上参数。MyBatis Log Free、Mybatis Log Ultra 这一类把日志合并还原成一条可执行 SQL，排查时省去肉眼对位。

三、写代码时就想知道这条链最终是什么 SQL。这是 SQL Visualizer 在的位置：不启动服务，把 MyBatis-Plus Wrapper、mapper XML 动态标签、注解 SQL、JdbcTemplate、JPA 派生方法、iBatis 2.x sqlMap 都渲染成带参数值的 SQL，动态条件是复选框、参数按类型填。应用跑起来后走 JDBC 层 agent 捕获真实参数、耗时、影响行数和调用栈，循环单查的 N+1 会挂红色徽章，从日志右键直接跳回 Java 源码行。SQL 看懂了按 Alt+Shift+J 还能反向生成 Wrapper。

四、想让 AI 参与排查。插件向 IDEA 内置 MCP Server 注册了 11 个只读工具（渲染 SQL、查表结构、执行计划、写风险检查、历史检索），Claude Code、Cursor 可以直接调。

边界如实说：静态预览不等于运行结果，静态常量会内联、分页字面量会直接算出；执行 SQL 和 EXPLAIN 需要 Ultimate 的 Database Tools；MCP 需要 IDEA 2025.2 以上。插件免费无广告、Apache-2.0，IDEA 2024.3 以上可装。

Marketplace 搜 SQL Visualizer，文档在 sql-visualizer.jvtools.cn。装不装看场景：如果只在控制台看日志，第二类就够了；如果经常改完条件想立刻知道 SQL 长什么样，第三类值得试。
