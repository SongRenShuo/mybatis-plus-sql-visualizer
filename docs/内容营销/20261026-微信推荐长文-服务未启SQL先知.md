# 服务未启，SQL 先知：一个把 Wrapper 变成 SQL 的 IDEA 插件

## 一、那个所有人都在忍的场景

你改了一个条件。

```java
queryWrapper.eq(StringUtils.isNotBlank(query.getUsername()), User::getUsername, query.getUsername());
```

改完盯着屏幕想：这条语句最后拼出来到底长什么样？`username` 进没进去？`deleted = 0` 有没有被拦截器补上？

标准流程是重启服务、发一次请求、翻控制台日志，看到 `Preparing: SELECT ... WHERE username = ?` 里参数还是 `?`，再去下一行 `Parameters: tom(String)` 对位。一天十几次，你得在「写代码」和「看日志」两种状态之间来回切换。

更难受的是没有日志的时刻：代码刚写完还没跑、review 别人的 Wrapper 链、接手 JPA 老项目看派生方法名。

以前改完条件，得先猜一遍 SQL 再跑起来验证。现在不猜了。

## 二、它做什么

写代码时把最终 SQL 算出来；应用跑起来后，真实参数、耗时、影响行数与源码位置自动走进列表；看懂了还能把 SQL 反向变回 Java。

插件叫 SQL Visualizer，免费开源（Apache-2.0），不发任何使用数据、无账号，支持 IntelliJ IDEA 2024.3 及以上。

## 三、写代码的时候

光标放在 Wrapper 链上按 `Alt+Shift+Q`，或者点行首的 gutter 图标。

![Wrapper 预览：左侧勾选动态条件、填参数，右侧实时出 SQL](https://sql-visualizer.jvtools.cn/demo/perf-advice.gif)

不启动 Spring 容器，不连数据库，纯静态解析。覆盖 MyBatis-Plus 各类 Wrapper 与服务链、MPJ 联表、mapper XML 动态标签、注解 SQL、JdbcTemplate 字符串 SQL，以及 xbatis、Easy-Query、Querydsl 这些链式框架。

`.eq(condition, ...)` 里那个布尔首参，在面板上变成了复选框，勾上取消 SQL 实时重渲染。参数按类型填，LIKE 自动补 `%`。没填的参数默认保留 `?`。`amount >= NULL` 恒不匹配，静默过滤比留个问号危险得多。填过的值按声明方法记住，两个方法互不串味。

## 四、跑起来之后

它和「日志还原类工具」最大的分岔点在这里。传统做法是应用开 TRACE 打印 `Preparing:` / `Parameters:`，插件解析文本。问题是日志里有什么你才能看到什么：参数被日志级别挡掉就没有，耗时得正则抠，影响行数拿不到。

SQL Visualizer 默认走增强捕获：给本机应用 JVM 挂个轻量 agent，直接在 JDBC 层采集，拿到的是真实参数、毫秒耗时、影响行数、报错原文、调用栈与目标库角标。默认开启、勾选即授权，启动期 SQL 也能抓到。

![增强捕获：真实参数、毫秒耗时、目标库角标、源码位置一并入列](https://sql-visualizer.jvtools.cn/demo/enhanced-capture.gif)

列表按慢查询阈值三档着色，可一键筛「只看慢查询」。更省时间的是同结构聚类：形状相同的语句归到一处，达 3 条就挂徽章，N+1 那种循环单查一眼露馅。

![同结构聚类：循环单查同一张表，5 条只差 WHERE 值，合并挂徽章](https://sql-visualizer.jvtools.cn/demo/n1-badge.gif)

右键「跳转到 Java」直达执行这条 SQL 的代码行，位置取自真实调用栈、不用配置；鼠标停在「调用栈:」上会弹 Frames 风格列表，点哪一帧跳哪一帧。心跳 SQL 可右键屏蔽，能按请求或方法聚焦，历史可检索、对比。

![调用栈弹层：点 Controller 帧直接跳到对应源码行](https://sql-visualizer.jvtools.cn/demo/sql-log-stack-jump.gif)

## 五、找到了慢 SQL，然后呢

点「执行计划」，插件按当前方言把 SQL 包成对应语句提交给原生数据库控制台，真实计划与面板上的静态建议同屏对照。

![EXPLAIN：真实执行计划与静态性能建议同屏](https://sql-visualizer.jvtools.cn/demo/explain-plan.gif)

UPDATE / DELETE 的「更多」菜单里有「预估影响行数」：把 WHERE 改写成等价的只读 `COUNT(*)`，经只读旁路试算，不进共享控制台，也不替换你正在看的 SQL。JOIN 多表写、无 WHERE 等六种形态它明确拒绝试算。

![影响面预演：顶部横幅给出「预估影响行数: 1」](https://sql-visualizer.jvtools.cn/demo/dml-impact.gif)

UPDATE / DELETE 缺少有效过滤时，确认弹窗会升级为无界写警示，列出命中的特征：无 WHERE、恒真条件、纯通配 LIKE 等。按钮不变，仍是一步 Yes / No。

![无界写警示：去掉 WHERE 后执行，弹窗指出「语句将作用于全表」](https://sql-visualizer.jvtools.cn/demo/danger-warning.gif)

方言冲突只提示不拦执行：按 Oracle 渲染的 SQL 提交到 MySQL，插件提示不一致但照样送过去，让数据库自己报语法错。只有一边方言未知的写操作才拦——那不是判断出冲突，是无从判断。

## 六、看懂了，还得能改

选中 SQL 按 `Alt+Shift+J`，或在「SQL → Java」页签粘贴。支持增删改查、JOIN、子查询、`GROUP BY`、`HAVING`、`DISTINCT`，输出形态五选一。

![SQL → Java：生成 Wrapper 链，选调用类与返回类型](https://sql-visualizer.jvtools.cn/demo/sql-to-java.gif)

生成的代码可直接编译，方法名以本地 jar 反编译为唯一权威。`UNION` 在 Java 层降成原文注释，`ILIKE` 这类静态无法映射的形态降成 `apply()` 透传。

实体类或 Database 表节点右键「生成 CRUD SQL」，自增主键默认不勾选，`@Version` 乐观锁列自动进 WHERE，`@TableLogic` 字段额外给一个逻辑删除变体，表无主键时降级为 `1 = 0` 占位，避免误生成全表语句。

![CRUD 生成：实体右键选语句类型，进预览可勾列](https://sql-visualizer.jvtools.cn/demo/crud-sql.gif)

回滚方面，INSERT 能自动推逆向 DELETE，但拿不到主键、谓词只能按整行，弹窗会警示并附 COUNT 让你自查。UPDATE / DELETE 不给自动回滚，因为插件没有执行前的原值；它给的是先查快照、结果自动填入生成回滚语句。

## 七、不只 MyBatis

项目一半 MyBatis、一半 JPA 的话，这套预览是同一入口、同一面板。

![JPA 派生查询：方法名直接预览成 SELECT / ORDER BY / LIMIT](https://sql-visualizer.jvtools.cn/demo/jpa-preview.gif)

覆盖 Repository 派生方法与 CRUD 写路径、`@Query`、`@NamedQuery`、Criteria、Specification、QBE、Hibernate HQL、`.hbm.xml` 命名查询。`Page<T>` 出 count 和数据两条，`@Embedded` 按宿主表列展平且不会拼出 `biz_biz_street` 这种双前缀。

## 八、给 AI 一副看得见 SQL 的手

AI 写 SQL 的通病不是不会写，是没有事实。它不知道你库里的真实列名，也不知道这条语句渲染出来是什么，于是给你一段看起来很像的 SQL，你复制出去跑，报 `Unknown column`。

SQL Visualizer 向 IDEA 内置的 MCP Server 注册了 11 个只读工具，让 Claude Code、Cursor、AI Assistant 这类 agent 直接调用：渲染真实 SQL、还原日志、查表结构、拿执行计划、检查写风险、回滚预案、检索历史。

![MCP：agent 经 IDE 内置 MCP 调 sqlv_check_sql 并给出结论](https://sql-visualizer.jvtools.cn/demo/mcp-agent.gif)

agent 检查 `DELETE FROM user WHERE id > 0`，工具返回「无风险发现」。规则认的是无 WHERE、恒真、纯通配 LIKE，`id > 0` 不在其中。agent 自己补了一句：这条实际上几乎会删全表，建议确认范围与备份。

工具只声明它能证明的事，把没覆盖到的余量留给人判断，而不是硬给一个「安全」的戳。前提是 IDEA 2025.2 及以上。

## 九、它不做什么

工具的价值一半在能做什么，一半在不假装能做什么。

它不是 APM，只做本机 JVM 的采集与预览，没有链路追踪和聚合大盘。

静态预览不等于运行结果：静态常量会被内联（预览 `IN (1)`，运行时 `IN (?)`），分页字面量会直接算出 `LIMIT 0, 10`（运行时 `LIMIT ?, ?`）。语义等价、文本不同。

Kotlin Wrapper 还不能可靠还原，所以不显示预览图标、不生成猜测 SQL。热挂载受驱动与语句创建时机限制，必要时重启应用。执行与 EXPLAIN 需要 Ultimate。

数据不出本机：插件不发任何使用数据，无账号、无激活校验，外部访问只有检查更新（默认关闭）和主动提交反馈。
