## 二、逐平台详解

### 2.1 dev.to

**入口**：`https://dev.to/new`（登录后）

**编辑器**：原生 `<textarea id="article-form-title">` + `<textarea id="article_body_markdown">`，直接 `fill()` 即可。

**标签**：
- 上限 **4 个**，满了输入框变 `aria-disabled="true"`
- **必须从建议列表点击选择**，`fill()` 后按 Enter 无效
- 建议项结构：`li > div.c-autocomplete--multi__tag-option`（不是 `__body li`）
- 标签名与 `#` 分属不同 `span`，正则锚 `^#java` 匹配不上 → 点第一个建议后按 `aria-label="Remove X"` 校验，名字不对就点 Remove 删除
- `intellij` **不是** dev.to 已有标签（建议会降级成 ai/openai/deepseek），用 `jetbrains`
- 已验证可用组合：`mybatis` / `java` / `sql` / `jetbrains`

**AI Disclosure**：编辑器有 `#post-ai-disclosure-btn`，三档 Hand Written / AI-assisted / Fully Autonomous。AI 起草的稿子选 **Some AI (AI-assisted)**。

**发布**：`Save Draft` 先存草稿，`Publish` 直接发。发布后 slug 从 `temp-slug-*` 变为正式 ID。

**风格**：技术长文（1,200~1,800 词），第一人称、具体场景开头、诚实写边界。dev.to 读者对硬广零容忍，作者身份必须在文中披露。

### 2.2 知乎

**入口**：目标问题页 → 「写回答」

**编辑器**：Draft.js（`.public-DraftEditor-content`）

**操作要点**：
- 「写回答」按钮常被 header 遮挡 → 用 DOM 级 `evaluate(() => btn.click())`，Playwright 普通 click 会超时
- 正文用 `keyboard.insertText(段落)` + `keyboard.press("Enter")` 逐段输入（Draft.js 不吃 `fill()`）
- 发布按钮在编辑器底部，文本「发布回答」；编辑已发布回答时是「提交修改」
- 已有「未发布的编辑草稿」时进入编辑会恢复草稿

**图片**（最易踩坑）：
- 点工具栏「图片」按钮**不会**触发 filechooser → 直接给隐藏 input 设文件：`input[type=file][accept*="image/gif"]`
- **插图前必须先按 Enter 建空行**，否则图会插进光标所在的句子中间，把完整句子截断
- **必须用真实鼠标点击目标段落内的位置**（Range API 设选区不触发 React focus）
- **gif 必须压到 800px 宽**——1440px 会被知乎**静默拒绝**（文件进了 input 但不触发上传，无 toast 无请求）
- atomic block（图片）点击选中后 `Delete` / `Backspace` 都删不掉 → 只能 `Ctrl+A` 全选 → `Delete` 清空 → 按正确顺序重建

**风格**：问答形态，先直接回答问题本身，作者身份在开头或显著位置披露，竞品中性归类不贬损。长度 500~1,000 字。

**风控**：短时间连续答多个问题可能触发限流。建议一天 1~2 个问题，且内容必须针对问题本身（不能模板化）。

### 2.3 掘金

**入口**：`https://juejin.cn/editor/drafts/new`

**编辑器**：bytemd + CodeMirror。用 API 一次写入，比逐字输入快几十倍：

```js
document.querySelector('.CodeMirror').CodeMirror.setValue(markdown)
```

**发布设置**：
- 分类：后端 / 前端 / Android / iOS / 人工智能 / 开发工具 / 代码人生 / 阅读
- 标签：**上限 1 个**（实测「你还能添加 0 个标签」）→ 选最核心的（如 `Java`）
- 封面：可选，建议 192×128 以上
- 摘要：100 字上限，通常自动提取
- 专栏 / 话题：可选

**坑位**：
- 标签输入框被 `.byte-select__placeholder` 遮挡 → 直接点 input 会超时，要点 placeholder 元素转发
- **真正的发布按钮是底部「发布博客」**；顶部 `.pub-btn` 的父容器 `.pub-container fixed` 常态 `display:none`，点它无反应

**审核**：提交后数分钟到数小时，个人主页显示「审核中」。通过后才有公开 URL（`juejin.cn/post/<id>`）。

**风格**：技术专栏长文（2,000~3,500 字），小标题分段，代码块 + 动图。掘金读者偏工程实践，喜欢「具体问题 → 具体方案」的结构。

### 2.4 CSDN

**入口**：`https://mp.csdn.net/mp_blog/creation/editor`

**编辑器**：**CKEditor 4**（实例名 `editor`）。默认进富文本模式，有「使用 MD 编辑器」按钮但点击常无反应 → 直接用 API 写 HTML：

```js
window.CKEDITOR.instances.editor.setData(html)
```

Markdown → HTML 转换用 `.local/md2html.py`（覆盖 h2-h4 / 代码块 / 行内代码 / 图片 / 链接 / 粗体 / 列表 / 段落；**不支持表格**，表格请改列表）。

**发布设置**：
- 文章标签：必填，可加多个（实测 5 个正常）
- 摘要：256 字上限
- 分类专栏：可选
- 文章类型：原创（默认）
- 可见范围：全部可见（默认）
- 封面：建议 16:9（1200×675 以上）

**坑位**：
- **真正的发布按钮是底部「发布博客」**（x 坐标约 1392）；顶部 `.pub-btn` 的父容器 `display:none`
- 封面：`input[type=file]` 有两个，选 `accept` 含 `.gif` 且**不含** `webp` 的那个；上传后必须点「确认上传」
- 编辑已发布文章再点「发布博客」会重新进审核
- 发文有**每日额度**（页面上显示「今日发文额度还有 N 篇」）

**封面处理**：公众号的 2.35:1 封面需补成 16:9（不裁内容，上下补底色）：

```
ffmpeg -i src.png -vf "pad=1800:1012:0:(oh-ih)/2:color=0xF5F7FA" out.png
```

底色取原图左上角像素（这张是 `rgb(245,247,250)`）。

**风格**：技术教程/实战文（1,500~3,000 字），标题含明确关键词（如 `p6spy`、`MyBatis-Plus`），结构清晰、有代码有图。CSDN 搜索流量占比高，标题的搜索意图要明确。

**AI 检索权重最高**：GEO 工具实测 `blog.csdn.net` 被 AI 引用 131 次，是掘金（27 次）的 4.8 倍。**中文内容优先发 CSDN。**

### 2.5 Medium（当前受阻）

- 发文 API 已于 2023 年废弃，只能网页编辑器
- 2026-11-23 实测：Google OAuth 回调页 `/m/callback/google` 空白不跳转，cookie 有 `uid`/`sid` 但服务端不认；清 cookie 重试、换正常浏览器均失败
- 判断：Medium 侧的回调处理问题，非本地环境问题
- 稿件已在 `docs/内容营销/20261123-英文平台发布包-草稿.md`，等平台恢复或换登录方式

### 2.6 Reddit（不建议代发）

- 人机验证墙 + 需要账号
- r/java 官方规则（Wayback 2024-10 快照）：**No Tutorials**（教程要去 r/learnjava）→ 帖子必须写成「问题 + 现状 + 提问」的讨论形态
- 另有两条未核实风险：需先 modmail 征得版主同意、可能禁 AI 生成内容
- **建议用户亲自处理**，AI 起草的稿子若平台禁 AI 内容需按自己口吻重写

## 三、内容策略

### 3.1 差异化（避免平台判重）

同一主题在不同平台不能复制粘贴。以 CSDN 两篇为例：

| 维度 | 第一篇 | 第二篇 |
|---|---|---|
| 切入 | 「改完 Wrapper 不知道 SQL」的开发流程痛点 | 「p6spy 换驱动成本高」的运维/审计痛点 |
| 结构 | 三类工具生态盘点 | 单一问题的多路径对比 |
| 关键词 | Wrapper / 预览 / MyBatis-Plus | p6spy / JDBC 驱动 / 日志还原 |
| 开头 | Wrapper 代码片段 | 评审会上被否的真实场景 |

### 3.2 去 AI 味清单

常见 AI 痕迹与改法：

| 原表述 | 改为 |
|---|---|
| `The formatting is not the hard part. The hard part is...` | `The formatting is the easy part. What makes this hard is...` |
| `they are not competitors so much as answers to different questions` | `They answer different questions rather than competing` |
| 三处 `What it needs / gives / does not give` 三段式 | 改两处为叙述句，保留一处 |
| `That last point matters more than it sounds.` | `That distinction is easy to miss.` |
| `Requirements, stated plainly:` | `Requirements:` |
| 「接下来的动作大家都熟：…」 | 「然后就是重启服务、发一次请求、翻控制台日志：…」 |
| 「我的解法是把这件事交给 IDE」 | 「后来我把这件事交给 IDE 了」 |
| 「工具的可信度一半在能做什么，一半在不假装能做什么」 | 「能做什么说清楚，不能做什么也说清楚」 |

### 3.3 事实核对

数字与边界必须与文档站一致（`docs/内容营销/20261121-D249中文平台发布包-草稿.md` §1.7 有核对表）：
- 15 种数据库方言（14 种有 EXPLAIN，GoldenDB 暂无）
- 11 个只读 MCP 工具
- IDEA 2024.3+；执行/EXPLAIN/JOIN 图需 Ultimate；MCP 需 2025.2+
- 免费、Apache-2.0、不发使用数据

### 3.4 作者身份披露

- dev.to：文中或 AI Disclosure 设置
- 知乎：开头一句「我是 XXX 的作者」
- 掘金 / CSDN：文末一行「本文作者是插件作者，功能与边界表述以文档站为准」
- Reddit：首段 `I'm the author`

## 四、配图规范

**尺寸**：所有 gif 压到 **800px 宽**（`scale=800:-1`），128 色调色板：

```
ffmpeg -i in.gif -vf "scale=800:-1:flags=lanczos,split[s0][s1];[s0]palettegen=max_colors=128[p];[s1][p]paletteuse=dither=bayer" -loop 0 out.gif
```

压缩后典型体积：150~600KB。原图 1266~1440px 会被知乎拒绝。

**外链兼容性**（实测）：
- 掘金：站内直链 `sql-visualizer.jvtools.cn/demo/*.gif` **正常显示**，且是懒加载（滚到视口才加载）
- CSDN：外链图**正常显示**
- 知乎：必须上传（走隐藏 file input），不支持直接引用外链

**封面**：
- 公众号 / 通用：`docs/内容营销/封面-主图-2.35-标题加代码块.png`（1800×766）
- CSDN 16:9：`docs/内容营销/封面-csdn-16x9.png`（1800×1012，pad 生成）

## 五、自动化操作速查

### 5.1 编辑器写入方式

| 平台 | 方式 | 代码 |
|---|---|---|
| dev.to | textarea fill | `locator('#article_body_markdown').fill(md)` |
| 知乎 | Draft.js 逐段 | `keyboard.insertText(para)` + `press("Enter")` |
| 掘金 | CodeMirror API | `document.querySelector('.CodeMirror').CodeMirror.setValue(md)` |
| CSDN | CKEditor API | `window.CKEDITOR.instances.editor.setData(html)` |

### 5.2 浏览器自动化环境

- 用 Edge 配置副本 + CDP：`--user-data-dir=<temp副本> --remote-debugging-port=9222`
- `playwright-core` 在 `C:\Users\USER\AppData\Local\Temp\pw-edge\node_modules\playwright-core`，**chromium 在 `mod.default.chromium`**
- 每次 `node_repl` 调用要重新 `import` + `connectOverCDP`
- 杀 Edge 用 PowerShell `Stop-Process -Name msedge -Force`（Git Bash 的 `taskkill /IM` 会被 MSYS 转成路径）

### 5.3 通用坑位

- **Playwright 普通 click 常被遮挡** → 用 `evaluate(() => el.click())` 做 DOM 级点击
- **`setInputFiles` 前先 `setInputFiles([])` 清空**，否则可能不触发上传
- **gif 尺寸超限时上传静默失败**（无 toast、无网络请求），优先怀疑尺寸而非限流
- 中文命令行乱码 → 写 UTF-8 文件再 `--data-binary`，或用 node_repl 直接传字符串

## 七、文档站侧的配套规则

改文档站 frontmatter 时注意（2026-11-23 踩坑）：

- **YAML 值含英文冒号 + 空格**（`IntelliJ IDEA: xxx`）会被当键值分隔符，`js-yaml` 抛 `mapping values are not allowed here`，**构建静默失败但 exit 0**
- 对策：值用单引号包裹；改完先 `yaml.safe_load` 试解析
- meta description 控制在 **150~160 字符**（CSDN SEO 扩展按此判定）
- 排查顺序：源文件 → YAML 解析 → dist 产物 → 线上，不要一上来怀疑缓存/CDN
