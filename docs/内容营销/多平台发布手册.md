## 二、逐平台详解

### 2.1 dev.to

**入口**：`https://dev.to/new`（登录后）

**编辑器**：原生 `<textarea id="article-form-title">` + `<textarea id="article_body_markdown">`，直接 `fill()` 即可。

**标签**：
- 上限 **4 个**，满了输入框变 `aria-disabled="true"`
- **必须从建议列表点击选择**，`fill()` 后按 Enter 无效
- 建议项结构：`li > div.c-autocomplete--multi__tag-option`（不是 `__body li`）
- 标签名与 `#` 分属不同 `span`，正则锚 `^#java` 匹配不上 → 点第一个建议后按 `aria-label="Remove X"` 校验，名字不对就点 Remove 删除
- `intellij` **不是** dev.to 已有标签（建议会降级成 ai/openai/deepseek），用 `jetbrains`
- 已验证可用组合：`mybatis` / `java` / `sql` / `jetbrains`

**AI Disclosure**：编辑器有 `#post-ai-disclosure-btn`，三档 Hand Written / AI-assisted / Fully Autonomous。AI 起草的稿子选 **Some AI (AI-assisted)**。

**发布**：`Save Draft` 先存草稿，`Publish` 直接发。发布后 slug 从 `temp-slug-*` 变为正式 ID。

**风格**：技术长文（1,200~1,800 词），第一人称、具体场景开头、诚实写边界。dev.to 读者对硬广零容忍，作者身份必须在文中披露。

### 2.2 知乎

**入口**：目标问题页 → 「写回答」

**编辑器**：Draft.js（`.public-DraftEditor-content`）

**操作要点**：
- 「写回答」按钮常被 header 遮挡 → 用 DOM 级 `evaluate(() => btn.click())`，Playwright 普通 click 会超时
- 正文用 `keyboard.insertText(段落)` + `keyboard.press("Enter")` 逐段输入（Draft.js 不吃 `fill()`）
- 发布按钮在编辑器底部，文本「发布回答」；编辑已发布回答时是「提交修改」
- 已有「未发布的编辑草稿」时进入编辑会恢复草稿

**图片**（最易踩坑）：
- 点工具栏「图片」按钮**不会**触发 filechooser → 直接给隐藏 input 设文件：`input[type=file][accept*="image/gif"]`
- **插图前必须先按 Enter 建空行**，否则图会插进光标所在的句子中间，把完整句子截断
- **必须用真实鼠标点击目标段落内的位置**（Range API 设选区不触发 React focus）
- **gif 必须压到 800px 宽**——1440px 会被知乎**静默拒绝**（文件进了 input 但不触发上传，无 toast 无请求）
- atomic block（图片）点击选中后 `Delete` / `Backspace` 都删不掉 → 只能 `Ctrl+A` 全选 → `Delete` 清空 → 按正确顺序重建

**风格**：问答形态，先直接回答问题本身，作者身份在开头或显著位置披露，竞品中性归类不贬损。长度 500~1,000 字。

**文章 / 专栏编辑器**（`zhuanlan.zhihu.com/write`，与「写回答」是两套完全不同的编辑器）

标题用 `textarea[placeholder*="请输入标题"]`，正文同样是 Draft.js（`.public-DraftEditor-content`），但它有一套**半成品 Markdown 输入模式**——页面角落会显示「Markdown 语法输入中」。实测边界：

- **只认逐字键入，不认 paste。** 合成 `ClipboardEvent` 派发 paste 只进纯文本，`##`、`**`、```` ``` ```` 全部原样留在正文里（`h2=0 / pre=0`）。必须 `keyboard.type("## 标题", {delay:25})` 才会转成 H3。
- **H3 而非 H2**：`## ` 转出来的是 `<h3 class="Editable-styled">`。
- **行内 `**粗体**` 不支持**：星号被吃掉但不加粗（`strong=0`）。稿子里有粗体的要么全去掉，要么用工具栏 Ctrl+B 手动加。
- **有序列表**：`1. ` 逐字键入会转 `<ol><li>`，但**第二项不能自己写 `2. `**（序号自动生成，写出来的 `2.` 会变成正文）。
- **代码块**：Markdown 的 ```` ``` ```` 能进 PRE，但**进去就出不来**——`Escape`、`Shift+Tab`、`Ctrl+Enter` 全部无效，连按两次 `Enter` 也只是加空行，后续文字全被吞进 PRE。可靠做法是：先按普通段落输入代码，再用 `Ctrl+Alt+C` 整块转 PRE。
- **合并相邻代码块**：光标移到第二块行首按 `Backspace` —— 但它是**直接把两段文字粘连成一行**（`?==> Parameters:`），必须在粘连处补一次 `Enter` 拆行。
- **代码块语言**：hover 代码块后右上角出现 `.Editable-languageSuggestionsInput input`（placeholder「选择语言」）。`fill("xml")` 后列表里 `Hxml` 排在 `XML` 前面，**必须按文本精确点选**。线上验证 `<code class="language-xml">`。

**图片 / 封面 / 封面裁剪**：
- 点工具栏「图片」弹出的是素材面板（公共图片库 / 表情包 / 个人素材 / 本地图片上传 / 手机扫码 / AI 配图），点「本地图片上传」**也不触发 filechooser**；直接给隐藏 input 设文件：`input[type=file]` 里 `accept` 含 `image/gif` 的那个（实测 index 1）。
- 素材面板会渲染成 `.Modal-backdrop` 挡住整个编辑器，**必须 `Escape` 关掉**才能继续点正文。
- 封面是另一个 input：`accept=".jpeg, .jpg, .png"`（实测 index 2，不吃 gif）。传完线上是 1440×810。
- **gif 压缩别用 ffmpeg 直转**：`-vf scale=800:-1` 把 769KB 的图放大到 **21MB**（默认 gif 编码不做调色板优化）。用 PIL 逐帧 `convert('P', palette=Image.ADAPTIVE, colors=128)` + `optimize=True`，同一张降到 702KB。
- 上传后 src 先是 `blob:`，转存完变成 `pic-private.zhihu.com`。**「上传失败」会直接写在 figure 的 innerText 里**（`Editable-imageUploader` + 「上传失败」），删掉重传即可。

**其他两个坑**：
- **标题框会被误灌**：测试其他快捷键（尤其 Tab）时焦点可能跑到标题框，之后所有输入都进标题。发布前**必须回读标题 value**——本次就出现过标题里混进 `AFTER_Shift_Tab```sqlBODY_Control_Enter` 的事故。
- **单次调用超时截断**：3400 字逐段 `insertText` 跑不完一次工具调用，会静默停在半途（内容缺一半、块粘连）。分批灌入，每批 ≤20 块。

**专栏**：创作中心 → 内容管理 → 「专栏」tab → 「创建专栏」（只填名称 + 封面上传，Lv 1 账号可建）。收录文章走专栏主页的「收录内容」→ 选文章 → 「收录」，刷新后「N 篇内容」+1。

**发布后线上检查**：`document.querySelectorAll('code.language-xml').length`、`img.ztext-gif` 数量、`pre` 是否成对。这些在编辑态看不出对错，只有线上 DOM 才有语言 class。

**风控**：短时间连续答多个问题可能触发限流。建议一天 1~2 个问题，且内容必须针对问题本身（不能模板化）。文章发布不排队审核，点完「发布」即公开。

**风控**：短时间连续答多个问题可能触发限流。建议一天 1~2 个问题，且内容必须针对问题本身（不能模板化）。

### 2.3 掘金

**入口**：`https://juejin.cn/editor/drafts/new`

**编辑器**：bytemd + CodeMirror。用 API 一次写入，比逐字输入快几十倍：

```js
document.querySelector('.CodeMirror').CodeMirror.setValue(markdown)
```

**发布设置**：
- 分类：后端 / 前端 / Android / iOS / 人工智能 / 开发工具 / 代码人生 / 阅读
- 标签：**上限 1 个**（实测「你还能添加 0 个标签」）→ 选最核心的（如 `Java`）
- 封面：可选，建议 192×128 以上
- 摘要：100 字上限，通常自动提取
- 专栏 / 话题：可选

**坑位**：
- 标签输入框被 `.byte-select__placeholder` 遮挡 → 直接点 input 会超时，要点 placeholder 元素转发
- **真正的发布按钮是底部「发布博客」**；顶部 `.pub-btn` 的父容器 `.pub-container fixed` 常态 `display:none`，点它无反应

**审核**：提交后数分钟到数小时，个人主页显示「审核中」。通过后才有公开 URL（`juejin.cn/post/<id>`）。

**风格**：技术专栏长文（2,000~3,500 字），小标题分段，代码块 + 动图。掘金读者偏工程实践，喜欢「具体问题 → 具体方案」的结构。

### 2.4 CSDN

**入口**：`https://mp.csdn.net/mp_blog/creation/editor`

**编辑器**：**CKEditor 4**（实例名 `editor`）。默认进富文本模式，有「使用 MD 编辑器」按钮但点击常无反应 → 直接用 API 写 HTML：

```js
window.CKEDITOR.instances.editor.setData(html)
```

Markdown → HTML 转换用 `.local/md2html.py`（覆盖 h2-h4 / 代码块 / 行内代码 / 图片 / 链接 / 粗体 / 列表 / 段落；**不支持表格**，表格请改列表）。

**发布设置**：
- 文章标签：必填，可加多个（实测 5 个正常）
- 摘要：256 字上限
- 分类专栏：可选
- 文章类型：原创（默认）
- 可见范围：全部可见（默认）
- 封面：建议 16:9（1200×675 以上）

**坑位**：
- **真正的发布按钮是底部「发布博客」**（x 坐标约 1392）；顶部 `.pub-btn` 的父容器 `display:none`
- 封面：`input[type=file]` 有两个，选 `accept` 含 `.gif` 且**不含** `webp` 的那个；上传后必须点「确认上传」
- 编辑已发布文章再点「发布博客」会重新进审核
- **每日发文额度**：默认 2 篇/天（页面显示「今日发文额度还有 N 篇」）。超额后点发布只弹「今日发文已达上限」对话框，**内容不会自动存草稿**——额度满时别浪费一次填表，先确认额度再动手

**封面处理**：公众号的 2.35:1 封面需补成 16:9（不裁内容，上下补底色）：

```
ffmpeg -i src.png -vf "pad=1800:1012:0:(oh-ih)/2:color=0xF5F7FA" out.png
```

底色取原图左上角像素（这张是 `rgb(245,247,250)`）。

**风格**：技术教程/实战文（1,500~3,000 字），标题含明确关键词（如 `p6spy`、`MyBatis-Plus`），结构清晰、有代码有图。CSDN 搜索流量占比高，标题的搜索意图要明确。

**AI 检索权重最高**：GEO 工具实测 `blog.csdn.net` 被 AI 引用 131 次，是掘金（27 次）的 4.8 倍。**中文内容优先发 CSDN。**

### 2.7 微信公众号

**入口**：`mp.weixin.qq.com` → 内容管理 → 草稿箱 → 新建图文

**编辑器**：ProseMirror 正文 + UEditor（`edui`）工具栏的混合体；正文容器是 `[contenteditable=true]` 里图片最多的那个 ProseMirror。

**写入方式**：用 `ClipboardEvent` + `DataTransfer` 粘贴 HTML 到 ProseMirror（`input`/`textarea` 的 fill 无效）。转换脚本 `.local/wx2html.py`：markdown → 内联样式 HTML，链接只保留文本（URL 统一列文末），支持裸 `<img>` 与 `<table>` 原样保留。

**图片——这里最容易翻车**：
- **并排的两张图会不一样大（2026-11-24 复盘）**。微信在插入时把宽度写死成 `width: Npx !important`，**N 取「插入那一刻该图所在单元格的可用宽度」**，不是原图宽度。两张 220×220 的二维码放进 `width:50%` 的表格：第一张插入时表格还空着，按原图落地 220px；第二张插入时左列已被第一张撑开，右格可分配宽度只剩 169px，于是写成 169px。而我给的表格没有 `table-layout:fixed`，`td` 的 `width:50%` 在自动布局下让位于内容，列宽变成 380 : 296（比值与 220 : 169 吻合），把 51px 的差放大成肉眼明显的大小差。
  - **源 HTML 两侧完全对称也没用**——`width:100%;max-width:200px` 会被微信剥掉重写成像素值。
  - 避坑优先级：①**先把并排图拼成一张图再上传**（如 500×220），永远等大且不受格宽影响；②表格加 `table-layout:fixed` + `td{width:50%}`，并在插入后于编辑器里手动把两张图拖成同宽；③不要指望靠 `max-width` 之类的 CSS 约束。
- **粘贴 HTML 里的外链图绝大多数不会转存**。实测 14 张里只有 1 张变成 `mmbiz.qpic.cn`，其余 13 张在正文里只剩空 `ProseMirror-separator` 占位。
- 后果不是"图不显示"而是**「自动保存失败」**：封面、正文都齐了也存不下来，一开始极易误判成封面缺失或会话过期。
- 判据：`Array.from(pm.querySelectorAll('img')).filter(i => !i.className.includes('separator') && i.getAttribute('src'))` 的数量应等于应有张数。全页 `document.images` 里 `mmbiz` 只有 1 张就是没转存。
- 正确做法：**逐张上传**。编辑器有隐藏的 `input[type=file][accept*="image/gif"]`，`setInputFiles` 即走上传通道；插入前先把光标精确定位到目标段落：

```js
const k = pm.children[idx];               // 目标段落/空 section
const r = document.createRange();
r.selectNodeContents(k); r.collapse(false);
const sel = window.getSelection();
sel.removeAllRanges(); sel.addRange(r);   // ProseMirror 会同步 DOM selection
pm.focus();
await fi.setInputFiles(path);             // 等待 3~4s 转存
```

- **不要靠坐标点空 section**：高度为 0，点击常落到前一段内部，图片会把段落切成两半（"…纯" / 图 / "静态解析…"）。用锚点文本找段落 + Range 定位才稳。
- gif 最大实测 1.6MB 可传，无需压缩；上传后 `data-type` 为 `gif` 时会转成 `mmbiz_gif`。

**原创声明**：点 `.js_original_apply` → 弹窗选「文字原创」（默认已选）→ **必须勾选协议 checkbox**（`.weui-desktop-form__checkbox`）→ 点「确定」。成功判据是设置区显示「文字原创 · 作者: xxx · 已开启快捷转载」，且正文首部出现「原创：」标记；`.js_unset_original_title` 里的「未声明」是隐藏的旧节点，别被它误导。

**原文链接**：点 `.js_url_area` 行 → 弹出 popover（`.popover_article_setting_large`，输入框 `.js_url`）→ 填 URL → 点「确定」。设置成功后 `.article_url_setting` 会 `display:block` 并显示链接本身。

**封面**：必须走「从图片库选择」→ 下一步 → 编辑封面（2.35:1 / 1:1）→ 确认。**判成功不要看「拖拽或选择封面」文案**（那是 hover 前的占位），要看 `.js_cover_preview_new` 的 `background-image` 是否已是 `mmbiz` 地址 + 容器是否有 `has_first_cover` 类。

**摘要**：`#js_description`，上限 120 字，实际按 100 字左右写。注意它会被自动填成标题，要手动覆盖。

**标题**：`#title`，上限 64 字。

**合集**：
- 编辑器里的合集选择组件（`js_article_tags_vue`）在草稿页是**注释掉的**，点「未添加」不出选择器——不是权限问题，是组件没渲染。
- 后台合集管理只接受**已发表**文章（弹窗原文：「只能选择已发表内容，如需添加草稿，请先前往草稿箱发表后添加」）。所以合集永远是**发表后**的动作。
- 创建合集：`/cgi-bin/appmsgalbummgr?action=edit`（**不带 album_id 就是新建**，`action=create` 是 404）。名称 ≤30 字、简介 ≤200 字，可以先建 0 篇的空合集，但「0 篇不可配置在账号主页展示」。
- 本账号已建合集：**SQL Visualizer**（`album_id=4795766439984857090`，连续阅读开启），另有 问题解决 / swagger / java / 编程。
- 公开链接：`https://mp.weixin.qq.com/mp/appmsgalbum?action=getalbum&album_id=<id>`

**校验数据源**：页面全局 `window.CGI_DATA['pages/album/edit'].edit_resp` 直接给出合集的 id/title/desc/篇数，比读 DOM 可靠。

**发表链路（2026-11-23 实测，三层确认）**：
1. 点底部 `button.mass_send`（群发）→ 弹「创作来源声明」：涉时事/公共政策/AI 生成才需声明，技术原创文选「无需声明并发表」
2. 弹「发表」面板：群发通知（消耗当日次数，默认开）/ 分组通知 / 定时发表 → 点「发表」
3. 再弹一次群发说明（会展示在公众号列表、可能被推荐到看一看）→ 点「继续发表」
4. 若触发风控会弹「微信验证」全屏 iframe：`扫码后，请联系管理员进行验证`，二维码是 `https://mp.weixin.qq.com/safe/safeqrcode?ticket=...`，**必须真人扫码**，自动化到不了这一步
5. 发表后进发表记录，状态「审核中」→ 实测约 2 分钟转「已发表」，此时才有 `/s/<id>` 公开链接

**合集与文章联动**：审核中的文章在合集「添加已有内容」里选不到，必须等「已发表」；合集只有 1 篇时文章底部**不展示**合集卡片，凑到 2 篇才会出现「合集 · 连续阅读」入口。发布后微信还会提示「已自动将文章生成为贴图草稿」（发布后优先推荐给非粉丝），是额外的触达机会。

**贴图（图片消息）实测（2026-11-23）**：
- 文章发表后微信自动生成一份贴图草稿，在草稿箱的「贴图」tab（与「文章」tab 并列），更新时间为生成时刻。
- 形态不是单张卡片，而是**把文章转成「多图 + 全文」**：实测 13 张图（1 张红底白卡标题图 + 12 张正文截图/动图）配 392 字正文，且自动带上「内容链接」指向原文，点进去能看完整文章。
- **不占群发额度**：发表弹窗明写「发表贴图无需开启群发通知」，与文章发表不同，不会消耗当天的群发次数。
- 独立推荐池：贴图有自己的「全部 / 文章 / 贴图」筛选，编辑页「平台推荐」默认已开启，推的是非粉丝流量。
- 标题字段上限 **20 字**，微信自动取原文标题会被硬截（本次截成「服务未启，SQL 先知：一个把 Wrapper 变成」，语义断裂），必须手动改成 20 字内的完整句子。注意卡片上的红底图是**生成时烧死的**，改标题不会重绘，所以图里文字与标题字段会不一致（图里是完整原标题，通常可接受）。
- 发表同样会触发「微信验证」扫码。
- **贴图不能进「文章合集」**：合集的「添加已有内容」列表只列文章，贴图不在其中（实测贴图已发表后仍不出现）。合集入口只能在文章侧生效。

**正文小心**：粘贴的 HTML 若带 `<h1>`，会作为正文首行进入正文（公众号有独立标题字段），粘贴后要 `h1.remove()`。

## 三、内容策略

### 3.1 差异化（避免平台判重）

同一主题在不同平台不能复制粘贴。以 CSDN 两篇为例：

| 维度 | 第一篇 | 第二篇 |
|---|---|---|
| 切入 | 「改完 Wrapper 不知道 SQL」的开发流程痛点 | 「p6spy 换驱动成本高」的运维/审计痛点 |
| 结构 | 三类工具生态盘点 | 单一问题的多路径对比 |
| 关键词 | Wrapper / 预览 / MyBatis-Plus | p6spy / JDBC 驱动 / 日志还原 |
| 开头 | Wrapper 代码片段 | 评审会上被否的真实场景 |

### 3.2 去 AI 味清单

常见 AI 痕迹与改法：

| 原表述 | 改为 |
|---|---|
| `The formatting is not the hard part. The hard part is...` | `The formatting is the easy part. What makes this hard is...` |
| `they are not competitors so much as answers to different questions` | `They answer different questions rather than competing` |
| 三处 `What it needs / gives / does not give` 三段式 | 改两处为叙述句，保留一处 |
| `That last point matters more than it sounds.` | `That distinction is easy to miss.` |
| `Requirements, stated plainly:` | `Requirements:` |
| 「接下来的动作大家都熟：…」 | 「然后就是重启服务、发一次请求、翻控制台日志：…」 |
| 「我的解法是把这件事交给 IDE」 | 「后来我把这件事交给 IDE 了」 |
| 「工具的可信度一半在能做什么，一半在不假装能做什么」 | 「能做什么说清楚，不能做什么也说清楚」 |

### 3.3 事实核对

数字与边界必须与文档站一致（`docs/内容营销/20261121-D249中文平台发布包-草稿.md` §1.7 有核对表）：
- 15 种数据库方言（14 种有 EXPLAIN，GoldenDB 暂无）
- 11 个只读 MCP 工具
- IDEA 2024.3+；执行/EXPLAIN/JOIN 图需 Ultimate；MCP 需 2025.2+
- 免费、Apache-2.0、不发使用数据

### 3.4 作者身份披露

## 五、自动化操作速查

### 5.1 编辑器写入方式

| 平台 | 方式 | 代码 |
|---|---|---|
| dev.to | textarea fill | `locator('#article_body_markdown').fill(md)` |
| 知乎 | Draft.js 逐段 | `keyboard.insertText(para)` + `press("Enter")` |
| 掘金 | CodeMirror API | `document.querySelector('.CodeMirror').CodeMirror.setValue(md)` |
| CSDN | CKEditor API | `window.CKEDITOR.instances.editor.setData(html)` |

### 5.2 浏览器自动化环境

- 用 Edge 配置副本 + CDP：`--user-data-dir=<temp副本> --remote-debugging-port=9222`
- `playwright-core` 在 `C:\Users\USER\AppData\Local\Temp\pw-edge\node_modules\playwright-core`，**chromium 在 `mod.default.chromium`**
- 每次 `node_repl` 调用要重新 `import` + `connectOverCDP`
- 杀 Edge 用 PowerShell `Stop-Process -Name msedge -Force`（Git Bash 的 `taskkill /IM` 会被 MSYS 转成路径）

### 5.3 通用坑位

- **Playwright 普通 click 常被遮挡** → 用 `evaluate(() => el.click())` 做 DOM 级点击
- **`setInputFiles` 前先 `setInputFiles([])` 清空**，否则可能不触发上传
- **gif 尺寸超限时上传静默失败**（无 toast、无网络请求），优先怀疑尺寸而非限流
- 中文命令行乱码 → 写 UTF-8 文件再 `--data-binary`，或用 node_repl 直接传字符串

## 七、文档站侧的配套规则

改文档站 frontmatter 时注意（2026-11-23 踩坑）：

- **YAML 值含英文冒号 + 空格**（`IntelliJ IDEA: xxx`）会被当键值分隔符，`js-yaml` 抛 `mapping values are not allowed here`，**构建静默失败但 exit 0**
- 对策：值用单引号包裹；改完先 `yaml.safe_load` 试解析
- meta description 控制在 **150~160 字符**（CSDN SEO 扩展按此判定）
- **VitePress 1.6.4 的 `themeConfig.logo` 对象形式（light/dark/alt）实测不渲染 alt**——即使 light+dark 都给全，产物仍是 `alt=""`（配置被静默忽略，构建照常成功）。要补 alt 只能用构建期替换：
  ```js
  transformHtml(code) {
    return code.replace(/(<img src="\/logo\.svg" alt="")/g, '$1SQL Visualizer')
  }
  ```
  注：装饰性 logo 写 `alt=""`+`aria-hidden` 本符合 a11y 规范，此改动只为过 SEO 工具的机械检查
- 排查顺序：源文件 → YAML 解析 → dist 产物 → 线上，不要一上来怀疑缓存/CDN
