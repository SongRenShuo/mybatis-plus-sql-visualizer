# 内测 beta.1 与 beta.2 功能验收文档（2026-11-06）

> **用途**：2026-11-06 同日发布的两个内测版（`v2026.11.6-beta.1` 与 `v2026.11.6-beta.2`）的人工功能验收手册。两版的功能清单、操作步骤与判定口径都在这里；每条结论由验收人填在 §七。
> **通道**：Gitee 内测版（Marketplace 稳定通道不收内测包）。
> **判定口径**：`PASS` / `FAIL` / `N/A`（前置不具备，必须写原因，不得留空）。`FAIL` 要附截图或 `idea.log` 片段。
> **对照提交**：beta.1 = tag `2026.11.6-beta.1`；beta.2 = tag `2026.11.6-beta.2`（提交号见 §一）。

## 一、准备

1. **装包**：按要验的版本装对应 zip
   - beta.1：`mybatis-plus-sql-visualizer-2026.11.6-beta.1.zip`
   - beta.2：`mybatis-plus-sql-visualizer-2026.11.6-beta.2.zip`
   - 安装：Settings → Plugins → 齿轮 → Install Plugin from Disk… → 选 zip → 重启。
   - 两版互斥，**先验 beta.1 再升 beta.2**（覆盖安装即可，设置保留）。
2. **版本核对**：Settings → SQL Visualizer → 关于，版本号应为 `2026.11.6-beta.1` / `2026.11.6-beta.2`；`update/update.json` 指向的版本以用户手改为准，**验收不看它**。
3. **演示工程**：`mybatis-plus-sql-visualizer-demo`
   - 通用功能：Run `MybatisPlusDemoApplication`（8081，默认 mysql profile）。
   - 磐维相关：Run 时加 `--spring.profiles.active=panwei`（`application-panwei.yml` 指向测试服务器磐维 A 实例 `103.36.220.245:26101/panweidb`，`pwadmin` / `Panwei@2026`；容器 `panweidb-ora`，`datcompatibility=A`）。**应用必须从 IDE 里启动**，增强捕获才挂得上。
4. **工具窗**：Find Action（Ctrl+Shift+A）搜「SQL Visualizer」，四页签：SQL 日志 / 日志 → SQL / SQL → Java / SQL 历史。
5. **iBatis 用例**：若手头没有 iBatis 2.x 工程，用「日志 → SQL」页签直接粘贴 §四 B2-2 给出的三行日志，效果等价（不需要真应用）。

## 三、beta.1 分项验收

### B1-1 页面数据源 HQL 识别与转换

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 打开自研框架工程里 `<pages>` 的 `<maintainPage>` XML，光标落在 `<datasource>` 的 SQL 文本上 | 左侧 gutter 出现预览图标；打开预览，面板元信息行显示「来源: HQL（已转换）」 |
| 2 | 看预览 SQL | 实体名已换成表名（如 `FROM BaseLocation` → `FROM base_location`）；`location.xxx` 属性路径换成真实列名 |
| 3 | 点面板上的「原文」页签 | 显示转换前原文，只读，可切回 |
| 4 | Settings → SQL Visualizer → 自研框架数据源语言 选「仅 SQL」→ 回预览 | 按原生 SQL 直显（不再转换）；切回「自动」恢复转换 |
| 5 | 在 dumb 态（打开工程后立刻）或实体解析不到的工程里预览 | 回退显示原文并给提示，不报错、不给错数据 |

### B1-2 Mapper ↔ XML 原生快捷键

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 光标在 Mapper 接口方法名上按 Ctrl+B（或 Ctrl+Click） | 跳到对应 XML 语句标签 |
| 2 | 光标在 XML 语句标签名上按 Ctrl+B | 跳回接口方法 |
| 3 | 任一位置按 Ctrl+Alt+Home | 弹出「关联符号」列表，可跳到对侧 |
| 4 | 在非 Mapper 的普通类方法上按 Ctrl+B | 行为与未装插件一致（跳到原生声明/实现） |
| 5 | Settings → Keymaps 改 GotoDeclaration 的快捷键 | 插件跳转跟随新键位（无需改插件设置） |

### B1-3 跨通道重复条目折叠

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 应用从 IDE 启动、增强捕获开启，执行一条会打印控制台 SQL 的查询 | 列表里同一次执行只出现 **1 条**（不出现「一条无位置 + 一条有位置」两行） |
| 2 | 看该条目的耗时/行数/来源位置 | 两通道的信息融合在同一条上（有耗时、有位置） |
| 3 | 关掉「SQL 去重」开关再执行同一查询 | 折叠仍生效（跨通道折叠与去重开关解耦） |

### B1-4 工具语句完成提示

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 在预览面板点「执行 SQL」，跑一条更新或工具语句 | 完成后提示「已完成」类中性文案，**不出现**「超时」 |

### B1-5 日志列表「类名#方法名」

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | Settings → SQL 日志 → 打开「列表显示类名与方法名」（默认关） | 列表来源位置后出现 `[类名#方法名]` 段 |
| 2 | 关掉开关 | 该段消失；切换即时生效（无需重开面板） |

## 四、beta.2 分项验收

### B2-1 磐维增强捕获（需要磐维实例）

前置：demo 以 `--spring.profiles.active=panwei` 从 IDE 启动；Settings → SQL Visualizer → 增强捕获开启。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 启动应用后打开 SQL 日志面板，访问 `http://localhost:8081/order/list` | 列表出现该查询；条目带**目标库角标** `Panwei（磐维） · panweidb@103.36.220.245:26101` |
| 2 | 看该条目 | 有耗时、有来源位置（`OrderController.java:38` 一类），参数区可展开 |
| 3 | 访问 `http://localhost:8081/order/list?minAmount=100&maxAmount=300&status=1` | 条目参数显示 `100 / 300 / 1`（不是 NULL、不是 `?`） |
| 4 | 看面板底部状态栏 | 增强通道「已收事件 N」持续增长；**不出现**「发现未登记 JDBC 实现：org.panweidb…」 |
| 5 | 双击条目打开预览 | 方言按 Oracle 渲染（`to_char`/`dual`/`to_date` 不被改写），可正常格式化 |

### B2-2 iBatis 2.x 参数解析（不需要真工程）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 打开「日志 → SQL」页签，粘贴下面三行（`Parameters` 是 Java 集合 toString） | 解析出 1 条语句 |
| 2 | 看还原 SQL | `WHERE ORGID = '00340025002200200006'`——**没有方括号**、值带引号 |
| 3 | 把第一行 SQL 换成 `INSERT INTO t (a,b,c) VALUES (?,?,?)`，参数行换成 `Parameters: [00340025002200200006, null, 测试Org]`、`Types: [java.lang.String, null, java.lang.String]` | 还原为 `VALUES ('00340025002200200006', NULL, '测试Org')`——不再整片 NULL、位置不错位 |

```
2026-11-06 10:14:23.518 DEBUG 8984 --- [main] j.s.PreparedStatement : {pstm-100023} Types: [java.lang.String]
```

### B2-3 IDEA 2026.3 热替换

前置：IDE 为 2026.3，已装 beta.1 或更早版本。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 用 beta.2 的 zip 走插件更新（或 Settings → Plugins → Install from Disk 覆盖安装） | **不提示「需要重启 IDE」**；插件版本变为 `2026.11.6-beta.2`，可继续工作 |
| 2 | 重启一次后再看版本 | 仍是 beta.2；功能正常 |

### B2-4 未登记驱动点名 + attach 补扫

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 正常磐维应用（已登记） | 状态栏**不显示**「未登记 JDBC 实现」（反向判据） |
| 2 | 若有未登记驱动（如某国产库新驱动）的应用：从 IDE 启动 | 状态栏/空态诊断行显示「发现未登记 JDBC 实现：<类名>（未纳入驱动白名单，增强仅靠接口兜底）」 |
| 3 | 数据源懒加载的应用（启动后第一次请求才建连接），attach 后等 10~30s 再请求 | 仍能采到 SQL（补扫 2 轮生效） |

### B2-5 MP 空 Wrapper 预览

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 在 `mapper.delete(null)` 行看 gutter | 出现预览图标；预览为 `DELETE FROM <表>` |
| 2 | 实体有 `@TableLogic` 时看同一条 | 预览转逻辑删除 `UPDATE <表> SET 删除标记=1 WHERE 标记=0` |
| 3 | `mapper.update(entity, null)` | 预览为 `UPDATE <表> SET …`；无 WHERE，面板给全表更新红字警示 |
| 4 | `service.remove(null)` | 同 delete 行为 |
| 5 | 非 MP receiver（`list.remove(null)` / `redisTemplate.delete(null)`） | 不出现图标 |

### B2-6 JPA delete / update 调用行图标

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | `repository.delete(entity)` 行 | 出现预览图标，预览为对应 DELETE |
| 2 | `ht.delete(entity)` / `ht.update(entity)` | 同上 |
| 3 | `JoinWrappers.delete(...)` / `service.update(wrapper)` | 仍按原语义（工厂/服务链），行为不变 |

### B2-7 运行期拼接的 SQL 预览

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 预览一段用 `StringBuilder` / `+` 拼接、含运行时变量的 JdbcTemplate 或自研 DAO SQL | 运行时片段显示为**一条合法块注释** `/* 运行时值: <表达式> */`，注释不外溢 |
| 2 | 看 `WHERE (...)` 部分 | 右括号与引号完整，不出现「括号被吃掉」 |
| 3 | 含三元表达式的拼接 | 常量条件取分支、两支相同折叠、其余单占位；不把两条互斥分支线性拼在一起 |

### B2-8 增强捕获停采可见

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 正常使用（IDE 建会话即下发 CONFIG） | 应用控制台**不出现**「会话建立后 15000ms 内未收到任何 CONFIG」告警；心跳 `gate` 为 0 |
| 2 | 若出现该告警 | 说明 CONFIG 未下发到应用（网络/端口问题），按提示「下发任一 CONFIG 即解除」；把该行贴进 issue |

## 六、已知边界（命中不算失败）

- 磐维「v 版」制品 `cn.com.panweidb.Driver` 未登记；实际使用的 `panweidb-jdbc-2.0.0.jar` 是 `org.panweidb.*` 整包重命名，已覆盖
- 磐维 PG / MySQL 兼容模式的库不会自动切方言（`db_compatibility` 不是 SQL 模式信号），需在面板手动改选
- iBatis 2.x 批处理（一次 prepare 多次 `Parameters:`）一期不支持；参数元素内含逗号或嵌套方括号时按逗号切分（`List.toString` 不可逆）
- 磐维 A 内核把 `rowid` 做成系统列，只影响测试套件的保留字扫描（按 `skipWords` 声明例外），不影响产品行为
- 内测包不上 Marketplace；Marketplace 稳定通道的版本要等转正
