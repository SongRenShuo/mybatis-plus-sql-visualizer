## 一、独立工作台「粘贴执行计划」（PEV-01）

> 入口在**「SQL 预览」页签顶部工具栏**，位置在「从文件加载」之后：图标按钮「粘贴执行计划」，悬停文案「从剪贴板读取执行计划（EXPLAIN 文本或 JSON）并渲染结构化视图」。

### A1 入口可见

**路径**：SQL 预览页签顶部工具栏。
**步骤**：① 数工具栏按钮：解析 / 格式化 / 从文件加载 / **粘贴执行计划** / 清空 / 在弹框中打开；② 悬停看说明。
**期望**：① 新按钮在第 4 位；② 悬停出上述说明文案。
**判读**：按钮缺失 = 不通过（先确认插件包确实来自本分支）。

### A2 JSON 粘贴：全管线（徽章 + 统计 + 收拢）

**路径**：工作台工具栏「粘贴执行计划」。
**步骤**：① 剪贴板放 P3 的 JSON 素材；② 点按钮。
**期望**：弹出「EXPLAIN · 粘贴」标题弹窗，内容为可折叠计划树；树根直接是计划首节点（没有一层无信息量的 `Plan` 包装）；若素材含 ANALYZE 数据（`Actual Rows` / `Actual Total Time`），树节点带 **⚠ ×N** 偏差徽章、树下方出现**耗时统计条**（表 / 索引 / 函数 / 节点类型 + 未解释占比）。
**判读**：徽章倍数 ≈ 估算与实际行数的比值（±舍入）；统计条里能看到素材里出现过的表名；无 ANALYZE 数据的 JSON → **无**徽章、**无**统计条（诚实降级，不是缺陷）。

### A3 text 粘贴：树 + 建议

**步骤**：① 剪贴板放 psql 文本树素材；② 点按钮。
**期望**：弹窗出同款树；若计划里有顺序扫大表，出现**索引/警示建议条**（如 `SEQ_SCAN`）；状态行显示「已渲染粘贴的计划（N 节点）」，N 与素材节点数一致。
**判读**：树结构与 psql 缩进层级一致；建议条只提示不执行。
**说明**：text 档无徽章/统计属**预期行为**（v1 边界，见 §六）。

### A4 psql 边框与折行形态

**步骤**：剪贴板放带 `┌─│└` 框线、折行续接、`Worker N:` 分段的 psql 输出，点按钮。
**期望**：框线被清洗、折行正确续接、Workers 段挂到 worker 叶节点——树正常成型。
**判读**：节点数手数一致；worker 级字段（如 Batches）不出现在节点警示里（worker 行不冒充节点溢盘）。

### A5 负例三连（诚实降级）

**步骤**：依次把 ① 一段普通文字（`hello world`）；② 形似 JSON 但不是计划的 `{"foo": {"bar": 1}}`；③ 清空剪贴板——各点一次按钮。
**期望**：① 状态行「不是可识别的执行计划：…」，**不开弹窗**；② 同左（原因段为「形似 JSON 但不是可解析的计划」）；③ 状态行「剪贴板没有文本」。
**判读**：三种情况弹窗数都为 0；状态行每次都有内容。

### A6 截断素材负例

**步骤**：把 psql 文本树**砍掉一半行**再粘贴。
**期望**：状态行给「存在无法识别的节点行（粘贴被截断或折行丢失？）」一类原因，不出残树弹窗。
**判读**：失败文案里能看出「截断/折行」方向；原文不进弹窗（宁失败不猜）。

## 二、控制台直出（PEV-05）

> 入口在**查询控制台编辑器右键菜单末尾**：「可视化执行计划」与「可视化执行计划（ANALYZE）」两个独立菜单项。

### B1 入口与禁用态

**路径**：各编辑器右键菜单。
**步骤**：① PostgreSQL 控制台选中一条 `SELECT ...`，看右键菜单末尾；② 在普通 Java 文件里看右键菜单；③ 在 Oracle（或 SQL Server）控制台里看。
**期望**：① 两项出现且可用；② 两项**禁用（灰）**——不在控制台没有语句与连接；③ Oracle/SQL Server 控制台里**禁用**（本批只收敛 PG=JSON 档、MySQL=表格档两族，其余方言保持原生 EXPLAIN 入口）。
**判读**：禁用态判定优先于执行判定——菜单一项在非两族方言里亮起即不通过。

### B2 普通可视化（不执行语句）

**路径**：PG 控制台。
**步骤**：① 选中 `SELECT * FROM <大表> LIMIT 10`；② 右键「可视化执行计划」。
**期望**：弹出结构化视图（与预览面板「执行计划」按钮同款组件）：头部「EXPLAIN · PostgreSQL · 数据源名 · 耗时 ms」、JSON 树、（若有命中）索引建议条。
**判读**：库端该 SELECT 可以执行（这是 EXPLAIN 的正常语义），但**无 ANALYZE 数据** → 视图里没有徽章、没有统计条；回到库端确认数据未变。

### B3 MySQL 表格档

**步骤**：MySQL 控制台选中一条 SELECT，右键「可视化执行计划」。
**期望**：只读表格视图（MySQL EXPLAIN 的 id/select_type/table/type/key/rows/Extra 列）；大表全扫时出现索引建议条（type=ALL）。
**判读**：表格列名与原生 EXPLAIN 输出一致。

### B4 ANALYZE 变体（真实执行）

**步骤**：PG 控制台选中一条只读 SELECT，右键「可视化执行计划（ANALYZE）」。
**期望**：视图带 `Actual Rows` 偏差徽章与耗时统计条；SELECT 被真实执行（这是 ANALYZE 语义），但只读语句对库无影响。
**判读**：徽章与统计条同时出现；头部耗时 > 0。

### B5 负例：DML + ANALYZE 拦截（本批核心安全面）

**路径**：PG 控制台。
**步骤**：① 选中 `UPDATE <表> SET <列>=<列> WHERE ...`（或 DELETE）；② 右键「可视化执行计划（ANALYZE）」；③ 记录库端数据状态；④ 同语句改点「可视化执行计划」（不带 ANALYZE）。
**期望**：② 弹通知「已拦截 EXPLAIN ANALYZE」，正文说明**会真实执行、触发器会触发、序列会烧号**，未执行；库端数据未变（COUNT 前后一致）；④ 出计划视图（不带 ANALYZE 的 EXPLAIN 不执行写，允许）。
**判读**：拦截通知的正文必须含副作用说明（不只是干巴巴「已拦截」）；③ 是硬判据——数据动了即不通过。

### B6 负例：未回填占位符

**步骤**：控制台选中含字面 `?` 的语句（如手写的 JDBC 形态），点任一动作。
**期望**：通知「SQL 仍含未回填的 ? 占位符…」，未执行。
**判读**：两类动作（普通/ANALYZE）都拦。

### B7 大计划收拢联动（PEV-06 既有入口生效面）

**步骤**：PG 控制台选中一条多表 JOIN 大查询，右键「可视化执行计划（ANALYZE）」。
**期望**：树中层大子树默认**收拢**并标 **(+N)** 规模；根层与首层展开；点收拢项能展开，手动展开不受限。
**判读**：首屏可见节点数明显少于树总节点数；(+N) 数字与展开后的子节点数一致（±1，含自身口径差）；全量超过 2000 节点时收拢更紧（自适应，肉眼表现为首屏更浅）。

## 三、徽章与统计细判读（PEV-02/03，配合 A2/B4）

### C1 三档色阶与阈值

**步骤**：① 构造偏差 ~×30 的 ANALYZE（如对无统计信息的新表查询）；② 构造更大偏差（统计严重过期）。
**期望**：徽章色随倍数分档（>10 提醒色 / >100 加重色 / >1000 最重色，具体色值跟主题）；悬停徽章出「行数估算与实际偏差 N 倍（EXPLAIN ANALYZE 数据）」。
**判读**：以 tooltip 数字为准对档（×25 应在第一档、×250 第二档、×2500 第三档）。

### C2 小样本豁免

**步骤**：对估算行数 < 10 的小表造偏差。
**期望**：不标徽章（小表偏差是常态噪音）。
**判读**：无 ⚠ 标记即通过；有标记即不通过。

### C3 统计条负例

**步骤**：用不含 `Actual Total Time` 的普通 EXPLAIN JSON 走 A2。
**期望**：统计条整块不出现（不是出现空条）。
