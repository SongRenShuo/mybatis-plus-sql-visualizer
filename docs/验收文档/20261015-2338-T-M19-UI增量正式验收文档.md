4. W460/W250/W230 看长句省略，双击完整预览、Ctrl+C 和右键“复制 SQL”，对照未截断的原始文本；开启脱敏时按 UI07 的脱敏文本比较。跳源码只选 S1/S3 真实来源条目，准确落到该 SQL 调用点；人工历史不能要求假定位。

### UI06 — R53 双通道状态与增强暂停

1. 开始“捕捉”，增强总开关关；底部应显示“控制台：已挂载 N 个，已扫描 M 行”和“增强：未开启”。有 SQL 条目时仍可见，停止捕捉则整行隐藏、不留分隔符。
2. 经用户同意给专属 S3 应用挂增强捕获；记录应用 PID、心跳和首次 SQL。预期增强状态与设置页一致，已挂载态含事件计数，不能用零事件证明捕获正常。
3. 点“暂停增强捕获”，继续发只读请求。预期提示“增强：暂停中…”，按钮变“恢复增强捕获”；应用连接、心跳与 CONFIG 链不被当作关闭处理。控制台通道照常，因此列表仍增长**不自动算失败**，必须区分来源。
4. 恢复后再发带可区分条件的请求，确认新的 agent 条目恢复，不重放暂停期间所有 agent 事件，不双份重复。总事件计数是接收口径，不要求等于当前列表数。
5. 总开关关→开与按钮暂停→恢复分别记录，不混同。退出测试应用应只影响该 PID，不能停止其他 JVM。状态栏按约 2 秒刷新记录延迟，不用固定截图瞬间误判。

### UI07 — R60 展示脱敏与原始数据边界

1. 仅在测试工程产生 `username=13800138000` 的 S1 查询；另用人工历史加入 `SELECT * FROM m19_acceptance WHERE password = 'M19_FAKE_PASSWORD' AND phone = '13800138000';`。不得执行该人工 SQL。

### UI09 — 调用栈业务帧、内部折叠与两端摘要

### UI11 — 三类本地数据清理及迟到回写

真实入口：设置的“SQL 日志”→“自动保存”分组；源码 `PluginSettingsPanelSections.kt` 和 `PluginSettingsPanel.kt`。不是工具栏“清空”，不是通用“清除缓存”。

1. 在隔离配置用 S2 建两条预览历史，参数 `username=M19_ACCEPT_A/B`，保存命名方案 `M19_A`；打开 A/B 两个预览面板。开启测试工程捕获文件保存，产生一条测试 SQL，再关闭自动保存，保留文件作为哨兵；备份/哈希仅测试配置与文件。
2. 检查三段披露始终可见：捕获文件默认不自动保存；预览历史默认随预览保存于 IDE 配置 `mp-sql-visualizer.xml`；参数历史/命名方案可能以明文 JSON 存同一文件。自动保存关闭不应置灰独立清理按钮。
3. 点“打开捕获历史目录”，预期只打开当前默认/自定义目录，文件哈希不变，不删除默认或旧自定义目录。操作系统无法打开时应报路径/权限失败，不能声称清空。
4. 点“清除预览 SQL 历史…”先取消：全部不变。再确认：预览历史含收藏/标签/条目内参数快照清除；参数方案 `M19_A` 和捕获文件仍在。若当前历史 UI 入口不能辨明应用级历史，使用隔离配置持久化内容和已有预览历史入口核对，不能把工具窗文件“历史”当同一存储。
5. 重新建一条预览历史；在旧 A 面板改参数，紧接着在设置点“清除参数历史与命名方案…”确认，回到旧 A/B 编辑、切方案、关闭。预期默认参数、命名方案和激活指针清除；旧面板缓存、待防抖写回均不能复活。配置正常保存并重启隔离 IDE后再核，不要求在 IDE 正写配置时读到瞬时最终值。
6. 下一次**新预览**输入 `M19_NEW` 可重新记录，证明不是永远禁止参数保存。预览历史和捕获文件在参数清理前后保持独立。
7. 点“清除缓存”，三种持久数据不能被连带删除；清理不得删除整个 `mp-sql-visualizer.xml`，其他插件设置（例如显示模式）保持。权限失败仅能在测试配置副本制造，不能改用户真实配置 ACL；失败提示不能冒称成功。

阻断：误删捕获文件、清一类连带另一类、旧面板/防抖写回复活、取消确认仍删除、误操作日常配置，任一发生立即停止后续清理并保存脱敏证据。
