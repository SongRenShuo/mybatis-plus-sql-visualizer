# R94 审阅后诊断反馈验收

## 本轮交付范围

在既有“分享 SQL”中新增“审阅诊断报告并反馈”，将严格投影后的 SQL 结构与诊断摘要交给既有反馈对话框，再由用户审阅、删段、编辑、明确同意后提交。**不是直接上传旧 R50 原始报告，也没有新增网络接口。**

- 发送目的地为既有官网公开需求池 `https://sql-visualizer.jvtools.cn/about/feedback`，正文沿现有 `FeedbackApi`，不发附件。
- 默认投影移除全部字面量（含布尔/NULL）、注释、参数名和标识符；无法处理的引号/方言形式或超限输入省略整段 SQL，绝不回退原文。没有完整方言语法判定时，COUNT/JSON等词也可能是合法表列名，因此只保留开头语句种类，其余字母token均匿名。输出保留符号和重复token关系，但不是可执行SQL，也不承诺完整SQL语法结构。
- 默认不包含原参数值、来源路径、调用栈、原始计划、NOTICE、回滚 SQL。
- 脱敏不是无机密保证，用户必须审阅。手工输入的正文按用户当前审阅快照发送，不暗中重新生成/替换。
- 诊断草稿不写磁盘，不自动发送。正文上限 16 KiB UTF-8 是客户端保护，不冒称服务端限制。

本轮不打开沙盒 IDEA、不提交线上反馈；下面 UI 步骤全部待验。headless fake sender 的结果仅证明接线/同意/载荷契约，不证明服务器收到反馈。

## UI 操作方法

### F1 入口与零请求前提

1. 在独立验收配置打开一条合成 SQL 预览，例如 `SELECT private_name FROM private_table WHERE password='M19_SENTINEL'`。
2. 从既有分享入口选择“审阅诊断报告并反馈”。默认仍选 Markdown，新增动作不能改变旧六个出口。
3. 预期打开的是现有反馈表单的诊断模式，目的地、字节计数、段落选择和默认未勾同意均可见；原始堆栈附件不出现。
4. 打开、切段、编辑、取消期间检查测试传输计数必须为0。不得向真实公网抓包发送该合成内容来“证明没有发送”。

### F2 逐段审阅与最终快照

1. SQL 文本应只剩结构、占位值和匿名标识符，哨兵 `M19_SENTINEL`、原表名、列名不在自动草稿中。
2. 不支持的 `q'[...]'`、美元引号、反斜杠歧义、未闭合引号应显示 SQL 段省略，不显示原 SQL。
3. 勾同意后修改正文或标题/联系信息，预期同意立即失效；未重新同意点击提交不得调用 sender。
4. 取消 SQL 段后必须在最终发送 `description` 中也消失，不只在预览隐藏。切段会重建草稿且清掉手工修改，界面必须事前说明。
5. 只有再次明确同意并提交后，才捕获一次不可变快照；原预览面板变化不得改变已捕获请求。

### F3 失败、重试和预算

1. 使用测试 sender 返回失败，表单保留已编辑正文，显示错误；不得自动重试。
2. 第二次提交须重新勾同意。
3. 6000 个汉字=18000 UTF-8 字节，超过本地上限必须阻止，不能静默截掉尾部再发送。
4. 界面和消息长行需在243/253/262、Light/Dark、100/125%检查可读与不裁切；滚动区域仍能看到最终正文与提交按钮。
5. 浏览器兜底只能打开现有反馈页面，URL不得携带诊断 SQL/参数；本轮不执行真实发送。

## headless 判据与反向点

- `ShareContentProjectionTest`：字面量/注释/参数名/标识符哨兵，未知引号省略、预算和引用边界。
- `DiagnosticShareDraftTest`：未同意、编辑撤同意、删段、UTF-8、不可变快照及一次性同意。
- `DiagnosticFeedbackReviewTest`：走真实 `ErrorReportDialog.doOKAction`，fake sender 捕获精确请求；取消/未同意/修改后零发送；删 SQL 段后发送内容中无该段；失败重试重审；附件恒空。
- `ShareDialogTest`：新增第七入口真实在场、默认仍为Markdown，默认草稿没有哨兵与原表名。
- `ErrorReportDialogLayoutTest`：旧错误/手动反馈布局和校验无回归。

反向验证必须临时撤掉提交前同意消费或真实投影接线，使上述真实发送边界测试变红，再完整恢复；仅断言按钮存在或纯模型为绿不能收口。
