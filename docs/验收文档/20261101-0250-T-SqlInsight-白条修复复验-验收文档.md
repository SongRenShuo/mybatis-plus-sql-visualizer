## 附记：`PropertiesComponent` 状态半写（独立于白条，登记备查）

现象：demo 项目 `.idea/workspace.xml` 中 `"mpsql.visualizer.last.runner.id"` 的值缺开头引号（`"mpsql.visualizer.last.runner.id": 8d6c2a1b-…`），每次 IDE 启动报 `SEVERE: Cannot init component state (ProjectPropertyService)` + `JsonDecodingException: Expected quotation mark '"', but had '8'`（偏移恒 3171）。

已核实：

- 插件只用公开 API `PropertiesComponent.setValue/getValue/unsetValue`，无自拼 JSON/XML（全仓 `PropertiesComponent` 引用逐条看过）。
- 但写入线程不安全：`DataSourceSelectorConsole.kt:423` 的 `rememberRunner` 位于 `prepareAfterEditorResolved` 内，该函数由 `sessionConsumer`（Database 插件 runner 建好 session 后的回调，`DataSourceSelectorResults.kt:341` 定义、`:360` 调 `prepareInConsole`）直接调用；`prepareInConsole` 的同步分支（`DataSourceSelectorConsole.kt:1171` 的 `if (firstEditor != null || !isDispatchThread)`）在编辑器已就绪或调用方非 EDT 时**不回 EDT**，同文件 1188 行注释亦自述「本分支在非 EDT 线程上，须归位 EDT」。即 `PropertiesComponent.setValue` 可能在后台线程执行。
- 时间线：demo 工程最后一次健康加载是 `mybatis-plus-sql-visualizer/build/MPSV-GifFresh`（2026-10-31 20:34:26–20:53:55，无该报错），该会话日志结尾无任何关停标记（`IDE is shutting down` / `Waiting for process detach` 计数均为 0）；下一次加载 `mpsv-sql-insight/build/MPSV-InsightWalk` 于 21:21:17（启动后 4 秒）即报错。损坏发生在 20:53:55–21:21:13 之间。
- 本轮 02:17:50 的强杀已被排除：同一报错（同偏移、同键）在 21:21、23:25、01:15 三次日志中已存在，早于本轮会话起点 02:07。

未核实：缺一个引号的字节级成因（平台序列化与保存竞争的具体形态），以及能否在正常退出下复现。按证据只登记「插件在后台线程写项目级 PropertiesComponent」这一不安全形态，不定论字节机制。
