### 4.1 分析 SQL（结构与来源）

入口：更多 → 分析SQL。面板内新增「SQL分析」页签，**不弹独立窗口**。

| 功能点 | 路径与操作 | 预期 |
|---|---|---|
| 结构树 | 更多 → 分析SQL → 看「结构与来源树」 | 分「语句结构与表读写角色」「结果字段与已证实来源」「值来源与行选择依赖」「诊断与覆盖范围」四块；未解析处显示局部原因而不是留白 |
| 读写图 | 切到「读写关系有向图」 | 只画读写关系边；JOIN 不会被画成写。节点可点，点后定位 SQL |
| 分析质量 | 看「分析质量」区 | 显示 CERTAIN / PARTIAL / AMBIGUOUS / UNKNOWN / CONDITIONAL 之一并给出依据；另显示「源码区间质量」与「已验证方言」 |
| 节点定位 | 点树节点或图节点 | 有已验证精确区间时选中该区间（提示「已定位到经过验证的源码区间」）；没有时选中整条 SQL（提示「没有经过验证的精确区间，已选择全语句；未猜测同名片段位置」）——后者是正常现象 |
| 复制摘要 | 点「复制分析摘要」 | 剪贴板得到文本摘要；超预算时明确写 omitted，不静默截断 |
| 离线声明 | 读面板顶部提示 | 明说「仅离线分析，不执行SQL，不读取数据库元数据。JOIN和筛选依赖不等于值血缘」 |
| 空文档 | 清空 SQL 后打开 | 显示「当前SQL文档为空，不会分析上一次SQL」 |
| 编辑失效 | 打开分析后改 SQL 文本 | 提示「SQL或预览已变化，旧分析已清除，请重新分析」；旧分析不复活 |
| 老结果不串页签 | 关闭预览再开另一条 SQL | 不显示上一条 SQL 的分析结果 |
| 显示预算 | 对超大语句（>200 节点）打开 | 提示「已达显示预算（200节点／400边／1000条详情），当前展示的是不完整子集」 |
| 输入超限 | 粘贴 >65,536 字符 | 提示「输入超过65,536字符，请缩小为单条语句后分析」 |
| 取消 | 分析中点点「取消」 | 提示「已取消分析，不会回填结果」 |
| 重新分析 | 改 SQL 后点「重新分析」 | 按新文本重跑，结果与新版一致 |

### 4.2 参数场景 / 渲染解释

入口：更多 → 参数场景，或 更多 → 渲染解释。**两个菜单项打开同一个面板**（同一能力的两种叫法，不是两个功能）。

| 功能点 | 路径与操作 | 预期 |
|---|---|---|
| 场景列表 | 打开 XML 预览 → 更多 → 参数场景 | 出现「场景与渲染解释」，列表含「当前输入」与已存命名预设；列显示场景名、参数数、关系数／失败 |
| 上限 | 预设多于 19 个 | 提示「展示当前输入及前19个已存场景，其余预设未分析」 |
| 只读性 | 选中另一个场景看详情 | 只读快照，不切换、不改写命名预设，参数面板不变 |
| 条件说明 | 读面板提示 | 明说「条件遵循预览开关，不代表真实运行路径覆盖」；trace 定位是展开节点路径，不是原 XML 偏移 |
| 非 XML 预览 | 对普通 Java Wrapper 预览打开 | 提示「参数场景需要XML预览模型；当前SQL和预设未改变」 |
| 脱敏导出 | 点「预览脱敏回归JSON」→「复制已审阅JSON」 | 参数值、标识符、预设名已移除；无网络请求；提示「此包不得作为SQL执行」 |
| 期望校验 | 「保存本页期望」→「验证当前场景」 | 仅确定语义可保存；无期望时显示 INCONCLUSIVE 而不是 PASS |
| 存储清理 | 参数存储被清后打开 | 提示「参数存储已清理，请重新打开预览后生成场景」 |

### 4.10 预览数据源指示行与换源（本轮合并新增，W12 定案改写）

来源：T-ExplainFailUx W2 初版 → T-ExplainSwitchNative W5/W6/W7 → **W12 定案（2026-10-24 用户实测三图）**。演进过程**推翻了多项早先形态**：自研数据源下拉（W2）被否决；W5 的「切换数据源」链接按钮 + 平台原生选择器弹层也被 W12 否决——平台 `getForcedDataSourceForExec` 的「选中即关联」无公开清除 API，插件自建入口第二次起必被短路成单源（日志实证 runners 5→1）。**最终形态：指示行只留纯文本，换源一律走右侧内嵌控制台头部的平台原生 `Data Sources` 菜单**。按旧形态去找下拉、链接按钮或插件弹出的选择器都不对。

| 功能点 | 路径与操作 | 预期 |
|---|---|---|
| 指示行 | 打开任一预览，看参数区下方 | 纯文本一行「数据源：」+ 三/四态之一，**没有下拉框、没有按钮、没有链接** |
| 态文案 | 分别在「有绑定」「只有上次使用记忆（模块级）」「只有上次使用记忆（项目级兜底）」「两者都无」四种情况打开预览 | 依次显示「已绑定：{名}」「数据源（本模块上次使用）：{名}」「数据源（上次使用）：{名}」「未绑定数据源（在控制台执行一次查询即可绑定）」——模块级与项目级由 T-ModuleScopedLastUsed W3 区分，且判据是「模块级键本身有无值」（`rememberedIsModuleScoped` 误判缺陷已修） |
| 换源入口 | 找插件自建换源控件 | **不存在**（W12 纪律，守卫 `换源一律走平台原生工具栏不得自建入口` 钉死）；换源走右侧内嵌控制台头部的原生 `Data Sources` 菜单（Detach Data Source + 全部源） |

| last-used 歧义不猜 | 改名制造同名多条数据源后打开预览 | 弃记忆走弹窗，不静默取首条（T-SI-02）；只清该模块那层记忆 |

### 4.11 选错源失败的就地引导（本轮合并新增，W12 定案改写）

来源：T-ExplainFailUx W1 → T-ExplainSwitchNative W6/W9 → **W12 定案** + **T-ExplainConsoleFirst W1/W6/W7/W8**。注意通道形态已变：**执行计划默认走预览窗内嵌原生控制台（形态 A）**，失败呈现由平台控制台原生负责；结构化通道（`explainStructuredRender`，默认关，推荐通知只提示一次）仍走就地横幅。旧手册里「必弹插件选择器」「切换后自动重试」的预期全部作废。

| 功能点 | 路径与操作 | 预期 |
|---|---|---|
| 直送链默认形态 | 对任意 SELECT 预览点「执行计划」 | 预览窗内嵌**原生控制台**（▶ 工具栏/Tx/Auto 等平台元素在场），不弹独立窗、不走旁路查询（T-ExplainConsoleFirst W1 形态 A 回归） |
| 直送链零源 | 工程没有任何数据源时点「执行计划」 | 提示去 Database 工具窗口，不空跑必然失败的执行 |
| 结构化通道就地横幅 | 设置开启 `explainStructuredRender` → 绑错库点「执行计划」 | 结果区就地出横幅（`showExplainWrongTarget`），**不弹模态** |
| 横幅换源动作（W12） | 点横幅上的「切换数据源」 | **打开 Database 工具窗口**（`openDatabaseToolWindow`）——不再弹插件自建选择器；次动作「在控制台打开」仍在 |
| 方言闸红条换源（W12） | 触发方言闸门阻断红条 → 点「切换数据源」 | 打开 Database 工具窗口；**不得**走 executeSql 执行链（W9 定例，守卫钉死） |
| 渲染方言缺失不误阻断 | 对渲染链未记录方言的载体（JPA／日志还原等）执行 | 按渲染器既有口径回落 MySQL，**不**因 `effectiveDialect` 为 null 判「按未知渲染」而阻断（W10） |
| 方言冲突不阻断执行 | 渲染方言与目标数据源方言不一致且无法自动重渲染 | 不再阻断执行；报错文案报**渲染方言**（`8619a3aff`：此前按目标源反推会与预览标头「方言： X（手动指定）」自相矛盾） |
| 列名错误不误判 | 构造 `Unknown column 'x'`（表在、列不在） | 仍走原错误出口，**不**进「选错源」档——换源解决不了列问题 |
| 认证失败优先 | 数据源未存密码 | 走认证档（平台凭据链/轻通知），不被「选错源」档抢走 |

## 五、需要人工定性的项

以下自动化测不出观感或真实交互，必须人眼判断：

1. 「SQL分析」页签内的树和图在窄面板下是否可读，图节点标签是否截断到无法辨认。
2. 读写关系图在 20+ 表的大语句下，缩放／滚动是否可用，是否出现节点重叠。
3. 「运行 SQL 分析」的请求时间轴条形图，在真实请求密度下是否还能看出区间并集与单条 SQL 的关系。
4. 场景列表在 20 个预设时，滚动与选中详情是否互相干扰。
5. 结果比较的审批流程（三个勾选 + 单次批准）在真实使用中是否过重，是否容易漏勾导致无法执行。
6. 离线 Trace 的 span 列表在数百条时是否可定位，链接模板错误提示是否指向具体字段。
7. 对象使用反查在模块范围内扫描大工程时的等待观感，是否提供可取消反馈。
8. 各洞察页签与预览编辑器之间的焦点切换：点树节点定位后，键盘焦点是否回到预期控件。
9. **数据源指示行在社区版的实际形态**：是否只留纯文本（W12 后不再有任何自建控件）、不报错，有没有残留空行或错位。
10. **选错源横幅在窄预览面板下**：文案是否被裁，两个动作按钮是否都可见可点；点「切换数据源」打开 Database 工具窗口的落点是否符合预期。

## 六、正常现象（先排除，再报缺陷）

- 点树节点后选中整条 SQL：未证明精确源码区间时按设计选全语句，不是定位失败。
- 「分析质量」显示 PARTIAL／AMBIGUOUS／UNKNOWN：解析器只对已验证子集给 CERTAIN，带星号、未绑定元数据、方言不支持等都会降级，属正常披露。
- 运行分析里大量「未知连接目标」：多主机／非标准 URL 或无连接事件时按未知隔离，不会合并成同一目标。
- 请求时间轴出现 INCONCLUSIVE：跨线程、终态缺失或采集不完整时按设计不判 PASS。
- 事务视图显示 UNKNOWN：只有 JDBC 边界事件被观测，CLOSE 不等于 COMMIT。
- 优化候选为空：没有命中已实现的三条规则时不编造建议。
- 结果比较拒绝执行：未选目标、未勾三项批准、参数未回填、方言未确认，任一不满足都会拒绝，属安全设计。
- 离线 Trace 导入被拒绝：超 1 MiB、字段非法、重复键或非 OTLP JSON 都拒绝。
- 对象使用提示「未使用陈旧偏移定位」：源文件已变化，按设计不跳旧位置。
- 编辑 SQL 后分析页签消失或变空：文档版本变化使旧结果失效，重新打开即可。
- **数据源指示行显示「未绑定数据源」**：预览从未在控制台执行过查询，属正常初态，执行一次查询即绑定。
- **预览里找不到「切换数据源」按钮**：W12 已把插件自建换源控件全部退役，换源走右侧内嵌控制台头部的原生 `Data Sources` 菜单，属设计而非缺陷。
- **点红条/横幅「切换数据源」打开的是 Database 工具窗口而不是弹列表**：W12 定案动作就是送用户到能换源的地方，属设计而非失灵。
- **勾选「启用所有会话的分析」后状态栏不是立刻变 `enabled=true`**：agent 确认是异步的（config 下发 → 回状态 → 建 boundary），勾选后约 0.4~1.2s 内自动落地（`063db9d6f` 修复后无需手动点刷新）；超过 3s 仍为 false 才是异常的，请记录。

## 七、不覆盖范围（不要按缺陷报）

- 未实现的语法形态：递归 CTE、存储过程内部、任意动态脚本、跨过程血缘。
- 请求观测仅限 Servlet 线程内（`SERVLET_THREAD_ONLY`）；异步、线程池、响应式、虚拟线程未承诺。
- 事务仅为代理连接／wrapper 生命周期证据（`PROXIED_CONNECTION_ONLY`），不认证真实池租借、XA 或跨线程传播。
- 结果比较是两次顺序读取，不是数据库原子快照。
- **性能**：新增请求追踪的延迟与 CPU 超出初始目标（P95 +27.17%、CPU +14.28pp），因此请求／事务追踪默认关闭，只在显式开启时承担成本。这是已披露的取舍，不是缺陷。
- 本机 Docker 不可用，5 个真实数据库方言用例在门禁中跳过；H2／SQLite 嵌入式验证覆盖语法形态，不等于方言运行时全覆盖。
- 结果比较、Schema 比较、影响面等仍只有合成 H2／SQLite 证据，未做真实业务库端到端。
