# T-SqlInsight SQL 洞察功能人工验收手册

> 2026-10-22 编写。对象：`t-sql-insight` 分支合入 dev 后的插件，重点覆盖 SQL 洞察九项入口。
> 配套：[插件自动化验收](./20261019-1140-T-SqlInsight-插件自动化验收-验收文档.md)（自动化读数、覆盖矩阵与限制）/ [实施与非UI验收台账](./20261016-2344-T-SqlInsight-实施与非UI验收台账-验收文档.md) / [开发计划](../开发计划/20261016-1716-T-SqlInsight-SQL洞察与关系流向分期建设-开发计划.md)。
> 用法：先按第二节走一遍冒烟（约十分钟），再按第三节逐项勾选。任何与预期不符，记下操作步骤和截图；先对照第五节排除正常现象，仍异常的按缺陷报。第四节是需要真人判断的项，不能靠自动化测试代替。

## 一、准备

1. 安装构建包：`mpsv-sql-insight-gate/build/distributions/mybatis-plus-sql-visualizer-2026.10.23-beta.2.zip`（以最新一次 `buildPlugin` 产物为准）。Settings → Plugins → 齿轮 → Install Plugin from Disk → 重启。
2. 核对版本：Settings → SQL Visualizer → About，应显示 2026.10.23-beta.2。注意同目录还留着旧的 2026.10.16 包，不要装错。
3. 演示工程：`mybatis-plus-sql-visualizer-demo`，从 IDE 里 Run 启动 `MybatisPlusDemoApplication`（8081）。SQL 日志与运行分析的前提是应用从 IDE 内启动。
4. 打开预览：SQL 日志工具窗双击任一条目，或 gutter 图标 / `Alt+Shift+Q`。
5. 打开「更多」：预览面板工具栏最右侧。洞察九项插在「回滚 SQL」之后，实际菜单文案与顺序为：
   分析SQL / 参数场景 / 渲染解释 / 运行SQL分析 / 导入离线Trace / 对象使用与影响 / 比较本地Schema快照 / 优化候选 / 比较SELECT结果；之后才是导入参数、差异对比、分享等原有项。

## 二、十分钟冒烟路径

1. 双击一条 SELECT 日志打开预览 → 更多 → 分析SQL。面板内出现「SQL分析」页签，含结构树、读写关系图、分析质量三块。
2. 点树里任一节点 → 预览编辑器对应语句被选中；若是整语句级范围，选中的就是整条 SQL（正常，见第五节）。
3. 切到 XML 预览（打开一个 Mapper XML 的动态 SQL）→ 更多 → 参数场景。出现「场景与渲染解释」，列出当前输入和已存预设场景。
4. 在同一预览上打开 更多 → 运行SQL分析。勾「启用所有会话的分析」→ 让 demo 跑几个请求 → 点「刷新快照」，工作负载表出现形状指纹、执行数、累计 JDBC 纳秒。
5. 更多 → 对象使用与影响。先在 IDE 里选中一个源文件，再打开本页 → 填表名 → 「扫描所选范围」→ 出现引用清单，点「打开选中引用」能跳回源码。
6. 更多 → 优化候选。对一条带函数包裹列（如 `WHERE DATE(created_at) = ?`）的 SQL，应出现带规则 ID 与 AST 证据的候选；没有候选时显示空态而不是编造。
7. 更多 → 比较SELECT结果。必须先明确选目标；不选时提示「请先明确选择目标」，不默认使用任何数据源。
8. 更多 → 比较本地Schema快照。左右各粘一份 `sql-visualizer-schema-v1` JSON → 出现增删改差异表。
9. 更多 → 导入离线Trace。粘贴一段 OTLP JSON（≤1 MiB）→ 出现 span 投影列表；不自动读剪贴板或文件。

九项都能打开且不抛异常，即冒烟通过。下面逐项验收细节。

## 三、分域验收

### 3.1 分析 SQL（结构与来源）

| 功能点 | 路径与操作 | 预期 |
|---|---|---|
| 入口 | 更多 → 分析SQL | 面板内新增「SQL分析」页签，不弹独立窗口 |
| 结构树 | 查看树 | 分操作类型、输入/写目标、输出字段、筛选/连接/分组步骤；未解析处显示局部原因 |
| 读写图 | 查看图 | 只画读写关系边，JOIN 不会被画成写；节点可点，点后定位 SQL |
| 分析质量 | 查看「分析质量」 | 显示 CERTAIN/PARTIAL/AMBIGUOUS/UNKNOWN/CONDITIONAL 之一，并给出依据 |
| 复制摘要 | 点「复制分析摘要」 | 剪贴板得到文本摘要；超预算时明确 omitted，不静默截断 |
| 空文档 | 清空 SQL 后打开 | 显示「当前SQL文档为空，不会分析上一次SQL」 |
| 编辑失效 | 打开分析后改 SQL 文本 | 旧分析不复活；重新打开得到新结果 |
| 老结果不串页签 | 关闭预览再开另一条 SQL | 不显示上一条 SQL 的分析结果 |

### 3.2 参数场景 / 渲染解释

| 功能点 | 路径与操作 | 预期 |
|---|---|---|
| 入口 | 更多 → 参数场景，或 更多 → 渲染解释（两个菜单项打开同一个面板） | 出现「场景与渲染解释」 |
| 场景列表 | 查看列表 | 含「当前输入」和已存命名预设（最多前 19 个）；不覆盖草稿 |
| 只读性 | 选中另一个场景 | 只读快照，不切换、不改写命名预设，参数面板不变 |
| 条件说明 | 读面板提示 | 明说「条件遵循预览开关，不代表真实运行路径覆盖」 |
| trace 定位 | 展开某场景 | 展示展开节点路径；不声称是原 XML 字节偏移 |
| 非 XML 预览 | 对普通 Java Wrapper 预览打开 | 提示「参数场景需要XML预览模型；当前SQL和预设未改变」 |
| 导出 | 「预览脱敏回归JSON」→ 复制已审阅 JSON | 参数值、标识符、预设名已移除；无网络请求；包不可执行 |
| 期望校验 | 「保存本页期望」→「验证当前场景」 | 仅确定语义可保存；无期望时显示 INCONCLUSIVE 而不是 PASS |

### 3.3 运行 SQL 分析

| 功能点 | 路径与操作 | 预期 |
|---|---|---|
| 入口 | 更多 → 运行SQL分析 | 出现「运行SQL分析」，默认不开启分析 |
| 总开关 | 勾「启用所有会话的分析」 | 显式提示影响所有已连接 agent 会话；关闭本页即停用 |
| 手动刷新 | 点「刷新快照」 | 只在点击时刷新，不常驻轮询 |
| 工作负载表 | 观察列 | 会话、形状指纹、执行数、累计 JDBC 纳秒、错误/未知、预算判定 |
| 目标身份 | 观察目标列 | 显示「已解析目标身份（不是数据库显示名）」；无法解析时显示未知连接/未知执行目标 |
| 请求时间轴 | 展开请求 | 标 requestId 与 requestTag 的区别；只代表请求线程内观测 |
| 事务视图 | 展开事务 | CLOSE 不等于 COMMIT；未知保持 UNKNOWN |
| 重复候选 | 同一形状重复多次 | 只显示「候选」，不宣称已证实 N+1 |
| 基线 | 点「保存本页基线」 | 提示已保存内存基线；缺生产端总量或质量证据时仍为 INCONCLUSIVE |
| 隐私 | 观察提示 | 只保留形状指纹与元数据，不上传；不替你开启 JDBC 捕获 |

### 3.4 离线 Trace 导入

| 功能点 | 路径与操作 | 预期 |
|---|---|---|
| 入口 | 更多 → 导入离线Trace | 出现「离线Trace投影」 |
| 粘贴导入 | 粘贴 OTLP JSON 后点「导入粘贴的JSON」 | 出现 span 列表；不自动读剪贴板 |
| 文件导入 | 点「选择本地Trace JSON文件」 | 文件选择器，读取后有界（≤1 MiB） |
| 超限/非法 | 粘贴 >1 MiB 或非法 JSON | 明确「导入已拒绝」，不部分导入 |
| 链接配置 | 填含 `{traceId}` 的 HTTPS 模板 → 打开选中 Trace 链接 | 校验只含一个 `{traceId}`、禁凭据、非 443 拒绝；不点击不发请求 |

### 3.5 对象使用与影响

| 功能点 | 路径与操作 | 预期 |
|---|---|---|
| 入口 | 更多 → 对象使用与影响 | 出现「显式文件使用反查」 |
| 范围 | 选择「当前文件」或「显式当前模块」 | 只在所选范围扫描；不启动全项目扫描 |
| 未选文件 | 没有选中源文件就打开 | 提示先选中源文件，不扫描 |
| 反查 | 填表名（`schema/table` 分段）→「反查对象引用」 | 出现文件、角色、位置清单 |
| 导航 | 点「打开选中引用」 | 跳回源码；文件已变化时提示「未使用陈旧偏移定位」 |
| 位置口径 | 观察提示 | 明说位置是源表达式/标签范围，不是解码后 SQL 的精确 token 区间 |
| 动态 SQL | 对动态拼接/未解析表达式 | 记为未覆盖并保留诊断，不猜 |

### 3.6 本地 Schema 比较

| 功能点 | 路径与操作 | 预期 |
|---|---|---|
| 入口 | 更多 → 比较本地Schema快照 | 出现「Schema快照比较」，左右两个粘贴区 |
| 比较 | 左右各贴一份快照 →「比较粘贴的快照」 | 出现表/列/变化清单，含可空性前后值 |
| 身份校验 | 两份数据库身份或版本相同 | 拒绝比较并说明原因 |
| 超限 | 单份 >1 MiB | 拒绝，不部分读取 |
| 无查询 | 全程观察 | 不查询、不自动绑定生产数据源 |
| 影响范围 | 缺少源码使用证据 | 明确标注影响范围不完整，不当作完整清单 |

### 3.7 优化候选

| 功能点 | 路径与操作 | 预期 |
|---|---|---|
| 入口 | 更多 → 优化候选 | 出现「静态优化候选」 |
| 函数包裹列 | `WHERE DATE(created_at) = ?` 这类对列套函数的谓词 | 出现 `SI.NON_SARG_COLUMN_FUNCTION`，附 AST 证据与「普通索引可能不适用」前提 |
| 宽投影 | `SELECT *` 或投影列很多的语句 | 出现 `SI.WIDE_STAR_PROJECTION`，说明列随 schema 增长的成本 |
| 笛卡尔风险 | 多表 FROM 但没有 ON/USING/NATURAL 且无 WHERE 连接谓词 | 出现 `SI.CARTESIAN_JOIN` |
| 只读 | 全程观察 | 不改写 SQL、不建索引、不执行 EXPLAIN 或查询 |
| 无候选 | 对单表简单等值查询 | 空态说明无命中，不编造建议 |
| 位置 | 缺精确区间时 | 不猜位置，退回整语句 |

### 3.8 SELECT 结果比较

| 功能点 | 路径与操作 | 预期 |
|---|---|---|
| 入口 | 更多 → 比较SELECT结果 | 出现「显式SELECT结果比较」；仅打开不执行 |
| 目标选择 | 「发现目标」→ 明确选一个 | 不默认选任何数据源；未选时提示 |
| 审阅 | 点「审阅准确SQL对」 | 显示两段完整 SQL、行数上限；不接受未回填参数 |
| 批准 | 勾「两段SQL均已填入明确字面参数」「已审阅SELECT函数副作用」「确认方言」→「单次批准此SQL对」 | **批准是复选框、任何时刻可勾；门禁在执行时校验**（未齐备点「执行已批准比较」会提示）；原样替换片段需另行批准。2026-10-31 复验订正：原文案「三勾齐备才可批准」会让走查者把未勾复选的视觉态误读成「置灰的批准按钮」 |
| 执行 | 点「执行已批准比较」 | 在新的只读 auto-commit 连接顺序执行；每条≤100 行/10 秒 |
| 非原子 | 观察提示 | 明说不是原子快照；未知或截断结果为 INCONCLUSIVE |
| 授权一次性 | 执行后再次执行 | 需重新审阅批准，不静默复用授权 |

### 3.9 写 SQL 影响面与事务关联

| 功能点 | 路径与操作 | 预期 |
|---|---|---|
| 入口 | UPDATE/DELETE 预览 → 更多 → DML 影响面 | 出现写目标、谓词、试算边界 |
| COUNT 语义 | 观察提示 | COUNT 只是未执行的试算计划，不代表提交或实际影响行 |
| 事务关联 | 先跑一个事务，再在预览里选该事务观测 | 冻结的写 SQL 与选中事务同屏；run/connection 相同也不宣称同一次执行 |
| 不自动归属 | 未显式选择事务 | 不自动把提交归属到本次预览 |

## 四、需要人工定性的项

以下几项自动化测不出观感或真实交互，需要真人判断：

1. 「SQL分析」页签内的树和图在窄面板下是否可读，图节点标签是否截断到无法辨认。
2. 读写关系图在 20+ 表的大语句下，缩放/滚动是否可用，是否出现节点重叠。
3. 「运行 SQL 分析」的请求时间轴条形图，在真实请求密度下是否还能看出区间并集与单条 SQL 的关系。
4. 场景列表在 20 个预设时，滚动与选中详情是否互相干扰。
5. 结果比较的审批流程（三个勾选 + 单次批准）在真实使用中是否过重，是否容易漏勾导致无法执行。
6. 离线 Trace 的 span 列表在数百条时是否可定位，链接模板错误提示是否指向具体字段。
7. 对象使用反查在模块范围内扫描大工程时的等待观感，是否提供可取消反馈。
8. 各洞察页签与预览编辑器之间的焦点切换：点树节点定位后，键盘焦点是否回到预期控件。

## 五、正常现象（先排除，再报缺陷）

- 点树节点后选中整条 SQL：未证明精确源码区间时按设计选择全语句，不是定位失败。
- 「分析质量」显示 PARTIAL/AMBIGUOUS/UNKNOWN：解析器只对已验证子集给 CERTAIN，带星号、未绑定元数据、方言不支持等都会降级，属正常披露。
- 运行分析里大量「未知连接目标」：多主机/非标准 URL 或无连接事件时按未知隔离，不会合并成同一目标。
- 请求时间轴出现 INCONCLUSIVE：跨线程、终态缺失或采集不完整时按设计不判 PASS。
- 事务视图显示 UNKNOWN：只有 JDBC 边界事件被观测，CLOSE 不等于 COMMIT。
- 优化候选为空：没有命中已实现的三条规则时不编造建议。
- 结果比较拒绝执行：未选目标、未勾三项批准、参数未回填、方言未确认，任一不满足都会拒绝，属安全设计。
- 离线 Trace 导入被拒绝：超 1 MiB、字段非法、重复键或非 OTLP JSON 都拒绝。
- 对象使用提示「未使用陈旧偏移定位」：源文件已变化，按设计不跳到旧位置。
- 编辑 SQL 后分析页签消失或变空：文档版本变化使旧结果失效，重新打开即可。

## 六、不覆盖范围（不要按缺陷报）

- GUI 观感之外的自动化证据见插件自动化验收文档；本手册不重复测试读数。
- 未实现的语法形态：递归 CTE、存储过程内部、任意动态脚本、跨过程血缘。
- 请求观测仅限 Servlet 线程内；异步、线程池、响应式、虚拟线程未承诺。
- 事务仅为代理连接/wrapper 生命周期证据，不认证真实池租借、XA 或跨线程传播。
- 结果比较是两次顺序读取，不是数据库原子快照。
- 性能预算：新增请求追踪的延迟与 CPU 超出初始目标，因此请求/事务追踪默认关闭，只在显式开启时承担成本；这不是缺陷，是已披露的取舍。

## 七、记录模板

发现异常时按下面五项记录，便于定位：

```
操作路径：更多 → ？
前置状态：SQL 类型 / 是否 XML 预览 / 是否绑定数据源 / 是否开捕捉
期望：
实际：
证据：截图 + 控制台/IDE 日志片段（脱敏后再贴）
```

日志位置：IDE 的 `Help → Show Log in Explorer`；插件相关行以 `[M36]`、`[SqlVisAgent]`、`[O-96fix2]` 等前缀标记。
