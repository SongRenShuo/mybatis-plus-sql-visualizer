## API 核实

本机缓存 MyBatis-Plus **3.5.17** 的 annotation/core 二进制和 sources jar 已分别用 javap、解压源码核查：

- `FieldFill` 有 DEFAULT、INSERT、UPDATE、INSERT_UPDATE 四枚举。
- `TableFieldInfo` 的 `withInsertFill` 只对 INSERT/INSERT_UPDATE 为真，`withUpdateFill` 只对 UPDATE/INSERT_UPDATE 为真。
- `MetaObjectHandler` 的 `insertFill(MetaObject)`、`updateFill(MetaObject)` 是用户可实现的入口；`strictInsertFill`/`strictUpdateFill` 有 MetaObject 与 TableInfo/List 两组重载。
- 默认 `strictFillStrategy(MetaObject, String, Supplier<?>)` 在原值为 null 且提供值非 null 时填充。这不代表任意用户 handler 都采用该策略。

生产实现不调用上述 handler API，仅使用解析出的枚举名。模拟优先级是本工具明确约定，不宣称与自定义 handler、数据库触发器、运行期时钟或登录上下文等价。

## 行为契约

| 注解值 | INSERT | UPDATE | UPSERT |
|---|---|---|---|
| INSERT | 可模拟 | 不模拟 | 不模拟 |
| UPDATE | 不模拟 | 可模拟 | 不模拟 |
| INSERT_UPDATE | 可模拟 | 可模拟 | 不模拟 |
| DEFAULT / null / 未知 | 不模拟 | 不模拟 | 不模拟 |

只模拟用户已勾选的可写列；WHERE 主键、乐观锁固定条件不模拟，开关和输入不自动勾列。UPSERT 即使方言退化成 INSERT，也因运行分支不明而不填。

每次新预览默认关闭。模拟值必须逐列手填，不提供 now、账号或其他默认值。输入框为空表示未提供，不表示 SQL NULL；当前不提供 SQL NULL 或空字符串模拟。普通显式参数及召回参数优先。模拟 overlay 不写入 `paramValues`，关闭开关按原参数重建原 SQL。

数值列 `quote=false` 只接受带可选符号、小数、科学计数法的十进制数字；表达式、十六进制、NaN、Infinity、逗号列表、注释均不作为数值插入。字符串单引号加倍；反斜杠、分号和控制字符拒绝，以免依赖不同方言的转义开关。字符串 `now()` 仅渲染为带引号的普通文本，绝不调用函数。无效模拟保留 `?`，参数区明确列出无效来源。

模拟值使用现有参数预设的独立保留键 `__field_fill__:<source>`，不是普通实参。启用态不持久化。切方案先清模拟状态，再只恢复目标预设包含的模拟键；没有模拟键的方案不得沿用旧值。清空参数也清模拟值。历史 SQL 快照回落无权恢复模拟键。参数历史存储代际失效后，旧面板编辑、切方案、延迟 flush、dispose 都不得把模拟值重新写回，新预览重建后才接纳新代际。命名预设仍是显式保存的快照，清工作区不删除用户另存的命名预设。

新增 headless 真实面板用例 `testTargetRerenderPreservesActiveSimulationEditingToggleAndPresetRecovery`：启用模拟→真实 PostgreSQL 目标重渲染→编辑原输入框→关闭/开启→恢复命名预设→再启用；并对照清理参数历史后再次切换 MySQL 必须关闭且不复活。改前实际 XML **1/1/0/0**，失败断言 `target rerender must retain active simulation`；加 ownership 迁移后 **1/0/0/0**；撤掉唯一修复行后 **1/1/0/0**，同一断言再次变红。恢复后最终五类定向实际 XML **55/0/0/0**（模型 3、R92 面板 8、CRUD 渲染 5、动态 batch 21、参数方案 18；2026-10-16 01:20 CST），修复与测试提交 `4a244c5c`。本次仍未启动沙盒 IDE、未跑全量或构建门禁。

## UI 待验步骤

1. 在带 `@TableField(fill=INSERT/UPDATE/INSERT_UPDATE)`、AUTO 主键和 `@Version` 的测试实体上，从实体 CRUD 动作打开 INSERT/UPDATE 预览，再从真实 saveBatch/updateBatchById/saveOrUpdateBatch 调用打开预览。确认参数行可见 fill 角标及独立“模拟值”输入，开关默认关闭。
2. 不勾 AUTO 主键，在 INSERT 填两个模拟值（字符串 `O'Reilly`、数值 `42`），确认关闭时 SQL 未变；勾选安全模拟后只进入适配模式且已勾选的列。主键不能自动勾选。
3. UPDATE 对照 INSERT 专属列与 UPDATE 专属列，确认仅更新适配列进入 SET；WHERE id/version 仍为原参数占位或普通输入值。取消某列后模拟不把该列补回。
4. UPSERT 输入任意模拟值并开启，确认 SQL 不填入模拟值，参数区提示 UPSERT 不填。
5. 普通参数输入 `explicit`，确认覆盖同列模拟；清普通参数后才恢复模拟。关闭模拟，确认回到原 SQL。
6. 数值模拟输入 `1; DELETE FROM t`、`now()`、`1 OR 1=1`、`1,2`；字符串输入含分号/反斜杠的文本。确认保持占位，有明确无效提示，不产生可执行表达式。合法字符串单引号必须加倍。
7. 另存“含模拟”“无模拟”两个预设并交替切换；只有前者有模拟字面量，二者启用态均关闭。清空参数、切默认工作区，确认旧模拟不自行恢复。
8. 开启模拟后在设置清除参数历史与命名方案；保留旧面板继续编辑、切预设、关闭，再打开同一预览。确认没有旧模拟召回；普通历史 SQL 回落也不能带回模拟键。
9. 在真实 262 IDE 的窄参数栏、Light/Dark 主题检查标签、输入框、无效提示可读性与键盘顺序。
10. 开启模拟后切换到不同目标方言触发无损重渲染，确认启用态和字面量保留；继续编辑、关/开、切回含模拟的命名预设应正常。清除参数历史后再次换目标，旧模拟不得恢复。以上全项本轮均待 UI 验收。
