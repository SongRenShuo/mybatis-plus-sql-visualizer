## 五、正式用例

### R01 — 单项目单模块、自动/手动与来源证据

1. 只开一份测试项目，设置“数据库方言”为“智能推断（跟随数据源）”。DatabaseTools 仅保留一个已授权测试候选。A1/A2/A3 从各自真实入口预览，同条记录生成 SQL、方言行、hover详情。
2. 预期来源与平台事实相符；文案可能是“IDEA 数据源提供者”“IDEA 解析作用域”“IDEA 有效 SQL 方言”“模块已学数据源”“项目候选共识”，不可要求所有样本都显示同一种。tooltip含来源、置信度和候选标识，不含完整 JDBC URL/凭据。
3. 显式手动改成另一方言，重新预览，预期“手动指定”优先且生成语法同步。回自动后重新检测/重开预览，不能保留手动旧标签。
4. 移除全部可信证据，预期“方言未验证：兼容按 MySQL 预览（证据不足）”或对应诚实状态，而不是 EXACT。无项目/多项目全局设置不以第一个项目冒充当前目标。

反例：当前项目已有 PG，另一项目最近 agent 是 MySQL，不能借另项目 URL覆盖本项目。一个标签等于 MySQL不能证明候选/来源正确。

### R02 — V178-1/2 真注入、Resolution Scope 与继承

1. 对 A1 注解 SQL、A2 XML SQL 正文，在 IDE 中先用平台的注入编辑/语言信息确认有没有真实 SQL PSI。记录宿主文件、注入片段、平台语言标识及其范围；无注入时必须标“宿主降级”，不能人造 SqlFile 后称真实注入。
2. 在该版 DatabaseTools 的 SQL Dialects / SQL Resolution Scopes 设置中选择测试文件/目录的有效方言与数据源作用域，截图记录**实际菜单路径**。这些属于平台菜单，版本布局未实测，不指定不存在的固定按钮。只设置一个证据源后重开预览，再增加第二种，逐步确认优先级。
3. 先目录级PG、文件级继承；再文件级MySQL覆盖。三版分别核注入窗口与original/宿主文件继承、预览源状态和生成语法，不能只核设置控件。
4. 同scope放两个MySQL源或MySQL+PG，分别截图实际provider、configured mapping与平台候选。续验已证getDataSources厂商候选不承诺按显式scope缩窄：**无真实provider且存在明确configured mapping时，当前正确结果是UNAVAILABLE及专用说明**，包括EMPTY、限定UUID、显式ALL，不能将候选升级STRONG或自行决定方言。仅真实provider给出可采信集合时才按集合判断一致/歧义；清除configured覆盖后的默认ALL恢复原项目共识。不得按旧“同scope同方言必RESOLVED”判本版失败。
5. Kotlin字符串SQL注入仅在实际注入在场时验；A7 Wrapper降级不是注入证据。没有可操作的真实注入入口则记录V178-2受限，不编造“注入成功”。

### R09 — 长WHERE、COUNT真值和写后状态

1. 先取三行表快照；完整预览准备单表UPDATE（仅预演），WHERE用§三长谓词。点击影响面预演，保存面板试算文本、库端提交文本与结果。两库各应COUNT=1，提示WHERE可截成200字符，真正COUNT不得截断，末尾`id=3`必须在场。
2. 对照去掉最后高选择性条件，COUNT应3。再造两条长谓词：第200字符落在运算符附近、落在字符串字面量中间；保留原始输入/字符位置/实际probe，预期完整谓词可执行且与直接全谓词COUNT一致，不产生半截字符串/运算符。
3. 无WHERE、JOIN/多表、解析失败、多语句分别给“不可用/无法解析/只支持单条”等诚实结果；不得为无WHERE偷偷扫描全表COUNT，也不报伪精确0。
4. 含WHERE的UPDATE点击执行后在写确认中取消、无WHERE UPDATE取消、DELETE取消，三行数据均保持不变。只读账号作为第二道防护，但权限报错不能替代“取消未提交”的证据。
5. 若额外授权成功写，限专属表id=3并保存前后值，先确认当前Runner事务语义。不能承诺IDE默认回滚；恢复数据须明确授权且只恢复本测试行，不删除整个测试库。

现有主控L4只覆盖长谓词的DB引擎语义与EXPLAIN；此R09通过IDE拿实际probe、取消提交、表状态的链仍未验。不能把CTE COUNT=1写成“Runner写安全通过”。

### R10 — EXPLAIN、真数据库错误与取消边界

1. 使用`SELECT id, marker FROM m19_acceptance WHERE id=3`，预览“执行计划”、模板EXPLAIN、若具备平台MCP则`sqlv_explain`分别记录目标与输出。MySQL/PG按各自方言渲染；结构化EXPLAIN默认关闭，先原生链，再显式打开设置实验开关验结构化链及回退。
2. Oracle/SQL Server/达梦等未配真库的方言只登记未验；离线方言枚举/源码输出不是可执行证明。不跑EXPLAIN ANALYZE或未知过程。
3. 选择绝不创建的 `m19_missing_table_20261015`，在预览“执行 SQL”、三个快捷模板动作、日志转SQL、可用时MCP四类入口制造同一缺表错误。每个入口保存实际请求SQL，不能将不同错误强作同一对照。
4. 核错误文本、SQLState、厂商码、Position有值时保留；复制错误与界面一致。PG缺表通常42P01，MySQL通常42S02/1146，以真实驱动响应为准，不能要求缺失字段伪造0。原始错误延迟到结果页出现之后仍应可见。
5. A1的`selectInvalidForRecording`可作语法错误源码样本；有来源时“定位到出错语句”只保证源语句起始行，驱动Position指执行SQL不等于mapper行；无源码的原始日志不显示假定位。失效测试连接另验连接错误，不混作SQLState语法错。
6. 超时边界：插件30秒保护仅MCP直连链，原生UI控制台不能宣称同样自动取消。只在专属测试连接、已确认原生停止动作可用时做短时可取消查询；记录具体取消动作、后台查询是否终止。没有安全样本不执行阻塞SQL，登记环境受限。
