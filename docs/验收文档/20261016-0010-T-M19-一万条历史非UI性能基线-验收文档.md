## 方法

- 2026-10-16 00:09:15 +08:00，Windows 11 专业教育版，Intel i5-10400F 2.90GHz。
- 总可见物理内存 33,449,416 KiB，开跑前可用物理 3,059,064 KiB、可用虚拟内存 6,593,796 KiB；共享机器有其他任务，不能据此宣称隔离空机性能或提升比例。
- JVM `-Xmx256m`，5 个**顺序**启动的新 JVM；每 JVM 先读一次、先检索一次，随后交错重复读取/检索各20次。
- 冷态定义为新 JVM 首次调用，**没有清理 OS 文件缓存**；样本文件刚写入，因此也不是物理磁盘冷读。源码启动器编译/启动时间不在计时区间内。
- 单文件 10,000 条、1,508,890 bytes，每条含合成来源、时间与单行 SELECT。每第十条含 `status = 'match'`。
- 每轮断言 Reader=10,000 条，Search扫描10,000、命中1,000、返回100、输出截断true、扫描截断false。不是只计时不验结果。
- 百分位用 nearest-rank：排序后取 `ceil(p*n)-1`。暖态汇总对100个原始样本计算，不取各轮P95的平均。

## 内存读数的解释

每 JVM `MemoryPoolMXBean` 的各堆池 peak used 相加分别为 269,090,816 / 268,435,456 / 267,911,168 / 267,682,400 / 267,911,168 bytes。**各池峰值不是同时发生**，相加值可高于 `-Xmx256m`，不能将它称为进程峰值/RSS或泄漏大小。这里只用来说明长批运行中的堆分配压力，进程 Commit、IDE 常驻与精确同时峰值未采集。
