## 一、结论：上一轮的「整行不可达」是误判，按钮可以自动化点中

**上一轮错在哪**：用固定坐标 (1342,261) 点「执行计划」，阳性对照「格式化」(1098,261) 也同偏 —— 两个都点空，误读成「整行不响应」。本轮实测**对话框每次会话位置会漂**（本轮工具栏 y=234，上一轮 y=261，差 27px），坐标必须每次现量。

**本轮验证**：用现量坐标 (1342,234) presshold 点击，一次命中——按钮出现高亮边框（obauto-06/19/30 帧），日志立即出现：

```
[M37.2] explainSql: dialect=OceanBase, len=144
[S2-12] runners empty → fallback to uniquely resolved data source 'ob_xc3@25881'
[S2-12] direct session created: com.intellij.database.console.session.MessageBusSession
[M36] console db-context: 库上下文对齐：? → xc3_test（数据源=ob_xc3@25881）
```

**所以「执行计划按钮转人工」这条登记作废**——按钮可自动化，只是坐标要现量。

## 二、真正挡住结构化面板的是驱动绑定（已定位并修复）

前几轮一直以为是按钮问题，实际是 OB 数据源驱动没绑上，EXPLAIN 走不了结构化通道。日志实证：

```
WARN RemoteProcessSupport - java.lang.ClassNotFoundException: com.mysql.cj.jdbc.Driver
  at com.intellij.database.remote.jdbc.impl.JdbcClassLoader$JdbcClassLoaderImpl.findClass
```

**根因链**（三步踩坑，全部实测）：
1. 数据源 `driver-ref` 写 `mysql.8` —— 沙盒驱动注册表里**没有这个 id**（只有 `cloud_sql.mysql.8`），平台解析不到 jar 路径。
2. 改成 `MySQL ConnectorJ` —— 仍失败：该 artifact 的 `<version>` 列表**只声明到 5.1.47**，没有 8.x/9.x 条目。
3. 补齐注册表 `<version version="9.7.0">` 条目 + 数据源写 `MySQL ConnectorJ/9.7.0` 显式钉版本 → **ClassNotFoundException 消失**（15:55 之后日志零命中）。

jar 文件本来就在盘上（`config/jdbc-drivers/MySQL ConnectorJ/9.7.0/com/mysql/mysql-connector-j/9.7.0/mysql-connector-j-9.7.0.jar`），缺的只是注册表条目。

已把这条写进 skill（第 8 条）：**日志出现 `RemoteProcessSupport … ClassNotFoundException` 就是驱动绑定问题，不是插件问题**。

## 三、顺带抓到的两个既有问题（非本轮引入，登记待评估）

### ① SEVERE SlowOperations on EDT（插件被点名）

```
15:55:13,017 SEVERE SlowOperations - Plugin to blame: SQL Visualizer version: 2026.10.31
15:55:13,018 SEVERE SlowOperations - Last Action: cn.song.mybatisplus.visualizer.ConvertToSql
15:55:13,021 SEVERE SlowOperations - Slow operations are prohibited on EDT.
```

触发点：点「执行计划」时。栈在 `promptDataSourceThenRetryStructured` → `prepareConsole` → `chooseAndPrepare` → `createTempPsiFile` → `PsiManager.findFile`。**既有代码**（`DataSourceSelectorResults.kt:1313`，git blame 指向 10-10 的 `1c114680`），非本轮引入。虽包在 `ReadAction.compute` 里，但在 EDT 上做 PSI 查找触发平台断言。

### ② PSI 目录查找深递归

同栈还有几十层 `FileManagerImpl.findDirectoryImpl` 递归 —— demo 工程 `.idea/sql-visualizer/exec/` 深层路径下 `PsiManager.findFile` 的目录查找开销。属既有形态，未栈溢出（未抛 StackOverflowError），仅作为 EDT 慢操作的放大器。

**建议**：①②合并成一个「执行计划链 EDT 慢操作收口」券（把 `createTempPsiFile` 的 PSI 查找移到 BGT，或改用 `VfsUtil`/`FileDocumentManager` 取文档不经 PSI）。**待用户点名立项**。
