# 第十九轮非 UI 真库只读语义验证

## 1. 范围与结论

用户本轮仅禁止启动沙盒 IDEA 进行 UI 验收，允许其他未完成事项继续。PostgreSQL 使用用户明确确认可用的 **DBX 开发测试连接 / PostgreSQL 16.14 / dbx_test**，不使用公司测试库；另使用本地 MySQL 连接。全文不记录地址、用户名、密码或业务 SQL。

本次实际执行了生产 COUNT 生成器和 EXPLAIN 方言渲染器，再通过 DBX 对真实引擎执行其只读输出。没有执行 UPDATE/DELETE、创建表或修改现有表。所有输入为三行合成 CTE/派生表。

**已通过：**长 WHERE 的末尾选择性条件保留，MySQL/PostgreSQL COUNT 均为 1；去除尾条件的负对照均为 3；两库均接受对应生产 EXPLAIN 语法并返回真实计划。

**未覆盖：**IDEA 的来源 PSI、Resolution Scope、Runner 选择、active console 绑定、UI 确认和拒绝写后的数据库状态、四个执行入口同一错误。这些不得因 DBX 查询成功而标通过。

## 3. 重放方法

既有目录中的探针：

- [M19ReadOnlyDbProbe.java](../../dev-support/M19ReadOnlyDbProbe.java)
- [m19-readonly-db-probe.ps1](../../dev-support/m19-readonly-db-probe.ps1)

以 PowerShell 执行（路径由执行者填写）：

```powershell
.\dev-support\m19-readonly-db-probe.ps1 `
  -PluginJar '<冻结构建的插件 JAR>' `
  -JdkHome '<JDK 17+，含 bin/java.exe>' `
  -GradleHome '<已有 Gradle 缓存目录>'
```

探针先输出实际 JAR SHA-256，然后分别输出 MySQL/PostgreSQL 的 UPDATE、DELETE 影响面 COUNT 和 EXPLAIN。输入 DML 仅用于纯函数解析，**不要把输入 DML 提交数据库**。数据库只执行输出的 SELECT/EXPLAIN。

COUNT 数据源：

```sql
WITH m19_rows AS (
  SELECT 1 AS id, 10 AS amount
  UNION ALL SELECT 2, 20
  UNION ALL SELECT 3, 30
)
```

谓词为 `amount >= 10` + 24 次 ` AND id >= 1` + ` AND id = 3`。探针断言显示用 `whereText` 恰为 200 字符，同时可执行 `probeSql` 仍以 `id = 3` 结束。UPDATE 与 DELETE 生成的 COUNT 完全相同，每引擎对该共享输出执行一次即可检验两者的共同输出语义，不夸大为四次独立执行。

负对照使用同一 CTE，仅以 `amount >= 10 AND id >= 1` 过滤，预期 3 行；它证明末尾条件有判别力，不是所有样本天然都返回 1。

## 4. 本轮实际结果

| 用例 | MySQL 8.0.12 | PostgreSQL 16.14 | 判据 |
|---|---|---|---|
| 连接只读核验 | VERSION + 常量 1 成功 | version + 常量 1 成功 | 使用指定测试连接 |
| 生产长 WHERE COUNT | `COUNT(*)=1` | `count=1` | 不能截掉尾部 `id=3` |
| 去掉末尾选择性条件 | `control_without_tail=3` | `control_without_tail=3` | 与生产完整谓词结果不同 |
| 生产 EXPLAIN | 4 行表格计划 | 1 行 JSON 计划 | 引擎实际解析并返回计划，非纯渲染测试 |

MySQL 的生产输出：

```sql
EXPLAIN SELECT id
FROM (SELECT 1 AS id UNION ALL SELECT 2 UNION ALL SELECT 3) m19_rows
WHERE id = 3;
```

结果主节点 `PRIMARY / <derived2> / ref / <auto_key0> / rows=1 / Using index`，其余三行分别为 DERIVED/UNION/UNION，`No tables used`。

PostgreSQL 的生产输出：

```sql
EXPLAIN (FORMAT JSON, VERBOSE) SELECT id
FROM (SELECT 1 AS id UNION ALL SELECT 2 UNION ALL SELECT 3) m19_rows
WHERE id = 3;
```

实际返回：

```json
[{"Plan":{"Node Type":"Result","Parallel Aware":false,"Async Capable":false,"Startup Cost":0.00,"Total Cost":0.01,"Plan Rows":1,"Plan Width":4,"Output":["3"]}}]
```

计划可能随引擎版本/优化器变化。验收不要求永久固定 `<auto_key0>` 或节点形态，只要求生产方言输出可执行、返回结构可读且合成输入结果一致。

## 5. 与 UI 验收的交界

上述结果可附在 O-145/V178 Runner 验收的“数据库前提已验证”栏，不能填进“点击执行后绑定正确目标”“取消后未写”“原生控制台报错可复制”等栏。UI 文档必须另列：

1. 实际从插件预览入口产生 SQL，而非在 DBX 粘贴。
2. 选择不同方言 Runner 后观察阻断/重渲染及二次确认。
3. 使用隔离可回滚测试数据，检查拒绝写不触发数据库写入。
4. 同一缺表错误在四入口查看原文、SQLState/厂商码、复制和有效定位。

本轮没有启动沙盒 IDEA，也没有把这些未执行项标通过。
