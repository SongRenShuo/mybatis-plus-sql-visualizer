## 二、为达成闭环填平的四个坑（每一条都是真机才暴露）

1. **驱动绑定**：沙盒 `config/options/databaseDrivers.xml`（已安装状态）缺 `mysql.8` 条目 → 远程 JDBC 进程 `ClassNotFoundException`。整拷宿主该文件后消失（详见 `docs/memory-archive/pitfalls/pitfall-sandbox-jdbc-driver-needs-installed-state.md`）。
2. **凭据**：数据源密码只在 URL 里（`user=xc3%40test&password=…`），平台凭据库没有 → 结构化通道走 `askPassword=true` 弹「Connecting to 'ob_xc3@25881'…」。手填 `xc3@test` / `Xc3_OB_2026` 即通。
3. **坐标**：对话框工具栏坐标每会话漂移，本轮实测按钮中心 `(1305,226)`（不是 `(1342,209)`）、凭据框 OK 在 `(1058,625)`、User/Password 行在 `y=540/587`。判据＝裁剪放大读坐标 + 悬停高亮自证（详见 `pitfall-sandbox-click-does-not-land-four-causes.md`）。
4. **结果形态**：真实 OB `EXPLAIN` 是**单列×多行**，解析器原先假设「一个 cell 装整段多行文本」→ 返回 null。修复（`b224ecd5`）新增 `planLines(rows)` 把两种形态展平成同一份行序列，面板与建议器同源受益（详见 `pitfall-explain-result-shape-real-vs-synthetic.md`）。

## 三、阈值决策（本轮由主控定）

`ROWS_THRESHOLD = 10_000` **保持不变**。理由：它是 MySQL/PG/OB 三方言共用的「小表全扫不噪音」口径；为了 3 行的演示表调低阈值会让真实小表开始报无意义建议。验收改为**造大表让全扫真正过阈**——OB 侧建 `s216_big`（20000 行，`ANALYZE TABLE` 后 `EST.ROWS=19343`）。
