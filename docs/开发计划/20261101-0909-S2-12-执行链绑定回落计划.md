## 一、侦察结论（javap 实证，243 平台 `database-plugin.jar`）

jar 路径：`ideaIU-2024.3.7.1-win/plugins/DatabaseTools/lib/database-plugin.jar`。

### 1.1 候选一 `runInDataSource(DbDataSource, String, Consumer<DatabaseSession>)` —— **可行**（经直取 session 等价实现）

`javap -p -c` 字节码（偏移 27~57）：

```
27: aload_0                      // ds
28: invokeinterface DbDataSource.getProject()
34: invokestatic  DbImplUtilCore.getLocalDataSource(ds)   // → LocalDataSource
44: invokestatic  DatabaseSessionManager.getSession(project, /*connectionPoint*/ localDs, sql)
52: invokeinterface Consumer.consume(session)
```

`DatabaseSessionManager.getSession(Project, DatabaseConnectionPoint, String)`（同 jar 字节码实证）：
先按 `point.getDataSource()` 取该源全部已有 session，逐个比对 `title == sql`；**找不到就走
`getSession$default(..., sql, ...)` 新建**——即无会话时会真开新会话，SQL 随 session 进入。
这正是平台「按源直取」执行通道的全部语义。

**插件侧等价实现**：本插件在册源是 `LocalDataSource`（`DataSourceSettings` 反射取得），
而 `LocalDataSource` 本身就是 `DatabaseConnectionPoint`（`runInDataSource` 把 `getLocalDataSource`
的返回值直接传给 `DatabaseConnectionPoint` 形参），因此插件可直接调
`DatabaseSessionManager.getSession(project, localDs, sql)` + `sessionConsumer.consume(session)`——
逐行等价于 `runInDataSource` 内部，且免掉插件不持有的 `DbDataSource`（PSI 模型）转换。

**结果去哪**：session 交给既有 `sessionConsumer`（`chooseAndPrepare` 现成构造）→
`prepareInConsole` → 控制台挂载 / 结果表 / 审计整链照旧。**不新建执行通道**。

**怎么接进 `runRunner`**：`runRunner`（`DataSourceSelectorResults.kt:1850`）对 runner 只做两件事——
反射 `runner.javaClass.getMethod("run").invoke(runner)`、`getRunnerName` 反射 `getDisplayName`。
故传一个**普通适配器对象**（public `run()` + `getDisplayName()`）即可全链复用
（no-op 拒跑判定走「无 runnable 字段 → false」自然通过；失败走 runRunner 既有的
onError / silent 清记忆 / 通知），无需子类化平台类。

### 1.2 候选二 `createDataSourceConsolesRunner(DbDataSource, Consumer<VirtualFile>)` —— **不可行（占位 runner）**

字节码：构造 `DatabaseRunners$4(name, ..., EmptyRunnable.getInstance(), ds, consumer, project)`；
`DatabaseRunners$4.getSubRunners()` 才是实质（构造「new console」子 Runner 列表）。
与组 Runner 同款形态：**run() 空转、实体在子项**——被 `isNoOpRunner` / `expandGroupRunners`
两条既有守卫正确识别为「不能执行的菜单项」。不作执行器（主控预案证实）。

### 1.3 定源依据（243 判不出绑定态，只用插件自有事实）

`DataSourcePerFileMappingsImpl` 243 不存在（主控已扫 523 jar）。优先级：
**学习绑定（`ModuleDataSourceBindingStore.dataSourceId(moduleKey)` → UUID 查源）>
last-used 记忆（`DataSourceSelector.lastUsedRunner(project, moduleKey)`，UUID 精确 → 名字唯一）>
单源**。任何一档歧义（名字多命中 / 多源无记忆）→ null，照旧出既有归因文案。
