# Gutter 图标响应防抖（P1）开发计划

> 状态：✅ 已落地（`SqlGutterLineMarkerProvider` 200ms 全局防抖窗口 `DEBOUNCE_MS`；2026-11-13 代码核对回填）
> 需求来源：用户反馈「连续点击 gutter 图标时偶尔弹出多个预览窗口，期望加防抖」。

## 1. 目标与范围

对 gutter 图标的 hover/click 事件加 200ms 防抖，避免用户连续悬停/点击时重复触发 PSI resolve。

**已确认决策**：
- 防抖范围：**仅 click 后的 resolve 路径**（`SqlGutterNavigationHandler.navigate`）；
- 快速路径（`getLineMarkerInfo`）保持 **O(1) 纯语法、零 resolve**（性能红线，不可突破）；
- 防抖策略：**时间戳哨兵**（`lastNavigateTime`），200ms 窗口内重复点击丢弃；
- 防抖粒度：**全局单一哨兵**（所有 gutter 图标共享同一 `SqlGutterNavigationHandler` 单例）；
- hover 不触发 PSI 操作（tooltip 为静态文案），无需防抖。

## 2. 现状分析

### 2.1 Gutter 快速路径（性能红线，不可触碰）

```kotlin
// SqlGutterLineMarkerProvider.getLineMarkerInfo（第 33-46 行）
override fun getLineMarkerInfo(element: PsiElement): LineMarkerInfo<*>? {
    val anchor = WrapperAnchorDetector.anchorElement(element) ?: return null  // O(1) 纯语法
    if (!gutterEnabled()) return null
    return LineMarkerInfo(
        anchor, anchor.textRange, SQL_PREVIEW_ICON,
        { MpSqlVisualizerBundle.message("gutter.tooltip") },  // 静态文案，无计算
        SqlGutterNavigationHandler,
        GutterIconRenderer.Alignment.CENTER,
        { MpSqlVisualizerBundle.message("gutter.accessible.name") },
    )
}
```

**结论**：`getLineMarkerInfo` 内无 PSI resolve，防抖不适用于此路径。

### 2.2 Click 路径（需防抖）

```kotlin
// SqlGutterNavigationHandler.navigate（第 58-64 行）
private object SqlGutterNavigationHandler : GutterIconNavigationHandler<PsiElement> {
    override fun navigate(e: MouseEvent?, elt: PsiElement) {
        val project: Project = elt.project
        SqlPreviewService.previewAsync(project, {
            project.getService(SqlPreviewService::class.java).preview(elt)  // ⚠️ PSI resolve
        }) { result ->
            SqlPreviewService.showResult(project, result)  // 弹窗
        }
    }
}
```

**问题**：用户连续点击同一 gutter 图标时，每次点击独立触发 `previewAsync`（后台 PSI resolve + 弹窗），导致：
- 多次后台线程并发执行同一 PSI resolve；
- 多个预览弹窗叠加显示（`showResult` 每次创建新弹窗）。

### 2.3 既有防护分析

`SqlPreviewService.previewAsync` 内部虽有异步调度（`executeOnPooledThread` + `invokeLater`），但**无防重入/防抖机制**——多次调用多次执行。

### 2.4 性能红线重申

| 路径 | 当前行为 | 防抖后 |
|------|----------|--------|
| `getLineMarkerInfo`（快速路径） | O(1) 纯语法，零 resolve | **不变**（不可触碰红线） |
| `navigate`（click 回调） | 每次点击触发完整 PSI resolve + 弹窗 | 200ms 内重复点击丢弃 |

## 3. 详细实施方案

### 3.1 时间戳哨兵防抖

在 `SqlGutterNavigationHandler` 内添加 `volatile` 时间戳字段：

```kotlin
private object SqlGutterNavigationHandler : GutterIconNavigationHandler<PsiElement> {

    /** 防抖窗口（毫秒）。 */
    private const val DEBOUNCE_MS = 200L

    /** 最近一次成功导航的时间戳（volatile 保证多线程可见性）。 */
    @Volatile
    private var lastNavigateTime = 0L

    override fun navigate(e: MouseEvent?, elt: PsiElement) {
        val now = System.currentTimeMillis()
        // 防抖：200ms 内重复点击丢弃
        if (now - lastNavigateTime < DEBOUNCE_MS) return
        lastNavigateTime = now

        val project: Project = elt.project
        SqlPreviewService.previewAsync(project, {
            project.getService(SqlPreviewService::class.java).preview(elt)
        }) { result ->
            SqlPreviewService.showResult(project, result)
        }
    }
}
```

### 3.2 方案对比

| 方案 | 优点 | 缺点 | 选用 |
|------|------|------|------|
| **时间戳哨兵** | 零依赖、无延迟、代码极简 | 全局粒度（不同图标共享窗口） | ✅ |
| Timer/Alarm 延迟执行 | 精确控制、可重置 | 增加延迟感、生命周期复杂 | ❌ |
| 按元素粒度哨兵 | 不同图标独立防杀 | Map 存储、内存泄漏风险 | ❌ |
| previewAsync 内部防重入 | 统一防护 | 需修改共享服务、影响其他入口 | ❌ |

**决策理由**：
- 时间戳哨兵零代码侵入，仅在导航入口加 2 行；
- 全局粒度足够（用户连续点击同一图标场景）；
- 200ms 窗口极短，不影响正常操作。

### 3.3 线程安全

- `@Volatile` 保证 `lastNavigateTime` 多线程可见；
- `navigate` 在 EDT 执行（平台约定），EDT 单线程无需额外同步；
- 若未来 `navigate` 可能从非 EDT 调用，改用 `AtomicLong`：

```kotlin
private val lastNavigateTime = AtomicLong(0L)

override fun navigate(e: MouseEvent?, elt: PsiElement) {
    val now = System.currentTimeMillis()
    val last = lastNavigateTime.get()
    if (now - last < DEBOUNCE_MS) return
    if (!lastNavigateTime.compareAndSet(last, now)) return
    // ... 执行导航
}
```

**当前采用 `@Volatile` 简化版**（EDT 单线程足够）。

## 4. 边界与已知限制

- **全局粒度限制**：200ms 内点击不同位置的 gutter 图标，后一次被防抖丢弃（符合预期——用户不可能 200ms 内移动到另一图标）；
- **不影响 hover**：tooltip 由平台 `LineMarkerInfo.tooltipProvider` 提供（静态文案），不触发防抖；
- **不影响快速路径**：`getLineMarkerInfo` 仍保持 O(1) 纯语法，零 resolve；
- **不影响编辑器 Action / 面板**：防抖仅作用于 gutter 图标 click，其他入口不受影响。

## 5. 测试策略

### 5.1 纯逻辑单测（新增 `SqlGutterDebounceTest`）

| 用例 | 操作 | 预期 |
|------|------|------|
| 首次点击 | `navigate(e, elt)` | 执行（`lastNavigateTime` 更新） |
| 200ms 内重复点击 | 连续调用 2 次（间隔 < 200ms） | 第 2 次丢弃 |
| 200ms 后再次点击 | 等待 > 200ms 后调用 | 第 2 次执行 |
| 防抖窗口边界 | 调用 → 等待 200ms → 调用 | 第 2 次执行（= 窗口） |
| 不同元素点击 | 点击 A → 立即点击 B | B 被防抖丢弃（全局粒度） |

**测试实现要点**：
- `SqlGutterNavigationHandler` 为 `object` 单例，`lastNavigateTime` 私有 → 需通过反射访问，或将 `lastNavigateTime` 改为 `internal` 可见性 + `@VisibleForTesting`；
- 推荐方案：提取防抖逻辑为独立纯函数，单测直接验证函数行为（不依赖 handler 实例）。

### 5.2 防抖逻辑提取（便于测试）

```kotlin
/**
 * 防抖判定（纯函数，便于单测）。
 *
 * @param lastTimeMs 上次导航时间戳（毫秒）
 * @param nowMs     当前时间戳（毫秒）
 * @param windowMs  防抖窗口（毫秒）
 * @return 是否应执行导航（true = 执行，false = 丢弃）
 */
internal fun shouldNavigate(lastTimeMs: Long, nowMs: Long, windowMs: Long = 200L): Boolean =
    nowMs - lastTimeMs >= windowMs
```

**单测**：

```kotlin
@Test
fun `shouldNavigate - first call allowed`() {
    assertTrue(shouldNavigate(0L, 1000L))
}

@Test
fun `shouldNavigate - within window blocked`() {
    assertFalse(shouldNavigate(1000L, 1100L))  // 间隔 100ms < 200ms
}

@Test
fun `shouldNavigate - after window allowed`() {
    assertTrue(shouldNavigate(1000L, 1200L))  // 间隔 200ms = 窗口
}
```

## 9. 风险评估

- **极低风险**：仅修改导航入口 1 处，添加 2 行防抖判定，不影响快速路径；
- **线程安全**：EDT 单线程调用，`@Volatile` 足够；
- **全局粒度副作用**：200ms 内点击不同图标被防抖——实际场景中用户不可能在 200ms 内移动并点击另一图标，可接受；
- **兼容性**：`System.currentTimeMillis()` 在所有平台可用，无 API 版本依赖。
