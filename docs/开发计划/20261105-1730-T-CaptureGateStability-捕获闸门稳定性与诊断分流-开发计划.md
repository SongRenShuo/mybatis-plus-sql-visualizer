## 二、验收发现的问题（3 项）

### P1 闸门抖动：CONFIG 下发即清确认态，产生 0.2~1.25s 的桥放行窗

实测（`mpsv-acc` 沙盒 `idea.log`）：

```
17:27:39.867 增强捕获接管沿（桥让位）
17:27:39.869 增强捕获闸门回落（桥恢复解析）：确认态=[pid=1920:待确认]   ← 2ms 后放行
17:27:40.079 增强捕获接管沿（桥让位）                                  ← 0.21s 后收回
```

用户上一轮现场同样形态，窗口 1.25s（16:36:20.904 → 16:36:22.150）。

根因：`configAckDisabled` 在 CONFIG 下发时被清回 `null`（`AgentSessionSupport.kt:632/640/649` 三处），
`captureConfirmedActive()` 要求 `== false`（`AgentManager.kt:1351`）→ 回执到位前闸门放开 → 桥完整解析一轮。

修法：**保留上一次确认值**，只在新回执到达时更新；另配「回执超时」兜底（下发后 N 秒仍未回执才视为失效，
建议 10s，与心跳窗同量级）。语义不变——「确认停采」立刻生效（回执是值不是布尔位）。

### P2 活性回落误触发：静默 10s 即解封，操作间隔正常就触发

实测：每次与上次调用间隔 >10s 就解封一次，解封瞬间产出一条无耗时的控制台条目。

```
17:28:16.458 活性回落：agent 已静默 ≥10000ms 而控制台仍有 SQL 行（第 1 次）
17:28:16.461 捕获归因: 通道=CONSOLE_BRIDGE 指纹=5f07b5f6 无耗时无源码
17:28:17.072 活性回落解除
17:28:30.579 活性回落：第 2 次（同样形态）
```

该机制要防的是「白名单漏驱动 → agent **从未**收到事件 → 双通道全哑」，与「用户手点间隔长」是两回事。

修法：判据收窄为「本会话**从未**收到过 agent 事件」（`AgentEventAdapter.receivedEvents() == 0`）才允许回落。
收到过事件即证明织入在工作；真断线有 `online=false` 那条路径兜底，不会双哑。

### P3 折叠日志被 `捕获归因` 吃掉：现场无法确认折叠发生

`跨通道等价键融合`、`跨通道同源未折叠`、`捕获归因` 三条共用同一个 10s 限频通道
（`SqlLogEntryBuffer.kt:811-821`，共用 `attributionLogNanos`）。控制台条目入队必然先打 `捕获归因`
（缺源码），紧随其后的折叠日志因此**永远**被抑制——本次验收 4 次折叠，日志一条都没有。

修法：折叠类诊断改用**独立限频通道**（各自一个 `AtomicLong`），或按类别分桶限频。不影响日志量级
（每条类别各自 10s 一条）。
