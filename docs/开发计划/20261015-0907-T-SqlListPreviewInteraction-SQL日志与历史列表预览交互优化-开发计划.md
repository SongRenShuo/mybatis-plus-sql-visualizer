## 一、问题与目标

用户在日志或历史列表里单击一条 SQL，有时只是想选中它、继续滚动或复制，却在短暂延迟后被浮层打断；查看下一条 SQL 时，又要处理当前预览，再等新预览打开。截图显示浮层覆盖了后续多条记录，遮挡列表浏览。

这不是 SQL 内容、高亮或格式化错误，而是“选择记录”和“主动阅读完整 SQL”共用了单击动作。目标是：

1. 普通单击只承担选择，不因误点生成浮层或夺走列表键盘焦点；
2. 用户主动开启浏览后，能沿列表连续查看上一条、下一条，切换 SQL 不要求手动关窗；
3. 保留双击打开现有完整预览、悬停零弹窗、列表多选复制、轻预览中临时改 SQL 后复制的能力；
4. 日志与历史二级列表遵循同一规则；窄工具窗可用，不在每个列表单元格创建 Editor。

## 二、现状与待验证前提

- `SqlLogPanel.kt:1346-1355` 与 `HistorySqlLogPanel.kt:393-403` 都把左键点击交给共享 `SqlClickPreview.onClick`，双击再走各自 `openPreview`。历史一级文件列表仍以双击进入文件内容（`HistorySqlLogPanel.kt:380-387`）。
- `SqlClickPreview.kt:104-107,113-139`：命中行的单击启 300ms 定时器；双击、空白、多选、Ctrl/Shift 点击会停表或关闭旧浮层；列表的选择由 Swing 先处理。`show` 在显示新 SQL 前取消旧弹层并重新创建 Editor（`:168-183`）。
- 弹层用 `setRequestFocus(true)`、点击外部关闭（`:195-212`）；它必须聚焦，才能保持 SQL 可直接编辑和编辑器内 Ctrl+C。故“只把焦点设为 false”不是等价修复：早期计划的四轮实施记录已实证会使编辑器看似不可编辑。
- 可编辑文本、复制按钮与 Ctrl+C/Insert、软换行、高亮及 Editor 释放见 `SqlClickPreview.kt:284-356,206-210`；格式化受现有 `logFormatSql` 控制，不增加平行格式化设置。
- 列表使用 `SqlEntryList`，renderer 有性能底线；完整预览走 `SqlLogPanel.kt:1766-1771` 与 `HistorySqlLogPanel.kt:798-808`，不应为轻预览交互重写。

**实施前须证伪的前提**：

1. 在 243/262 真机上核实“点开浮层后点另一行”实际是点击被浮层遮挡、外点取消后事件仍能选中下一行，还是点击只关窗需再点一次；两种结果都不改变误触问题，但影响方案 A/C 的事件处理方式。不能仅凭截图或 headless 推断弹层穿透。
2. 核实日志列表自动追加、尾部跟随、排序/筛选刷新和历史搜索/懒加载时，选中条目的稳定身份及列表 model 索引如何变化；不能拿旧索引继续展示另一条 SQL。
3. 如选择新增面板/动作，先核对项目既有工具栏分组、Keymap 占用和 243/262 可用的 UI API；以本地平台制品签名及真实界面为准，不在计划阶段虚构快捷键或假定某个 API 存在。
4. 轻预览目前允许直接编辑临时 SQL。若改为跟随选择，必须先定义“编辑未复制时切换条目”策略，不能悄悄覆盖编辑内容。

## 三、备选方案

| 方案 | 单击未主动开启浏览时 | 主动浏览、切换下一条 | 优势 | 代价与风险 |
|---|---|---|---|---|
| A：显式唤起的轻浮层 | 仅选中；用列表上的预览动作（可配键位/右键入口）打开浮层 | 浮层内“上一条/下一条”；切换时复用同一个可编辑区域，不必关窗 | 改造范围较小，基本保留原有外观与工具窗空间 | 浮层仍遮列表；列表与浮层焦点往返复杂，键盘连续浏览需明确焦点路径；箭头必须跟当前过滤/排序视图走 |
| **B：显式开启的固定预览区（推荐）** | 仅选中；工具栏“预览”切换键默认关闭 | 开启后在列表下方固定区域展示当前单选 SQL；在列表单击或方向键选择下一行，原位更新，不新建浮窗 | 完全消除误弹与遮挡，连续浏览依赖原生列表导航；两个列表复用一套交互语义 | 要处理窄高窗口的空间分配、编辑中切换及刷新生命周期；实现/真机验收量高于 A |
| C：单击仍出浮层，但浮层跟随列表 | 仍会因误单击打开 | 点击另一行自动替换浮层内容，或在浮层内切换 | 用户无需学新入口；改动量可能较小 | 没有解决“只是点一下却弹预览”；浮层焦点与遮挡仍在。只适合作为过渡优化，不推荐作为最终方案 |
| D：只保留双击完整预览 | 仅选中 | 每条双击打开完整弹窗 | 实现最少，最克制 | 失去轻量阅读、临时编辑和连续浏览，不推荐 |

### 推荐 B 的交互草案

```text
SQL 日志 / SQL 历史（二级）
┌────────────────────────列表────────────────────────┐
│ ① 单击仅选中    ↑/↓ 切换    Ctrl/Shift 多选仍按原规则 │
├────────“预览”已开启时才出现的分隔条─────────────────┤
│ 当前单选 SQL：可编辑高亮区     复制  恢复原文  关闭预览 │
└──────────────────────────────────────────────────────┘
```

- 默认关闭，首次开启时显示当前选中 SQL；无选中显示空态，不自动选第一条。关闭只折叠预览区，保持列表选择；再次打开显示当时所选。开关属于各页 UI 状态，本期不额外添加全局持久化设置；若用户更偏好“记住开关”，可在定案时调整。
- 预览区采用可调整高度的纵向分区：列表始终保有可操作的最小可见区域；工具窗过矮时不自动弹覆盖层，允许手动折叠；水平窄窗不插右侧固定宽栏。一个预览区最多持有一个 Editor，不在 renderer 创建 Editor。
- 预览打开且为单选时，选择变更只替换区内 SQL；不再排程 300ms、取消/重建 JBPopup。用户点击预览编辑器才移交焦点；从列表选择条目不强制把焦点抢到编辑器。多选时保留列表焦点和 Ctrl+C 批量语义，预览区显示“已选 N 条，单选可预览”而不猜选哪一条。
- 编辑器依旧可直接临时修改并复制；一旦文本偏离原 SQL，预览区**固定在正在编辑的条目**并标注“已修改，暂不跟随列表”。列表可继续选择，但不覆盖草稿；“复制”仍取编辑后的文本，“恢复原文/继续跟随”由用户明确触发。折叠预览不销毁当前草稿；面板 dispose 时临时文本随当前 UI 生命周期结束，不写回日志或历史文件。此项要真机验证文案和操作数，避免编辑后被意外卡在旧条目。
- 关闭预览区的动作不等于关闭完整 SQL 预览。双击仍打开现有完整预览；右键菜单、复制快捷键和 SQL 格式化设置维持原语义。历史切回文件列表时折叠并清空二级预览上下文，下次打开文件按当时选择重新绑定，不显示旧 SQL；临时编辑只保证在当前历史文件的 SQL 浏览期间不被切换行覆盖，返回文件列表会结束这份临时草稿。
- 工具栏预览切换入口在日志页放在同一工具栏行的常显文字按钮（左侧图标动作组与右侧类型/去重控制之间），历史二级页在导航工具栏放常显文字按钮；不能只给图标式 `ActionToolbar` 的动作设置文本，因为该栏可能只画图标。Keymap 快捷键、右键“预览 SQL”本轮不新增；极窄窗口按钮与右侧控件宽度仍待真机走查。

### 用户定案：迁移引导与实施范围（2026-10-15）

用户选择 **B：默认关闭的固定底部预览区**，要求在当前 master 分支实施。旧版单击会弹轻预览，因此首次升级后单击 SQL 行、底部预览尚未开启时，在列表下方展示**一次性、就地、非模态、不抢焦点**的引导：

> 单击现在只选中 SQL。点击「预览」可在底部连续查看；双击仍可打开完整预览。 [开启预览] [知道了]

- “预览”入口须有清晰可见的文字，不只依赖图标 tooltip；提示中的“开启预览”直接展示当前选中 SQL，“知道了”收起提示，后续不重复。即使提示已关闭，入口仍可发现。
- 引导只在一次真实左键单击命中行时触发，空白、右键、双击、多选/修饰键、自动选择与程序刷新不触发；显示提示不创建 SQL Editor、不覆盖列表、不夺键盘焦点。
- 两页共用一个应用级“一次性已看过”标记：提示在首次有效单击后等待 300ms，第二击先到则取消，避免双击时闪现；提示真正出现时写入标记，点“开启预览”或“知道了”都收起提示，另一页不再重复。测试须隔离标记，不依赖真实机器配置。
- 本次顺带保证全键盘可达：明确的“预览”按钮可经工具栏键盘导航触发，打开后列表仍可用上下键切换；不预设与现有 Keymap 冲突的组合键。

### 若选 A 的边界

浮层必须由**明确动作**打开，不能只是把单击定时器改长；上一条/下一条以当前可见列表 model 为准，更新列表选择并避免自己触发关闭弹层。浮层内编辑后切换条目同样要保留或明确处置草稿，不允许静默覆盖。点击列表空白、关闭/失焦、双击完整预览的生命周期需重新定义，不能沿用当前 `onClick` 的“每次单击都关旧浮层”规则。

## 四、定案与执行边界

1. **主形态**：B 固定底部预览区；默认关闭、各页会话态独立。首次点选用一次性就地引导迁移，不能为了兼容旧习惯恢复自动浮层。
2. **编辑草稿切换**：内容被修改后固定正在编辑的 SQL；列表仍能自由选择，但不会静默覆盖草稿。“恢复原文/继续跟随”由用户主动触发。
3. **入口范围**：首版工具栏提供明确文字“预览”的切换入口，加就地引导“开启预览”按钮；双击保留完整预览。不能只靠不可发现的图标或要求用户猜键位。
4. **实施位置**：仅当前 master 工作树，尊重已有 `.gitignore` 和 `record/` 的并行工作；不主动提交、合并、推送或发布。

## 八、二轮修复：预览分隔条白边与日志页入口（2026-10-15）

用户在 SQL 历史页截图指出列表与底部预览间出现白色点状横线；SQL 日志页截图指出预览文字按钮挤在右侧「全部/移除重复」之间碍事。用户选择日志页按钮方案 A：左侧动作图标，不保留右侧常显文字按钮；两项一起改，完成后再跑测试。
