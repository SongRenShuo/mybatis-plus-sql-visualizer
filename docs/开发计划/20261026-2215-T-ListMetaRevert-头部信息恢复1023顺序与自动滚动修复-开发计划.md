## 二、诉求二：自动滚动机制是否丢失

### 2.1 实测结论：机制存在，但有一个长期缺陷

**不是本次退化**——用 `git show 2026.10.23:.../SqlLogPanel.kt` 核对，该版本的滚动事件接线与
当前**完全一致**，同样没有「滚回底部则恢复跟随」的逻辑。

现状行为（读 `TailFollowState` + `SqlLogPanel` 接线）：

| 动作 | 结果 | 是否正确 |
|---|---|---|
| 默认（面板打开 / 清空后） | `FOLLOWING`，新日志到达自动滚到底 | ✅ 符合预期 |
| 鼠标滚轮滚动 | `onUserScroll()` → `PAUSED` | ✅ 符合预期 |
| 拖滚动条 | `onUserScroll()` → `PAUSED` | ✅ 符合预期 |
| 键盘 ↑↓/PgUp/PgDn/Home/End | `onUserScroll()` → `PAUSED` | ✅ 符合预期 |
| **手动滚回最底部** | **仍是 `PAUSED`** | ❌ **不符合预期** |
| 点「滚动到底部」按钮 | `scrollToBottom(resume = true)` → `FOLLOWING` | ✅ 符合预期 |

### 2.2 根因

`onScrollToEnd()` 的**唯一调用方**是 `scrollToBottom(resume = true)`（`SqlLogPanel.kt:303`），
而它只被「滚动到底部」按钮触发（`:1192`）。滚动事件监听器里**没有任何一处**在用户把滚动条
拖到底时调用 `onScrollToEnd()`——`verticalScrollBar.addMouseListener` 只监听了 `mousePressed`
并调用 `onUserScroll()`（`:1559-1562`），缺少 `AdjustmentListener`。

结果：用户手动滚回底部后，必须**额外点一下按钮**才能恢复自动跟随。这确实违反用户描述的
「滚到底就继续自动滚动」。

### 2.3 修复方案

给 `verticalScrollBar` 加 `AdjustmentListener`：滚动位置到达底部（含容差）时调
`onScrollToEnd()` 恢复跟随。

```kotlin
scrollPane.verticalScrollBar.addAdjustmentListener { e ->
    if (e.valueIsAdjusting) return@addAdjustmentListener   // 拖动过程中不判定，避免误恢复
    val bar = e.adjustable as JScrollBar
    // 容差 2px：滚动条 maximum 与实际可滚范围差可视高度，用「距底 ≤2px」判定
    if (bar.value >= bar.maximum - bar.visibleAmount - SCROLL_BOTTOM_TOLERANCE_PX) {
        tailFollow.onScrollToEnd()
    }
}
```

关键设计点：

- **`valueIsAdjusting` 必须跳过**：拖动过程中会连续触发，中途经过底部不代表用户要跟随；
  只有松手后停在底部才算。否则用户「拖到底再拖回来」会经历一次误恢复。
- **容差判定用 `maximum - visibleAmount`**：Swing 的 `maximum` 是「内容总高」语义，
  真正能滚到的最大值是 `maximum - visibleAmount`。直接比 `maximum` 永远不成立
  （这正是这类 bug 最常见的写法错误）。
- **只加监听、不改状态机**：`TailFollowState` 语义正确，不动它。

> **待验证前提 P2**：`JBScrollPane` 的 `verticalScrollBar` 在内容不足一屏时
  `maximum - visibleAmount` 可能为 0 或负数，此时任何位置都算「在底部」——会在用户滚动
  （其实没得滚）时立刻恢复 FOLLOWING。需实测：内容不足一屏时该判定是否产生副作用。
> 处置：若产生副作用，加一条「仅当可滚范围 > 0 时才判定」的前置条件。

> **待验证前提 P3**：等宽字体/可变行高模式下 `maximum` 会随布局变化，`AdjustmentEvent`
> 是否在内容追加时也触发（可能被误判为「用户在底部」而恢复跟随——但那正是想要的）。
> 需确认不会出现「用户已滚上去、追加内容后 maximum 变化导致 value 恰好落在容差内」的误恢复。

### 2.4 同时保留的既有入口

「滚动到底部」按钮行为不变（`resume = true` 仍显式恢复）。新增的监听是**补充**，
不是替代。

```kotlin
if (e.valueIsAdjusting) return          // 拖动中不判定
```
