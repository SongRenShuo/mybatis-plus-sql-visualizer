### D258 CHP 盯防与三件低成本对位吸收

- **动机**：CHP 3.7.0/3.7.1（11-23/11-24）是唯一本窗有产品动作的竞品，且已有 3.6.8 Java Agent、3.6.9 AI Skill、MCP 12 工具三线；我方 11 工具全只读，`sqlv_check_sql`/`sqlv_mapper_check` 返回值缺「我检查了什么/没检查什么」的元信息。
- **三件吸收**（均 S 级，互不依赖，可分批）：
  1. **覆盖度契约**：给 `sqlv_mapper_check` / `sqlv_check_sql` 返回结构加 `checksExecuted` / `checksSkipped`（含跳过原因）+ `recommendation` 四档。典型场景：无数据源时报 `checksSkipped:["tableColumnResolution（未配置数据源）"]` 而非静默通过；JSqlParser 解析失败降级正则时明写 `astBasedAnalysis（已降级，精度下降）`。**CHP 3.6.7 明确从「数值置信度」改过来，我方不复刻旧形态。**
  2. **`ifTests` 逐条分支覆盖**：`sqlv_render_sql` 增 `ifTests`（如 `{"status != null": true}`）/ `allIfTestsTrue|False`，返回 `ifTestResults:[{test,result,source}]`。我方 `Ognl.kt` 是自研解析器，**强制 true/false 只需渲染前注入覆盖表，不需改求值器**——比 CHP 更容易实现。
  3. **AI Skill 生成**：MCP 设置页加按钮，为 Codex / Claude Code / Cursor / WorkBuddy 生成 SKILL.md（工作流 + 工具参数参考 + 已知边界）。底稿可改造 `docs/mcp/MCP-Tools-Agent-Guide.md`。**写盘须显式确认、不覆盖已有非本插件产物。**

### D259 Mapper XML 格式化（保留动态标签）

- **动机**：车道 D 实测我方 `grep -rln "formatMapperXml|MapperXmlFormatter|XmlFormat" src/main` **零命中**；CHP 3.7.0 重做、3.7.1 立刻修「长列压成一行」，说明这是它认定的高频场景。我方只有预览产物的 `SqlFormatter`（格式化渲染出的 SQL），**不格式化用户源文件**。
- **为什么不能直接调平台 XML formatter（本项最关键的设计约束）**：mapper XML 里 SQL 是**文本节点**，平台 XML formatter 只认结构——要么把整段 SQL 当一个长字符串原样不动，要么按字符宽度硬折，把 `WHERE a = 1 AND b = 2` 从中间劈开。更麻烦的是 `<if test>` 内部的 SQL 是**语法不完整的片段**（可能以 `AND` 开头、无 `SELECT`），拿完整语句去解析必然失败。**必须自己做，且按「安全区段」格式化。**
- **三层结构**：
  - **M1 结构保真（往返一致）**：`SecureXml` 解析成 DOM，序列化必须逐项保住——属性顺序（`<select id="x" resultType="y">` 不得变序）、**实体转义状态**（`&lt;` 在 SQL 里是有语义的比较符，不得反序列化成 `<` 后被当标签开头）、CDATA 原样、注释位置、换行符（遵守项目 line-ending-policy，CRLF 不得变 LF）。**验收判据：格式化功能关闭时输出与输入逐字节相同**——这条先过，才谈格式化。
  - **M2 可格式化区识别**：遍历节点，只把满足条件的文本段交给格式化器——语句根节点（`select`/`insert`/`update`/`delete`/`sql`）的直接文本子节点、动态标签**内部**的文本段（`if`/`where`/`set`/`trim`/`foreach`/`choose`，按**片段**处理而非完整语句）；一律跳过 `#{}` / `${}` 所在 token、字符串字面量、注释。我方 `xml/SqlNode` 树已能区分动态标签与纯文本节点，此层不从零写。
  - **M3 `SqlFormatter` 片段模式**：现有实现假设输入是完整语句（有子句结构）；片段模式只做「关键字大小写统一 + 行内空格规整」，**不做子句换行**（无 FROM 可依据）；缩进用相对基准＝父节点缩进 + 2 空格。
- **触发面**：mapper XML 右键「格式化 SQL 语句」；`Ctrl+Alt+L` 光标在语句内时只格式化该语句。**只手动触发，不做保存时自动格式化。**
- **硬性合入条件（本册最重要的一条）**：**格式化前后同一语句渲染出的 SQL 必须逐字一致**——须先造夹具（含 `<if>`/`<foreach>`/`<include>`/`#{}`/`${}`/注释/字符串字面量/`&lt;` 实体/CRLF），格式化前渲染一次、格式化后再渲染一次，比对结果。**实施顺序固定在「先造夹具再写代码」**，不能反过来。不通过不合入。
- **安全阀**：判不准的区段原样保留、不猜——与 CHP 口径一致（其原文「跳过可能改变 SQL 含义的语句」承认存在「判不准就不动」的档位）。
- **不做**：不改语义、不改结构、不重排标签属性顺序；不做「跳过语义会变的语句」以外的智能推断；不做自动格式化。
- **工作量拆解**：M1 往返保真 + 一致性测试 / M2 可格式化区识别 / M3 片段模式 / M4 触发面 + 设置项 / M5 反向验证夹具。大文件（数千行 mapper）须保证全程在 EDT 外完成。
- **复杂度与风险**：M；**本轮四项里风险最高**——唯一会改用户源文件的一项，格式化出错且用户已保存则损失真实。因此必须单独窗口、不与低风险改动混批，且依赖 IDE undo。

### D260 EXPLAIN 结构化渲染转正为默认

- **动机**：DBX `components/explain` 路径最后一次提交 `f62f75d585`（2026-10-09，48 天前）、32766 源仓停更 4.5 个月、pg-explain 2 年未更新却 23,697 下载 4.60 分——**需求被验证、供给侧全行业冻结**。我方现在默认通道是「预览窗内嵌原生控制台执行 EXPLAIN」，结构化渲染是**实验开关 + 非模态对话框**；用户点「执行计划」看到的是控制台原始文本而不是图。
- **改的是结果区排布，不动执行链**：
  - 结果区两个 tab：**计划树**（默认）+ **原始输出**（控制台文本）。
  - 开关语义反转：从「默认关、开了才出图」变成「默认开、用户可关掉只看原文」。
  - **渲染失败必须降级、不得显示空树**：JSON 解析不出来时显示原文 + 一行说明「该方言计划格式未适配，已显示原始输出」。空树比原文更让人困惑。
- **复用面**：既有 `ExplainJsonPlanTree` / `ExplainPlanResultView` / `ExplainPlanDiff` / `ExplainIndexAdvisor`。**不新建渲染组件、不引入 JCEF/pev2**——pg-explain 的 pev2 是 Vue 组件，接 Swing 需 JCEF 桥，成本高且与轻量化定位冲突，列远期备选、不进本册。
- **关键前提（实施第一步，先证伪再动手）**：**平台 Database 控制台可能把 EXPLAIN 结果直接渲染成表格，拿不到原始 JSON 文本**——若成立，结构化渲染无从谈起。故第一步不是改代码，而是真机跑 6 方言（MySQL / PG / Oracle / SQL Server / DM / OpenGauss）确认三件事：①各方言能否拿到 JSON；②默认 EXPLAIN 是否出表格（若是，须在模板里显式指定 `FORMAT JSON`）；③我方 `ExplainJsonPlanTree` 能否解析该形态。**解析不了的方言诚实降级回原文——降级本身就是合格交付，不算失败。**
- **不做**：不新增方言 EXPLAIN 模板（14 条已接，GoldenDB 诚实不接入的口径不变）；不改执行通道（仍走原生控制台）；不改任何数据流。
- **验收**：M1 真机 6 方言覆盖矩阵 / M2 结果区 tab 改造 / M3 开关反转 + 降级路径 / M4 定向测试 + 反向验证（造一个解析不了的 JSON，断言降级为原文而非空树）。真机 6 方言各跑一次确认默认出树、tab 可切原文、开关回退路径可用。
- **复杂度与风险**：M；风险低——不动执行链、不动渲染组件、不改数据流，只改「结果显示在哪」。

### D261 评分资产从零到一

- **动机**：车道 B 实测我方 `/rating` 返回 `votes: {}`（零票），搜索列表端**无 `rating` 字段**（115 条检索命中里 56 条缺该键，缺失集中在零票插件）；而同量级 SQLite Lens 仅 2 票、MyBatiSuite/Ptah 各 1 票即在列表端拿到星级。r43 曾据 `meanRating=4.06326` 判「评价资产首次破零」，**本轮三插件交叉验证证明那是站点全局常量，破零判断作废**。
- **落法（三步，全部待用户令）**：
  1. 面向已安装用户的**低打扰引导**——**形态建议：面板内一行 + 一次性气泡（用户敲定）**，遵守「弹窗克制红线」，**不得**做启动弹窗；
  2. 文档站/Marketplace 描述加一句轻量「如果它省了你的时间，评个分」；
  3. 已有内容（知乎 15 答 + 6 文、掘金 3 篇、CSDN 3 篇）**回链处统一补评分入口**。
- **不做**：不刷评、不做任何形式的诱导性奖励（违反 Marketplace 规则）；不在主链路上弹窗。
- **验收**：Marketplace `/rating` 直方图非空；`searchPlugins` 响应中出现 `rating` 字段。**这是唯一可机判的完成标志**。

### 已拍板的三项

1. **D259 做，但排最后且单独窗口**。理由：它不改语义只动排版，风险性质与「生成 Java 代码」不同，CHP 连修两版说明需求真实；但它是唯一有不可逆风险的一项（格式化出错 + 用户已保存），不该和低风险改动混在一批里赶进度。若后续认为「写」这条路不该开，可直接砍掉 D259，不影响其余三项。
2. **D260 默认开计划树、原文降为次级 tab**。原生文本对多数人没信息量；解析不了的方言走降级路径（显示原文 + 一行说明），不得显示空树。
3. **D261 引导形态＝面板内一行 + 一次性气泡**。不做启动弹窗（遵守弹窗克制红线），不刷评、不做诱导性奖励。
