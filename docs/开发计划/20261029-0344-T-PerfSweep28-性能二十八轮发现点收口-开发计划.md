## 一、背景与范围

2026-10-27 复查遗留四个可修点已随 T-PerfSweep27 四券全部销账（头部行缓存、Resolver 族上限、补全降噪＋HqlGutter 前置、AUDIT_CTX 清扫）。本轮复查基线推进 23 笔生产码提交，**首次出现高级别新发现**：外部贡献合入的 Mapper 双向跳转里 Java→XML 方向 Provider 缺门控、缺 memo、缺开关，daemon 慢趟上每方法声明付 O(mapper 文件数) PSI 遍历，5s TTL 过期后的全项目 XML 索引重扫也落在 daemon 线程内（详见调研报告 §四.1）。其余新增面（T-SqlDialectPrewarm、agent 织入通道、ExecFileBinding）均健康，无中高级发现。

本批处置范围：

- **P1 修**：MapperJavaToXml 门控与 memo＋两 Provider 接组闸（1 券）；
- **P2 修**：XML→Java 方向 allScope/DumbService 卫生批、三处技术性无上限缓存收口、守卫与测试卫生批（BannedApi 现行红＋O147 临时目录泄漏＋排序比值判据基数），共 3 券；
- **微随批**：StringSqlMethodGutter 文件级门控（F 系遗留终账，1 券）；
- **不修登记**：F103、AUDIT_CTX 清扫触发时机、Resolver 整体清空策略（理由见 §二表尾）。

## 三、券详单

### T-PerfSweep28-01（R28-1＋R28-2）：MapperJavaToXml 门控与 memo ＋ 双 Provider 接组闸

- **现状**：①createMarker 判定链三层 O(1) 后即 locate（MapperNavigationLineMarkerProviders.kt:65-70），无接口判定、无负 memo，普通 Java 类每个方法声明每慢趟付一次 O(N_mapper) 根标签遍历；②locateUnderRead 命中也不早退（:58-66 为统计多模块同名扫完全部文件）；③文件清单 TTL 5s 过期后全项目 XML FileTypeIndex 枚举＋逐文件 PSI 解析发生在 daemon 慢趟线程内（:132-154）；④两个 Provider 均未接 GutterGroups 任何组闸，用户无逃生口。
- **修法**（四件一体）：①`containingClass?.isInterface == true` O(1) 前置（P-1 通过后）；②文件级/接口级轻门控可选做，若 P-1 的 isInterface 已滤掉绝大多数站点则 memo 为主要手段，不叠加文本特征门控（避免「自定义 base mapper 不含 BaseMapper 子串」漏杀——该形态 20261029 复盘已登记）；③locate 结果按 `(namespace, id)` memo，正负结果都缓存，生命周期挂 FileListSlot 同代失效（P-2/P-3 定形态）；④两 Provider 接 GutterGroups 组闸（P-4 定组），开关判定位置遵循「锚点→开关→重逻辑」定例。
- **先红后绿判据**：①新用例「非 Mapper 接口 Java 文件 N 个方法 × 慢趟 2 趟 → 断言 locate 索引全扫次数（indexScanCount 测试缝）与根标签遍历次数不超过每窗口 1 次」——修复前全扫随 TTL 过期出现 ≥1、根标签遍历 = 方法数×N_mapper×趟数，先红；②反向=摘除 memo 与门控 → 用例①回红，贴两次读数；③多模块同名夹具（两 mapper 同 namespace 同 id）断言首命中文件与行号在改造前后逐字一致（P-3）；④组闸用例：关 mapperXml（或所选）组 → 两 Provider 标记产出为零且 locate 零调用；开组 → 标记产出与现 HEAD 一致；⑤既有 MapperXmlLocatorTest 全绿（含 TTL 语义用例），不动其断言。
- **风险与交互**：memo 挂 FileListSlot 后，右键路径（LogToSqlPanel 直调 locate）与 gutter 路径共享同代缓存——右键跳转的新鲜度口径不得劣于现行为（TTL 窗口语义已声明）；GutterGroups 归组若选 mapperXml，用户关该组会同时关掉 XML 语句预览图标族，实施记录须写明；GutterIconDedupTest 16 用例须维持绿。

### T-PerfSweep28-02（R28-3）：XML→Java 解析收窄 projectScope ＋ DumbService 守卫对齐

- **现状**：resolveInterfaceMethod 用 `GlobalSearchScope.allScope(project)` findClass（MybatisXmlTargets.kt:180-182），namespace 全限定名场景库 scope 纯浪费；且无 DumbService 守卫（同文件 resolveClass :161 有），dumb 态返回不完整结果。
- **修法**：allScope→projectScope（P-5 通过后）；dumb 态早退返回 null（与 resolveClass 同型）。若 dumb 早退导致索引重建期 gutter 短暂消失，属平台一致行为，实施记录注明。
- **判据**：①多模块夹具断言 projectScope 命中业务模块接口；②dumb 态夹具断言零 findClass 调用；反向=还原 → 用例红。
- **风险与交互**：频率已被语句标签锚点收窄，本券为一致性卫生项，单独提交可独立回滚。

### T-PerfSweep28-03（R28-4）：三处技术性无上限缓存收口

- **现状**：SqlLogFileReader.countCache（键=历史文件路径，SqlLogFileReader.kt:153）、HibernateNamingConfigProbe.cache（键=projectBase|资源目录，:113）、SqlPreviewService.activePreviewDialogs（ConcurrentHashMap 键强持 Project，值弱引用，:2006）——均基线前既有微项，长会话跨多项目缓慢累积。
- **修法**：前两处套 HbmXml 负缓存 4096 超限整体清空范式（仓内现成：HbmXmlEntityResolver.kt:41-54）；activePreviewDialogs 按 P-6 证伪结果选「键换弱键（配合同步）」或「挂项目关闭钩子自摘」（hookProjectsClose 先例：DataSourceSelector.kt:2269-2272）。
- **判据**：①各新增用例「写入超限 → 条目数收敛且清空后可重填」；反向=摘上限 → 用例红；②PluginCacheManager.clearAll 覆盖面守卫维持绿。
- **风险与交互**：上限淘汰不得造成同键二次读取结果可观测差异（三者均为纯缓存值，无学习态）；activePreviewDialogs 若挂项目钩子，注意插件动态卸载路径不新增泄漏点。

### T-PerfSweep28-04（R28-5）：StringSqlMethodGutter 文件级门控（F 系遗留终账）

- **修法偏离（实施时定稿）**：计划原文写「文件级特征门控」，实施时发现该 Provider 的候选方法名集（JDBC_TEMPLATE_METHODS ∪ DAO_STRING_SQL_METHODS）含 `update`/`delete`/`execute`/`insert`/`query` 等业务代码高频词——文件文本含任一名字的判据近乎恒真，文件级门控精度趋零、形同虚设。改为**方法体引号预筛**：`body.text` 不含 `"` 时不可能存在字符串字面量实参（字符串 SQL 必为字符串字面量），O(body) 单次字符扫描替代 `PsiTreeUtil.collectElementsOfType` 全子树遍历（零分配、逐节点访问），命中精度 100%（无引号 → 必无候选）。判据①「无特征大文件夹具断言整文件零遍历」相应改为「无引号方法体夹具断言零遍历」（测试缝 bodyScanCount）。
- **现状**：组开关前置正确（:60-62），每方法名叶子付一次方法体子树遍历（:92-106），仅 200K/方法体护栏（:94,:123），无文件级门控——与 CriteriaQueryGutter 20261027 前的病灶同型。
- **修法（定稿，见上方偏离说明）**：`hasStringSqlCall` 入口加方法体引号预筛——`if (!body.text.contains('"')) return false`，测试缝 bodyScanCount（companion internal val AtomicInteger，在预筛之后的全子树遍历前自增）。
- **判据**：①无引号方法体夹具（30 个方法、零字符串字面量）两次慢趟断言 bodyScanCount=0——修复前为 60，先红；②含字符串 SQL 的方法标记产出与现 HEAD 一致（GutterIconDedupTest 全绿兼任）；反向=摘预筛 → 用例①红。
- **风险与交互**：预筛为纯前置短路，命中路径行为逐字不变；文本块 `"""` 含引号字符不误伤；GutterIconDedupTest 维持绿。

### T-PerfSweep28-05（R28-6＋R28-7＋R28-8）：守卫与测试卫生批

### 实施中的坑（实录）

1. **memo 挂独立槽会跳过清单新鲜度检查**：首版把 memo 挂 `StatementMemoSlot`（按 fileListSlot 实例身份判定），memo 命中时根本不调用 `mapperXmlVirtualFiles`，导致既有 `testT_P5_05_TTL过期后重扫` 变红（expected 2 but was 1）——TTL 过期后不重扫。改为 **memo 直接作为 FileListSlot 的成员**，先取新鲜槽再查 memo，语义与既有 TTL 契约严格一致。
2. **ConcurrentHashMap 不接受 null 值**：负结果（locate 返回 null）直接 put 抛 NPE，把 5 个既有用例带红。改 MISS 哨兵承载负缓存。
3. **测试入口选错**：StringSqlMethodGutterLineMarkerProvider 只实现 `getLineMarkerInfo`（快速路径），无 `collectSlowLineMarkers` 重载——用后者驱动是空跑（bodyScanCount 恒 0），须逐 leaf 直调。
4. **夹具 namespace 与接口包名必须一致**：Java→XML 定位靠 `containingClass.qualifiedName` 拼 statementId，测试里 interface 放 `com.demo` 而 XML namespace 写 `com.demo.mapper` 时必然落空（标记 0）；另「非接口零触达」断言须用不含接口方法的独立夹具，否则同文件接口方法的定位会把计数抬高。
