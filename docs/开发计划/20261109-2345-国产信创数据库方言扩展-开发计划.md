## 二、券分解

### 券 A：TiDB（MySQL 族，P0）
- 族底版 `MySqlDialect`；差异：EXPLAIN 支持 `EXPLAIN ANALYZE`（真执行）与 `EXPLAIN [FORMAT = …]`；URL `jdbc:mysql:` 不劫持（TiDB 无专用子协议，靠角标位 + 别名「TiDB」在 MCP 别名表）；无专用驱动（增强捕获触点 10 跳过并注明）。
- 角标：TiDB 显示名进 `JdbcUrlDialects` 需子协议证据——TiDB 无自有子协议，**角标不做**，在 KDoc 说明「按 MySQL 识别是正确行为」（GoldenDB KDoc 同款先例）。
- EXPLAIN Entry：`EXPLAIN {sql}`（TABLE），证据=官方文档级（docs.pingcap.com EXPLAIN）。

### 券 B：PolarDB-X（MySQL 族，P1）
- 族底版 `MySqlDialect`；URL `jdbc:polardbx:`（专用驱动 polardbx-connector-java）+ `jdbc:mysql:` 不劫持。
- EXPLAIN：MySQL 风格 `EXPLAIN {sql}`（官方文档级）。

### 券 C：PolarDB Oracle 兼容版（Oracle 族，P1）
- 族底版 `OracleDialect`；URL `jdbc:polardb:` / `jdbc:polardb2:`；驱动类 `com.aliyun.polardb.*` 前缀登记增强捕获。
- EXPLAIN：Oracle 风格（MP `POLARDB`→OracleDialect 同族）——按 Oracle 族推定，标「官方文档级（兼容声明）+ 族推定」。

### 券 D：GBase 8a + GBase 8c（P2）
- **GBase 8a**：族底版 `MySqlDialect`（LIMIT offset,n、反引号）；EXPLAIN **仅 SELECT**——Entry 登记 + `ExplainGate` 首关键字白名单该方言特判（复用既有门机制）；URL `jdbc:gbase:`（8s 同子协议！`gbase` 子协议歧义：8a/8s 共用——推断按 8a 处理 + KDoc 注明歧义与手动改选路径）；角标 GBASE 已在册（复用）。
- **GBase 8c**：族底版 PG/openGauss；URL `jdbc:gbase8c:`；证据=官网文档级（8c 基于 openGauss/GaussDB 内核）+ 族推定。

### 券 E：神通 Oscar + 优炫 UXDB（P2）
- **Oscar**：族底版 `OracleDialect`；URL `jdbc:oscar:`（默认端口 2003）；驱动 `com.oscar.Driver` 登记增强捕获；EXPLAIN Oracle 族推定。
- **UXDB**：族底版 `PostgreSQLDialect`；URL `jdbc:uxdb:`；EXPLAIN PG 族推定（`EXPLAIN {sql}` TEXT 或 FORMAT JSON 按证据定，无证据走保守 TEXT 档）。

### 券 F：AntDB + 崖山 YashanDB（P2）
- **AntDB**：族底版 `PostgreSQLDialect`；URL `jdbc:antdb:`；KDoc 注明 PG/Oracle 双引擎、按 PG 模式渲染，Oracle 模式用户手动切。
- **YashanDB**：族底版 `OracleDialect`；URL `jdbc:yasdb:`；MP `YASDB` 同族佐证。

### 券 G：虚谷 XuGu（P2，混合自有）
- 族底版按官方文档核对：分页 MySQL 风格 LIMIT 为主（`docs.xugudb.com` 在册）；引号/注释规则按官方 SQL 参考；EXPLAIN `EXPLAIN {查询}` 在册（官方文档级）。
- KDoc 逐项标「官方文档级 / 待真机校验」；URL `jdbc:xugu:`；驱动 `com.xuguedata.jdbc.XuguDriver` 登记。

### 券 H：识别/角标位（不做渲染方言）
- TDSQL：MCP 别名表 + `JdbcUrlDialects` 角标（`tdsql` 子协议有证据才加；MySQL 版走 `jdbc:mysql:` 不劫持）。
- 星瑞格 SinoDB / 行云 XCloud：仅角标（有子协议证据才加）；KDoc 注明 Informix/自有族渲染暂无、诚实降级。
- 磐维角标升级：`JdbcUrlDialects` 显示名复核（现「Panwei（磐维）」），不动 `SUBPROTOCOL_TO_DIALECT` 的 Oracle 映射（T-IbatisPanwei 定案维持）。

### 券 I：守卫同步与回归收口
- 注册接线测试批量更新（`DmDialectRegistrationWiringTest` 模板）：全量方言注册在册 + URL 推断 + 角标/渲染映射独立维护三条线对账。
- `DialectExplainTest` 逐方言断言表与 `ExplainSupport` 一致。
- 归属文档同步：`docs/架构设计/` 下方言归属子系统文档 + `DialectDocTableGuardTest`/兄弟文档站表格（先例：方言数变化须同批改文档站，§五.1 风险）。
- 设置页下拉回归（注册表顺序驱动，平台 UI 面按 L13 口径：全量未跑 = not run 待收口）。
- CHANGELOG `[Unreleased]` 回填（提交即回填纪律）。

## 三、实施顺序与批次

1. **S1 基建摸底**：grep 全部 `DialectRegistry`/方言名消费点，产出本轮「必须同批改」的守卫清单（对 §一.11 触点表校准，防漏）。
2. **S2 券 A→H 逐券实施**：每券一提交（或两券一提交），每提交过编译（L11）；方言对象按族就近放 `sql/` 包（既有单文件惯例）。
3. **S3 券 I 收口**：守卫 + 文档 + CHANGELOG + 定向测试全量读数。
4. **S4 验收**：`testFast` 快桶 + 方言定向面（Dialect* 测试类）；平台 UI 面与全量按 not run 条款如实登记。

## 四、验收判据

- `DialectRegistry.dialects` 25 个；每方言 `byName` 往返一致。
- 每新方言：URL 子协议推断命中且值逐字等于 `name`（拼错回落 MySQL 是静默错误——测试钉住）。
- `DialectExplainTest` 全绿（新 Entry 与实现一致）。
- 反向验证（S2）：任选两方言摘掉注册 → 对应接线测试变红，复挂转绿。
- 守卫类（成对注册、文档表、接线对账）全绿。
- 文档：调研报告 + 本计划 + 归属子系统文档同步；CHANGELOG `[Unreleased]` 记账。

## 五、Not run / 边界登记

- 平台 UI 测试（testShards 全量）本轮未跑——设置页仅注册表驱动的内容变化，无布局改动；如 CI 全量红按 L13 口径收口。
- 真机端到端验证（EXPLAIN 真机执行）本轮无——所有新方言 EXPLAIN 均为文档级/族推定档，产物文案不做「已验证」表述。
- GBase `gbase` 子协议歧义（8a/8s 共用）：按 8a 处理，KDoc 注明；不做 URL 端口嗅探（无证据不猜）。
