## 一、背景与依据

第八轮复查的基调是「修复大验收 + 合流新子系统首轮审计」：T-PerfSweep4 十八项修复全部验收通过，系列首次发现清零；T-MergeDev2Master 合流进来的四个新子系统（MCP 工具集、执行护栏、回滚链、CRUD 生成）零新增常驻线程/定时器/监听器，合流是干净的。但新子系统带来本轮唯一的「中」级发现——执行链每次执行对同一 SQL 文本做两次 JSqlParser 解析（入口 DDL 判定 + 收尾兜底失效），均发生在 EDT；同类重复解析还出现在确认流与回滚链（一次大 DML 点击最坏 4 次解析、3 次在 EDT）。此外方言智能推断默认开启后暴露两条结构性问题：`DialectRegistry.effective` 无结果缓存单次预览重复探测约 7 次，且经 `AgentManager.getInstance` 把增强捕获的两条常驻守护线程变成「预览一次即驻留」。其余为有界长尾。

本计划 15 项任务 + 1 项不改定案（发现 7 DynamicInstallSupport EDT 占用系平台动态卸载语义要求、用户主动触发，留档不改不占任务），一次收口、一道门禁。

## 三、方案

**T-PS5-01（执行链 DDL 判定解析复用，中）**：`MetadataInvalidator` 内加单槽解析缓存——`mayChangeMetadata` 以 SQL 文本指纹（引用相等 + 长度 + 哈希三重快判）命中即复用上次解析判定布尔，未命中才 `CCJSqlParserUtil.parseStatements`；**失效动作照常每次执行**（入口预判 + 收尾兜底两次 invalidateAll 语义不变，失效本身 O(1) 引用清空）——复用的只是解析与判定，不是失效。配套批脚本廉价预筛：语句数超阈值（建议 50，实施定案）时先做不含 DDL 关键字（词边界扫描复用既有形态）的快速排除，排除失败才进 AST 解析，预筛结果与 AST 判定取或（fail-closed 语义不回退）。测试：同文本两次判定只解析一次（解析计数探针）/ 预筛排除路径与全解析判定等价（DDL 用例表驱动）/ fail-closed 回归。

**T-PS5-02（确认流/回滚链解析共享，中低）**：共享基建落在 `UnboundedWriteDetector.detect` 返回结构——携带已解析的 `Statement` 列表（或文本指纹+缓存槽，与 T-PS5-01 同槽位）；`RollbackSqlGenerator.generate` 加携解析入参重载，`SqlPreviewPanel.kt:838` 回滚注册链传入确认阶段产物不再二次解析。JSqlParser AST 复用纪律：**只读**（generate/detect 均为纯遍历，注释声明不得改写节点）。跨调用共享缓存（非同执行流内传递）不做——语义面窄、单执行流内传递已消掉最坏路径的 3 次中的 2 次。测试：确认→回滚链解析计数断言 / generate 结果与独立解析逐字节一致。

**T-PS5-03（方言 effective 缓存 + 调用点收敛，中低）**：两件组合——
1. `DataSourceUrlProbe.firstUrl` 结果加 per-project 缓存（URL 变更低频），失效双保险：AgentSession 建会话/断开时清（会话事件点已有）+ TTL 上界（建议 5s，实施定案；数据源编辑后至多一个 TTL 窗口内方言滞后，写入注释）。agentUrl 侧（CopyOnWriteArrayList 快照遍历）本就廉价不缓存。
2. `SqlPreviewService.buildPreviewResult` / JPA 路径入口求一次 `currentDialect()` 后传参，九处调用点收敛为入口一次（签名改动局限本文件）。
测试：URL 不变时探测只发生一次（反射计数探针，探测函数可注入替身）/ TTL 过期后重探 / 手动方言模式路径零探测回归。

**T-PS5-04（AgentManager 常驻面解耦，中低）**：两件组合——
1. 推断用 agentUrl 移轻量持有者：新建应用级 object（如 `AgentUrlRegistry`，volatile 字段即可——同刻至多一个活跃推断上下文，实现时核实多会话语义后定 Map 或单值），AgentSession 建会话/关闭时写清；`Dialect.kt:452-456` 与 `PluginSettingsPanel.kt:1360-1365` 改读 registry，**不再经 `AgentManager.getInstance` 触发服务 init**。DialectInference 优先级语义（agent URL > 数据源 URL > null 回退）不变。
2. `AgentManager` init 的 monitor（5s 巡检）改为首条会话建立才启动（executor 保持惰性单线程不变）；SETTINGS_CHANGE 监听随实例化仍在（服务真被增强捕获用到时才有，语义不变）。
测试：纯预览场景（增强捕获零使用）AgentManager 类不初始化（静态哨兵断言）/ registry 写清时序 / 巡检懒启后 sweepOffline 语义回归（死会话清理路径）。

**T-PS5-05（XML 定位缓存，中低）**：`MapperXmlLocator` 缓存 FileTypeIndex 文件列表（per-project，字段 + 项目 Disposable 清理），失效用廉价代数校验（缓存时记录 `PsiManager` 代际不可行——改用 TTL 上界建议 5s + 取用时 `virtualFile.isValid()` 校验，失效文件即刻重扫一次，实施时读 `:81-100` 实际形态后定案）；rootTag 解析每次照做（PSI 平台自身有复用）。**红线约束：不得引入 PsiTreeChangeListener/EditorFactoryListener**（两族在册 0，缓存失效不走 PSI 监听）。`XmlCrossNsFragmentResolver` 同款缓存 refid→fragment 映射（同 TTL + isValid 纪律），`:54-56` 零成本短路保留。测试：命中路径无索引遍历（探针）/ 文件删除后 isValid 校验回退 / TTL 过期重扫正确性。

**T-PS5-06（schema 全扫限额，中低）**：`McpSchemaFormatter`/`McpSchemaContextService` 链对单调用全扫加限额——首个 miss 表触发全扫后，本次调用内后续 miss 表**不再重扫**（调用内记住「已全扫过」标志，直接按未找到披露）；跨调用维持既有正/负缓存语义不变。T-MC-02 表名一次扫描索引（`DatabaseSchemaResolver.kt:137-138` 预案）作为可选增强记录不实施（改动面大、负缓存已吸收高频痛点）。测试：单调用 k 表 miss 只全扫一次 / 命中与 miss 混合调用结果正确 / 既有负缓存 TTL 回归。

**T-PS5-07（epActive 复位 + 冗余清理，低）**：`SqlCaptureGate.epActive` 增设复位点——增强捕获总开关关闭时复位（挂 AgentManager 开关下降沿，与 `:180-183` 上升沿重置冷却对称）；`SqlLogConsoleBridge.kt:378` 不可达冗余判断删除；复位语义定案写入注释（EP 链路失效的极端场景由短路计数 debug 日志可观测兜底维持）。测试：关开关→复位→新控制台桥路恢复解析 / 开关往返状态机断言。

**T-PS5-08（conflictProbeProjects 强引用清理，低）**：`DataSourceSelector.kt:3510-3511` 改弱引用（`java.lang.ref.WeakReference` 惯例已有）或挂 project disposable `doWhenDisposed` 清理——实施时读 F6 探针消费形态后定案，探针判空语义不变。测试：项目关闭后引用可回收（弱引用可达性断言，GC 宽松写法防 flake）。

**T-PS5-09（attachFilter 死分配删除，低）**：`SqlLogConsoleBridge.kt:312-347` 首组 `config` 版三解析器创建删除，直接用 `cfg0` 重建的那组；纯删码零语义变化，编译门禁即可。

**T-PS5-10（sqlIndex 懒清理，低）**：`RollbackSnapshotStore` 按 id 取值处（`:111-113` 已判 null）顺手 `sqlIndex` 反向清理不可达指纹（遍历代价高则仅在 register 时批量对账一次）；容量语义注释对齐 LRU 100 条口径。测试：淘汰后取值 null 行为不变 / 长会话模拟 sqlIndex 规模有界。

**T-PS5-11（浮层解析预算，低）**：`buildMergeAdText` 调用前按语句数预检——超上限（建议 100，实施定案）跳过逐语句 AST 预检、浮层按既有「异构不静默丢按 N 分之 M 披露」口径给出计数披露（渲染面 8KB 预算与计数后缀恒可见惯例不回退）；上限内维持现状。与 T-PS5-02 的共享解析基建自然受益。测试：超限披露文案 / 上限内结果不变。

**T-PS5-12（冷路径正则与 Formatter，低）**：`AgentManager.kt:642` readHelloPid 正则提 companion 常量；`LogTimestampParser.kt:75` SimpleDateFormat 改 ThreadLocal 按格式串缓存（照 `SqlLogPanel.kt:1919-1923` 惯例，SimpleDateFormat 非线程安全必须 ThreadLocal 隔离）。测试：解析结果回归断言（既有用例口径）。

**T-PS5-13（负缓存容量上界，低）**：`DatabaseSchemaResolver` 负缓存 size 超上限（建议 512）整体清空（照 `Ognl.kt:959`/`StackLocator` CACHE_MAX 惯例）；TTL 惰性过期语义不变。测试：容量溢出清空后行为正确 / 既有 TTL 回归。

**T-PS5-14（设置页控件懒建，低·可选件）**：`PluginSettingsPanel` 七分区控件字段改 `by lazy`，`SectionConfigurable` 按 section 触发所需分区构建；**前置守卫**：isModified/apply/reset 对未构建分区控件的空引用路径必须全量排查（懒引用首次触达即构建天然规避 null，但比对顺序变化属行为面）——实施前读 `:1340-1464` isModified 全链后定案；改动面收益比不佳时按「诚实不实施」留档。测试：七子页逐一 isModified/apply/reset 回归（既有用例口径）。

**T-PS5-15（引导监听弹后注销，低）**：`OnboardingAnchorTip` 通知弹过后 disconnect messageBus 连接（`AtomicBoolean` 单飞点即注销点）；项目关闭路径语义不变。测试：弹过后 fileOpened 不再触达（探针）/ 未弹过路径行为不变。

**T-PS5-16（清账验证）**：全量 testShards 绿；性能第八轮报告 §5 发现点表逐项标注「已收口 + 提交号」回填；§5 发现 7 不改定案在报告侧留痕。

### 逐项落地

**T-PS5-01（执行链解析复用）**：`MetadataInvalidator` 加单槽 `ParseSlot`——命中判据 = 引用相等 →
长度 → 哈希 → **内容全等收口**（计划原案只到哈希，32 位碰撞理论上可致收尾兜底漏判，补内容比较
把误命中概率降为 0，代价是同长度异实例文本上一次字符串比较）。缓存只复用解析与判定，**失效动作
照常每次执行**（入口 + 收尾两次 invalidateAll 语义不变）。批脚本预筛取**否定式**：分号计数超
`batchPrefilterStatements`（50）且全文无任何 DDL/提交关键字（词边界扫描）→ 直接判 false 不进 AST；
关键字命中仍由 AST 权威判定（`SELECT 'DROP TABLE'` 类字面量不误失效），fail-closed 方向不回退。
计划原案「预筛结果与 AST 判定取或」按此收窄为「预筛只做否定排除」——取或会把字面量命中当 DDL
误失效，与既有「字符串内关键字不误伤」用例直接冲突。

**T-PS5-02（确认流/回滚链共享）**：共享基建落在 `UnboundedWriteDetector` 的 AST 单槽
（`parseStatementsShared`），`detect` 与 `RollbackSqlGenerator.generate` 共用——两条链都以「文本」
为输入，槽位天然对上，**零调用点改动**即把一次大 DML 点击的最坏 4 次解析降到 1 次。
另加 `generateFromParsedStatements(cleaned, statements, pk)` 携解析入参重载供同执行流显式传递
（`generate` 委派它，无死代码）。AST 只读纪律：两实现经 grep 核实纯遍历（无 `set…`/`with…`
写节点调用），纪律写入字段 KDoc，逐字节一致用例兜底。
**偏离计划一处**：计划原文要求「`SqlPreviewPanel.kt:838` 回滚注册链传入确认阶段产物」——该文件
本波由并行任务 T-PC2-04 占用（派活方明令不碰），故改为**单槽机制实现同一收益**（面板零改动即可
命中确认阶段的 AST）；面板侧若要改成显式传参，一行即可接上 `generateFromParsedStatements`。
跨调用共享缓存（计划原案不做）实际以「单槽 + 内容全等」落地，属机制等价而非语义放宽。

**T-PS5-03（方言缓存 + 调用点收敛）**：`DataSourceUrlProbe` 加单槽 TTL 缓存（默认 5s，项目**弱引用**
键，异项目不命中）；失效双保险 = 会话生命周期点 `invalidate`（由 AgentManager 收口调用）+ TTL 上界。
`SqlPreviewService` 各预览入口求一次 `currentDialect()` 后透传（`applyJpaMethodEnhancements` /
`buildJpaPreviewResult` 加 `dialectOverride` 参数，签名改动局限本文件），单次预览的 `effective`
调用由 3 次收敛为 1 次。方言推断优先级（agent URL > 数据源 URL > null 回退）与手动模式零探测
语义均有用例钉住。

**T-PS5-04（AgentManager 解耦）**：新增 `AgentUrlRegistry`（应用级 object，零线程零监听，项目弱引用
Map——多项目同开各按自身会话 URL，不降级为全局单值）。写入点全部由 AgentManager 在会话生命周期
（attach 成功 / premain 回连 / URL 首次捕获 / 摘除 / 关闭 / 销毁）以 `lastConnectionUrl()` 结果回写，
语义与解耦前逐字一致。`Dialect.kt` 与 `PluginSettingsPanel.refreshInferredLabel` 改读持有者，
**不再经 `getInstance` 触发服务实例化**（源码级哨兵守卫把关）。monitor 5s 巡检改首条会话建立才懒启
（`ensureMonitorStarted` + 建立时兜底清扫一次），SETTINGS_CHANGE 监听与 executor 惰性语义不变。

**T-PS5-05（XML 定位缓存）**：`MapperXmlLocator` 缓存「已筛出的 mapper XML VirtualFile 列表」，
