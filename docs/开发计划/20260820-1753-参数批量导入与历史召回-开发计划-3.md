# 参数批量导入 / 历史召回（P-05）开发计划

> 状态：✅ 已落地（`ParamImportDialog`/`ParamImportParser`/`ParamHistoryCache`；2026-11-13 代码核对回填）
> 需求来源：用户新需求「参数面板支持剪贴板批量导入参数值 + 同一实体类查询复用上次填的参数」。

## 1. 目标与范围

在 SQL 预览面板（`SqlPreviewPanel`）的参数输入区增加两项能力：

1. **剪贴板批量导入**：用户从 Postman/Insomnia/数据库客户端复制的参数列表（JSON / CSV / key=value 格式）可一键填入参数面板，免去逐框手敲。
2. **历史参数召回**：同一实体类的查询在不同预览间复用上次填的参数值（按 `表名 + SQL 模板指纹` 缓存），重新打开预览时自动回填。

**已确认决策**：
- 导入触发方式：参数面板顶部新增「导入」工具栏按钮 + 右键菜单项（与既有复制/格式化/刷新按钮并列）。
- 历史缓存作用域：project 级内存缓存（`SqlPreviewPanel` 实例级 Map + 持久化到 `PluginSettings.State` 的轻量 JSON 字符串），不跨项目共享。
- 缓存键 = `tableName`（或 `statementId` for XML）+ `SQL 模板指纹`（rawSql 的 SHA-256 前 16 字符），缓存值 = `Map<source, value>`。
- 缓存上限 50 条（LRU 淘汰），单条无 TTL（跟随 IDE 会话生命周期）。

## 2. 架构与数据流

```
用户复制参数文本（JSON/CSV/key=value）
  → ParamImportParser.parse(text) → Map<String, String>
      ├── JSON 路径：Jackson-less 自研轻量解析（仅扁平 object，嵌套不支持）
      ├── CSV 路径：首行 header + 单行值（Postman/Insomnia 导出形态）
      └── key=value 路径：行分隔，`=` 左侧 trim 为 key，右侧 trim 为 value
  → SqlPreviewPanel.importParams(map)
      → 按 source 匹配 paramFields（模糊匹配：key ≡ source 或 key ≡ #source）
      → 回填 paramValues + 触发 renderSql()
      → 未匹配项 → 通知提示（"已导入 N 项，M 项未匹配"）

历史召回：
  showResult() 初始化 paramValues 后
    → 计算缓存键（tableName + rawSql 指纹）
    → 查历史缓存（PluginSettings.state.paramHistory）
    → 命中 → 按 source 回填（用户已输入值优先，不覆盖）
    → 未命中 → 保持现状（initialParamValues 优先，空串兜底）
  onParamChanged() / onConditionValueChanged() 用户输入时
    → 更新 paramValues 后同步写回缓存（debounce 500ms）
```

## 3. 模块设计

### 3.1 ParamImportParser（纯逻辑，可独立单测）

新增 `src/main/kotlin/cn/song/mybatisplus/visualizer/ui/ParamImportParser.kt`：

```kotlin
object ParamImportParser {
    fun parse(text: String): Map<String, String> = when {
        text.trimStart().startsWith("{") || text.trimStart().startsWith("[") -> parseJson(text)
        text.contains("\n") && text.lineSequence().first().contains(",") -> parseCsv(text)
        else -> parseKeyValue(text)
    }

    fun parseJson(text: String): Map<String, String>  // 扁平 JSON，value 仅 String/Number/Boolean
    fun parseCsv(text: String): Map<String, String>    // 首行 header，第二行值
    fun parseKeyValue(text: String): Map<String, String> // 每行 key=value
}
```

**格式兼容清单**：

| 来源 | 示例 | 解析路径 |
|------|------|----------|
| Postman (JSON) | `{"name":"张三","age":28}` | parseJson |
| Insomnia (JSON) | `{\n  "status": 1\n}` | parseJson |
| DBeaver 导出 (CSV) | `name,age\n张三,28` | parseCsv |
| 手写 key=value | `name=张三\nage=28` | parseKeyValue |
| URL query string | `name=张三&age=28` | parseKeyValue（`&` 视为分隔符） |

**边界处理**：
- JSON 嵌套对象 / 数组 → 跳过该 key（不递归展平），未匹配项计入通知。
- CSV 值含逗号 → 引号包裹（RFC 4180 最小兼容）。
- key=value 无 `=` 的行 → 丢弃。
- 空文本 / 解析失败 → 返回空 map，UI 提示「未识别到有效参数」。

### 3.2 ParamHistoryCache（纯逻辑，可独立单测）

新增 `src/main/kotlin/cn/song/mybatisplus/visualizer/ui/ParamHistoryCache.kt`：

```kotlin
class ParamHistoryCache(private val maxSize: Int = MAX_HISTORY_SIZE) {

    private val cache = LinkedHashMap<String, Map<String, String>>(maxSize + 1, 0.75f, true) // accessOrder = true (LRU)

    fun computeKey(tableName: String?, rawSql: String): String
    fun save(key: String, params: Map<String, String>)
    fun recall(key: String): Map<String, String>?
    fun clear()

    companion object {
        const val MAX_HISTORY_SIZE = 50
        fun fingerprint(sql: String): String  // SHA-256 前 16 hex
    }
}
```

**持久化策略**：
- 内存缓存（LRU LinkedHashMap）供运行时快速读写。
- 持久化到 `PluginSettings.State.paramHistoryJson`（JSON 字符串），IDE 重启后恢复。
- 序列化/反序列化用 `kotlinx.serialization` 或自研最小 JSON（避免引入新依赖）。
- 写回时机：debounce 500ms（避免每次击键都序列化）。

### 4.3 历史召回提示

- 召回成功：参数面板顶部短暂显示淡入提示（`BalloonBuilder` 或 `StatusWidget`）"已恢复上次参数（N 项）"。
- 用户手动覆盖后：不提示（以用户输入为准）。

## 5. 边界与已知限制

- JSON 解析仅支持扁平 object（嵌套不展平），复杂结构建议用 CSV 或 key=value。
- CSV 仅支持单行值（多行值场景用 JSON）。
- 历史缓存不跨项目共享（project 级隔离）。
- 缓存键依赖 `tableName`，无表名（纯文本预览）不缓存。
- XML 预览的 `foreach` 集合值不参与历史召回（动态键不稳定）。
- 批量列级勾选（INSERT/UPDATE/UPSERT）的参数不参与历史召回（列名动态）。
