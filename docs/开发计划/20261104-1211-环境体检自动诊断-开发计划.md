# 环境体检自动诊断（档 1 三段式 + 档 2 日志匹配）开发计划

- 立项：2026-11-04 12:11
- 前置：`dev@4ef92d3c`（含 UI-001/002/003/004/005 五处真机缺陷修复）
- 关联验收文档：`docs/验收文档/20261104-0410-dev-vs-master-262沙盒增量功能验收-验收文档.md`
- 需求来源：用户真机反馈「既然都有体检了能不能自动诊断推断问题原因和解决方法？」

## 一、现状

体检（NEW-18）已有：五项采集（数据源 / 方言 / 增强捕获 / 捕获覆盖 / Community 可用性）、`OK/WARN/FAIL/UNAVAILABLE` 四级、每项 `facts` 事实行 + 非绿灯 `guidance` 修复指引、UI-005 后带 `elapsedMs` / `CheckOutcome` / 总耗时。

缺口：`facts` 是**事实罗列**，`guidance` 是**泛泛建议**（「请连接数据源」）。用户看到数字，仍要自己判断「这会导致什么、为什么、下一步点什么」。

另一处更值钱的信息完全没进体检：**用户撞到的异常就在 `idea.log` 里**，但体检不读。本轮五个真机缺陷中，UI-001（`Slow operations are prohibited on EDT`）与 UI-002（`Read access is allowed from inside read-action only`）都有明确日志特征，本可被自动识别。

## 二、目标

### 档 1：把体检项从「事实 + 泛指引」升级为「症状 → 原因 → 动作」

不新增采集，只把已有结论讲成人话。例：

| 现状 | 目标 |
|---|---|
| 事实：`数据源 7 个，已连接 2 个，已内省 1 个`<br>指引：`请连接并使用数据源` | 症状：`预览打开可能需要选源，执行会报「未绑定数据源」`<br>原因：`有数据源但当前模块未建立绑定，且无上次使用记录`<br>动作：`在预览面板点一次「执行 SQL」并选择数据源，之后会自动记住` |

### 档 2：新增「近期日志诊断」采集项

读 `idea.log` 尾部固定窗口，按**模式表**匹配，输出：

- 命中的已知缺陷（带编号与修复版本）
- 命中的通用异常类别（驱动缺失 / PSI 失效 / 临时文件建链失败 / 表解析失败 …）

未命中时给 OK 态并说明扫描范围（「尾部 256 KB 内未发现已知异常模式」），不冒充「一切正常」。

## 三、设计

### 3.1 数据结构（`diagnostic/EnvironmentCheckReport.kt`）

`EnvironmentCheckItem` 增加两个可选段，**保留 `guidance` 作为「动作」**（避免改 5 个既有规则的全部构造点与既有测试）：

```kotlin
val symptom: String? = null,   // 会导致什么（用户视角的症状）
val cause: String? = null,     // 推断出的原因（不是复述事实）
// guidance 语义收窄为「动作」：改注释，不改字段名
```

渲染：非绿灯项按 `症状 / 原因 / 动作` 三行输出，缺哪段跳过（不打印空标签）。绿灯项维持现状（只有 facts）。

### 3.2 模式表（新增 `diagnostic/KnownIssueCatalog.kt`）

```kotlin
internal data class KnownIssueRule(
    val id: String,              // 短 id：ui-001 / driver-missing ...
    val titleKey: String,        // 结论文案 bundle key
    val actionKey: String,       // 动作文案 bundle key
    val allOf: List<String>,     // 必须同时出现的子串（AND）
    val anyOf: List<String> = emptyList(),  // 至少命中一个（OR，可为空）
    val severity: CheckLevel,    // 命中后该条结论的等级
    val fixedIn: String? = null, // 已修复版本（null＝仍在册）
)
```

第一批规则（全部来自真机实证）：

| id | 特征 | 结论 |
|---|---|---|
| `ui-001` | `Slow operations are prohibited on EDT` AND `ScanBannedApiUsages` | 已知缺陷 UI-001（存量扫描 EDT 慢操作），已修复 |
| `ui-002` | `Read access is allowed from inside read-action only` AND `consumeCachedTempPsiFile` | 已知缺陷 UI-002（池线程读 PSI 无读锁），已修复 |
| `driver-missing` | ANY(`NoClassDefFoundError`, `ClassNotFoundException`) AND ANY(`com.mysql`, `org.postgresql`, `com.microsoft.sqlserver`, `oracle.jdbc`, `dm.jdbc`) | 数据库驱动缺失或未下载 |
| `psi-invalid` | `PsiInvalidElementAccessException` | PSI 失效（临时文件被覆盖/重解析） |
| `exec-temp-fail` | `Failed to create temporary SQL file` | 执行临时文件建链失败 |
| `table-unresolved` | `Unable to resolve table` | 表无法解析（数据源未内省或表名/映射不符） |
| `platform-component` | `Cannot init component state` | 平台自身组件初始化异常（非插件问题，可忽略但要留痕） |

判定：`allOf` 全命中 且（`anyOf` 为空 或 至少一项命中）。**大小写不敏感**、按子串匹配（不用正则，避免用户日志里的特殊字符炸回溯）。

### 3.3 日志读取（新增 `diagnostic/IdeaLogTails.kt`）

- 路径：`PathManager.getLogPath()` + `/idea.log`；文件不存在 → 该项降级为 `UNAVAILABLE` 并说明。
- 只读**尾部 256 KB**（常量，可配）：`RandomAccessFile.seek(length - N)`，跳过可能被截断的首行（读到第一个 `\n` 之后才开始）。
- 只读当前文件，不读 `idea.log.1` 等轮转文件（避免跨会话噪声）。
- 编码 UTF-8。
- 每行只保留**匹配判定需要的部分**，原始行不写入报告。

### 3.4 新增采集项 `logDiagnosisItem`

- 走 `EnvironmentCheckBounded` 有界内核（单项预算共享，超时降级）。
- 命中条数上限 5（按 `KnownIssueRule` 去重，同一规则只报一次 + 出现次数）。
- 等级：命中 `severity` 最高者；未命中 `OK`。
- 事实行：每条 `[id] 结论文案（出现 N 次）`；动作行：对应 `actionKey`。

### 3.5 隐私边界（硬约束）

体检报告会被用户贴到工单/issue，**不得携带日志原文**：只输出规则 id、结论文案、命中次数。绝不把用户 SQL、连接串、文件路径写进报告。此点须有测试钉住（断言渲染结果不含日志原文片段）。

### 6.4 与计划的偏差

1. **数据源「有源但无绑定且无上次使用」仍是绿灯**。计划 §二 参考文案说的是这个态，但代码里
   `count > 0` 即 OK；把它升级成 WARN 会让「刚配好数据源、还没执行过」的用户每次体检见黄，
   且会翻转既有 `test总评取最严重项` 的期望（`WARN` 严重度 2 高于 `UNAVAILABLE` 1，总评会变）。
   按「与代码冲突以代码为准」，症状/原因落在两条真正非绿灯的分支（无 Database 插件 / 零数据源）。
2. **`KnownIssueRule` 多一个字段 `eachOfAny`**（组间 AND、组内 OR）。计划的 `allOf + anyOf` 表达不了
   `driver-missing` 的「ANY(异常类名) AND ANY(驱动包)」：两组都是选择题，且不能退化成「任意一组命中」——
   实测那样会把 `Loading class \`com.mysql.cj.jdbc.Driver'. This is deprecated` 这类正常日志判成驱动缺失。
3. **驱动包名收点号与斜杠两种写法**（`com.mysql` 与 `com/mysql` …）。`NoClassDefFoundError` 打印的是内部名
   `com/mysql/...`，首版只写点号时该用例直接红——真机形态比计划表里的五个点号包名更宽。
4. **`fixedIn` 全部为 null**。UI-001/UI-002 的修复只在 dev（CHANGELOG 仍在 Unreleased），没有已发行版本可填；
   结论文案里写明「dev 已修，尚未发行」，不用假版本号。
5. **渲染对绿灯项连 guidance 一并抑制**（不止症状/原因），严格对齐「绿灯项只有 facts」。
   既有 `test渲染逐项标注等级` 的标签断言由「修复指引：」改为「动作：」——只改标签，判定口径未动。
6. 日志项命中时 facts **只列命中条**，未命中才写「尾部 N KB + 规则 N 条」；命中时扫描范围由隐私收益让位。
7. **超长单行（整窗无换行）从窗口开头解码**，保留半行而不返回空——计划 §五 只要求「不抛异常」，
   这里选了「宁可保留半行也不空手而归」。多字节截断的半行另有专门用例钉住（断言无 U+FFFD）。
