## 一、需求与交互

在 SQL 日志工具栏增加「加入交流群」动作，位置固定为**排序按钮右侧、帮助按钮左侧**。点击后打开一个可关闭的弹框，按文档站「微信交流」区域呈现两块内容：左侧「作者微信」，右侧「交流群」。每块展示二维码、标题及说明。首次打开不自动跳浏览器，也不改变日志捕获、排序、搜索、预览或帮助的状态。

中文内容与文档站保持一致：

| 卡片 | 二维码 | 标题 | 说明 |
|---|---|---|---|
| 左 | `/wechat-qr.png` | 作者微信 | 扫码添加作者为朋友，欢迎交流插件使用与开发话题；加好友时请备注「SQL Visualizer」。 |
| 右 | `/group-qr.png` | 交流群 | 扫码加入 SQL Visualizer 交流群；群码失效时可添加作者微信。 |

弹框采用 IDE 原生模态对话框与主题色，不把网页 CSS/JCEF 页面直接嵌入运行时；尽量保持截图中「两张并排、二维码居中、标题在下、说明可换行」的层次。工具栏为图标动作时，`AnAction.text` 不等于屏幕上常显文字，须有明确的「加入交流群」悬停提示和无障碍名称；按钮图标以本地平台制品中确实存在的图标为准，不凭猜测写 API。窄屏弹框允许两卡纵排或在内容区滚动，不能裁掉二维码和失效提示。

## 三、实施方案

1. **工具栏接线**：定义单一「加入交流群」动作，放在 `sortModeAction` 和 `HelpAction()` 中间。动作仅负责创建/显示弹框，不持有网络任务或永久图像缓存；项目/面板销毁时不能留下异步 UI 回调。既有操作在前、信息类动作收尾及平台溢出行为不变。
2. **弹框布局**：用平台对话框组件创建两块等宽卡片，二维码约 180px、标题和可换行说明居中，留足白边与两卡间距；优先组件布局而非 HTML 图片标签，避免默认主题下出现白块、暗色主题文字不可读。窗口尺寸受屏幕可用区域约束，支持键盘关闭、标准焦点顺序和屏幕阅读器可识别的图片说明。中文采用上表原文；英文文案在 bundle 中单独给出自然译文，不复用官网英文关于页当前「去 README 找最新码」的不同失效建议，除非实施前产品文案已统一。
3. **二维码来源和加载**：以文档站同源 HTTPS 资源 `https://sql-visualizer.jvtools.cn/wechat-qr.png`、`https://sql-visualizer.jvtools.cn/group-qr.png` 为首选，而不是将当前限时码固化进插件版本；仅在用户点击后加载，禁止 EDT 同步网络访问。限制超时、下载大小与可解码图片尺寸，失败时两卡分别给出清晰的不可用状态，并提供「打开官网交流页」的显式入口供用户手动查看最新内容；不要悄悄退回可能过期的仓内二维码，也不要把过期码展示成“当前可入群”。图片加载和 UI 更新服从弹框生命周期，离线环境可正常关闭。打开官网须用户主动点击，不随弹框打开自动访问关于页。
4. **文案与资源**：新增标题、动作提示、图片替代文字、加载中/失败/打开官网等中英文键；保证两份 bundle 键一致。二维码地址与官网关于页地址集中定义，避免文案、plugin.xml 与运行时入口手写多份后无声漂移；官网资源更新后无需发插件新版即可展示新图。

### Cool Request 参考实现与取舍（2026-10-15 补充）

用户给出 `F:/code/Java/Github/other/houxinlin/coolrequest-vip` 的工具栏与弹框截图，作为交互参考。源码核对：`src/main/java/dev/coolrequest/view/component/CoolRequestView.java:129-141` 把 `ContactAnAction` 放进工具栏；`src/main/java/dev/coolrequest/action/actions/ContactAnAction.java:37-44` 使用聊天图标，点击直接显示 `ContactDialog`；`src/main/java/dev/coolrequest/view/dialog/ContactDialog.java:34-76` 以 `DialogWrapper + JBTabs` 呈现 WeChat/公众号/QQ 三个渠道，一次显示一张约 300×300 的码。

- **吸收**：入口用能看出“交流”的三点对话气泡语义，而不是单人头像或网页图标；点击即到原生弹框；图片居中、有边距、可直接扫码，不把入群动作隐藏在帮助文档里。将原计划“图标待定”收敛为**三点对话气泡方向**，图标旁排序、帮助的固定顺序仍以本插件工具栏为准。
- **不照搬**：本需求指定的两块内容是官网「作者微信」「交流群」卡片，默认同时展示标题和说明；不新增公众号/QQ，也不把两卡强制改成一次只能看一张的页签。两卡在窄窗口可纵排，不能因为参考实现采用 400×400 页签就牺牲原需求。
- **许可边界与图标定向**：参考仓根目录 `LICENSE` 是 GPL v2 文本，而 `src/main/resources/icons/svg/chat.svg` 与 `icons/idea/icons/svg/chat.svg` 文件头明确标注 GPL-3.0+；本仓 `LICENSE` 为 Apache-2.0。**不得复制、改色或描摹其 SVG 路径，不得移植其 Java/Swing 实现代码及二维码图片**。用户明确选择参考“三点对话气泡”的语义，由本插件独立绘制 `src/main/resources/icons/communityChat.svg` 与 `communityChat_dark.svg`：16×16、左下小尾巴、绿色轮廓 `#4FB477`、紫色三点 `#B48EFF`，按用户后续意见取消气泡内部底色，亮暗主题均为透明背景、仅保留轮廓和三点；路径坐标独立设计，不取参考仓 SVG 路径。已画好资源，但**尚未接入工具栏**；实施时用真机检验亮暗主题、16px 清晰度及与现有排序/帮助按钮的视觉节奏，必要时微调自有图形。

## 四、待验证前提与风险

1. 打开 `https://sql-visualizer.jvtools.cn/{wechat-qr,group-qr}.png` 时实际是否能匿名获取图片、是否有重定向或缓存，必须在实施前用真实请求核实；源码中的引用不等于线上可达，更不等于二维码此刻仍可扫码入群。二维码有效性要在发布/真机验收时用真实扫码确认，失效则由站点维护者更新源图。
2. 核实 243/253/262 平台中选定图标、异步下载与对话框生命周期 API 的真实签名；需要平台 API 时先查本地 jar/源码，不假定新版本方法在 243 可用。
3. 对话框在窄侧栏、小屏、125%/150% 缩放、Light/Dark 下能否保持两卡和说明完整；如果横排放不下，优先纵排，不要求与网页逐像素相同。
4. 官网中文与英文失效文案目前不同；本计划按用户截图与中文官网的「群码失效时添加作者微信」落地，实施前若官网文案已变更，先核对产品文案再改，不把本计划旧文本当绝对真相。
5. 从插件请求官网图片会发生外网访问；入口由用户主动点击触发，应避免页面加载/捕获日志时预取，失败不影响本地 SQL 功能，也不记录二维码 URL 中的额外用户数据。

## 五、测试与验收

- **先测再接线**：扩展 `SqlLogPanelLayoutTest`，实测真实 `toolbarGroup` 中恰有一个入群动作且排序 < 入群 < 帮助；临时去掉或换位动作时测试应变红，不能仅凭图标/源码字符串空绿。复核窄宽平台溢出及 Help 末位语义。
- **弹框定向测试**：验证点击动作可打开弹框、两卡顺序/标题/中英文说明、图片大小和失效引导；用本地受控图片响应验证成功、HTTP 失败、超时、损坏/超限图片、关窗后晚到结果，不让测试依赖真实官网或 EDT 网络。至少做一次反向验证：删掉排序与帮助间的新动作或交换两卡，期望对应测试变红。
- **既有回归**：跑 `SqlLogPanelLayoutTest`、`SqlLogPanelSortAndSlowQueryTest`、`HelpUiTest`、`HelpDialogTest`、`BundleParityGuardTest` 及新增弹框测试；执行任何 Gradle 前先按并行登记表 `check`，子任务只跑定向类。全部实施完成后由只读收口代理单次 `testShards --no-configuration-cache`；若仅新增一般 Swing UI，不因本计划单独启动发布构建校验。
- **真机验收**：243/262 及当前 IDE，在 SQL 日志栏确认按钮位于排序和帮助之间；宽、窄工具窗均可点到（包括平台 `»`）；打开后两码可扫码、文本与官网一致、主题/缩放无裁切；断网时有失败提示且可关闭，重新打开后恢复；排序、帮助与日志捕获照常工作。未扫码确认时只能记“图片显示正常”，不能记“群可加入”。
