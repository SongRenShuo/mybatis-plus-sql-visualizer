## 解决方案体系

### 策略一：测试缝（Test Seam）模式

**目标**：将 EDT/UI 回调中的业务逻辑抽离为可测方法。

**已验证的先例**：
- `pickForTest()` — 绕过 ChooseByNamePopup 直调 `setPicked`
- `callerModelForTest()` — 绕过 ChooseByNamePopup 委托模型

**适用范围**：所有 UI 回调中的 PSI 属性读取和业务逻辑。

### 策略二：契约测试（Contract Test）

**目标**：验证组件接口的输入输出契约，确保接缝处不丢信息。

**核心原则**：断言 = 下游组件的所有 `result.xxx` 读取点。

### 策略三：端到端集成测试

**目标**：覆盖完整链路 PSI → 定位 → 转换 → SQL 生成 → 参数回填。

**T0031 已实施 JPA 链路**，本计划扩展到其他链路。

### 策略四：行为测试（Behavior Test）

**目标**：测试用户可见的行为结果，而非内部实现。

**适用**：弹窗显示/隐藏、参数输入后 SQL 更新、警告信息显示。

### 策略五：沙盒验证清单

**目标**：对永远无法 unit test 的代码，建立沙盒/真机验证清单。

**原则**：每次改动相关代码后，必须在沙盒中验证特定行为。
