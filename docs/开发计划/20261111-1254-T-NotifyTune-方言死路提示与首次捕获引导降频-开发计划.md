## 一、竞品做法（券 A 的对照）

MyBatisCodeHelper-Pro 在打开 MyBatis 文件、其 SQL 方言未配置时弹一条气球：标题「Mybatis文件的sql方言未配置」、
正文「方言未配置，格式化和代码补全会出现问题，请参考网址 here 配置下」，两个动作「配置」「当前项目不再提示」。

它成立的四点：

1. **主动**：不等用户去翻设置，在「用得上」的时机出现；
2. **说后果**：不是「请配置」，而是「不配置会出什么问题」；
3. **一键到修**：动作直跳配置面，不是只丢一个网址；
4. **尊重用户**：「当前项目不再提示」把续扰权交回用户。

它的前提与本插件**不同**：MCBHP 的方言是**必须显式配置**的；本插件默认是**智能推断**
（`PluginSettings.dialectAuto=true`），多数项目零配置即可。故只抄**形态**，不抄「必须配置」的语义。

## 三、吸取的精华（取舍）

**要吸取（形态）**：用得上时主动告知；说后果而非下命令；「一键到修」直跳目标；「本项目不再提示」永久抑制。

**不吸取（语义/频次）**：

- 不把方言变成必须配置项——推断优先，提示只在**推断走到死路**（`Status.UNAVAILABLE` 且无方言名）时出；
- 不阻断任何功能（预览/高亮/执行照常按兜底跑）；
- 不新增通知组（复用 `preview` 组，`plugin.xml:365`）、不新增模态弹窗；
- 不做「每次会话都提醒」的引导——两个券都收敛到「一次为限」。

## 四、券 A：SQL 方言死路主动提示

### 4.1 触发链（廉价优先，热路径零涉足）

新增 `onboarding/DialectGapTip.kt`（`ProjectActivity`，与 `OnboardingAnchorTip` 同形）订阅
`FileEditorManagerListener.fileOpened`（`onboarding/OnboardingAnchorTip.kt:46-53`），`plugin.xml` 追加一个
`postStartupActivity`（仿 `plugin.xml:400`）。`onFileOpened` 逐层早退：

1. 开关 `dialectTipEnabled` 开；
2. 本项目未被永久抑制；
3. **每安装一次**（持久化，见 §4.4）——不再是每会话；
4. 首用锚点引导让位——`onboardingAnchorTipShown==true`（新用户先看「预览怎么用」，不叠第二条）；
5. 文件是「SQL 承载文件」（见 §4.5）；
6. 后台线程在 ReadAction 内算 `DialectRegistry.decision(project, file, ...)`，**仅当 `status == UNAVAILABLE && dialectName == null`**
   才领取展示权并弹通知（`runCatching` 包住，异常静默；`isUnitTestMode` 跳过 notify、持久化照常）。

### 4.2 呈现（标题与插件能力面对齐）

插件支持 MyBatis / MyBatis-Plus / MPJ / iBatis 2.x / MBG Example / JPA-HQL（Pages）/ JdbcTemplate / 通用 XML 内联 SQL，
标题**不能带 MyBatis**：

- 标题：`SQL 方言未能确定`（en: `SQL dialect could not be determined`）
- 正文：`智能推断未能确定此处 SQL 的方言，预览渲染与执行路由暂按 MySQL 兜底；遇 Oracle / PostgreSQL / SQL Server 等会有差异。`
- 动作：`去设置方言` → §4.3；`本项目不再提示` → §4.4

### 4.3 「去设置方言」定位链（复用，勿重造）

`PluginSettingsFolderConfigurable` 现仅有 log 专用入口 `openSqlLogSettingsFocused`（`config/PluginSettingsFolderConfigurable.kt:490`）
与内部测试缝 `requestFocusOnOpenForTest`（`:503`）。新增**通用**入口 `openSettingsFocused(project, pageId, hint)`，
把 `openSqlLogSettingsFocused` 收成它的一层薄封装；方言行所在页 = `ID_PREVIEW`（`:470`；`SubPageRef(ID_PREVIEW, SqlPreviewConfigurable)` `:517`），
hint = `MpSqlVisualizerBundle.message("settings.dialect")`（该行取值键，`config/PluginSettingsPanelSections.kt:177`）——
定位+高亮复用既有 `navigateToPage → focusTarget`（滚动+黄闪+橙框，`:186`），零新样式。

### 4.4 抑制存储（`PluginSettings.State`，`config/PluginSettings.kt`）

- `var dialectTipEnabled: Boolean = true`（全局开关，默认开）；
- `var dialectTipSuppressedProjects: MutableList<String> = mutableListOf()`（本项目不再提示，按项目路径哈希）；
- `var dialectTipShown: Boolean = false`（**每安装一次性**，对齐 `onboardingAnchorTipShown` `PluginSettings.kt:719` 的既有约定）。

### 4.5 「SQL 承载文件」识别面（不止 MyBatis）

`OnboardingAnchorTip.anchorHintHit` 现有启发表（`OnboardingAnchorTip.kt:157`）是 MyBatis/iBatis 口径：
Java/Kotlin 侧是 `QueryWrapper`/`UpdateWrapper`/`JoinWrapper`/`MPJLambdaWrapper`/`Wrappers.`/`@Select|@Insert|@Update|@Delete`，
XML 侧是 `<select|<insert|<update|<delete|<hibernate-mapping|<sql-query`。缺本插件已支持的另外几族：

- JdbcTemplate：`JdbcTemplate`、`jdbcTemplate.`、`queryForList(`、`queryForObject(`、`queryForMap(`；
- JPA / HQL：`@Query`、`@NativeQuery`（`<sql-query>` 已在表内）；
- iBatis：`<sqlMap`（`<select` 等已覆盖其语句标签）。

新增一份本券专用的判定函数（纯函数、测试缝），先用文本启发式早退，命中再进后台决策；**不把 `anchorHintHit` 直接改成超集**
（那是首用引导的语义，改动会连带影响其误报面）。

## 五、券 B：首次捕获引导降频

### 5.1 降频方案

- **B1 持久化一次性**：新增 `PluginSettings.State.firstCaptureGuideShown: Boolean = false`（application 级），
  展示即置 true，跨会话/跨项目不再出现（对齐 `onboardingAnchorTipShown` 的既有约定）；companion 记忆保留为热路径短路。
- **B2 不与自动展开叠加**：把 `maybeAutoShow()` 改为返回「本次是否真的展开了窗口」（现无返回值；`shouldAutoShow` 纯函数不动），
  同一回调里若已展开，跳过气球——窗口本身已是「发现」，而气球文案「已收录到 SQL 日志工具窗」在窗已开时是废话。
- **B3 窗口已可见即跳过**：`ToolWindowManager.getToolWindow(TOOL_WINDOW_ID)?.isVisible == true` 时不再弹。
- **B4 补开关**：`firstCaptureGuideEnabled: Boolean = true`，设置页界面节与 `settings.onboardingAnchorTip`（bundle 681/655）同区；
  关闭后全程静默。补上红线准入五问的第 3 问。

结果：默认用户在装好后的第一次捕获至多看到一次（自动展开已生效时连这一次也省），之后永不重复。

### 5.2 不改什么

- 不改 `logAutoOpenOnCapture` 的自动展开语义与 60s 防抖；
- 不改 `T-AutoShowSuppress`（用户手动关窗后本会话抑制）；
- 不删气球——保留为「未自动开窗」时的兜底。

## 七、决策点（给用户拍板；未拍板按「推荐」实施）

- **D-1 触发状态口径（券 A）**：仅 `UNAVAILABLE`（**推荐**，推断真死路）｜或含 `AMBIGUOUS/CONFLICT`（更啰嗦，且二者已有面板内处理）。
- **D-2「配置」目标（券 A）**：跳插件方言行 `ID_PREVIEW`（**推荐**，插件自己的模型，auto/手动都在此）｜或跳平台 `SQL Dialects`
  （`ShowSettingsUtilImpl.showSettingsDialog(project, "SQL Dialects", null)`，`T-DialectGateUx` 已用）｜或两动作并列。
- **D-3 抑制粒度（券 A）**：本项目永久 + 每安装一次性（**推荐**，照抄竞品语义）｜仅每安装一次性。
- **D-4 与首用引导的关系（券 A）**：方言提示让位于 `OnboardingAnchorTip`（**推荐**，避免一次开文件弹两条）｜并列。
- **D-5 一次性粒度（券 B）**：每安装永久（**推荐**）｜每项目｜维持每会话（现状）。
- **D-6 与自动展开的关系（券 B）**：auto-open 生效时跳过气球（**推荐**，气球退化为「未自动开窗」时的兜底）｜两者都保留。
- **D-7 开关默认值（券 A/B）**：默认开 + 一次性（**推荐**）｜默认关。

## 八、待验证前提（实施者先证伪再动手）

- **P-1**：`FileEditorManagerListener.fileOpened` 回调里调 `DialectRegistry.decision` 的成本——决策链含
  `DataSourceUrlProbe.candidateDialects`（有 TTL 缓存）与模块解析；须实测「后台线程 + 每文件至多一次」不引入可感卡顿；
  若重，改成「预览/设置被打开时」触发或加结果缓存。
- **P-2**：通知动作在 headless / 无项目时不得抛（`isUnitTestMode` 跳过 notify、持久化照常，仿既有守卫）。
- **P-3**：hint 文本必须随语言取同一 bundle 键（`settings.dialect`），否则英文环境「跳了但不亮」——`T-SettingsFocusFromLink` P2 同坑。
- **P-4**：`dialectTipSuppressedProjects` 用项目路径哈希，须避免同机同名项目误抑制；`@State` 反序列化缺字段默认空表（`MutableList` 须给可变实例，防 XmlSerializer 给 null）。
- **P-5**：`@State` 新增五个字段的老配置反序列化默认值（缺字段=默认值；布尔默认值与出厂语义一致）。
- **P-6**：「自动展开是否真的生效」的取数口径——`maybeAutoShow` 现靠 `onAutoShowRequest()` 无回执，改为返回值或用
  `toolWindow.isVisible` 事后判；两者在「已计划但未布局」窗口下可能不一致，实施时统一为一个判据并登记读数。
