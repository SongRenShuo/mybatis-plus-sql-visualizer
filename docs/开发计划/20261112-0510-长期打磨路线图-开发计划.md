## 〇、总原则（承调研报告结论）

1. **先交付，后新增**：当前 30+ 件已完成的用户可感增量压在发行链之外（dev F 队列 15 项 + 三支收口车道），任何新功能排期都排在「把已做好的发出去」之后。
2. **护城河排序**：静态预览正确性 > 运行期捕获可靠性 > 信创/国产库面 > iBatis 独占 > MCP 深度 > EXPLAIN 解读层（最后一个是唯一还没占住的，且窗口在关小）。
3. **红线维持**：不做付费订阅、纯格式化器、MCP 工具数竞赛、数据库管理工具化、独立桌面应用化；无用户请求不扩方言。
4. **每项验收必带**：定向测试以判据数收读数（S3）、反向验证成对（S2）、UI 面声明「全量未跑＝not run」（L13）、发行前置门禁绿而非 buildPlugin 成功（L28）。
5. **用户专属动作单列**：update.json 补账（D211）、W1 发射（D200）、合流授权（D212/B 表）、凭据豁免定案——助手侧只准备材料。

## 三、长期（2027 Q1 之后，方向性）

> 主题一句话：**从「工具」走向「SQL 调试平台」——AI 原生、洞察驱动、生态解耦**。本档只立方向不排期，每条启动前单独立项。

1. **MCP/AI 环深化（创新引领候选）**：从「11 个工具」走向「有结论的核查」——`sqlv_check_sql`/`sqlv_perf_advice` 返回体附可解释结论链（哪条规则、什么证据、置信度），让 AI 客户端能引用而不是复述；评估 Agent Skills 形态（仓库已有 acp/MCP 经验：`docs/调研报告/20260914-0317-IDEA-ACP与平台AI原生能力-调研报告.md`）。风险：工具数竞赛是红线，深化的是**结论质量**不是数量。
2. **SQL 洞察平台化**：关系流向（t-sql-insight 二期）→ 跨语句执行序列视图（一次请求的 SQL 链路+N+1 可视化）→ 与调用栈时间线融合。这是唯一可能形成「数据资产」的环（历史已全量落盘），也是竞品结构性做不了的（无捕获环）。
3. **信创叙事产品化**：25 方言 + BannedApi 体检 + 真机验证矩阵打包成「信创开发模式」（文档页+设置场景组），面向政企用户的官网专页；按用户需求继续扩方言（红线：无请求不扩）。
4. **宿主能力 EP 化 + 上游版本监听**（F-11 合流后深化）：为未来「多 IDE（WebStorm/Android Studio）或拆分子插件」留架构余地；上游 MyBatis 版本变更监听提示兼容性。
5. **Kotlin→Java 的终局**：若 2.2 裁决继续跟版，长期考虑按「功能冻结域」缩小同步面（docs/CI 不再翻译，只同步 src 生产码），把每轮成本压到常数。
