## 三、券详单

### T-PerfSweep29-01（R29-1）：RailCellRendererBase 多行模式取源惰性化

- **现状**：`sqlLineFragmentsFor` 在缓存检查之前无条件执行 `withTerminator(displaySqlForList(entry, mode, maskOn))`（RailCellRendererBase.kt:295）。多行模式（KEYWORD_WRAP/FORMATTED）缓存命中时该值不被使用；脱敏开启时 displaySqlForList 内部走 `DisplayMasker.maskDisplay(entry.restoredSql, masked)`（SqlListFragmentRenderer.kt:63）全量词法打码，O(SQL 长)——即脱敏开＋多行模式下每次重绘×每个可见格（约 10~30）付一次打码后丢弃。该取源扩面是 T-LogListAnchor 券01 的有意行为（KEYWORD_WRAP 取完整 SQL），本券只修成本位置、不动语义。
- **修法**：把 `val sql = withTerminator(displaySqlForList(entry, mode, maskOn))` 拆两处——SINGLE_LINE 分支内现算（语义不变）；多行分支只在缓存未命中时计算（作为 semanticLineFragments 的入参），命中路径零取源调用。P-1 通过后实施；withTerminator 与打码的先后顺序保持逐字不变。
- **先红后绿判据**：①新用例「多行模式＋脱敏开，同条目连续两次渲染，断言取源调用计数缝=1」——修复前=2，先红（贴两次读数）；②反向=还原取源位置 → 用例①回红；③渲染输出逐字一致：KEYWORD_WRAP/FORMATTED/SINGLE_LINE 三模式×脱敏开/关夹具与现 HEAD 全部一致，SqlListFragmentRendererTest、LogEntryRailPerfTest（17 例）、SqlLogPanelRendererUiTest、HistoryCellRendererTest 全绿；④脱敏开关运行期切换后首帧重算（P-3 夹具）。
- **风险与交互**：T-LogListAnchor 券01 的换行语义（完整 SQL＋4096 预算）逐字保留；RailCellRendererBase 为两页渲染器（日志页 LogEntryListCellRenderer 与历史页 HistoryCellRenderer）共同基类，两页均须在夹具覆盖内；改动不触碰条目级缓存字段本体（LogSqlModels.kt:239-248），T-PerfSweep27 券01 的头部行缓存判据不涉。
