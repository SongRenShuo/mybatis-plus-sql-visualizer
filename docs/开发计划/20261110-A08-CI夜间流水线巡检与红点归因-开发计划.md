## 五、实施记录（本分支）

### 5.1 改了什么

只改 `.github/workflows/nightly-full.yml` 的 `dialect` job，两处、纯 CI 配置层：

1. 在「真机方言验证」之后补一步 `失败诊断输出（断言消息与 summary 打到任务日志）`（`if: failure()`）：从 `build/test-results/**/TEST-*.xml` 读 `<failure|error message="...">` 并 `HtmlDecode` 打进日志（与 `fast`/`tests`/`extras`/`build-plugin` 腿同一口径），再补读 `build/reports/dialectExternalVerify/summary.md` 的四桶明细。summary 在断言前已落盘，失败时必有内容。
2. 「上传方言验证摘要」的 `if` 从 `steps.matrix.outputs.ready == 'true'`（隐含 `success()`）改为 `${{ !cancelled() && steps.matrix.outputs.ready == 'true' }}`，让成功与失败都上传，取消运行不传。

`src/main` 零改动；没有新增 gradle 任务、没有碰 secret、没有触发任何对外动作。

### 5.2 为什么只修这一层

- e2e 的根因在 `MPV_DB_*` secret 指向的实例不可达，属配置面，改 workflow 逻辑去「容忍」等于把环境红伪装成绿，不做。
- dialect 的根因在外部实例，本任务拿不到具体 key/异常（且无权处置实例）；但「红得不可归因」是**仓内自己的诊断缺口**，能安全复现、能自证，属于 A-08 册「可本地复现的」那一档，修它正好让下一次夜间红直接可读。
- 这层修复不改变任何测试的通过/失败判定，只增加失败时的可观测性，因此不需要全量门禁；按纪律只做定向自测 + 反向验证。
