## 〇 执行红线（闲时任务必须遵守）

1. **禁止一切合流**：insight→dev、master→dev、dev→master、k2j 同步、分支合并，全部停等用户主动点名（本册 B 表）。遇到任务需要合流才能验收时，交付到「补丁 + 自测读数 + 合并方案」，不得动树合并。
2. **禁止推送与发布**：不 push 任何远端、不建 tag、不发行、不传 Marketplace、不发对外内容（公众号/群/评论/issue）。推送与发行均属外发动作，须用户令。
3. **禁止改 `update/update.json`**：该文件只有用户能改（现行定例）。
4. **禁止 GUI/桌面自动化**：不启动 runIde 沙盒、不做桌面点击录屏（同一时刻只允许一个 GUI 操作者）；凡验收依赖真机/GUI 的任务，只产出「步骤 + 判据 + 期望读数」，交用户执行。
5. **代码类改动一律落独立分支**：新建 `t-idle-<任务>` 分支（独立工作树）实施，自测通过后提交在分支上，**不合并、不推送**；文档类可直接提交 master（不推送）。
6. **构建纪律**：跑任何 gradle 前先 `python C:\Users\USER\.zcode\cli\parallel_tasks.py check` 并登记；构建并发 ≤2 路；全量 `testShards` 单路收口（`-PtestShardMaxLane=5` 自适应限流，禁降片）；不 `clean`、不 `--stop`；长命令后台跑、不 sleep 轮询。
7. **提交纪律**：中文提交信息；含反引号的内容写文件后 `git commit -F`（Git Bash 反引号陷阱）；每件完成即提交，不攒批。
8. **停手上报**：遇到需要用户决策（表 B）、环境不具备、或读数与文档前提冲突，登记「待用户」并跳过，不自行改设计。
