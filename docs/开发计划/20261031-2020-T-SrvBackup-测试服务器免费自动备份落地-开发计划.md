## §一 需用户拍板的三项（其余可自行推进）

### 1. BK-01 存储后端选七牛 Kodo（P0，用户裁量）

- **推荐：七牛云 Kodo 标准存储，单空间，华东-浙江2（0.115 元/GB/月，最便宜档）**。
- 备选：腾讯 COS（50GB×180 天，容量宽松、对象锁最全，但半年后按量）；B2/R2（egress 免费，但跨境恢复慢）。
- 理由见调研报告 §2.1：唯一同时满足「无到期日的免费额度 + 境内恢复速度 + 个人实名可开 + S3 兼容」。
- 需用户做的：注册并实名 → 建空间（私有）→ 建 AK（见 BK-02）。
- 判据 V-B1：空间可写，`restic init` 成功。

### 2. BK-02 密钥权限模型（P0，安全红线，需用户确认取舍）

- **推荐：单一 AK，bucket 级读写删权限 + 仓库口令离线保存**（最简），并把「只写不可删」留给第二阶段的不可变归档桶。
- 备选：拆两个 AK（每日仓：读写删；归档桶：仅 PutObject），运维稍重但入侵时损失受限。
- 不推荐：AK 给账号级全权限；口令只存在本机（等于没备份）。
- 判据 V-B2：主机上 `grep` 不到仓库口令明文（口令单独 600 文件 + 离线副本两处）。

### 3. BK-03 告警通道（P1，用户裁量）

- **推荐：healthchecks.io 免费 20 check（心跳式，26 小时无 ping 发邮件）**，零成本、不受国内 IM 限制。
- 备选：企业微信群机器人 webhook（免费、即时，但需用户提供 webhook 地址）；Telegram bot（需自担跨境可达性）。
- 判据 V-B3：人为造一次失败（改错仓库名），26 小时内收到告警。

## §二 分阶段实施

### P0 准备（用户动作，约 20 分钟）

1. 七牛注册 + 实名认证，建空间 `sv-backup`（私有、标准存储、华东-浙江2）。

   > **20261031 控制台实测更正（三条硬事实）**：
   > ① **未实名时「私有」权限是禁用的**，新建空间只能选「公开」——公开空间等于把备份暴露给任何人读，方案不可接受，因此**实名认证是前置硬门槛**，且免费 10GB 额度按官方口径也只对实名用户开放。
   > ② **华东-浙江2（`cn-east-2`）已停止新建**，控制台原文「该区域已转存量运营，请选择其他区域创建空间」→ 新建空间只能落 **华东-浙江（`cn-east-1`）**，存储单价以该区为准（不再是 0.115 那档，需按控制台账单页复核）。
   > ③ **空间名全局唯一**，`sv-backup` 已被占用；本轮改用 **`songsrv-backup`**。
2. 控制台建 AK/SK，权限绑到该空间；AK 只填进 `/etc/svbackup/credentials`（600，root）。
3. ~~登录 VPS 购买面板，确认快照能力与到期规则~~ **20261031 用户已确认：无快照能力、到期为「永久使用」**（回填见 §六）。
4. 生成 restic 仓库口令（32 字符随机），**离线存两处**（密码管理器 + 另一台设备），不写进任何备份产物。

### P1 基座（约 1 小时，改动全部落在宿主，不碰容器）

1. 目录约定：`/var/backups/svbackup/{dumps,logs}`、`/etc/svbackup/`。
2. `dump-all.sh`：逐库导出到 `dumps/<UTC 日期>/`，每步 `set -euo pipefail` + 空文件判定（`test -s`，小于阈值即 `exit 1`）。用调研报告 §4 的容器内绝对路径，命令形态：
   - `docker exec xc3-mariadb mysqldump -u... --single-transaction --no-tablespaces ... > x.sql`（**纯文本不压缩**，见下条）
   - `docker exec xc3-highgo /opt/HighGo6.0.1-cluster/bin/pg_dump -Fc -Z0 ...`
   - `docker exec xc3-vastbase /home/omm/vbdata/install/vastbase/bin/pg_dump -Fc -Z0 ...`
   - `docker exec xc3-opengauss /usr/local/opengauss/bin/gs_dump -Fc -Z0 ...`
   - `docker exec xc3-gaussdb-kernel503 /opt/gaussdb/app/bin/gs_dump -Fc -Z0 ...`
   - `docker exec xc3-mssql /opt/mssql-tools18/bin/sqlcmd -C -Q "BACKUP DATABASE ... TO DISK='/var/opt/mssql/backup/x.bak'"` 然后 `docker cp` 出来
   - `mysqldump -h127.0.0.1 -P25881 -u'xc3@test' ... > ob.sql`（宿主机直连 OB）
   - **禁止 `| gzip`**：压缩交给 restic，否则跨天去重失效、等于每天全量重传。代价是暂存目录会到十几 G，脚本要限制本地保留 2 代（`/` 余 160G，够）。
3. `collect-meta.sh`：`docker ps -a --format`、`docker images --digests`、`docker inspect` 全量 JSON、`/etc/docker/daemon.json`、`/opt/xc3-*/start.sh`、`/etc/apt/sources.list*`、root crontab、sshd 配置 → 打成一个 `meta.tar.zst`。
4. `/etc/svbackup/credentials`（600）与 `/etc/svbackup/pass`（600）就位；凭据一律不写进仓库、不写进 shell 历史（脚本内 `--password-file`）。

### P2 首次全量 + 体积复核（约 1.5~3 小时，后台跑）

1. 仓库地址与参数（七牛，缺 `-o s3.region` 会签名失败）：
   `RESTIC_REPOSITORY=s3:s3.cn-east-2.qiniucs.com/sv-backup`，每次调用带 `-o s3.region=cn-east-2`；凭据走 `AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY`，口令走 `--password-file /etc/svbackup/pass`。
2. **先跑 1GB 测试数据的接入验收**（造测试数据 → 首次备份 → 追加增量看是否只传增量 → `check --read-data-subset=10%` → restore 比对 → 删快照 prune → 备份中途 kill 后重跑看是否续传）。七牛 S3 兼容层只承诺「涉及接口已兼容」，multipart/DeleteObjects 支持情况必须自证，全过再上生产。
3. `restic init` → 首次 `restic backup --limit-upload 3000 --retry-lock 10m`。
4. 记录 `restic stats --mode raw-data` 的真实仓库体积，**回填判据 P4**（调研报告 §7）：≤10GB 则整个方案常态 0 元成立；>10GB 则按 0.115 元/GB 估算月费并回报用户。
5. 首次跑完立刻做一次 `restic check`。

### P3 定时与告警（约 30 分钟）

1. `svbackup.service` + `svbackup.timer`（`OnCalendar=*-*-* 19:00:00` UTC ＝ 北京 03:00；机器时区是 UTC，必须写 UTC），timer 带 `Persistent=true` 以便关机错过后补跑。
2. service 加 `flock` 防重叠、`TimeoutStartSec=6h`、`OnFailure=svbackup-alert@%n.service`。
3. 每次 restic 调用带 `--retry-lock 10m`（进程被 kill 后残锁会让下次报 already locked，等锁比 `unlock` 安全）。
4. 成功后 `curl -fsS -m 10 <healthchecks-ping-url>`；日志 `journalctl -u svbackup` 可查。
5. **滚动保留＝新备份顶掉最旧**：`restic forget --keep-last 7 --prune --max-repack-size 2G`（`--keep-last N` 就是「只留最近 N 份」，只 forget 不 prune 不会释放空间）。待 P2 实测单份增量后再定 N（默认 7）。
6. **容量闸门（七牛没有原生开关，必须自建）**：备份前置检查 `restic stats --mode raw-data --json` 的 `total_size`，超过 **9GB** 就先降档 prune，仍超则**中止本次备份并告警**（不做破坏性操作）。三道闸设计见调研报告 §3.4。
7. **两条护栏**：单份 dump 体积超过上一份 2 倍时告警并跳过上传；控制台另设「余额/费用预警」。
8. **禁止给 restic 仓库前缀配生命周期删除规则**——它按天删、不懂 restic 引用关系，会删掉在用 pack 直接毁仓；只允许配未完成分片清理。

### P4 恢复演练（每周，自动化）

> 逐库恢复命令、单文件直出、整机重建五步与演练节奏见调研报告 **§5 恢复怎么做**（工具路径已逐个实测在位）。

1. `restic restore latest --target /tmp/verify --include /dumps/` + `restic check --read-data-subset=5%`。
2. 抽一个小库（HighGo 或 MariaDB）真恢复到临时容器，`SELECT count(*)` 比对，比对结果写日志。
3. 判据 V-B4：连续两周演练通过，才算备份可用。

### P5 加固（第二阶段，可选）

1. 第二个桶开对象锁（WORM），AK 只给 PutObject，放**月度全量归档**，防「主机被入侵后连备份一起删」。
2. 每季度把最新一份归档复制到本地或第二家云（B2 免费 10GB 可作第三副本）。
3. 前提：P2 实测体积 + 归档体积合计 ≤10GB，否则要接受少量月费。

## §四 红线与纪律

- **不碰数据库容器配置**：不重启、不改 `daemon.json`、不改端口、不动现有 `--restart` 策略；备份只读数据 + 写宿主目录。
- **必须限速**：`--limit-upload 3000`（KB/s），备份不能把出口打满影响测试。
- **时区口径**：机器是 UTC，所有定时点写 UTC 并注明北京时间，避免「以为凌晨跑其实中午跑」。
- **失败必须响**：脚本禁止 `|| true` 吞错误；管道必须 `set -o pipefail`（`mysqldump | gzip` 是「假成功」最经典来源：mysqldump 认证失败会输出到 stderr，gzip 照样压出合法小文件并返回 0）。
- **口令离线**：仓库口令、AK 不落在被备份的机器上做唯一副本。
- **不动无关文件**：`update/update.json`、插件代码、其他会话在途文件一律不碰。
