## 1. 问题与根因（证据驱动）

### 1.1 用户症状

- 插件设置 → 界面语言 → 选择「跟随系统」；
- 当前 IDE 界面语言为 English（Settings → Appearance & Behavior → System Settings → Language and Region → IDE Language: English）；
- **插件界面仍为中文**——「跟随系统」未生效。

> 注：与 M16.1「切 en 保存不生效」是**不同症状**：M16.1 是切换链路/持久化问题（已修）；本次是 **AUTO 分支解析目标错误**——AUTO 能保存、能生效，但生效到了**错误的语言**。

### 1.2 根因：AUTO 跟随的是 JVM locale，而非 IDE 界面语言

`util/MpSqlVisualizerBundle.kt:78-84`：

```kotlin
private fun currentLocale(): Locale = runCatching {
    when (PluginSettings.getInstance().state.language) {
        "en" -> Locale.ENGLISH
        "AUTO" -> Locale.getDefault()          // ← 根因
        else -> Locale.SIMPLIFIED_CHINESE
    }
}.getOrElse { Locale.SIMPLIFIED_CHINESE }
```

**`Locale.getDefault()` 是 JVM 默认 locale**（进程启动时由 OS 区域 / `-Duser.language` VM 参数决定），**不是 IDE 界面语言**。IDEA 的界面语言是独立设置（Language and Region → IDE Language），与 JVM locale 无绑定关系。

用户场景拆解（OS 中文 + IDE 语言设为 English）：

| 项 | 值 |
|----|----|
| OS / JVM locale（`Locale.getDefault()`） | `zh_CN`（跟随 OS，不受 IDE 设置影响） |
| IDE 界面语言（用户设置生效） | `en` |
| 插件 AUTO 解析结果 | `zh_CN` → 加载中文 bundle ❌ |
| 用户预期 | 跟随 IDE 界面 → English ✅ |

**语义错位**：设置面板文案「跟随系统」的用户预期 = **与 IDE 界面语言一致**（IDE 的语言设置本身也有「System default」选项）；当前实现却跟随 JVM locale——两者在「IDE 语言 ≠ OS 语言」时必然分离。

### 1.3 平台 API 实证（2025.3.5 / 2025.3.6.1 发行版实测）

修复前先验证了「取 IDE 界面语言」的可用 API（反编译发行版 jar）：

| 候选 API | 2025.3 现状 | 说明 |
|----------|-------------|------|
| `com.intellij.util.ui.UIUtil.getUiLanguage()` | ❌ **已移除** | 2025.3 的 app.jar 中 `UIUtil` 类无任何 `*UiLanguage` 方法（2020.1~2024.x 时代的经典 API） |
| `com.intellij.ide.ui.LanguageSettings` | ❌ **已不存在** | app.jar 中无此类（2022.x 引入，后随语言设置重构移除） |
| `com.intellij.l10n.LocalizationUtil` | ✅ **存在**（util-8.jar） | Kotlin `object`（`INSTANCE`），公开 API：`getLocale(): Locale`（IDE 界面语言；IDE 语言为「系统默认」时回退 `Locale.getDefault()`）、`getLocaleOrNullForDefault(): Locale?`（系统默认时返回 null）、`getDefaultLocale()` |
| `com.intellij.l10n.LocalizationStateService` | ✅ 存在但 `@ApiStatus.Internal` | 内部 API（getSelectedLocale/setSelectedLocale），**插件不应依赖** |

> 实证方法：`unzip -l` + 常量池字符串扫描 + jbr 反射打印 2025.3.5/2025.3.6.1 发行版 `app.jar`/`util-8.jar`。`since-build=253`（plugin.xml:9）与 l10n 包引入版本匹配，**API 兼容无风险**。

## 2. 修复方案（定位到现有代码）

### T-M23.1-01：AUTO 分支改读 IDE 界面语言

**改动点**（仅 `util/MpSqlVisualizerBundle.kt`）：

```kotlin
private fun currentLocale(): Locale = runCatching {
    when (PluginSettings.getInstance().state.language) {
        "en" -> Locale.ENGLISH
        "AUTO" -> LocalizationUtil.getLocale()   // IDE 界面语言；系统默认时内部回退 Locale.getDefault()
        else -> Locale.SIMPLIFIED_CHINESE
    }
}.getOrElse { Locale.SIMPLIFIED_CHINESE }
```

- `com.intellij.l10n.LocalizationUtil` 为 Kotlin object，Kotlin 侧直接 `LocalizationUtil.getLocale()`（Java 侧 `INSTANCE`）；
- 行为对照：

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| IDE 语言 = English（OS 中文） | `Locale.getDefault()`=zh → 中文 ❌ | `getLocale()`=en → 英文 ✅ |
| IDE 语言 = 简体中文 | zh（碰巧一致） | zh ✅（不变） |
| IDE 语言 = System default（OS 中文） | zh | `getLocale()` 内部回退 `Locale.getDefault()`=zh ✅（不变，无回归） |
| 测试环境（LightPlatform，settings 未注册 / l10n 扩展不可用） | 兜底中文 | `runCatching` 兜底中文 ✅（契约不变） |

**验收**：① 真实 IDE 设 IDE 语言 English → 插件 AUTO → 立即英文；② IDE 语言中文 → AUTO 中文；③ IDE 语言切回 System default → 跟随 OS 语言；④ 重启 IDE 后设置保持（AUTO 已持久化，M19 写穿链路不动）。

### T-M23.1-02：AUTO 兜底回归测试

- 新增 `MpSqlVisualizerBundle` AUTO 分支用例：**环境不可用时兜底中文、不抛异常**（对齐现有「settings 未注册兜底中文」契约——fixture 下 `LocalizationUtil.getLocale()` 依赖扩展框架，大概率不可用，恰好覆盖兜底路径）；
- 真实 IDE 手动清单为行为正确性的主验收（fixture 无法模拟「IDE 语言 = en」——IDE 语言属应用级环境，非插件配置；计划中明确此边界，不强行 mock 平台服务）。
