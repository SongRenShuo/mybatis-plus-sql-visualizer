## 二、为什么不能 cherry-pick

1. **文件已分叉**：dev 把 `DataSourceSelector.kt` 拆成 `Console* / Runners / BottomCollapse / ConsoleText / Results` 等，同一段逻辑在 master 里行号与上下文完全不同 → cherry-pick 必冲突。
2. **修复依赖 dev 新文件**：UI-003 引入 `execute/PreviewPreparePick.kt`、UI-004 引入 `ui/DialectGateRenderDialect.kt`；新文件本身可以直接取（无冲突），但**调用点必须按 master 的旧结构手工接**。
3. **依赖符号在 master 可能不存在**（见 §四待验证前提，UI-003 已确认一项）。

## 三、方法：新建 worktree 逐项重放

```bash
git worktree add wt-backport -b backport-thread-dialect-fixes master
```

- **逐项一笔提交**，不批量（便于单独回滚与审阅）。
- 新文件：`git checkout dev -- <路径>` 直接取，再核对 master 侧 import/依赖是否成立。
- 存量文件：读 dev 实现 → 按 master 结构手工改（保 master 布局，只搬语义）。
- 每项完成立即提交；**不得 `git merge dev`**（那会带上 290 笔重构）。

## 四、逐项要点与待验证前提

### 4.1 UI-003 预览阶段不再弹选择器（**需降级**）

- dev 实现分两步：B（`ExecBindFallback.pickTarget` 按「学习绑定 > last-used > 单源」静默选源）→ A（仍不唯一则不弹不建链）。

### 4.2 UI-004 方言状态行与顶部同源

- master 有 `ui/DialectStatusRefresh.kt`、`ui/SqlPreviewPanelExecution.kt`（`currentDialectDecision` / `executionDialectGateRequest` 共 7 处）→ 可移植。

- 保留两条既有定案：XML 载体不做字符串替换冒充重渲染；方言冲突放行不拦执行。

### 4.3 A `ChooseDataSourceTakeoverGroup` 的 EDT 读 PSI

- 平台原文指名违反 `ActionUpdateThread`。修法二选一：声明 `ActionUpdateThread.BGT`，或把 PSI 可用性判定移出 update 路径（改事件驱动 + 缓存）。
- **待验证前提**：master 的 `ChooseDataSourceTakeoverGroup` 与 dev 版本是否同构（先用 `git diff` 确认，差异大则以 master 现状重新设计修法）。

### 4.4 B 执行链 EDT 做 findDirectory

- 落点：`prepareInConsole` / `prepareAfterEditorResolved` / `continuePrepareAfterTempFile` / `runRunner`。
- 慢操作链为 `FileManagerImpl.findDirectory → ProjectFileIndexImpl.isUnderIgnored → WorkspaceFileIndexDataImpl.ensureIsUpToDate`。
- **待验证前提**：master 上这些 EDT 路径是否与 dev 同构（dev 侧已因 T-ExecSlowOps 改造过）。若 master 仍是同步形态，修法要按 master 结构重设计，不能照抄。

### 4.5 C Write-unsafe 写文档

- 落点：`SqlExecutor.execute` → `reuseSharedConsole` → `executeOnConsole`。
- 修法：文档写必须 write-safe 投递（`ModalityState.nonModal()` / `invokeLaterWriteSafe`），**不用** `ModalityState.any()`（any() 恒 write-unsafe）。
- 风险最高（改投递模态可能影响执行时序），要求 master 侧执行链定向测试全绿。
