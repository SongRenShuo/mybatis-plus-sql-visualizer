# 工具窗口面板内存泄漏修复开发计划

> 状态：✅ 已实施（2026-11-13 代码核对回填——四面板 `Disposable` + `Disposer.register`/`messageBus.connect(disposable)` 挂树已成惯例，`LogToSqlPanel` 实现 `Disposable.dispose()`）
> 需求来源：`runIde` 日志分析——IDE 退出时 `Disposer.assertIsEmpty` 检测到 4 个插件组件挂在 `ROOT_DISPOSABLE` 下未被释放（Memory leak detected）。

## 1. 目标与范围

修复 4 个内存泄漏，使 IDE 退出时不再报 `ObjectTree - Memory leak detected` SEVERE。

| # | 泄漏组件 | 注册点 | 所在文件 |
|---|---|---|---|
| 1 | `LogToSqlPanel` | `addDocumentListener(..., this)` → `ObjectTree.register` | `LogToSqlPanel.kt:103` |
| 2 | `SqlInputEditor` | `addDocumentListener(..., this)` → `ObjectTree.register` | `SqlInputEditor.kt:156` |
| 3 | `SqlToJavaPanel` | `addDocumentListener(..., this)` → `ObjectTree.register` | `SqlToJavaPanel.kt:210` |
| 4 | `SqlPreviewPanel` | `messageBus.connect(this)` → `MessageBusConnection` | `SqlPreviewPanel.kt:204` |

**已确认决策**：
- 修复方式：`Disposer.register(parent, child)` 将子面板注册为父 Disposable 的孩子 → 父 dispose 时级联释放子面板及其监听器。
- 不改 `dispose()` 方法本身（现有释放逻辑正确），仅补上 Disposer 树的父子关系。
- 不动 `addDocumentListener` 的 `this` 参数（`this` 作为 listener 的 parentDisposable 语义正确，问题在于 `this` 未被注册到父 Disposer 树下）。
- 不新增单元测试（泄漏检测仅在 IDE 退出时触发，`runIde` 日志即为验证信号；改动仅 3 行 `Disposer.register`，回归风险极低）。

## 2. 现状分析

### 2.1 根因：子面板未注册到 Disposer 树

IntelliJ 的 `Disposer` 系统通过 `ObjectTree` 管理 `Disposable` 对象的父子层级。`addDocumentListener(listener, parentDisposable)` 会将 `parentDisposable` 注册为 `ROOT_DISPOSABLE` 的孩子（如果它尚未注册）。IDE 退出时，`Disposer.assertIsEmpty` 检查 `ROOT_DISPOSABLE` 是否全部 dispose —— 未注册的组件挂在根下又从未被释放 → Memory leak detected。

**当前调用链**：

```
SqlLogToolWindowFactory.createToolWindowContent()
  └─ new SqlLogPanel(project, manager)   // content.setDisposer(panel) → 注册到 content
       ├─ LogToSqlPanel(project)          // ← 未注册为 SqlLogPanel 的孩子！
       │    └─ addDocumentListener(l, this)  // this=LogToSqlPanel → 注册到 ROOT_DISPOSABLE ✗
       └─ SqlToJavaPanel(project)         // ← 未注册为 SqlLogPanel 的孩子！
            ├─ SqlInputEditor(project, "") // ← 未注册为 SqlToJavaPanel 的孩子！
            │    └─ addDocumentListener(l, this)  // this=SqlInputEditor → 注册到 ROOT_DISPOSABLE ✗
            └─ addDocumentListener(l, this)  // this=SqlToJavaPanel → 注册到 ROOT_DISPOSABLE ✗
```

`SqlLogPanel.dispose()` 手动调 `logToSqlPanel.dispose()` + `sqlToJavaPanel.dispose()`，但 Disposer 树不知道这层关系 → 子面板仍在 `ROOT_DISPOSABLE` 下残留。

### 2.2 SqlPreviewPanel 泄漏路径不同

```
SqlPreviewDialog.init()
  └─ SqlPreviewPanel(project)           // ← 未注册为 DialogWrapper 的孩子！
       └─ messageBus.connect(this)      // MessageBusConnection 注册为 this 的孩子
```

`messageBus.connect(this)` 返回的 `MessageBusConnection` 是 `Disposable`，注册为 `this`(=SqlPreviewPanel) 的孩子。`SqlPreviewPanel.dispose()` 调 `Disposer.dispose(this)` 会级联释放 connection。**但** `SqlPreviewPanel` 自身从未被注册到 `SqlPreviewDialog` 的 Disposer 树 → 整个 panel + connection 挂在 `ROOT_DISPOSABLE`。

### 2.3 各面板 dispose() 现状（均正确，无需改动）

| 面板 | dispose() 内容 | 评价 |
|---|---|---|
| `LogToSqlPanel.dispose()` | `releaseEditor(inputEditor)` + `releaseEditor(resultEditor)` | ✅ 正确 |
| `SqlInputEditor.dispose()` | `removeDocumentListener` + `releaseEditor` | ✅ 正确 |
| `SqlToJavaPanel.dispose()` | `inputEditor.dispose()` + `releaseEditor(resultEditor)` | ✅ 正确 |
| `SqlPreviewPanel.dispose()` | `Disposer.dispose(this)` 级联释放 connection | ✅ 正确 |

## 3. 修复方案

### 3.1 改动 1：`SqlLogPanel` 注册子面板

**文件**：`src/main/kotlin/cn/song/mybatisplus/visualizer/log/SqlLogPanel.kt`

**位置**：`init` 块开头（第 181 行后）

**改动**：

```kotlin
init {
    // 注册子面板到 Disposer 树：父面板 dispose 时级联释放子面板（及其 DocumentListener），
    // 避免 IDE 退出时 ObjectTree 报 Memory leak detected
    Disposer.register(this, logToSqlPanel)
    Disposer.register(this, sqlToJavaPanel)

    // ... 后续 init 代码不变
}
```

**效果**：`SqlLogPanel` dispose → Disposer 级联 dispose `logToSqlPanel` + `sqlToJavaPanel` → 它们的 `dispose()` 释放 editor 和 listener → 不再挂在 `ROOT_DISPOSABLE`。

### 3.2 改动 2：`SqlToJavaPanel` 注册 `SqlInputEditor`

**文件**：`src/main/kotlin/cn/song/mybatisplus/visualizer/log/SqlToJavaPanel.kt`

**位置**：第 96 行（`inputEditor` 字段声明后）

**改动**：

```kotlin
private val inputEditor = SqlInputEditor(project, "")
init {
    // 注册到 Disposer 树：面板 dispose 时级联释放 SqlInputEditor 的 DocumentListener
    Disposer.register(this, inputEditor)

    // ... 后续 init 代码不变
}
```

**效果**：`SqlToJavaPanel.dispose()` 已调 `inputEditor.dispose()`，加上 `Disposer.register` 后，双重保障（Disposer 树知道这层关系）。

### 3.3 改动 3：`SqlPreviewDialog` 注册 `SqlPreviewPanel`

**文件**：`src/main/kotlin/cn/song/mybatisplus/visualizer/ui/SqlPreviewDialog.kt`

**位置**：`init` 块中 `panel.showResult(result)` 后

**改动**：

```kotlin
init {
    title = MpSqlVisualizerBundle.message("dialog.preview.title")
    panel.showResult(result)
    // 注册面板到弹窗 Disposer 树：弹窗 dispose 时级联释放面板及其 messageBus 连接
    Disposer.register(this, panel)

    // ... 后续 init 代码不变
}
```

**效果**：`DialogWrapper.dispose()` → 级联 dispose `SqlPreviewPanel` → `panel.dispose()` 调 `Disposer.dispose(this)` 释放 messageBus connection。

### 3.4 注意事项

- `Disposer.register` 幂等：同一 parent-child 对重复注册无害（内部有检查）。
- `SqlLogPanel.dispose()` 中的 `logToSqlPanel.dispose()` / `sqlToJavaPanel.dispose()` 显式调用**保留**——即使 Disposer 树已级联释放，显式调用有 `disposed` 标志守卫，不会重复释放。
- 三个改动各 1 行，共 3 行新增，0 行删除。

## 6. 风险评估

| 风险 | 等级 | 缓解 |
|---|---|---|
| `Disposer.register` 导致双重 dispose | 低 | 各 `dispose()` 方法已有 `disposed` 标志守卫，幂等安全 |
| 影响现有测试 | 极低 | 仅加 Disposer 注册，不改动任何业务逻辑 |
| 影响运行时功能 | 极低 | 面板生命周期与此前一致（手动 dispose + Disposer 级联 = 同一时机） |
