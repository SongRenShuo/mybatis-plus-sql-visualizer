## 六、纪律与红线（承袭＋新增）

承袭：dev 并 master 须用户允许；k2j 轨永不并入；`update/update.json` 只有用户能改；并行 gradle 前查 `parallel_tasks.py`、构建并发上限 2 路；子代理只跑定向测试、全量单路收口；收口禁 `&&` 串联；守卫类改动必反向验证；落笔前 `git log <基线>..HEAD` 重测；后台长任务不阻塞等待。

**新增三条**：

1. **留底是持续动作，不是一次性动作**——每次并行推进会话结束前必须 push 自己的分支；「未合内容先留底再动树」在第二十三轮之后又被打破一次（本轮 189 笔本地单点），故升级为每会话收尾检查项。
2. **合流顺序不可颠倒**：`master ← dev ← insight`。绕过 dev 直接合 insight，用户拿不到 gutter 多选与设置场景归组，且**不会报任何错**——这类静默丢功能比冲突更危险。
3. **默认值变更必须进发行说明**：R45 把结构化 EXPLAIN 从默认关翻成默认开，属用户可感知行为变化，CHANGELOG 与发行说明缺一即视为漏项。
