# MPJ fill 关联填充（MPJ 1.5.1+）开发计划

> 状态：✅ 已落地（T-MpjFill：`MpjLambdaConverter` fill 解析 + `FillClause` 模型；2026-11-13 代码核对回填）
> 需求来源：MPJ 1.5.1+ 新增 `fill(field, tagField)` API，需预览引擎支持其 SQL 语义渲染。

## 1. 目标与范围

MPJLambdaWrapper 的 `fill(field, tagField)` 方法（MPJ 1.5.1+）实现**关联填充**语义：主查询执行后，收集结果集中关联键 → 对关联表发起 `IN` 附加查询 → 内存回填到主结果集合。

本计划目标：在预览引擎中**忠实复刻 fill 的 SQL 行为**，渲染为两段式：
1. **主 SELECT**：既有 MPJ 联表查询（复用 MpjLambdaConverter 完整管线）
2. **fill 附加 SELECT**：`SELECT <关联表列> FROM <关联表> WHERE <tagField> IN (<关联键列表>)`

**已确认决策**：
- fill 的 IN 列表中关联键来源为主查询结果集，**静态预览无法真实获取**——渲染为 `IN (?)` 占位符（1 个 `?` 代表关联键列表），与既有运行时占位符语义一致
- fill 为**附加查询**，不改变主查询形态——主 SELECT 独立渲染，fill 结果作为第二段追加展示
- 支持 fill 全部 6 种形态（见第 3 节），按 MPJ 1.5.1+ 官方 API 签名分派
- fill 与 selectCollection 语义区别：selectCollection 生成 JOIN 子查询（影响主 SELECT），fill 为独立附加查询（不介入主 SELECT）

## 2. fill 语义与 MPJ 官方对照

### 2.1 官方源码行为（MPJ 1.5.1+）

```java
// MPJ 官方 fill 方法族（JoinAbstractLambdaWrapper.fill 系列）
public Children fill(MFunction<T> field, SFunction<R, Object> tagField) { ... }
public Children fill(MFunction<T> field, SFunction<R, Object> tagField, String mapperTagField) { ... }
public Children fill(MFunction<T> field, SFunction<R, Object> tagField, String mapperTagField, int limit) { ... }
public Children fill(MFunction<T> field, SFunction<R, Object> tagField, String mapperTagField, boolean condition) { ... }
public Children fill(MFunction<T> field, SFunction<R, Object> tagField, String mapperTagField, R data) { ... }
public Children fill(MFunction<T> field, SFunction<R, Object> tagField, String mapperTagField, int limit, R data) { ... }
```

### 2.2 6 种形态分派

| 形态 | 签名 | 语义 |
|------|------|------|
| 1 | `fill(field, tagField)` | 基础形态：主表字段 + 关联表字段 |
| 2 | `fill(field, tagField, mapperTagField)` | 关联表字段名为字符串（非 lambda） |
| 3 | `fill(field, tagField, mapperTagField, limit)` | 限制附加查询返回条数 |
| 4 | `fill(field, tagField, mapperTagField, condition)` | 条件控制是否执行 fill |
| 5 | `fill(field, tagTagField, mapperTagField, data)` | 指定数据源对象（不从主查询收集） |
| 6 | `fill(field, tagField, mapperTagField, limit, data)` | 数据源 + 条数限制 |

### 2.3 渲染形态

```
-- 主 SELECT（既有 MpjLambdaConverter 管线）
SELECT t.id, t.name, t.station_id
FROM device t
LEFT JOIN station s ON s.id = t.station_id
WHERE t.deleted = 0

-- fill 附加 SELECT（本计划新增）
SELECT s.id, s.station_name FROM station s WHERE s.id IN (?)
```

## 3. 架构与数据流

```
WrapperChain（含 fill 调用）
  → MpjLambdaConverter.convert()
      → 既有管线：主 SELECT 生成（selectAs/join/selectCollection/union/from/around）
      → parseFill(call)：fill 调用 → FillClause 模型
  → SqlGenerator.generate()：主 SELECT SQL
  → SqlGenerator.generateFill(fillClause)：fill 附加 SELECT SQL（新增）
→ PreviewResult（新增 fillClauses 字段）
→ SqlPreviewPanel：主 SQL 后追加 fill 段渲染
```

### 3.1 新增模型

```kotlin
/**
 * fill 附加查询子句（MPJ 1.5.1+）。
 *
 * @param childTable    关联表 TableInfo（psi 解析或类名推断）
 * @param childAlias    关联表别名
 * @param selectColumns 关联表 SELECT 列列表
 * @param tagField      关联表 IN 条件列（关联键字段）
 * @param limit         附加查询条数限制（null 表示不限制）
 * @param condition     条件控制（null 表示无条件，true 执行/false 跳过）
 * @param data          指定数据源对象（null 表示从主查询结果收集）
 */
data class FillClause(
    val childTable: TableInfo,
    val childAlias: String,
    val selectColumns: List<ColumnRef>,
    val tagField: String,
    val limit: Int? = null,
    val condition: Boolean? = null,
    val data: SqlValue? = null,
)
```

### 3.2 PreviewResult 扩展

```kotlin
data class PreviewResult(
    // ... 既有字段 ...
    /** fill 附加查询子句列表（MPJ 1.5.1+），按调用顺序；无 fill 调用为 null */

)
```

## 4. 详细实施方案

### 4.1 MpjLambdaConverter 扩展

在 `MpjLambdaConverter.kt` 中新增 fill 解析：

```kotlin
// fill 方法名常量
private const val FILL_METHOD = "fill"

// convert() 中收集 fill 调用
val fillCalls = chain.calls.filter { it.methodName == FILL_METHOD }

// 解析 fill 调用 → FillClause
private val fillClauses = fillCalls.mapNotNull { parseFill(it, mainAlias) }

// 注入返回结果
return base.copy(
    // ... 既有字段 ...
    fillClauses = fillClauses.ifEmpty { null },
)
```

### 4.2 parseFill 实现

```kotlin
/**
 * 解析 fill 调用 → FillClause（MPJ 1.5.1+）。
 *
 * 6 种形态分派：
 *  1. fill(field, tagField) — 2 参
 *  2. fill(field, tagField, mapperTagField) — 3 参（第 3 参字符串列名）
 *  3. fill(field, tagField, mapperTagField, limit) — 4 参（第 4 参整数）
 *  4. fill(field, tagField, mapperTagField, condition) — 4 参（第 4 参布尔）
 *  5. fill(field, tagField, mapperTagField, data) — 4 参（第 4 参值）
 *  6. fill(field, tagField, mapperTagField, limit, data) — 5 参
 *
 * @param call       fill 调用
 * @param mainAlias  主表别名（fill 结果映射回主表字段）
 * @return FillClause；解析失败返回 null（容错）
 */
private fun parseFill(call: WrapperCall, mainAlias: String): FillClause? {
    val args = call.args
    if (args.size < 2) return null

    // 第 1 参：主表字段（MFunction<T>）→ 关联键来源列
    val fieldColumn = (args.getOrNull(0) as? WrapperArg.ColumnArg)?.column ?: return null

    // 第 2 参：关联表字段（SFunction<R, Object>）→ 推断关联表
    val tagFieldArg = args.getOrNull(1)
    val childTableAndTagField = when (tagFieldArg) {
        is WrapperArg.ColumnArg -> {
            // lambda 字段引用 → 从列推断关联表（需 psi 层 EntityRefArg 上下文）
            // 简化：取列的实体类名推断表名
            val childClass = tagFieldArg.column.tableAlias ?: return null
            childClass to tagFieldArg.column.columnName
        }
        is WrapperArg.ValueArg -> {
            // 字符串列名 → 形态 2/3/4/5/6
            val tagField = (tagFieldArg.value as? SqlValue.Literal)?.unquoted ?: return null
            // 关联表需从后续参数或上下文推断
            // 简化：暂不支持字符串 tagField 无 EntityRefArg 上下文
            return null
        }
        else -> return null
    }

    val (childTable, tagField) = childTableAndTagField

    // 可选参数：limit / condition / data
    var limit: Int? = null
    var condition: Boolean? = null
    var data: SqlValue? = null

    when (args.size) {
        3 -> { /* 形态 2：第 3 参为 mapperTagField 字符串列名 */ }
        4 -> {
            val arg3 = args.getOrNull(3)
            when {
                arg3 is WrapperArg.ValueArg && (arg3.value as? SqlValue.Literal)?.unquoted?.toIntOrNull() != null -> {
                    limit = (arg3.value as SqlValue.Literal).unquoted.toIntOrNull()
                }
                arg3 is WrapperArg.ValueArg && (arg3.value as? SqlValue.Literal)?.unquoted?.toBooleanStrictOrNull() != null -> {
                    condition = (arg3.value as SqlValue.Literal).unquoted.toBooleanStrictOrNull()
                }
                else -> data = arg3.asValue()
            }
        }
        5 -> {
            // 形态 6：limit + data
            limit = (args.getOrNull(3).asValue() as? SqlValue.Literal)?.unquoted?.toIntOrNull()
            data = args.getOrNull(4).asValue()
        }
    }

    // condition = false → 跳过 fill（不生成 FillClause）
    if (condition == false) return null

    // 关联表 SELECT 列：默认全列
    val selectColumns = childTable.columns.map { col ->
        ColumnRef(tableAlias = childTable.entityClassName.replaceFirstChar { it.lowercaseChar() }, columnName = col.columnName)
    }

    val childAlias = childTable.entityClassName.replaceFirstChar { it.lowercaseChar() }

    return FillClause(
        childTable = childTable,
        childAlias = childAlias,
        selectColumns = selectColumns,
        tagField = tagField,
        limit = limit,
        condition = condition,
        data = data,
    )
}
```

### 4.3 SqlGenerator 扩展

```kotlin
/**
 * 生成 fill 附加 SELECT SQL（MPJ 1.5.1+）。
 *
 * 渲染形态：
 * ```
 * SELECT <列> FROM <表> WHERE <tagField> IN (?)[ LIMIT <n>]
 * ```
 *
 * @param fillClause  fill 子句模型
 * @param dialect     数据库方言
 * @return fill 附加 SELECT SQL
 */
fun generateFill(fillClause: FillClause, dialect: Dialect = MySqlDialect): String {
    val sb = StringBuilder("SELECT ")
    sb.append(fillClause.selectColumns.joinToString(", ") { renderColumnRef(it, dialect) })
    sb.append(" FROM ").append(renderTableName(fillClause.childTable.tableName, dialect))
    sb.append(" ").append(fillClause.childAlias)
    sb.append(" WHERE ").append(renderQualified(ColumnRef(columnName = fillClause.tagField), dialect))
    sb.append(" IN (?)")
    fillClause.limit?.let { sb.append(" LIMIT ").append(it) }
    return sb.toString()
}
```

result.fillClauses?.let { fills ->
    if (fills.isNotEmpty()) {

```

## 5. 边界与已知限制

- **关联表推断**：fill 的 tagField 若为 lambda 引用（`Station::getId`），需 psi 层 EntityRefArg 携带 TableInfo；字符串列名形态无实体上下文时需容错（暂不渲染）
- **IN 列表占位符**：静态预览无法获取主查询结果集，统一渲染 `IN (?)`——与面板参数对照表语义一致
- **condition = false**：fill 被条件禁用 → 不生成 FillClause（预览中不展示）
- **data 数据源**：指定数据源对象形态，IN 列表仍渲染 `?`（值来自对象属性，静态不可知）
- **limit**：直接渲染 `LIMIT n`（整数常量，无兼容性差异）
- **嵌套 fill**：多次 fill 调用按 chain 顺序依次追加渲染

## 10. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 关联表推断失败（字符串 tagField 无上下文） | fill 段不渲染 | 容错返回 null + 文档化边界 |
| MPJ 官方 fill 行为变更 | 渲染与实际不一致 | R7 待 MPJ 官方输出对照（既有策略） |
| 多次 fill 导致 SQL 段过长 | 面板展示冗长 | fill 段可折叠（后续迭代） |
| IN (?) 占位符用户困惑 | 不理解为何不是具体值 | 面板注释说明（i18n 文案 `panel.fill.comment`） |
