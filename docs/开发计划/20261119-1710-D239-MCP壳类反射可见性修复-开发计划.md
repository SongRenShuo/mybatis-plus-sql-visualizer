# D239 MCP 工具集壳类反射可见性修复（开发计划 · 方案 A）

- **立项**：2026-11-19 17:10，用户拍板「按推荐立项」（推荐＝方案 A：壳类字节码补齐）。
- **前置**：D238 已定案根因（见 `20261119-1550-D238-MCP工具清单热重挂只列前几个-开发计划.md` §4.4/4.5）。
- **严重度**：P1——MCP 工具清单在 2026.3 上只列 1~3 个（不稳定），**不可发版**。

## 一、问题陈述（一句话）

平台通过 **kotlin-reflect 扫 toolset 类上带 `@McpTool` 的 suspend 方法** 来生成工具清单；
我们为绕 Marketplace verifier 而在运行期手写字节码生成的「壳类」**没有 Kotlin metadata、declared 方法为 0**，
平台扫不到方法 → `requireAnyTool` 抛 `IllegalArgumentException` → **打断整轮 toolset 遍历**，
表现为「只列出注册顺序前 N 个，N 随机（1 或 3）」。

真机证据（2026-11-19）：

```
11 个壳类全部：declared=0  all=19~23  kotlinMeta=false
注册顺序反转 → 只列出反转后的前 3 个（history_search/mapper_check/reverse_sql）
平台字节码：requireAnyTool 在空列表时 new IllegalArgumentException + athrow
```

## 二、目标

壳类在反射层「看起来就是一个真 Kotlin 类」，使平台对**每一个** toolset 都能正常展开出自己的工具，
从而恢复「11 个工具稳定可见」。

## 三、技术方案（三层补齐，缺一不可）

现状壳类（`TinyClassFileWriter.shellBytes`）只生成：`final class X extends <业务类> implements McpToolset` + 一个无参构造器。

补三层：

### 3.1 复制父类 `@Metadata`（决定 kotlin-reflect 是否把它当 Kotlin 类）

- 从 `superClass.getAnnotation(kotlin.Metadata::class.java)` 读全部字段（`kind`、`metadataVersion`、`data1`、`data2`、`extraString`、`packageName`、`extraInt`）。
- 在壳类 class 的 `RuntimeVisibleAnnotations` 里写一条等价的 `Lkotlin/Metadata;`。
- 解析方向：kotlin-reflect 解析壳类时按这份 metadata 列出「应存在的函数」，随后到壳类自身方法表里按签名匹配——
  **只要 3.2 的 override 方法签名一致就能匹配上**。

### 3.2 为每个带 `@McpTool` 的父类方法生成 override（决定方法能否被匹配）

- 遍历 `superClass.declaredMethods` 中带 `@McpTool` 的**非私有**方法（含 suspend 形态：末位多一个 `Continuation` 参数、返回 `Object`）。
- 生成同描述符的 override，方法体：`aload_0` + 逐参数 load + `invokespecial <superClass>.<name><desc>` + `areturn/return`。
- 方法 flags：`ACC_PUBLIC`（与父类一致即可，无需 `ACC_SYNTHETIC`——合成标志会让 kotlin-reflect 忽略）。

### 3.3 复制方法注解（决定平台能否认出「这是工具」）

对每个 override 方法复制父类方法的 `RuntimeVisibleAnnotations`：
- `@com.intellij.mcpserver.annotations.McpTool`（name/title，纯 String）
- `@McpDescription`（含 String 与数组）
- `@McpToolHints`（含枚举数组）

实现策略：**从父类方法反射读注解实例 → 按 `Annotation` 的 `elementValues` 逐项编码**，避免手写每个注解的参数表。
先落 `@McpTool`（最小可用面），`@McpDescription`/`@McpToolHints` 第二批补——缺它们只是描述/hints 不全，工具本身可调用。

### 9.1 实际是四层缺陷叠加，一层一层才见底

| 轮次 | 现象（真机读数） | 真因 | 处置 |
|---|---|---|---|
| 一（`7020dfc23`） | 11 个壳类 `declared=1 kotlinMeta=true`，但 `tools/list` 0 个 | 枚举注解 `type_name` 写成 `Ljava/lang/Enum;`（`enclosingClass ?: superclass` 对无类体常量退化），JDK 抛 `AnnotationTypeMismatchException (Found data of type java.lang.Enum.TRUE)` | 改 `if (javaClass.isEnum) javaClass else superclass` |
| 二（`4d764b21c`） | 仍 0 个 | 把上一条误判成「metadata 不匹配」而摘掉 metadata；无 metadata → kotlin-reflect 走 Java 视图 → 平台 `CallableBridge` 报 `Continuation … of parameter 'argN' is not serializable` | 恢复 metadata（误判订正） |
| 三（`756011136` 内） | 11 个壳类各自 `asTools` 都出 1 个工具，但聚合清单只有 2 个 | 复制的 metadata 描述了业务类**全部**成员，壳类只声明工具方法 → `KotlinReflectionInternalError: Could not compute caller for function: private final suspend fun executeExplain(...)`；只有「metadata 里仅一个工具函数」的两个类活着 | 为业务类其余方法生成同签名占位（抛 `UnsupportedOperationException`），跳过与 `McpToolsetSupport` 同签名的 |
| 四（`756011136` 内） | 自检 11/11 全绿，`tools/list` 仍只有 1 个（连发 3 次重算请求无效） | `McpToolsListProvider.requestUpdate` 走 `computeAllMcpTools(previous)`，**复用**注册初期那份「只含前 1 个工具」的 provider 缓存 | 先经合成访问器调 `access$invalidateReflectionProviders` 摘缓存，再 `requestUpdate` |

顺带修掉：`encodeAnnotationValue` 漏了 8 种原始类型数组（`IntArray` 不是 `Array<*>`，被 `toString` 成 `"[I@…"`，`Metadata.mv()` 必踩）。

### 9.5 多版本核对（2025.3 / 2026.2 / 2026.3）

平台侧口径按版本不同（各版本发行版 `plugins/mcpserver/lib/mcpserver.jar` 字节码实证）：

| 版本 | kotlin-reflect | `CallableBridge`（参数必须可序列化） | 工具清单缓存 |
|---|---|---|---|
| 2024.3 (243) | 2.0.21 | 无（旧 mcpServer 形态，插件整体静默跳过） | — |
| 2025.3 (253) | 2.2.20 | 有 | 无 `McpToolsListProvider`，每次现算 |
| 2026.2 (262) | 2.3.20 | 有 | 有 provider 但无缓存（`emitMcpTools` 现算），无 `requestUpdate` |
| 2026.3 (263) | 2.4.0 | 有 | `toolsByProvider` 缓存 + `requestUpdate` + `invalidateReflectionProviders` |

结论：**缺陷在 253/262 同样存在**（同一条 `KClasses.getFunctions` → `getPreferredToolAnnotation` → `CallableBridge` 链），
修法一致；只有 263 需要「先摘缓存再重算」，253/262 没有缓存入口——代码里按 `requestUpdate` 是否存在分流，
缺失时记 INFO（老版本每次启动不再留 WARN）。

核对手法（不切 gradle 平台，直接用各版本发行版自带的 kotlin-reflect 与平台 jar 跑 D239 两个测试类）：

```
java -cp "build/classes/kotlin/{main,mcpStub,test};build/classes/java/test;
          <distro>/lib/*;<distro>/lib/modules/*;<distro>/plugins/java/lib/*;
          <distro>/plugins/Kotlin/kotlinc/lib/kotlin-reflect.jar;<distro>/plugins/Kotlin/kotlinc/lib/kotlin-stdlib.jar;
          junit4;hamcrest" org.junit.runner.JUnitCore <两个测试类>
```
