# 移除历史召回弹框 + 参数面板清除按钮开发计划

> 状态：✅ 已实施（2026-11-13 对账回填——`showRecalledHint` 弹框与 `panel.param.history.recalled` bundle 键已删，`panel.param.clear` 清除按钮在 `SqlPreviewPanelParamPanel` 在库）
> 需求来源：用户反馈——① 去掉「参数导入已恢复上次 N 项参数」弹框提示；② SQL 预览左侧参数面板全选/全不选附近新增「清除」按钮，用于清空参数值。

## 1. 目标与范围

1. **移除历史召回弹框**：去掉 `recallFromHistory()` 命中后弹出的 `Messages.showInfoMessage` 提示框（「参数导入已恢复上次 N 项参数」）。历史召回逻辑本身保留（参数值仍自动回填），仅去掉弹框打扰。
2. **新增「清除」按钮**：在参数面板的「全选/全不选」按钮旁新增一个「清除」按钮，点击后清空当前分区所有参数输入框的值（置空字符串），并触发 SQL 重渲染。

**已确认决策**：
- 移除范围：仅去掉 `showRecalledHint()` 的弹框调用及该方法本身；`panel.param.history.recalled` bundle 文案同步清理（中英文）。
- 「清除」按钮位置：在 `conditionSectionHeader()`（动态条件分区）和 `batchSectionHeader()`（批量参数列分区）的 EAST 按钮组中追加。
- 「清除」按钮行为：清空值输入框文本 + `paramValues` 对应条目置空字符串 + `renderSql()` 重渲染 + 触发 `saveToHistory()`（与手动清空输入框一致）。
- 不影响复选框勾选态（全选/全不选的功能独立保留）。

## 2. 现状分析

### 2.1 历史召回弹框（需移除）

private fun recallFromHistory() {
    val key = historyCacheKey() ?: return
    val history = paramHistoryCache.recall(key) ?: return
    if (history.isEmpty()) return
    var applied = 0
    history.forEach { (source, value) ->

### 2.3 参数值清空逻辑参照

手动清空单个输入框时走的路径：`DocumentListener` → `onParamChanged(source, value)` → `paramValues[source] = value` + `renderSql()` + `saveToHistory()`。

「清除」按钮需批量执行相同逻辑：遍历当前分区的所有 source → 置空字符串 + 更新输入框文本 + 重渲染 + 保存缓存。

### 3.2 新增「清除」按钮

#### 3.2.1 动态条件分区清除按钮

```kotlin
private fun conditionSectionHeader(): JBPanel<JBPanel<*>> {
    selectAllButton = compactButton(MpSqlVisualizerBundle.message("panel.condition.selectAll")) { setAllConditions(true) }
    selectNoneButton = compactButton(MpSqlVisualizerBundle.message("panel.condition.selectNone")) { setAllConditions(false) }
    clearButton = compactButton(MpSqlVisualizerBundle.message("panel.param.clear")) { clearConditionValues() }
    return sectionHeaderRow(
        MpSqlVisualizerBundle.message("panel.condition.section"),
        listOf(selectAllButton!!, selectNoneButton!!, clearButton!!),
    )
}

/** 清空动态条件分区所有参数值（不影响勾选态）。 */
private fun clearConditionValues() {
    val views = current?.previewModel?.conditionViews.orEmpty()
    views.forEach { view ->
        view.valueSources.ifEmpty { listOfNotNull(view.valueSource) }.forEach { source ->
            paramValues[source] = ""
            syncParamFieldText(source, "")
        }
    }
    renderSql()
    saveToHistory()
}
```

#### 3.2.2 批量参数列分区清除按钮

```kotlin
private fun batchSectionHeader(): JBPanel<JBPanel<*>> {
    batchSelectAllButton = compactButton(MpSqlVisualizerBundle.message("panel.condition.selectAll")) { setAllBatchColumns(true) }
    batchSelectNoneButton = compactButton(MpSqlVisualizerBundle.message("panel.condition.selectNone")) { setAllBatchColumns(false) }
    batchClearButton = compactButton(MpSqlVisualizerBundle.message("panel.param.clear")) { clearBatchValues() }
    return sectionHeaderRow(
        MpSqlVisualizerBundle.message("panel.batch.columns"),
        listOf(batchSelectAllButton!!, batchSelectNoneButton!!, batchClearButton!!),
    )
}

/** 清空批量参数列分区所有参数值（不影响勾选态）。 */
private fun clearBatchValues() {
    val model = current?.batchModel ?: return
    (model.toggleColumns + model.fixedColumns).forEach { col ->
        paramValues[col.source] = ""
        syncParamFieldText(col.source, "")
    }
    renderSql()
    saveToHistory()
}
```

## 6. 风险与注意事项

- **bundle key 清理**：`panel.param.history.recalled` 删除后需确认无其他引用（grep 确认仅 `showRecalledHint()` 使用）。
- **清除按钮与全选/全不选视觉区分**：三个紧凑按钮并列（全选/全不选/清除），需确认 FlowLayout 不截断（参照现有双按钮布局，第三个按钮应正常展示）。
- **不影响历史召回核心逻辑**：移除的仅是弹框 UI 层，`paramHistoryCache.recall()` 回填 + `renderSql()` 链路完整保留。
