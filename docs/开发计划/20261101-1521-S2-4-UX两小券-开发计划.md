## 一、券①侦察结论：换源链路现状与机制链

### P2 原始定义（T-DialectInferPollution §三，20261024-1136 册）

> 「last-used 数据源变化时，若预览渲染方言与新数据源方言不一致，自动重渲染预览（不等执行计划
> 闸门拦）」——涉及 last-used 写入点（rememberRunner）触发面板重渲染的生命周期编排，改动面大，
> 列为 T-DialectStatusLiveRefresh 的后续增强（P2）。

### 现状：生命周期编排已在，重渲染被明确关掉

2026-11-01 凌晨 `36a41af6`（「换源后存活预览面板即时刷新头部绑定行与方言徽章」）已把 P2 说的
「生命周期编排」建完：

- **换源成功事件**：`LastUsedChangeEvents.TOPIC`（项目级 messageBus），写入侧
  `DataSourceSelector.rememberRunner` / `forgetLastRunner` / `forgetAllLastUsed` 广播
  （DataSourceSelector.kt:1059/1082/1107）。
- **订阅侧**：`SqlPreviewPanel.init` 订阅（SqlPreviewPanel.kt:827-832）→
  `scheduleHeaderSourceRefresh()`（120ms 防抖 + 线程归位）→ `refreshHeaderSourceNow()`。
- **关键缺口**：`refreshHeaderSourceNow()` 调的是
  `refreshDialectStatusRow(rerenderSql = false)`（DialectStatusRefresh.kt:144-148）——**只刷
  头部绑定行 + 方言徽章，明确不重渲染 SQL**。当时注释理由「换源事件不是用户编辑，不得改写
  编辑器文本」。

### 为什么现在可以安全打开重渲染

`refreshDialectStatusRow(rerenderSql = true)` 的重渲染腿 `rerenderIfBoundDialectDiffers`
（DialectStatusRefresh.kt:159-168）**自带三重护栏**，恰好覆盖 P2 的关切：

1. `shouldRerenderForBoundDialect`（纯函数，DialectGateExitPolicyTest 已钉）：
   仅 `Source.BOUND_DATASOURCE`（last-used/绑定源这一具体目标）+ 目标方言≠渲染方言 + 用户未编辑；
2. 文本护栏：`currentEditorSql() == lastRenderedSql` 才重渲染——用户编辑永不吞；
3. 能力护栏：`rerenderForExecutionTarget` 模型不支持无损重渲染（xmlModel/分页行）自返回 false；
   MANUAL/CONFLICT 终态被 `pickStronger` 挡住（刷新链永不覆盖手动选择）。

换源场景走查（T-DialectInferPollution 现场逆放）：预览按旧源 PG 渲染（BOUND_DATASOURCE）→
用户切回 mp_demo（MySQL）→ 广播 → 重算决策 fresh=BOUND MySQL RESOLVED → `pickStronger`
同秩(2)不同内容 → 替换 → 方言不同且文本未动 → 重渲染成 MySQL。反向切换同构。

### 结论

**券①成立**，且改动面极小：`refreshHeaderSourceNow` 的 `rerenderSql = false` → 默认 true
（走既有渲染链 `rerenderForExecutionTarget`，不新造渲染器、不引全局单例），另更新 4 处
「不重渲染」时代的注释（DialectStatusRefresh.kt 两段 KDoc、SqlPreviewPanel.kt:824-826、
DataSourceSelectorLastUsedEvents.kt 文件头 KDoc）。

### 券①测试设计

新测试类 `SourceSwitchRerenderTest`（BasePlatformTestCase，同包 ui）：

- 正例：CrudSqlGenerator INSERT（batchModel，MySQL 渲染，CrudSqlPreviewPanelRenderTest 先例）
  → `probeByNameForTest` 缝注入（pg 源名 → PG jdbc url）→ `plantLastUsedMemoryForTest` 初始
  MySQL 源 → `rememberRunner` 切到 PG 源（生产写入入口，内部广播）→ dispatch+轮询断言
