## 二、目标

1. `CHANGELOG.md`、`docs/变更记录.md` 不再无限增长——旧内容按时间归档，主文件只保留近期 + 归档指引。
2. `docs/MEMORY.md` 索引：①补齐 511 条漏登记；②修复 10 条失效链接；③约束索引行长度（每条一行、控制在 ~200 字符），把详情留在被指向的文档里。
3. 全程不改变任何被引用文档的内容与位置语义（除非确需改名，改名须同步全仓引用）。

## 三、方案与决策点

### 3.1 CHANGELOG.md

- **约束（须先验证，见 P1）**：`build.gradle.kts:8` 应用了 `org.jetbrains.changelog` 插件，其 `path` 默认指向根 `CHANGELOG.md`；虽然 changeNotes 已由 `build.gradle.kts` 的 patchPluginXml 显式配置（不依赖该插件解析），但**插件的 `changelog` 扩展与 `patchChangelog` 等任务仍默认读根 `CHANGELOG.md`**。
- **D1（根文件保留 + 旧版归档）**：根 `CHANGELOG.md` 保留最近 N 个版本（建议 N=8，覆盖在售与近版），更早版本移入 `docs/变更记录/changelog-archive-{YYYY}.md`（新目录）；根文件顶部加归档指引链接。
- **D2（不动插件 path）**：保持 `CHANGELOG.md` 在根、插件 path 默认值不变——把归档做成「根文件仍存在且结构合法（Keep a Changelog），只是内容截短」，插件任务不受影响。

### 3.2 docs/变更记录.md

- **D3（按年拆分 + 根保留索引与最近）**：`docs/变更记录.md` 改为按年归档 `docs/变更记录/{YYYY}.md`，根文件保留「说明 + 最近一年 + 各年份链接」。纯 docs，无构建依赖（实测 grep 无代码读取），拆分安全。
- **D4（逐行迁移不重排）**：迁移时逐行原样搬运（表格行整行剪切），不做内容重写，保证零语义漂移；搬完用行数/字符数对账。

### 3.3 docs/MEMORY.md

- **D5（补积压）**：按目录分批补登记漏登记条目；**只增不改既有行**（避免与并行会话冲突）。每条一行摘要，超长摘要截断并把详情留给被指向文档。
- **D6（修失效链接）**：10 条 `20260820-*` 失效链接按「文件存在且语义对上」原则改指真身；语义对不上的（文件确已不存在）改为纯文本并注明「原文档已不存在」，**不指向错文档**（沿用 `project-doc-conventions` 的既有判据）。
- **D7（瘦身既有长行）**：`docs/MEMORY.md` 内已有的超长索引行（部分单行数千字符）压缩到一行摘要——此项与并行会话有冲突风险，**建议单独提交、改动最小化**，或延后到补积压之后。
- **D8（分阶段）**：补 511 条是机械但量大的活，按目录分 3~4 批提交（开发计划 / 调研报告+验收文档 / 其余），每批跑一次链接存在性校验。

## 四、待验证前提

- **P1（关键）**：`org.jetbrains.changelog` 插件在根 `CHANGELOG.md` 被截短后，`./gradlew` 常规任务（含 `buildPlugin`/`patchPluginXml`）**不受影响**——须实测：先本地截短一份 CHANGELOG 试跑 `./gradlew tasks --all | grep -i changelog` 与 `./gradlew patchPluginXml`，确认无解析失败。若插件要求完整 `[Unreleased]` 段，则截短策略须调整为「保留 `[Unreleased]` + 最近版本 + 归档」。
- **P2**：`docs/变更记录.md` 确无构建/测试依赖（已初步 grep：仅 `mpv-release.gradle.kts` 注释提及 CHANGELOG，未提及变更记录）；拆分后全仓 grep `变更记录.md` 的引用逐处核对。
- **P3**：`docs/MEMORY.md` 索引补登记期间**无并行会话同时改该文件**（本仓高频并行）——实施前 `git status` + 与他人协调，避免巨型表格行冲突。
- **P4**：`docs/内部/` 是嵌套私有仓工作副本（`.gitignore:95`），索引补登记**不得**把它纳入（其内容不入公开索引）。
- **P5（2026-10-10 补）**：仓库已落 `.gitattributes`（`28103a1`，仓库 LF / 检出 CRLF）——本任务的拆分/改名**无需再手工处理行尾**（此前「新建文件默认 LF 要随批转回」的人工步骤作废）。验证时用 `git cat-file -p HEAD:<path>` 读 blob 确认仓库侧为 LF 即可（工作树是 CRLF 属正常）。
