## 一、背景与依据

三件事，一件是免费的验收清单，一件是守住生态位叙事，一件是盯住最大盲区：

1. **structuredContent 协议合规核查**。DBX 在与我们交付 MCP 工具的同一周返工：批执行返回从裸数组改为 `{"results": [...]}` 对象（`crates/dbx-mcp/src/server.rs:949`）——MCP 协议要求 structuredContent 必须是 JSON object，数组不合法。我们的三只读工具（`SqlVisualizerToolset.kt` sqlv_render_sql :58 / sqlv_schema_context :103 / sqlv_explain :141）全部返回 `String`，理论上平台应把它包进 content 文本块而非 structuredContent——但这只是推断，必须对 262 mcpserver.jar 做一次序列化路径实证，不能拿「应该是」当「验证通过」。
2. **位差叙事**。CodeHelperPro 的 `validate_mybatis_mapper` 是校验器（告诉你 SQL 可信度、给测试指引），我们的 `sqlv_render_sql` 是渲染器（直接给 agent 可执行 SQL + schema 上下文）。agent 消费 SQL 时校验是辅助、渲染是主链——这个位差目前只存在于我们自己的报告里，工具描述、plugin.xml、README、marketplace 页四处用户可见面都没有讲。
3. **MyBatisX 过审复查触发器**。MyBatisX（540.9 万下载）待审新版已压 8 天以上，开源仓库 2024-08 起死亡、纯闭源上传，内容完全盲区。它是唯一一个能一夜改变格局的玩家，需要一台低成本的哨兵。

## 三、方案

**T-MG-01（核心核查）**：实证 262 mcpserver.jar 对 `String` 返回的序列化路径。javap `com.intellij.mcpServer` 包的 CallToolResult/内容包装类（262 平台 `plugins/mcpserver/lib/*.jar`，Python zipfile + 常量池法）；辅以真机一条 `sqlv_render_sql` 调用看平台日志/响应原文。判定分支：a) 走 content 文本块 → 记录结论归档，本轮无需改码；b) 走 structuredContent → 必须包对象（参照 DBX `{"results": [...]}` + statement_index 字段形态），同时 243/253 行为差异留痕。**结论两种都要落进计划 §八，禁止不核查就跳过。**

**T-MG-02（多语句返回面核查）**：`sqlv_render_sql` 的 filePath 模式可一次渲染多条语句（产物自带 `-- SQL #N` 注释头）。核对纯文本多语句形态对 agent 消费是否友好（无歧义切分），必要时在 @McpDescription 补一句「多语句以 -- SQL #N 注释行分隔」。纯文案改动，零协议风险。

**T-MG-03（位差叙事四处落点）**：
- `SqlVisualizerToolset.kt` 三处 @McpDescription 各补一句差异化（英文，面向 agent/开发者）：渲染器定位 + 只读确定性 + 与校验类工具的互补关系；
- README MCP 段与 marketplace-custom-page.html 各加一小节「MCP：给 AI agent 的确定性 SQL 工具」，一句话位差（校验器告诉你可不可信，渲染器直接给可执行 SQL）；
- plugin.xml description 若有 MCP 字样随同步（bundle parity 守卫覆盖的面照常走双语）。

**T-MG-04（MyBatisX 过审哨兵）**：新增 `dev-support/check_competitor_watch.ps1`——curl Marketplace updates API（10119 MyBatisX、14522 CodeHelperPro 付费版、32766 Analyzer），对 changeNotes 关键词扫描（preview / log / restore / mcp / validate / 校验 / 预览 / 还原），命中即打印告警块；网络失败走 `-x 127.0.0.1:7890` 兜底（照抄 ci-verify.ps1 的代理处理）。注册进既有 Windows 计划任务（与 ci-verify 同任务追加或独立每日任务），输出追加日志文件供人工巡检。纯脚本，不进插件产物。

**T-MG-05（文档同步）**：CHANGELOG [Unreleased] Added/Changed 条目（文案类改动进 Changed）、变更记录总册行、第四轮报告 §11 索引状态回填「N-16 已立项 → 已交付」。
