# 开发流程：派活与验收清单

> 本文是 `AGENTS.md` 第 3 条指向的作业细则：主控怎么派活、子代理怎么交活、收口怎么验收。只写可执行动作，规则来自多轮并行开发的实际返工点。

## 一、派活模板

每条派活必须写死以下六项，缺一项就会在现场临时猜：

1. **工作树与分支**：`git worktree add .worktrees/<名> -b t-<名> <基线>`；分支用扁平名，不用 `feature/` 前缀（第三方工具曾连坐删除 `feature/` 整目录）。
2. **写集**：列出该车道会碰的文件/目录，并保证与其它车道互斥；计划册、`CHANGELOG` 这类多车道共写的文件提前说明冲突处理方式。
3. **只跑定向**：`./gradlew test --tests "<FQCN>"`（agent 子项目 `:sql-visualizer-agent:test --tests "<FQCN>"`）。禁 `testShards` / `verifyGate` / `verifyPlugin` / `clean` / `--stop` / 全量。
4. **并行登记**：跑 gradle 前 `python C:/Users/USER/.zcode/cli/parallel_tasks.py check`；有活跃任务先 `register --name <名> --sandbox <工作树绝对路径>`，跑完 `done --name <名>`（禁裸 `done`，它会注销全部活跃任务）。
5. **提交纪律**：每完成一件可提交的就立即提交；`git add` 具体文件；消息写文件后 `git commit -F`（消息里禁反引号——Git Bash 会做命令替换；中文用 Write 工具写文件，Bash 直传中文易乱码）。
6. **报告字段**：改动文件、提交哈希、定向读数（N/失败/错误/skip）、反向验证读数、未完成项与风险。没跑过的读数不许写「全绿」。

红线（每条派活都写）：不 push、不合流、不建 tag、不动 `update/update.json`；不碰别人的工作树；计划回写只写自己工作树里的副本，主仓副本只读。

## 二、验收清单

1. **读数可复核**：读数要能对上 `build/test-results/*.xml` 或 Gradle 输出，不接受「全绿」两个字。
2. **反向验证**：每条修复至少一条「摘掉必红」探针，贴摘除与还原两次读数。守卫/扫描类改动还要证明探针有判别力——合成样本只能证明「规则看得见我造的形态」。反证优先走自动化工具 `dev-support/reverse_probe.py`：改既有行为的提交用 `--commit` 整提交反打；新增能力型提交（机制与测试缝同批落地，整提交反打必然编译不可判）用 `--patch` 手术式补丁（禁用机制判定、保留测试缝，补丁入库 `dev-support/reverse-probes/` 并登记进该目录 README 清单）。锚定用例集按机制最小面取（禁带回归面）；脚本四态判定（通过/失败/补丁冲突/编译不可判）原样贴进报告，退出码非 0 时如实注明。
3. **not run 条款**：没跑的测试、门禁、真机逐项列「没跑 + 为什么」；环境受限只能写「环境受限未验证」，不得拿受限环境读数冒充验证通过。
4. **合并复核**：冲突按「保留双方」解（计划册章节要重排后回读）；合并后在集成分支重跑定向——各支自报读数之和不是权威读数。
5. **文档三件**：计划册状态与实施记录、`docs/索引/开发计划.md` 索引行、`CHANGELOG`（带提交哈希）；改契约的同批更新 `docs/架构设计/` 归属文档。

## 三、并行与资源

- 构建并发默认上限 2 路；用户显式放开才可突破。
- 长命令一律后台启动，禁 sleep 轮询；子代理拿不到锁就记录证据交回主控复跑。
- 子代理并发默认 ≤3（账户限流）；派活前确认当前车道数。
- **多组并行部署/运维任务**（2026-11-12 整机重建实测）：主控把「恢复作业基准」写成服务器上的共享文件（端口/镜像/变量名的唯一事实源），凭据只放服务器 600 文件、基准里只写变量名；各组读同一份、写集互不重叠。组间抢带宽/抢共享资源/孤儿进程**由主控读 `ps`/`du` 证据后统一处置**（清孤儿、定错峰顺序），不叫子代理自己 kill。判据落在「写进磁盘的字节」与「实连通不通」：环境会把库名/容器名/变量名在显示层替换成随机串，别拿显示串改脚本，用逐字节 hex 或实连自证。别在任务运行中改脚本——在途进程会读到写到一半的中间态（内嵌 Python 泄漏到 shell 报 syntax error），改前先确认无在途读者、改完 `bash -n` + 内嵌语言 `compile` 双检。详见 `docs/LESSONS.md` L56 与 `docs/经验总结/20261112-2140-测试服务器整机重建与备份体系入仓-经验总结.md` §五。

## 四、常见坑（本轮实测）

- **工作树的 `.git` 是文件不是目录**：提交消息写 `/tmp/msg.txt`，不要写 `.git/COMMIT_MSG`。
- **Windows 长路径删不掉**：用 `\\?\` 前缀 + `rd /s /q`，写成 `.ps1` 执行（Git Bash 会把 `/X` 参数当路径转义）。
- **「缺 jar 才 skip」的名单别混厂商**：把新厂商塞进 `JAR_OPTIONAL_BYTE_LAYER` 会让 MariaDB/SQLite 的 absent 判据变假，整条用例被 skip 掉；正确做法是进 `BYTE_VERIFIABLE_EXCLUDES` 并单开专项用例。
- **新增 i18n 键**要中英双份并过 `BundleParityGuardTest`；新增能力面常连坐 convention 守卫（元守卫登记、计数、白名单），先跑守卫再改实现。
