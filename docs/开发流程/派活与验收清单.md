# 开发流程：派活与验收清单

> 来源：T-MagpieGems W6（2026-10-23），机制对齐 magpie 的 code-standards 验收条款。给子代理派活时**整段复制本模板**并按任务填写；收口复核时逐条打勾，**没跑的检查项必须标 `not run`，不得省略**——magpie 原文："What wasn't tried with the real thing isn't built on and isn't told to users as working."

## 一、派活模板（复制即用）

```
【任务】<一句话目标>。参考：<计划文档相对路径 + 节名>。
【工作树】只在 <绝对路径> 工作（分支 <分支名>）；绝不碰主仓与其它工作树。
【写集】<允许改的文件/目录清单>；写集之外一律不动。
【现状结论】<已核实的 文件:行号 事实直接给，不让子代理重复考古>。
【验证前提】<需要先证伪的假设，写「先证伪再动手」>。
【测试纪律（硬性）】
  - 只跑本任务定向测试：./gradlew test --tests "<FQCN>"（多个并列）；纯逻辑桶用 testFast；
    testFast 与 --tests 同用必失败，禁混用。
  - 禁跑全量/testShards/verifyGate/verifyPlugin/buildPlugin；禁 clean；禁 --stop。
  - 跑 gradle 前：python C:/Users/USER/.zcode/cli/parallel_tasks.py check；
    有活跃任务先 register --name <车道名> --sandbox <独立沙盒>，跑完 done --name <车道名>
    （禁裸 done，会注销全部）。
  - --tests 过滤不匹配会静默跳过：读数按「每类用例数」收，判据数对不上就是没跑。
  - 守卫/迁移类改动：摘掉新分支反向探针必须变红，贴两次读数。
【提交纪律（硬性）】
  - 每完成一件可提交的就立即提交；中文提交信息写 UTF-8 文件用 git commit -F（禁 -m 内联）。
  - 提交后 git show --stat HEAD 确认只含自己写集的文件，读数贴进报告。
  - commit body 带验证记录（跑了什么定向、读数多少），不写在聊天里就算数。
【报告】改动文件清单 + 每步提交 hash + 定向读数（按类：通过/失败/跳过）+ 反向读数 + 遗留；
  禁出现「全量绿」这类没跑过的读数；环境失败如实登记 not run。
【回填】计划 §实施记录回写你工作树里的副本，主仓副本只读。
```

## 二、验收清单（收口复核逐项打勾）

| # | 检查项 | 读数 |
|---|---|---|
| 1 | 定向测试：按类给通过/失败/跳过数，判据数=XML 类数 | |
| 2 | 反向验证：摘修复分支变红（贴两次读数）；不可观测的按「防御保留、不登记为已验证」 | |
| 3 | `git show --stat HEAD` 每笔只含自己写集文件 | |
| 4 | commit body 含验证读数 | |
| 5 | 改动落 config/State/守卫类 → testFast 整桶跑过 | |
| 6 | 写集外文件零改动（git diff --stat 对账） | |

| 8 | 教训补记：有新复发 → docs/LESSONS.md 加条目（规则+hash+Seen） | |

## 三、收口与全量

- 全部车道完成后**单派一个只读收口代理**跑权威全量（按登记表独立沙盒）；主控并行写文档，**收口期间禁改 `src/main`**（改了绿就过期，必须复跑）。
- 全量只单路；跑前 `timeout 10 docker info` 验 daemon 活性；禁降片。
- 构建校验（verifyGate/verifyPlugin/verifySmoke/buildPlugin）只在大改动或发版前跑；大改动判据见 `~/.zcode` 用户指令「验证与收口纪律」。
