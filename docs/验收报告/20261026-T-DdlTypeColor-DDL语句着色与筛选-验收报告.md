# T-DdlTypeColor 验收报告：DDL 语句纳入类型着色与筛选

> **验收日期**：2026-10-26
> **实施分支**：`master`
> **计划文档**：[20261026-2110-T-DdlTypeColor-...-开发计划.md](../开发计划/20261026-2110-T-DdlTypeColor-DDL语句纳入类型着色与筛选-开发计划.md)
> **用户两项定案**：①视觉用虚线色条区分 DDL 与 DML；②归类按主控推荐

---

## 一、解决的问题

改造前 `CREATE` / `ALTER` / `DROP` / `TRUNCATE` 全被归为 `OTHER`，而 `OTHER` 不参与着色——
建表删表语句在列表里**没有任何类型标识**，筛选弹窗里也勾不到，想「只看结构变更」做不到。

## 二、交付内容

### 2.1 分类扩展

| 新类型 | 覆盖首 token | 着色 | 语义 |
|---|---|---|---|
| `CREATE` | `CREATE` / `ALTER` / `RENAME` | 复用 INSERT 绿 | 结构性新增/变更 |
| `DROP` | `DROP` / `TRUNCATE` | 复用 DELETE 红 | 结构性删除/清空 |

`MERGE` / `REPLACE` / `CALL` 仍留 `OTHER`（不着色、不进筛选）——归任何一档都会误导。

**为什么不直接复用 INSERT/DELETE 档**：筛选是按类型勾选的。若 CREATE 就是 INSERT，
勾「只看插入」会把建表一起筛出来——语义错误。类型独立、颜色复用，两者解耦。

### 2.2 视觉：虚线色条

| 语句 | 色条形态 |
|---|---|
| DML（SELECT/INSERT/UPDATE/DELETE） | 3px 实心（不变） |
| DDL（CREATE/DROP） | 3px **虚线**，实 3px / 空 3px |

语义：虚线 = 「不连续」「非普通数据操作」。不额外占宽度（侧栏空间敏感），
比加粗含蓄、比双色在 3px 内更有辨识度。

### 2.3 筛选

`FILTERABLE_TYPES` 从 4 项扩到 6 项，筛选弹窗新增「建表」「删表」两项，
可单独筛选结构性变更。

## 四、实施中抓出的真 bug：同色画同色 = 没画

初版 `paintComponent` 是「先铺 `background` 底色，再按段填 `background` 前景色」——
前景与底色同色，渲染出来**整条全实心**，虚线完全没生效。

隐蔽性在于：**形态断言（`dashed == true`）照样通过**，深色背景上看 3px 宽的实心绿条
与虚线绿条也容易糊过去。最终靠**像素序列实测**抓出：

```
修复前：DASH pattern=[########################################]   ← 全实心
修复后：DASH pattern=[###...###...###...###...###...###...###.]  ← 正确交替
```

修法：空白段**不铺任何底色**，让父容器背景自然透出。

已沉淀两条像素级守卫（不是形态断言，是渲染后逐像素读）：
- `test虚线色条_像素序列为实空交替`——断言存在 `#` 与 `.` 且以 `###...` 开头
- `test实心色条_像素全填满`——实心形态不得出现空白段

## 五、既有断言的三处改判

三处既有测试断言了旧语义，已按新语义更新并在注释里写明改判理由：

| 文件 | 原断言 | 新断言 |
|---|---|---|
| `LogStatementClassifierTest` | `TRUNCATE 归 OTHER` | `TRUNCATE 归 DROP` |
| `LogStatementClassifierTest` | 全类型等价表 `TRUNCATE → OTHER` | `TRUNCATE → DROP` |
| `HistoryCellRendererTest` | `OTHER 不应着色`（用 TRUNCATE 举例） | CREATE 取绿、DROP/TRUNCATE 取红、MERGE 仍不着色 |

## 六、待真机确认

**虚线在深色主题下的辨识度**——本次唯一的主观判断项，headless 测不出观感。

若偏弱，调 `TypeColorBar.DASH_ON` / `DASH_OFF`（两个常量，改一个数即可），
**不要改回实心**——用户明确选了虚线，观感问题应通过调整段长解决而非放弃形态。

另需确认：
- 三种显示模式下虚线段是否都正常（单行模式行高较矮，段数较少）
- **与「整行淡背景」样式组合时的边界**：该样式下根本不画色条（`applyCrudColorMark` 的
  `STYLE_BACKGROUND` 分支把 `colorBar` 设为不可见），故 DDL 的虚线标识**会消失**，
  只剩底色深浅——而 DDL 与对应 DML 底色相同（CREATE 与 INSERT 同绿、DROP 与 DELETE 同红）。
  **这是本次改动的已知边界**：选了「整行淡背景」的用户，在该样式下无法区分 DDL 与 DML。
  默认样式是「左侧色条」，多数用户不受影响；如需覆盖该样式，可另立任务在背景混色比例上区分
  （如 DDL 用 1.6× 混色），但本次不做——不擅自扩大改动范围。
