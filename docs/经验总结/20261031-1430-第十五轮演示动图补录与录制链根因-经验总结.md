# 第十五轮演示动图补录与录制链根因（2026-10-31）

> 触发：R15 补录计划六张片子（dialect-gate 重录 / mapper-nav-jump / xml-editing-support /
> preset-method-binding / ddl-type-color / stack-scheduler-thread）。其中 R1 与 N3/N5 分别撞上
> 两条**与插件无关**的链路问题（平台 runner 枚举、沙盒构建静默死亡），N2 撞上一条**真插件缺陷**。
> 结论先行：**本轮的时间成本几乎全花在「录制链路的环境与平台语义」上，而不是录制本身**；
> 真正需要改产品代码的只有一处（`ParamBraceTypedHandler` 嵌套判据），其余全是判据缺失。

## 一、量化归因

| 段 | 耗时占比 | 产出 | 卡在哪 |
|---|---|---|---|
| R1 dialect-gate | ~40% | 1 张（重录） | 平台 runner 枚举方言过滤 + 目标库选错 + 提示行被报错覆盖 |
| N1 / N2 / N4 | ~25% | 3 张 | N2 是插件缺陷（先证伪再修）；N4 是 combo 交互 |
| N3 / N5 | ~35% | 2 张 | 沙盒构建静默死亡（跨会话复现两次才定位到外部工程配置） |

**R1 的六次 take 里只有最后一次成片**：前五次全部是「选择器不弹」「执行到 PG 报错」「提示行被覆盖」。
**N3/N5 的前两轮尝试零产出**：构建进程根本没起来，应用跑不起来，捕捉面永远「已挂载 0 个」。

## 二、沙盒构建与启动

### 2.1 构建静默死亡（本轮最大成本）

- **现象**：`log/build-log/build.log` 停在 `Pre-loaded process ready`（无编译行、无错误行）；
  运行配置报 `Process not started by some reasons. Probably build process failed`；
  MCP `build_project` 180s / 300s 两轮都 `{"isSuccess":false,"problems":[],"timedOut":true}`。
  界面只在 Build Output 里留一行 `java: Cannot compile module 'shardingsphere-h2-demo'` +
  气泡「Please add JDK 8 or later」。
- **根因**：沙盒 IDE 读的是**外部工程配置**
  `<sandbox>/system/projects/<proj>.<hash>/external_build_system/modules/<module>.xml`，
  其中 `LANGUAGE_LEVEL="JDK_17"`（由该模块 pom 的 `maven.compiler.release=17` 导入）与项目 SDK 8
  冲突 → 编译中止 → 整个构建进程退出 → 应用起不来。
- **踩过的弯路**：先改了 demo 仓 `.idea/compiler.xml`（`<module target="1.8"/>`）并重启 IDE，
  日志里仍然报 17——**沙盒不读 demo 的 `.idea/compiler.xml`**，两套配置。这条弯路白烧一轮重启。
- **处置**：把 `external_build_system/modules/<module>.xml` 的 `LANGUAGE_LEVEL` 改 `JDK_1_8`。
- **判据链（修完必须三步全过）**：Build Output 有编译行 → `execute_run_configuration` 返回
  `fullOutputPath` → `curl :8081/user/list` 200。
- **附带教训**：`build_project` 的返回里 `problems:[]` 是**假绿信号**——它只报编译诊断，不报
  「进程没起来」。判构建要看 `build-log/build.log` 的末行与 Build Output 面板。

## 三、捕捉面边界

- **Database 控制台（DbConsole）执行的 SQL 不进捕捉面**：诊断行恒
  「控制台：已挂载 0 个」，而在 Run 控制台里跑的应用能被挂上（`已挂载 2 个`）。
  想拍 DDL/DML 素材**必须让应用自己执行**——本轮给 demo 调度任务加了一次性
  `createDemoTable()` / `dropDemoTable()`（首拍建表、第六拍删表），DDL 条目才进列表。
- **捕捉开启时机**：应用已在跑时再开捕捉能挂上（实测），但**历史条目不回扫**——开完要重新触发
  一次动作（重启应用最省事）。
- **判据**：开录前读诊断行 `已收事件 N 条 / 控制台：已挂载 N 个`，两处都非零才算在收。

## 四、平台 runner 枚举（R1 的真因）

- **runner 按 exec 文件方言过滤**：exec 文件被按渲染方言预映射后（日志
  `[M36] dialect pre-mapped to PostgreSQL for mpsql-exec.sql`），平台只返回该方言的数据源：
  有 PG 源时 `[M36] runners=1` → `single runner, run directly` → **数据源选择器永不弹**；
  把两个远端 PG 源临时移出 `.idea/dataSources.xml` 后变成 `runners=6` → `show popup with 6 runners`
  → 选择器才出现。
- **推论**：任何「让用户选一个不匹配数据源」的演示，都必须先构造「渲染方言没有对应数据源」的
  环境，否则演示不出选择动作。
- **目标库选择的硬条件**：`FROM "user"` 要真跑通，①目标库得有全字段——`mp_demo.user` 13 列，
  `mpj_demo.user` 只有 `id/name/age/sex/head_img` 五列；②数据源 URL 要带
  `sessionVariables=sql_mode=ANSI_QUOTES`。MCP `create_database_connection` **拒**带该参数的 URL，
  只能先纯 URL 建源、再改 `dataSources.xml` 补参数。
- **放行态信息行会被真实报错覆盖**：`showStatus()` 走下一拍 EDT，真实执行错误随后覆盖同一个
  infoLabel。想让「方言不一致」提示停在画面里，**执行必须成功**；否则提示行只在画面闪一帧。

## 五、UI 交互实测（每条都白试过至少一轮）

| 现象 | 真因 | 处置 |
|---|---|---|
| 点日志条目的栈 chip 无反应 | 栈弹层是**预览面板 meta 行悬停**触发（`StackFrameHover`，400ms 防抖），列表 chip 点了只选中条目 | 双击条目开预览 → 悬停「调用栈:」 |
| 预设下拉切到同一项参数不回填 | combo 选**同值项是 no-op** | 先切「默认预设」再切回目标预设 |
| combo 第一次点不开弹层 | 首击可能只给焦点 | 「点了没弹就再点」，最多三轮 |
| 弹层里点选项反复落空 | JBPopup 项在边缘命中率差 | 键盘 `Up/Down + Enter` + 回填像素断言兜底 |
| 栈 chip 点不到 | 工具窗太窄，`[SchedulerDemoTask.java:40]` 被截断 | 录制前先拖宽工具窗，再标坐标（中途改宽＝整批坐标作废） |
| 「知道了」/快速预览提示条点不掉 | 列表内嵌提示条对合成点击免疫 | 容忍入镜，或先关「快速预览」引导 |
| `Ctrl+A` 把 demo 源文件清空 | 模态预览对话框关掉后，同样的键打到编辑器（两次） | 任何「全选+替换」前断言目标窗口存在性；误伤恢复＝**先关页签 → git checkout → 重开**；**IDE 退出会把脏文档写回盘**，退出后要再 checkout 一次 |
| 点 IDE 区域却打到别的应用 | 全屏 topmost 应用在前台（magpie） | 合成输入前断言 `GetForegroundWindow()==IDE hwnd`；不一致先 Alt 按放 + `SetForegroundWindow` |

## 六、产物与验收

- **poster 默认取 kept frame #N，不一定是关键定格**：R1 首版 poster 落在光标压住信息行的那帧，
  要按内容选帧；**光标 overlay 会烧进画面**，收尾落点必须避开关键文字（本轮重录一次）。
- **接缝 diff 口径**：结构性变化（首帧纯预览 / 末帧带提示）允许 >1 并登记（R1 实测 6.06）；
  同态场景应 <1（N1 0.03 / N4 0.18 / N2 0.33）。
- **抽帧核对**：`ffmpeg -vf "select=eq(n,N)"` 抽帧 + PIL crop/zoom，比整图目视快且能定位到行。
- **规格校验工具化**：本轮把逐张手核改成 `node record/tools/verify_gif.mjs --dir <目录>`
  （尺寸/帧数/帧率/时长/体积/poster 六项 + 例外清单 `gif_spec_allow.json` 带原因），
  全站 69 张一次跑完 69/69 通过。

## 七、插件缺陷（本轮唯一需要改产品代码的）

### 7.1 `#`/`$` 自动补 `{}` 在主流排版下全灭（已修）

- **现象**：`UserMapper.xml` 的 `<where><if>` 体内行尾敲 `#`，只落裸 `#`，不补 `{}`。
- **根因**：`ParamBraceTypedHandler.inStatementText` 只看**一层** parent（`tag.parentTag`），
  `<if>` 的 parent 是 `<where>`，两个都不在语句标签集里 → 直接 `return false`；
  同时 `offset >= tag.textRange.endOffset` 把「子标签体内正文」与「子标签标记区」混为一谈。
  真实 mapper 几乎全是 `<where><if>` / `<choose><when>` 排版 ⇒ 功能在主流形态下全灭。
- **修复**（`e69c6e5d`，T-XmlBraceNested）：改为「最近语句标签祖先（任意深度，`take(64)`）+
  体内容孩子（XmlTag/XmlText/XmlComment）推导标记区」。计划草案里的 `tag.startTag` / `endTag`
  **在 262 平台不存在**（javap 实证），编译期被拦下。
- **测试**：`ParamBraceTypedHandlerTest` 新增 5 用例（嵌套 if/when 体内、单层 if 体内、语句属性区、
  自闭合子标签之后）+ 原 6 用例 + `XmlGapEditingAssistTest` 11 用例 = 22/22 绿。
  首轮 2 红里有 1 红是**夹具错**（光标放在 `{` 前撞上「先查后插」守卫）——写用例前先看清早退分支。

### 7.2 `#{…,` 结构属性键补全不出（待查）

- 现象：`#{status,` + `Ctrl+Space` 出的是 SQL 关键字/列名，没有 `jdbcType=` / `javaType=`。
- 伴随平台 `AsyncCompletion` SEVERE：`MpSqlMapper:UserMapper.xml != MpSqlMapper:UserMapper.xml`
  （注入身份断言，日志两次实录），栈落在 `CompletionInitializationUtil.setOriginalFile`。
- 影响：站点正文「`#{}` 占位符补 `jdbcType`/`javaType`/`typeHandler` 等结构属性」在当前 2026.2
  实测不成立 → 文案需加限定或回落，待定位后定夺。

## 八、结论与下轮动作

1. **录制开工前的三件事**（已并入 skill 坑 79/80/81）：构建能否起来（`build.log` 越过
   `Pre-loaded process ready`）、捕捉面是否挂上（诊断行非零）、runner 枚举是否符合演示需要。
2. **演示「冲突」类功能必须构造冲突环境**，不能指望默认状态出现选择动作。
3. **判据缺失是主要成本来源**：本轮 8 条 UI 交互坑里 6 条是「我不知道它是这么交互的」，
   不是「它坏了」。下轮遇到「点了没反应」，先查源码的交互契约（悬停/点击/键盘），再怀疑坐标。
4. 承接文档：`docs/录制/演示GIF录制指南-说明文档.md`（操作手册）、
   `.agents/skills/ide-demo-gif/SKILL.md`（坑表 79~89 已并入）、
   文档站 `docs/验收文档/20261031-第十五轮同步演示动图补录-验收文档.md`（逐图判定与读数）。
