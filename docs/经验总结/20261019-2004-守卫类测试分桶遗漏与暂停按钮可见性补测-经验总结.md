# 守卫类测试分桶遗漏与暂停按钮可见性补测——经验总结

- 日期：2026-10-19 20:04
- 背景：T-EnhancedCaptureDefaultOn（增强捕获默认开启）与 T-AgentPauseVisibility（暂停按钮方案 B）落地后，全量 `testShards` 先后抓到两处守卫失败；暂停按钮的可见性改动此前没有对应用例。
- 结论：两处守卫缺口不是「没写测试」，而是定向验证没有跑 `testFast` 快桶；暂停按钮是真实缺测。补测后 `testFast` 4100/0/0/6，布局测试 19/0/0。

## 二、为什么定向测试没有覆盖

1. `SettingsRealityGuardTest` 与 `GuardSelfTestCoverageMetaGuardTest` 的源码都**不含 `com.intellij` 引用**。按 `buildSrc/src/main/kotlin/mpv-testing.gradle.kts:284-295` 的划桶规则，它们属于 `testFast` 快桶。
2. 本轮定向验证用的是 `./gradlew test --tests <手选清单>`，走平台 `test` 任务，不会执行 `testFast`；两个守卫都不在手选清单里，所以定向全绿。
3. 全量 `testShards` 的类全集包含它们，才把缺口暴露出来。
4. 结论：改动触达 `PluginSettings.State` 或新增/删除守卫类时，`test --tests` 不是充分验证面；`testFast` 才是快桶的正确入口。

## 三、补测内容

1. `EnhancedCaptureDefaultOnGuardTest.test兼容字段豁免不得过期`：扫 `src/main`，断言两个兼容字段只在 `config/PluginSettings.kt` 出现；并断言 `loadState` 仍归一 `confirmed=true`、`rejectedAtMs=0`。防止 `compatOnly` 豁免变成永久免检。
2. `EnhancedCaptureDefaultOnGuardTest.test本守卫类已登记到元守卫`：断言本类出现在 `GuardSelfTestCoverageMetaGuardTest.GUARD_CLASSES` 中；单跑快桶即可抓到「新守卫类未登记」。
3. `SqlLogPanelLayoutTest.test增强暂停动作在方案B下始终不可见`：`enabled` × `paused` 四象限，全部断言 `isVisible=false`、`isEnabled=false`，并断言动作对象仍在 `toolbarGroup`。
4. 既有守卫本身保持运行：`SettingsRealityGuardTest` 4 例、`GuardSelfTestCoverageMetaGuardTest` 8 例；没有用豁免替代断言。

## 五、流程改进

- 改 `PluginSettings.State`：`testFast` + `PluginSettingsPersistenceTest` + `SettingsIOTest`，不要只跑手选的平台测试。
- 新增/删除守卫类：先登记 `GUARD_CLASSES`，再跑 `testFast`；不要只跑新守卫类本身。
- UI 显隐改动：用 `AnActionEvent.createFromAnAction` + `action.update` 做行为断言，不能只断言动作在组内。
- 全量门禁：`testShards --no-configuration-cache`；若另一会话正在同一工作树改 `src/main`，改隔离工作树跑，避免并发编译竞态。
- 失败轮不要只看退出码：管道/后台任务的退出码可能是末命令的；读 XML 的类数与失败数。

## 五A、同类缺口全仓排查（2026-10-19 晚，第二轮）

用户追问「还有没有同族问题」。三个方向排查与结论：

1. **零执行测试类**：磁盘 737 个测试文件逐一比对「文件名基名 vs `class` 声明类名」。唯一特例
   `CrudPreviewFlowAndTypesTest.kt`（实际类 `DbTypeQuoteHintTest`）——但划桶脚本类名提取失败时
   **回退文件名**、成功时用声明类名，两侧（分片/fast）都取**声明类名**入 include，
   无匹配不上的零执行风险；`testExternal` 6 类全显式 FQCN 同样无险。
2. **UI 动作显隐**：全仓 `presentation.isVisible/isEnabled/isEnabledAndVisible` 写点 22 处逐一对照测试。
   缺口 G-B：历史页二级右键「跳转到 Mapper XML」（`HistorySqlLogPanel.JumpToMapperXmlAction`）的
   `resolved != null` 显隐规则无任何用例——近亲（最近执行弹框）有用例、纯解析函数（SqlLogPanelXmlJumpTest）
   有用例，但「解析绿 ≠ 动作 update 接线绿」正是暂停按钮的同族形态。补 2 例（无 mapperStatement 隐藏 /
   XML 不存在隐藏）+ `JumpToMapperXmlAction` 改 `internal`（测试缝，仿 `CompareSelectedAction` 先例）；
   反向：探针恒显示 → 恰 2 红。
3. **设置页绑定**：`SettingsRealityGuardTest` 断言二只保证「控件符号出现在 apply/reset 体里」，
   绑错字段不红（源码扫描的结构性盲区）。缺口 G-C：`enhancedCaptureCheck` 三向绑定
   （isModified / apply 写回 / reset 回读）无运行期用例。补 1 例真实驱动 `AllSectionsConfigurable`；
   反向探针「apply 写成脱敏复选框」第一版 **0 红**——根因是夹具没把两枚复选框拉成不同值，
   错误值与期望值撞车；修正夹具（脱敏框拉到与开关相反值）后恰 1 红。**教训：反向探针的夹具
   必须保证「错误行为」与「正确行为」可观测地不同，否则探针无判别力。**

补测读数：`HistorySqlDiffTest` 8/0/0（含 2 新例）、`PluginSettingsPanelBindingTest` 16/0/0（含 1 新例）、
四类定向 33/0/0；`testFast` 4100/0/0/6。探针全部还原（`grep RED PROBE` 零命中）。
