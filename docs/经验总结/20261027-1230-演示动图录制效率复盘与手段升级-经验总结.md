# 演示动图录制效率复盘与手段升级（2026-10-27）

> 触发：T-DemoGifFix1026 批 4 录制两小时零产出，用户要求深度分析、总结沉淀、升级录制手段。
> 结论先行：**这次浪费的根因不是「录制难」，而是把「状态依赖重的图」和「状态依赖轻的图」
> 混在同一套手工流程里做，且缺少开工前的环境就绪探测**。升级方向是「分层 + 前置探测 +
> 语义定位」，不是换工具。

## 一、量化归因

### 1.1 两段的产出对比（同一套脚本、同一个沙盒）

| 时段 | 时长 | 产出 | 类型 |
|---|---|---|---|
| 23:26–02:20 | ~3h | **10 张合格片** | 全部是「预览面板内的确定性交互」 |
| 11:37–12:24 | ~47min | **0 张** | `explain-plan`：依赖真实数据库执行 |

单张耗时：成功段平均 18 分钟/张（含脚本改造），失败段单张烧掉 6 个 take 仍未成。

### 1.2 失败 take 的归因分布（本轮全部记录）

| # | 现象 | 根因类别 | 是否可前置探测 |
|---|---|---|---|
| 1 | 预览渲染成 PostgreSQL | **环境状态**（三处方言来源之一：demo 仓 `.idea/sqldialects.xml` 的 PROJECT 映射） | ✅ 可 |
| 2 | Alt+Shift+Q 静默无效 | **环境状态**（索引期，坑44） | ✅ 可 |

**6 类里 4 类可以前置探测掉，1 类可模板化，只有 1 类（弹层定位）需要新手段。**

### 1.3 决定成败的关键变量

对比成功段与失败段，共同点不是「哪张图」，而是**状态依赖深度**：

| 依赖深度 | 例子 | 本轮成功率 |
|---|---|---|
| L0 纯预览面板内交互（gutter/Alt+Shift+Q/勾选/填参） | r03 r06 r04 a17 a26 a46 wrapper a9 | **8/8** |

## 二、五个结构性缺陷（这次踩到的，都要修）

### 2.1 缺「开工前环境就绪探测」

每次重启沙盒后，方言、索引、数据源记忆、工具窗状态都可能是错的，但脚本是在
**第一个动作**上才暴露问题——等于用 take 当探针。本轮 6 个废 take 里 4 个属于此类。

**沉淀**：`record/b4_run.py` 的三道闸门（G1 窗口矩形 / G2 索引空闲 / G4 前台是沙盒）
是雏形，但 G2 判据三次校准失败（像素位置猜错），最终靠 robot 组件树才成。
→ 需要把它做成**通用 preflight**，覆盖更多状态项。

### 2.2 定位手段「硬编码坐标」占主导

skill 里早有定论（2026-10-26 调研）：82 个 scene 脚本里纯 robot 定位的 30 个零硬编码
坐标、零返工；纯坐标的 43 个全靠 `(x, y)`。本轮 a11 的 6 次失败**全部**源于弹层坐标。

而弹层是 JBPopup，`robot.menu_items()` 对它返回 0（查不到 `ActionMenuItem`）——
这是已知盲区，但我仍然用硬编码坐标去点，等于明知有坑还踩。

### 2.3 「状态断言」覆盖率不足

成功段的脚本有断言（面板就位、复选框内芯颜色、Guard SQL 区变化），失败段没有：
- a11 没断言「数据源弹层真的弹出来了」
- 点「执行计划」前没断言「预览还在」
- 点弹层项后没断言「选中的是 mpj_demo 而不是 dbx_test」

**没有断言 = 失败要等到转制后目视才发现 = 一个 take 的完整成本。**

### 2.4 环境状态有三处以上来源，且无单一真相

方言就有三处（全局 XML / 项目级 JSON / `.idea/sqldialects.xml` 的 PROJECT 映射），
数据源「上次使用」还有模块级分桶。每次排查都要逐一试，本轮光定位方言就废了 4 个 take。

### 2.5 批 4 的性质被低估

复核文档给这 22 张的判定是 **MINOR——功能正确、可用，只有画面瑕疵**。它们和
10 张 SERIOUS 不是一类活：SERIOUS 是「画面承诺对不上必须修」，MINOR 是「锦上添花」。
我却按同样的流程（逐张 take + 闸门 + 目视）去做，成本结构完全错配。

## 三、沉淀：下次开工的 SOP

### 3.1 按状态依赖深度分批（最重要）

```
L0（纯预览面板）→ 一次开工连录 8~10 张，成功率接近 100%
L1（需真库执行）→ 单独一段，先手工跑通一条再批量
L2（需 demo 应用）→ 单独一段，demo 常驻 + 应用从 IDE 内启动（捕获链硬约束）
L3（平台原生控件）→ 每张单独预算 3 个 take，弹层类必须先做定位探测
```

**禁止混批**：L0 和 L3 混在一起，L3 的失败会污染 L0 的构图与状态。

### 3.2 开工前 preflight（每次沙盒重启后必做，1 分钟）

新增 `record/preflight.py`，逐项探测并打印结论，**任何一项 FAIL 都不开录**：

| 项 | 判据 | 修法 |
|---|---|---|
| P1 窗口矩形 | `GetWindowRect == (277,25,1647,1009)` | MoveWindow |
| P2 索引空闲 | robot 组件树无 `Analyzing` | 等 |
| P3 前台是沙盒 | `GetForegroundWindow == hwnd` | 夺前台 |
| P4 渲染方言 | 开一次预览，读头部文本应为 `MySQL` | 查三处来源（见 3.4） |
| P5 数据源记忆 | `workspace.xml` 的 `mpsql.visualizer.last.runner` 是预期源 | 清或改 |
| P6 无残留弹窗/浮层 | robot 查已知弹窗标题 = 0 | 关 |
| P7 工具窗状态 | 该开/该关与分镜要求一致 | Ctrl+Shift+F12 |
| P8 demo 应用（仅 L2） | `curl 127.0.0.1:8081/user/list` = 200 | 启动 |

### 3.3 每个 take 的硬性守卫（已部分实现，需补齐）

1. **开录前**：`require()` 断言目标面板/弹窗真的存在（不是「我以为它开着」）
2. **每次点击后**：`after_click()` 断言画面有变化（已实现，但覆盖率不够）
3. **关键选择后**：断言「选中了正确的那一项」（a11 缺这条，导致点了 PG 源还不知道）
4. **收尾**：`gate_frame_scan.py` 扫跳行弹窗/红色色簇（已实现）

### 3.4 方言三处来源的排查顺序（写进脚本注释与记忆）

```
1. demo/.idea/sqldialects.xml          ← PROJECT 级映射，最快命中（本轮根因）
2. demo/.idea/sql-visualizer/mp-sql-visualizer-settings.json   项目级插件设置
3. 沙盒 config/options/mp-sql-visualizer.xml                   全局（须 IDE 退出后写）
```

### 3.5 成本纪律

- **单张连续 2 个 take 失败 → 停手诊断**，不允许第 3 次盲试（本轮 a11 试了 6 次）
- **MINOR 类图不追求一次到位**：允许「够用即收」，把时间留给 SERIOUS
- **每完成一张立即转制 + 入库 + 提交**，避免「攒着一起做」导致状态漂移

## 四、升级手段（按性价比排序）

### 4.1 【高】弹层定位：像素双帧 diff（已有实现，需接入）

`record/probe_menu_pix.py` 已验证过：打开菜单截帧 A → 键盘 Down×1 截帧 B →
`ImageChops.difference(A,B).getbbox()` 得到首项高亮带 → 推算项高与各项 y。
**天然免疫 hover 读图的 24~48px 漂移**，不依赖组件树。

→ 接入方式：`record/menu_pix.py` 提供 `locate_menu_items(screenshot_a, screenshot_b)`，
弹层类脚本统一调用，替代硬编码行坐标。

### 4.2 【高】状态断言库：把「我以为」变成「我验证」

在 `verify.py` 增加三个语义断言（不是像素，是 robot 组件）：

```python
assert_panel_open("SQL Visualizer - SQL 预览")
assert_no_dialog(["分享 SQL", "Connecting to", "Settings"])
assert_selected_text(contains="mpj_demo@localhost")   # 弹层选中项
```

→ 覆盖率目标：**每个 take 至少 3 条断言**（开录前 1 条 + 关键动作后 2 条）。

### 4.3 【中】robot-server `/js/execute` 通道（潜力大，但要先验证）

skill 调研报告提到 robot-server 有未启用的 `/js/execute`（反编译实证），
可在 IDE 进程内直接触发 Action、读弹窗内部状态、30fps 截图、合成鼠标事件。
**若可用**，能一次性解决「弹层定位」「等真实状态替代 sleep(3.6)」「读组件内部文本」。

**但本轮未能验证**（jar 内路由字符串未提取成功，需反编译 `RobotServerImpl$startServer$2$N` 系列类）。
→ 列为**下一个调研项**，不是当前依赖。

### 4.4 【中】把「等固定时长」换成「等状态」

当前大量 `time.sleep(3.6)`（预览渲染）、`sleep(10)`（EXPLAIN 结果）。这些是猜时间。
若 `/js/execute` 可用，改为轮询真实状态；不可用则至少改成「像素稳定即继续」
（`wait_stable` 已有，但阈值与区域要按场景标定）。

### 4.5 【低】视觉模型辅助定位

调研已证伪（小图标 0/4），不再投入。
