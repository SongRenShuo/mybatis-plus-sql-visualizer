# 发版门禁墙钟压缩第三期——home 外迁转正与直连销案（T-ReleasePerf8 经验总结）

> 2026-10-24。接续 T-ReleasePerf6/7。分支 `t-releaseperf8`（基于 dev `cf0c7deb`），工作树 `mpsv-releaseperf8`。
> 用户令逐字同题第三轮：全量测试与 releaseGate 压时、效果不变内容不减。计划：`docs/开发计划/20261024-0240-T-ReleasePerf8-发版门禁墙钟压缩第三期-开发计划.md`。

## 一、本轮最重要的认知修正：55min 不是「在线语义不可压缩」，是「冷 home × 代理慢窗」

T6 曾把 verifyMarketplace 判为「在线口径不可压缩」（freshness 是本体），T7 把整链地板压到 613s 后宣布结构最优。但发行日实测连续三轮 31m9s / 54m11s / 55m8s——裂缝的真正成分本轮取证清楚了：

1. **下载税只在冷 home 支付**：R0 冷树一轮下载 3.33GB/3m50s（快代理窗 ~14MB/s），R1 warm 一轮**下载 0 字节**（loaded-plugins 131 文件全 kept）。verifier 缓存键 = `pluginId_buildNumber.zip`，home 在 `build/` 下 → 换工作树（发行常规操作，detached 验证树）= 整组冷下载。
2. **跨轮复用率极高**：主树（10-14 下载）vs rp8（10-24 下载）131 个 build 号 130 个一致，仅 1 个插件版本前进（+89MB）——10 天跨度的 marketplace 依赖集合 97.5% 稳定。
3. **发行日 30m 下载段 = 代理慢窗**：同是 3.33GB，快窗 3m50s、慢窗（~2MB/s，10-08 实录）30m。verifier 行为没变，变的是 Clash 出口吞吐（6~15 倍漂移）。

所以 T6 L5「home 迁出 build/」的销案理由（「发行日历史全暖窗」）是被三条发行日读数直接证伪的过期前提——本轮按新证据复审转正：**home 缺省迁到 `GRADLE_USER_HOME/mpv-verifier-home/{gate,marketplace}`**，发行 detached 树从此天然暖。`-PverifierHomeRoot=build` 一词回退既有形态。

## 二、销案与定案

- **N2 直连提速：销案**（curl 双轮交错，代理 13.3/12.6 MB/s vs 直连 7.7/8.0 MB/s，代理反而快）。教训：本机网络形态下「绕过代理」不是提速手段，代理慢窗的正确对策是别在冷 home 下重付 3.33GB。
- **N3 home 外迁：转正**（依据与验证见上）。gate 与 marketplace 保持分家（离线/在线语义不互染）；verifyPlugin（报告生成器，不在发版链）维持 build/ 原位零行为变化。
- **N1 探针方法论沉淀**：`dev-support/verify-net-probe.ps1`（loaded-plugins 快照/diff）+ 既有 proc-sampler + verifier 自报的 "Total time spent downloading" 行，三件套即可把任何一轮门禁的下载税拆干净。
- 全量测试（日常 testShards）侧零新杠杆，维持 T9 地板声明；releaseGate 内分片窗本就藏在 marketplace 窗口里。

## 三、实施三坑（PS/Gradle 交叉地带，全部反向验证抓出）

1. **doFirst lambda 引用脚本顶层函数 → CC「cannot serialize」**（mpv-testing 同款实证第三次现身）。解法=逻辑挪 `buildSrc/src/main/kotlin/VerifierHomeGuard.kt`（独立 .kt 的顶层函数编译为普通类，MarketVerdictChecker 同款先例）。
2. **PS 5.1 多行 script block 里跨行 `-and` 静默失灵**：Where-Object 恒空、无任何报错；改单行拼接后同进程同条件立刻命中。PS 多行管道只在行尾是 `|` 时可靠续行，行尾二元运算符续行在 5.1 不可靠。
3. **`$found = ... | ForEach-Object {...}` 捕获即吞输出**：赋值后管道输出不打印，`if (-not $found)` 又无 else——探到冲突反而静默放行，与守卫目的正好相反。必须 `else { $found }`。
4. 附：PS 脚本含中文 + UTF-8 无 BOM → PS 5.1 按 ANSI 误读直接解析炸（Git Bash CJK 同族），`dev-support/` 下 PS 工具一律全 ASCII；stdout 重定向时 PS 输出 `#< CLIXML` 噪声，判定前要清洗。

反向验证实录：伪造带 `PluginVerifierMain` + 共享 home 命令行的常驻 java 进程 → 前两版探测恰各漏一个形态（多行版 CLEAR、无 else 版也 CLEAR），第三版 BUILD FAILED 5s 硬失败并给出处置指引；撤假进程后 CLEAR + verdict parity。

## 四、终局读数与并发面回退

S5 权威轮（第 3 跑，05:03~05:15）**BUILD SUCCESSFUL 11m15s 全绿**：testShards 8116/0/0/10（较 T7 基线 +24% 测试基数）、六 verdict Compatible 计数逐字一致、e2e PASS=26 FAIL=0、**verifyGate 与 verifyMarketplace 下载均 0 字节**——home 外迁后发行 detached 树的冷税（3.33GB × 代理窗速 4~30min）整类消除，整链回到暖窗地板形态（675s，长杆仍是 marketplace 610.7s，其余环节全部藏在其窗口内）。

共享 home 重开 T-VerifierHomeIso 消灭过的冲突类，防线两道：①全量门禁互斥既有定例（两份 releaseGate 叠跑本就因 Commit 破线被禁）；②doFirst 锁探测（探到外部 verifier 指向同一 home 即硬失败；探测自身故障降级 WARN 放行，主防线不让位）。回退：`-PverifierHomeRoot=build`。

操作注意（rp8 实录两条）：①新树跑 releaseGate 需带 `-Pe2eDemoDir=<join demo 路径>` 或先落 `.local/local.env`（MPSV_DEMO_ROOT）——`.local` 不入库，detached 树天然缺；②发行轮现在天然免冷下载，但**首次**在某台机器上仍要付一次 3.4GB（可从任一暖树把 `build/verify-home-marketplace` 拷入 `GRADLE_USER_HOME/mpv-verifier-home/marketplace` 播种）。

## 五、附带发现（交后续轮）

- **agent attach 集成测试可无限挂起**：S5 首跑 `AgentManagerPremainReattachTest.testP4_attach装载关再开_原端口rebind接住回连重建会话` 的子应用 JVM 在 `AgentManager.acceptPremain` 等回连握手 75 分钟未超时（jstack 实录，testShard3 整链被拖死）。预热轮同链全绿=负载/时序敏感。挂起无超时是机制缺口（与 Docker 半活态挂起同族），建议后续轮给 attach 握手加预算上限并登记 flake。
- releaseGate 内 verifyMarketplace 与 e2e 的一处时序余量：e2e `mustRunAfter testShards`（聚合），分片窗若延长会挤压 marketplace 尾窗——本轮未动（T6 L3 销案面），仅登记。
