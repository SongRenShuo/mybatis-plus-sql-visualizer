# 录制沙盒许可失效的新真因：缺 `idea.key` 而非 agent 未加载（2026-10-25）

> 背景：本仓录制沙盒靠 ja-netfilter 的 `-javaagent` 补丁维持 IDEA Ultimate 许可。这个坑此前已沉淀过一版（`20261023-1810`），当时把根因定在「agent 没随启动加载」。本轮发现**那个结论不完整**——agent 加载了照样会弹试用横幅。

---

## 一、这次的现场

发版收尾后重开录制沙盒，界面右上角挂着 `Start Free Trial`。按旧档的判据查，一切「正常」：

| 检查项 | 结果 |
|---|---|
| 平台 `bin/idea64.exe.vmoptions` 含 qwdn 行 | ✅ 有（第 25 行） |
| 沙盒 `config/idea64.exe.vmoptions` 含 qwdn 行 | ✅ 有（第 1 行） |
| `jcmd <pid> VM.command_line` 里有 `-javaagent:...qwdn-afb.jar` | ✅ 逐字在 |
| `jcmd <pid> VM.class_hierarchy \| grep -c janetfilter` | ✅ **53**（连 `plugins.power` 都在） |
| 界面 | ❌ 仍弹 `Start Free Trial` |

**agent 确实跑起来了，许可就是不生效。** 旧结论「agent 没加载」在这里完全解释不通。

## 二、真因：许可实体不在

沙盒 `config/` 里**没有 `idea.key`**。

```
build/MPSV-GifFresh/.../config/idea.key   → 不存在
%APPDATA%\JetBrains\IntelliJIdea2026.2\idea.key → 5300 字节，存在
```

补丁做的事是**绕过签名校验**，它本身不生成许可。许可实体是 IDE 从 `config/idea.key` 读出来的那份证书。文件没了，校验绕过也就无从谈起——所有 hook 都正常工作，只是没有东西可校验。

**为什么会没**：`build/` 被 clean 过（发版流程必做）。整个沙盒目录随之消失，config 里那份 key 一并没了。下次 `runIde` 重建沙盒时只建空壳，**不会**把 key 恢复回来。

## 三、处置

```bash
SBX=build/MPSV-GifFresh/mybatis-plus-sql-visualizer/IU-2026.2.1/config
cp "C:/Users/USER/AppData/Roaming/JetBrains/IntelliJIdea2026.2/idea.key" "$SBX/idea.key"
```

重启沙盒后，两条判据同时成立才算解决：

1. 右上角 `Start Free Trial` 消失
2. `//div[@accessiblename='Database']` 命中 1 个 `com.intellij.openapi.wm.impl.SquareStripeButton`

第 2 条不能省。横幅消失可能只是还没渲染完，`Database` 命中才是 Ultimate 能力真解锁。

## 四、顺带推翻的旧口径：2.x 不再 merge 沙盒 vmoptions

旧档写「`gradle runIde` 会把沙盒 `config/idea64.exe.vmoptions` merge 进平台 `bin/`」。这条**对 IntelliJ Platform Gradle Plugin 2.x 不成立**。

源码实证（`intellij-platform-gradle-plugin-2.18.1-sources.jar` → `IntelliJPlatformArgumentProvider.kt`）：

```kotlin
val vmOptions = launch
    .vmOptionsFilePath
    ?.removePrefix("../")
    ?.let { platformPath.resolve(it).readLines() }
    .orEmpty()
```

`launch` 来自平台 `product-info.json`，其 `vmOptionsFilePath` 就是 `bin/idea64.exe.vmoptions`。**沙盒 `config/` 那份从头到尾没被读过。**

那为什么平台 `bin/` 那份里有 qwdn 行、进程命令行也带上了？因为那行是**手工写进 `bin/` 的**，不是 merge 过来的。所以旧档里「merge 有效」的观测结论本身没错（qwdn 确实进了 JVM），但归因错了——进 JVM 的是 `bin/` 那份的内容，不是 `config/` 那份的。

**可行路线三条**（推荐第 2 条）：

1. 写平台 `bin/idea64.exe.vmoptions` —— 有效，但会被 transform 缓存重建覆盖
2. 构建脚本里用 `jvmArgumentProviders` 显式传 —— 本项目已落 `-Pmpvs.licenseAgent=<jar 路径>`
3. 改 `~/.7t` 侧配置 —— 依赖补丁自身机制

本项目在 `buildSrc/src/main/kotlin/mpv-runide.gradle.kts` 的 `runIde` 块里加了：

```kotlin
val licenseAgent = providers.gradleProperty("mpvs.licenseAgent").orNull
    ?.takeIf { it.isNotBlank() }
    ?.takeIf { file(it).isFile }
jvmArgumentProviders.add(CommandLineArgumentProvider {
    licenseAgent?.let { listOf("-javaagent:$it") } ?: emptyList()
})
```

属性缺席时一个参数都不加，其他机器/CI 零影响。

## 五、三个假线索

排查时被下面三样东西带偏过，记下来别再追：

1. **`~/.7t/logs/7-tool.log` 里的 `[license] generate ok codes=[IU] expiry=7777-07-07`**
   看着像 agent 生成了许可，其实是独立 GUI 工具「7-Tool」写的日志——那个目录是它的，不是 ja-netfilter 的。ja-netfilter 本身不写日志文件。
2. **IDE 日志 `JVM options: [...]` 列表里没有 qwdn**
   那行只记录平台 vmoptions 文件展开后的内容，不是完整命令行。要看真实参数必须用 `jcmd <pid> VM.command_line`。
3. **进程命令行带 qwdn 就等于「补丁生效」**
   命令行对了、类也加载了（53 个 janetfilter 类），仍然会因为缺 key 而弹横幅。这两个都不是许可生效的充分条件。

## 六、修正后的排查顺序

```
1. 沙盒身份     ls -lt build/MPSV-<名>/…/log/idea.log        # mtime 在刷新
2. agent 加载   jcmd <pid> VM.class_hierarchy | grep -c janetfilter   # >0
3. 许可实体     ls <沙盒>/config/idea.key                    # 存在
4. 能力解锁     robot.py find "//div[@accessiblename='Database']"  # 命中 1
```

旧档是 `1 → 2 → 界面`，漏了第 3 步。本轮就是卡在这里。

## 七、教训

**「某项机制已生效」和「某项能力可用」是两回事。** 前一轮确认了 agent 加载，就把「许可失效」归到别处；这一轮确认了命令行带参数、类也加载，还是没想到去数许可实体。

判断链上的每一环都该有**独立的、可证伪的证据**。`jcmd` 看类加载是 agent 的证据，不是许可的证据；横幅消失是 UI 的证据，不是能力的证据。缺 key 这件事，只有 `ls config/idea.key` 能证明。

## 八、重启沙盒时必须带全三个参数（2026-10-26 实测漏带一次）

本轮为了改沙盒配置重启 IDE，只带了 `-PgifRecord=true -Pmpvs.licenseAgent=...`，
**漏掉 `-PgifRobotServer=true`**，结果 `prepareSandbox` 重建沙盒 `plugins/` 目录时把
robot-server 清掉了——`record/robot.py` 全部请求报「连不上 robot-server（127.0.0.1:8580）」，
`idea.log` 里也再没有 `robot` 相关行，沙盒 `plugins/` 只剩 `ml-llm` 与主插件。

正确命令（三个参数缺一不可）：

```bash
./gradlew runIde -PgifRecord=true \
                 -PgifRobotServer=true \
                 -Pmpvs.licenseAgent=C:/Users/USER/.7t/patch/qwdn-afb.jar
```

三者的分工：

| 参数 | 作用 | 漏了会怎样 |
|---|---|---|
| `-PgifRecord=true` | 切 262 平台 + 独立沙盒 `MPSV-GifFresh` | 落到 243 开发态，录制构图与坐标全不对 |
| **`-PgifRobotServer=true`** | **把本地 `record/robot-plugins/robot-server-plugin` 装进沙盒** | **robot-server 消失，组件定位全线失效** |
| `-Pmpvs.licenseAgent=<jar>` | 注入许可 agent（`jvmArgumentProviders`） | 弹 `Start Free Trial`，见本档前七节 |

**为什么会漏**：`-PgifRobotServer` 在 `build.gradle.kts` 里是「独立生效、不要求 gifRecord 同开」
（为 UI243 验收沙盒设计），所以它看起来像可选项；但 `prepareSandbox` 每次重建 `plugins/`，
**不声明就等于不安装**——手工拷进去的插件会被清掉（这条在 gradle 注释里已写明，本轮又踩了一次）。

**判据**：重启后立刻 `python record/robot.py probe`，通不了就是没装。另可查
`build/MPSV-GifFresh/.../plugins/` 下应同时有 `mybatis-plus-sql-visualizer`、`ml-llm`、`robot-server-plugin`。

## 九、两个 fallback 脚本的最终处置（2026-10-26）

`record/sandbox-full.vmoptions` 与 `record/sandbox-start-full.cmd` 是 20261023 那次
「以为是 fallback 启动方式的问题」时留下的产物，本档第五节第 2 条已判「应视为废弃」。
本轮确认它们**不该进版本控制**并做了处置：

- **理由**：① `IDEA_VM_OPTIONS` 对直接启动的 `idea64.exe` 无效，这条路根本不可能生效；
  ② 脚本里硬编码了 `C:\Users\USER\.gradle\caches\9.7.0\transforms\af228bcb...` 这条
  **会被缓存重建清掉的绝对路径**，换机器/清缓存即失效；③ 正解已经是
  `-Pmpvs.licenseAgent=<jar>`（走 `jvmArgumentProviders`，见本档第四节）。
- **处置**：移入 `record/tmp/`（gitignored 的本机暂存目录），不提交、不删除，保留可追溯。
  仓库根的未跟踪噪音随之清掉。
