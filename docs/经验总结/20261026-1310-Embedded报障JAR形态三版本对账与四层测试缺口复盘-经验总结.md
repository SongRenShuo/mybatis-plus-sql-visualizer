## 一、排查时间线（每步都先证伪再前进）

3. **exec 落盘互证**：同次预览写盘的 `demo/.idea/sql-visualizer/exec/mpsql-exec.sql` 与对话框**共用同一 `result.sql`**（`prewarmExecTempFile`）——exec 内容正确 + len 差额=持久化 `formatSql:true` 的换行 ⇒ 对话框 SQL 正确。
4. **生产管线探针**：以 demo 仓逐字形态（javax 短名导入/Lombok/嵌入类无内层 @Column）走真实解析+转换链，三条渲染全对。

## 二、取证手法沉淀（可复用）

- **预览对话框与 exec 文件同源互证**：拿不到对话框截图时，exec 落盘（`.idea/sql-visualizer/exec/mpsql-exec.sql`）就是同一 `result.sql` 的紧凑形态；len 差额对账 `formatSql` 换行即可确认对话框内容。
- **沙盒日志考古**：默认沙盒在 `.intellijPlatform/sandbox/<插件>/IU-*/`，`idea.log` 的 gutter 栈帧（`navigate$lambda`）能指认用户点了哪个方法；`[T-DbSchemaCompletion] schema 预热: tables=…` 行说明 TableInfo 建成（排除实体未解析）。
- **W1 诊断日志前置**：报障未定根因时先落带来源标签的判定日志（本轮 `[T-EmbeddedIdentify]`：命名档/来源/嵌入列清单/降级 WARN），下一次复现一条日志直接归因——本轮用户复现会话的日志行（`naming=NONE/probe-miss columns=[createdTime→created_time]`）当场排除了判定层。
- **三版本对账法**：tag/历史 tip 建 `git worktree` + 同款探针（夹具与现版本逐字一致）跑同输入，读数逐字节比；先 `git log -S "<版本串>"` 验证版本串是否真实存在，避免对错基线。
- **历史读数存档是免费证据**：`build/w3-jar-readings-*.txt` 这类当年取证 dump 直接回答「二进制注解读取通不通」，省一轮重建测试。

## 三、为什么既有测试没接住（四层缺口）

1. **判定层**：`6919d8ef` 的三个新测试全是 `nearestModuleRootPath` 纯函数单测；「模块判不出 → 下一步去哪」无用例，且当时「回落工程级」**仅在实体模块无 resources 目录时可达**——「有 resources 但无命名配置」组合形态无人构造。
2. **锚点形态**：既有命名测试（`JpaEmbeddedColumnNamingTest` 8 例）锚点全在 light fixture 内存源码里，物理构造不出真实文件布局；工程级测试只测 anchor=null 路径，与模块收范围无交集。
3. **桶位错位**：JAR 形态既有 W3 测试是 Heavy 桶（仅全量分片跑，定向永远碰不到），且断言的是「注解读得到」而非「命名档与最终列名」——**取证绿冒充行为绿**。
4. **锚点不一致（根因级）**：同一条预览链上找实体类用**宿主**模块 scope（`EntityClassResolver.searchScope(context)`），判嵌入列命名却用**实体**模块——两处各改各的、无人对账一致性。若有「同场景下找得到类 ∧ 命名也从宿主判出」的一致性用例，缺陷在 10-13 落地当天就会红。

## 五、流程改进（防复发三手段）

1. **改「查找范围」类逻辑**：必须回答「判不出时下一步去哪」，并为每个分支造**真实文件布局夹具**（temp 目录 + 模块标记 + resources）——纯函数单测够不着组合形态。
2. **同链路多处按锚点收范围**：收口时写**锚点一致性用例**（同场景下所有查找锚点要么同源、要么有显式级联），并在两处代码注释里互链。
3. **Heavy 桶能力进定向验证**：JAR/多模块/索引类能力若与本轮改动相关，计划里必须标明桶位；「全量桶里有」不得冒充「定向覆盖了」；取证类测试（证可读性）与行为类测试（证判定与产物）分开写。

## 六、实施坑（本轮新增）

- Kotlin 给方法加带默认值的参数会改 JVM 签名，未重编的陈旧测试字节码运行期报 `NoSuchMethodError`（Gradle 按内容哈希不触发重编、`touch` 源文件也未必生效）——删 `build/classes/kotlin/test` 下陈旧类重编即消。
- 两个实体解析器均已有 companion object，新增 companion 报 Conflicting declarations——LOG 并入既有块。
- Heavy 桶造文件必须包 `WriteCommandAction`（EDT 写访问断言）；真实文件 PSI 需 `PsiTestUtil.addSourceRoot` 后 `PsiManager.findFile` 才可达。
