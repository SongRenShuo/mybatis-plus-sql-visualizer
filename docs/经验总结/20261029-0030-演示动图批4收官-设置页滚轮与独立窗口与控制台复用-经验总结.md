## 二、三类新坑（每类都有多轮返工作背景）

### 1. 设置页滚动：真实滚轮有效，其余全灭

- `PostMessage(WM_MOUSEWHEEL)`、PageDown（会切左树选项）、Tab 逐格（30px/22 次）全部无效；
  **`pyautogui.scroll` 真实滚轮有效**——前提是先把鼠标 `moveTo` 内容区（如 (1200,700)）再滚。
- 速度约 **0.3px/档**：40×`scroll(-100)` ≈ 2.5s 从页顶滚到目标行，放 take 内可接受。
- **滚动位置不跨「关→开」保留**：重开设置回页顶，滚动段只能在 take 内做。
- **左树行位随树内容与过滤状态漂移**：同一行 y 在过滤前后差几十像素（未过滤树
  SQL Log≈497，点 450 会选到 SQL Preview）。点树行前必须截图现核；
  先用搜索框过滤再按过滤后的行位点更稳。
- 2026-10-13 坑 35「pyautogui.scroll 无效」的口径就此修正：当时鼠标没落在内容区。

### 2. 独立 JDialog 攻防：抢前台、吞点击、会叠隐藏实例

插件与 IDE 的三类弹层都是**独立窗口**，不是通知条：
「源码跳转配置」（每次勾选/注入都会重新弹）、「Add Files to Git」（注入生成文件后
IDE 立刻弹）、「回滚 SQL」「选择注入模块」等业务弹窗。

- **抢前台吞点击**：弹出后 `GetForegroundWindow` 就是它，对设置页/复选框的一切
  点击都被吞（症状＝「点了没反应」）。处置＝场景里封装
  `close_window(title)`：EnumWindows 按标题精确匹配 → `PostMessage(WM_CLOSE)`，
  在「点开关」「点 OK」之后各插一次。
- **「Add Files to Git」勾一次 Don't ask again 可根治复发**；勾选框/Cancel 的 y
  要按窗口 rect 的 `bottom−24` 算（整图目测会点到窗外）。
- **多次试录会叠出多个隐藏实例**：n11 实测 6 个「回滚 SQL」叠在同一 rect，
  robot 按文本找按钮一次匹配 6 个、点击落在隐藏实例上无效果。
  处置＝录前按标题循环 `WM_CLOSE` 清空（清到枚举不到为止）。
- **多选对话框初始勾选状态不固定**（模块对话框上一轮可能全空也可能全勾）
  → 「逐行取消/补勾」必错，正解＝「全不选 → 只勾目标」（底部一行两个按钮）。

### 3. 执行控制台复用：绑定数据源不一致（插件缺陷，已派单）

- 预览绑 `mp_demo@localhost`，快照/执行却跑在 `mpj_demo` 的旧控制台上。
  实证：快照查询 `SELECT * FROM user WHERE id='2' AND deleted=0` 报
  `Unknown column 'deleted'`；直连核实 mp_demo.user 有 deleted 列（id 5/6/7）、
  mpj_demo.user 没有（id 1/2/3）。
- Close All Sessions / 关逻辑删除注入都改不了绑定；预览头部的数据源 chip
  点开无可切换菜单。
- **录制侧绕过**：给控制台所在库的目标表临时补缺失列
  （`ALTER TABLE user ADD COLUMN deleted TINYINT DEFAULT 0`，录完 DROP COLUMN）。
- **已派后台子代理修复**（worktree `mpsv-t-console-bind`，分支 `t-console-bind-fix`）：
  方向＝控制台查找/复用增加「绑定数据源一致」校验，配对缓存 key 加数据源标识。
- 顺带排除了两条假设：`UserMapper.xml` 的 `<update>` 末尾**本身写死**
  `and deleted = 0`（关逻辑删除注入无效）；Close All Sessions 不改绑。

### 4. EXPLAIN 跨次对比的三个前提

- 「预览面板内结构化渲染 EXPLAIN」默认关，且开关在 SQL 预览页**首屏之下**
  （配合真实滚轮）；
- 「跨会话保留原始 EXPLAIN 计划」默认关，不开则基线列表为空、对比条不渲染；
- **造真实差异的通用手法＝先跑一次存基线 → 改环境（建/删索引）→ 再跑**：
  有索引 `type=ref/key=idx_share_scheme/rows=2`，删索引后
  `type=index/key=PRIMARY/rows=4`，对比条才不是「计划无变化」。
- 对比条右对齐，**默认 940 宽弹窗下整块被裁到屏幕外**（robot 算出 x≈2569）；
  该弹窗**不可拖拽改尺寸** → `SetWindowPos(hwnd, 300,40,1330,940, SWP_NOZORDER)`。

## 三、本轮新增的自检/定位手段

| 手段 | 解决什么 | 要点 |
|---|---|---|
| 像素采样判勾选态 | robot 组件树不暴露 JBCheckBox.selected；开关跨 take 漂移 | 勾选态蓝底：`b>110 且 b−r>40` 像素 >25；prep 里采样归一化 |
| `close_window(title)` | 独立窗口抢前台/吞点击/叠隐藏实例 | 按标题精确匹配 + WM_CLOSE；点开关与点 OK 之后各插一次 |
| 亮帧扫描 | 浏览器/白屏抢前台整段污染录制区 | 逐帧灰度均值连续 >110 即废片；比逐帧目视快且不漏 |
| `SetWindowPos` 定形 | 弹窗尺寸不可拖拽、内容被裁 | 按句柄直接定位到录制区内（400,40,1330,940） |
| 运行绿三角定位 | IDE 内启动被录应用 | 配置下拉箭头 → Recent Configurations 选配置 → 绿三角（x 随配置名长度漂）；Ctrl+Shift+F10 无效 |

## 四、流程级教训

1. **状态漂移比坐标偏更隐蔽**：开关跨 take 漂、模块对话框初始状态不定、
   隐藏实例叠加——三者的共同解法都是「录前把状态归一化成已知态，并用
   断言/像素采样确认」，而不是相信上一次 take 的结尾状态。
2. **成片体积超预算的收缩顺序**：`--fps 13` + `--hold 1.2 --tail 2.0` 先行
   （n12 从 3.6MB→1.8MB）；滚动段是体积大头，滚动循环 sleep 压到 0.01s。
3. **验收只认已提交文件**：本轮多张片的「现场看是对的、提交后才发现问题」
   都被「对已提交文件抽首/末/关键帧」拦下；`gate_frame_scan` 的亮帧告警
   （灰度均值>110）是浏览器污染的最快判据。
4. **demo 仓污染三条已验证的还原路径**：注入产物＝删生成目录 + `git checkout`；
   paste 打进源文件＝撤销无效时走 Local History Revert；行号错位＝
   `goto_col` 失败即中止不落键。
