# IntelliJ 插件演示 GIF 录制经验沉淀

> 数据基线：2026-09-09 ~ 2026-09-10，为文档站（mybatis-plus-sql-visualizer-docs）录制 8 张功能演示 GIF（annotation / jpa / batch / code-completion / wrapper / sql-log / sql-to-java / xml）。

> **固化（2026-09-12）**：本方法论文档已固化为 ZCode 用户级 skill **`ide-demo-gif`**（`~/.zcode/skills/ide-demo-gif/`，内含通用化工具脚本与场景模板，跨项目可用）。通用能力（gifkit/assemble）改动的权威源是 skill 目录，本仓库 `record/` 的副本改动前先同步；场景坐标只动本仓库 scene_tN。配套操作手册在文档站仓库 `docs/演示GIF录制指南-说明文档.md`。

## 一、背景与目标

- **成品规格**（对齐官方演示）：15fps、暗色主题、画面仅 IDE 窗口（严禁任务栏/桌面元素）、关键结果定格 1.5~2s、首尾帧一致循环无缝、单张 4~6MB 内（本批实际全部 ≤3MB）、每 GIF 配同名 PNG poster 兜底。
- **清晰度三件套**：IDE UI 缩放 150%（Settings → Appearance → UI Scale）+ 编辑器 18pt + 窗口开到接近全屏只框编辑器/弹窗紧致区域。8 张 GIF 在站点 688px 功能页列与首页 1000px 级容器里文字均锐利。
- **录制手段是「脚本重放 + 帧稳定采样」**，不是 ZCode 逐步操作——后者每步一次往返的通信死时间会录成一顿一顿的空窗。脚本内动作间隔就是 200~400ms 真实演示节奏，ZCode 只负责生成脚本、启停录屏、检查产物。

> 本文不重复决策理由（为何 15fps、为何不上 mp4、为何关 auto-zoom），只沉淀「怎么录得稳、录得快、录得真」。

## 二、整体录制架构

```
scene_tN.py（动作序列：贝塞尔轨迹 + 紧凑 sleep 间隔）
        │ 一次性重放
        ▼
Recorder.start()（mss 15fps 连续抓帧 → ffmpeg rawvideo 管道 → libx264 qp0 无损 mp4 中间产物）
        │ 抓帧同时 GetCursorPos/GetAsyncKeyState 记 curlog（mss 不含光标）
        ▼
wait_stable()（按需等待画面稳定：触发动作后不盲 sleep，稳定才推进，消化 IDEA 偶发 1s→3s 抖动）
        ▼
assemble.py：解帧 → 帧稳定空白压缩 → 光标回绘 → palettegen/paletteuse 转 GIF → 抽 poster
```

核心思想：**成片时间轴由「画面是否稳定」锚定，而不是 wall-clock 定时**。中间产物是**无损 mp4**——录一次，可反复调 assemble 参数重转制，不用为改节奏/帧率/尺寸重录。

### 关键脚本职责

| 文件 | 职责 |
|------|------|
| `gifkit.py` | 基础库：贝塞尔轨迹移动、点击/双击/右键、快捷键、输入/剪贴板粘贴、`wait_stable` 帧稳定采样、`Recorder` 录屏（mss→ffmpeg 管道 + 光标日志）、标定抓帧 |
| `assemble.py` | 后处理：mp4 解帧 → 静态段识别（分块最大均值差）→ 空白压缩 → 光标回绘 → 两通道转 GIF → 抽 poster |
| `shot.py` | 单步标定工具：`shot L T W H out.png` 抓帧 / `click X Y` / `move X Y` / `pos` / `key combo` |
| `scene_tN_*.py` | 各分镜的动作脚本（坐标常量 + 动作序列 + wait_stable 锚点 + 定格时长） |

## 三、录制管线实操（按顺序）

### 1. 环境准备（一次性成本）

1. **切 2026.2 沙盒**：用仓库内置开关 `./gradlew runIde -PgifRecord=true`（2026-09-11 起录制四项配置已收敛为此属性开关，见 §五；无需再临时改 build.gradle.kts）。跑前 `python C:\Users\USER\.zcode\cli\parallel_tasks.py check`，有并行任务先 register 独立沙盒。
2. **暗色主题**：Settings → Appearance → Theme 选 Islands Dark（官方同款暗色基准），设置一次整个录制周期不动。
3. **三件套**：UI Scale 150% + 编辑器 18pt + 界面自定义字体 15pt。
4. **demo 工程**：导入覆盖所有分镜的样例工程（本批用 `mybatis-plus-sql-visualizer-demo`，含 LambdaQueryWrapper 链/@Select 注解/XML 动态 SQL/saveBatch/JPA Repository/SQL 文本/可打印 Preparing 日志的应用）。

### 2. 坐标标定（每张 GIF 首录前必做）

- 用 `shot.py shot` 抓全屏窗，**逐帧裁出关键控件**（gutter 图标、弹窗复选框/输入框/按钮、SQL 面板、取消按钮），确定每个动作的屏幕坐标。
- **弹窗内控件必须在弹窗打开状态下定位**——弹窗是浮层，坐标随弹窗位置漂移，不在空态下标 GUI 控件。
- 把坐标写成 scene 脚本顶部常量，一次标定、逐条复用。
- 本批核心坐标规律（窗口 frame 屏幕区约 (277,25,1370,984)，脚本内坐标 = 屏幕坐标 - 277 - 25 的相对值，或直接写屏幕坐标由 `click` 处理——**统一用屏幕坐标最简单**）：
  - 弹窗布局「类型行 + 动态条件复选框列（约 x=425~430）+ 参数输入区 + SQL 面板 + 底部取消按钮（约 (1478,822)）」
  - 编译器 gutter 图标 y 随目标行变化，需 Ctrl+G 定位行后现抓。

### 3. 录制（scene 脚本）

```python
r = Recorder(REGION, OUT)   # REGION 即抓屏区域，OUT 为无损 mp4 中间产物
time.sleep(1.2)             # 让前一次操作的画面稳定
r.start(); time.sleep(0.5)
click(*GUTTER)              # 动作 1
w = wait_stable(REGION)     # 等弹窗稳定
time.sleep(1.6)             # 关键结果定格
...                          # 后续动作
print("frames:", r.stop())
```

要点：

- **`press('enter')` 在 JBR 沙盒里被吞**（JDK 21/24 的 MANIFEST/键盘实现差异），**必须用 `keyDown('return'); keyUp('return')`**。`press('space')`/`press('down')`/`press('backspace')` 等普通键正常。
- **`Ctrl+Space` 补全是微软拼音中英切换热键**，会被 IME 拦截——本批 code-completion 全程不触发手动补全，依赖 IDEA 自动弹出（输入「join us」自动弹表名补全）。
- **滚轮对 IDEA 编辑器无效**，SQL 面板滚到 WHERE 用「点击聚焦 + `Ctrl+End`」；拖滚动条会误选文本，避免。
- **循环无缝**：让首尾帧一致——T1 jpa 双弹窗场景在结尾回跳起始行；T3 code-completion 结尾撤回编辑还原现场。这样即使首尾状态天然不同（如 sql-to-java 输入/输出区内容）也能把接缝 diff 压到接近 0。

### 4. 帧稳定采样（gifkit.wait_stable）

- **实测教训：全帧平均绝对差会把小面积变化稀释成「静态」**。首个 T7 版本用全帧均值，输入框回显这类「几行字变化」被判成静态，整段被裁到 4s。**必须用「16×16 分块取最大均值差」**：`np.abs(a-b)` 降到 4× 采样后 reshape 成 16×16 块，`blocks.mean(axis=(1,3,4)).max()` 作为 diff。
- 阈值标定：分块最大均值差 < 1.2 判稳定，稳定持续 ≥8 帧推进（约 0.53s）；4s 硬上限覆盖 IDEA 偶发的 3s 加载抖动。
- `wait_stable` 返回 -1 表示超时——调用方打印、查产物，不静默录烂帧。

### 5. 转制（assemble.py）

```bash
python assemble.py perf/tN.mp4 perf/tN.gif --width 1280 --poster perf/tN.png
# wrapper-preview 因首页共用升 1440 宽
python assemble.py perf/t4_wrapper.mp4 perf/t4_wrapper.gif --width 1440 --poster perf/t4_wrapper.png
```

参数：`--hold 2.2`（静态段保留秒）、`--lead 0.5`（开头静态保留）、`--tail 1.0`（结尾静态保留）、`--thr 1.2`（静态判定阈值，与 gifkit 一致）。

转制内部流程：

1. mp4 按 15fps 解帧为 PNG。
2. 静态段识别（分块最大均值差），超长静态段裁剪到 cap 秒（开头 0.5s、中段 2.2s、结尾 1.0s）——把等待弹窗的空白裁掉，关键结果定格保留。
3. **光标回绘**：读 `mp4.curlog`（Recorder 同步记的 `frame,x,y,left_down`），给保留帧画箭头 + 点击涟漪（left_down 由 False→True 的帧起向后 4 帧画扩散圈）。
4. 两通道转 GIF：`palettegen=stats_mode=diff` → `paletteuse=dither=sierra2_4a:diff_mode=rectangle`。
5. poster 取「最后一段 ≥1s 的保留静态段末帧」（即收尾关键结果定格帧），无满足段退化为最长静态段末帧。

### 6. 逐张验收（不可省略）

每张转制后：

- **抽帧抽查**：`ffmpeg -i x.gif -vf "select='eq(n\,NN)'" -vsync 0 chk.png`，在动作节点、弹窗定格、结果定格三处抽帧确认内容正确（补全弹窗是否弹出、UNCHECK 后 SQL 是否收缩、形态切换后代码是否变化）。
- **poster 一致性**：确认 poster 恰为关键结果帧（不是空弹窗帧）。
- **循环接缝**：assemble 会打印首末保留帧差，实测除 sql-to-java（首尾状态天然不同，约 3.0）外都 ≤1。

## 四、偏离开销的真实记录（最重要的经验）

计划文档的分镜是「意图」，插件真实行为才是「权威」。本批三处分镜偏离，都是先按计划录了发现不对再改：

1. **特写切镜未采用**：分镜是「全景动作 → 切特写定格 → 切回」，但弹窗本身就是画面主体（占幅 >55%），放大没有收益；而且切镜→拼接与修订七「单段直出不拼接」冲突。**结论：弹窗/代码即主体的功能演示不需要特写切镜，把框选区域对准弹窗即可。**
2. **T3 code-completion 关键字补全不存在**：计划是「se → Ctrl+Space → 选 SELECT」，实测插件只有表名/列名/参数名补全，没有关键字补全；加上本机 Ctrl+Space 是 IME 热键，最终改为文档承诺的表名补全「join us 自动弹出」。**结论：录制前先手动戳一遍补全实际表现，别照着文案摆拍不存在的项。**
3. **T6 sql-to-java 编辑器 Action 未注册**：计划是「选中 SQL → Alt+Shift+J」，但 ConvertSqlToJava 动作在本 262 沙盒里没有注册（Find Action 不可见、快捷键无响应，类与 bundle key 都在 jar 里，原因未查明）。最终改走侧边栏「SQL → Java」tab 粘贴即转——这也是文档承诺的触发方式之一。

**通用原则：演示素材以插件实际表现为准，文档文字纠偏另起任务；录制前先逐一验证每个分镜动作在当前沙盒版本里真实存在、真实生效。**

## 五、平台踩坑（2026.2 沙盒编译 + Windows 输入）

### 262 沙盒编译三处必改（已内置为 `-PgifRecord` 开关，无需临时改动）

| 问题 | 现象 | 解法 |
|------|------|------|
| 平台类文件 v69 | `compileJava` 报「类文件具有错误的版本 69.0，应为 61.0」，找不到 ToolWindowFactory 等符号 | `jvmToolchain(24)`（javac 17/21 读不了 v69，javac 24 读 v69 仅警告） |
| JCEF 拆分为独立插件 | `SqlLogPanel.kt:822 Unresolved reference 'jcef'` | `bundledPlugin("com.intellij.modules.jcef")`（262 起 JCEF 从平台核心拆出） |
| 并行任务沙盒互锁 | 多会话同仓跑测试时沙盒/索引互锁 | 按登记表加 `sandboxContainer = layout.buildDirectory.dir("独立名")`（属主扩展块，不是 dependencies 块）；旧沙盒 `config/` 可整体 cp 进新容器保设置 |

**以上三处已内置**：自 2026-09-11 起由 `-PgifRecord=true` 一并生效（`build.gradle.kts` 的 gifRecord 分支统一控制平台版本、jcef、toolchain 与 `sandboxContainer`），**录完无需再 `git checkout` 还原**——开关默认关闭，不带 `-PgifRecord` 即为 243 常规态。下表保留作「为什么必须是这三项」的成因说明。

### 沙盒激活

复制主 IDE `idea.key` 到沙盒 config 不生效，转 Activation code 粘贴也报 Key is invalid（证书绑定主安装）。沙盒以免费评估/非商业模式运行即可，全部功能可用。主题设置独立于日常 IDE，互不影响。

### Windows 输入法交互

- **pyautogui `press('enter')` 被 JBR 吞** → 用 `keyDown/keyUp('return')`（见上）。
- **`Ctrl+Space` 是微软拼音中英切换热键** → 录制补全场景别触发它。
- **多行文本写编辑器的可靠姿势是剪贴板粘贴**：`paste()` 用 Win32 `GlobalAlloc(GLobalAlloc...SetClipboardData(CF_UNICODETEXT))` + `ctrl+v`，绕开输入法（直接 typewrite 中文/特殊字符会丢）。**注意 `SetClipboardData/GlobalAlloc` 要有正确的 argtypes/restype，否则返回的句柄被截断成 32 位 → GlobalLock 访问越界崩溃。**
- 录制过程频繁 typewrite 会把 IME 切到中文模式，结尾按一次 Shift 恢复（结束态不确定，提醒用户即可）。

### 其他

- **mss 抓屏不含光标**：光标的平滑/点击涟漪靠 assemble 按 curlog 回绘，这是「脚本重放不依赖 Recordly 光标叠加层」的关键。
- **验证应用是否启动别用截图猜**：Services 控制台全文可「Ctrl+A → Ctrl+C」后从剪贴板读出（写个小脚本），grep `PortInUseException`/`BeanCreationException` 定位启动失败——比逐屏翻控制台高效得多。本批 T5 即靠此发现 8081 被 RocketMQ 占用。
- **demo 工程端口冲突**：8081 被本机 RocketMQ 占用，临时改 `application.yml` 端口录 T5，录完还原。

## 七、常见坑（Pitfalls）清单

1. **全帧均值差稀释小变化** → diff 必须 16×16 分块取最大；gifkit 与 assemble 的 diff 度量要一致。
2. **press('enter') 被 JBR 吞** → keyDown/keyUp('return')。
3. **Ctrl+Space = IME 中英切换** → 补全场景别触发，依赖 IDEA 自动弹出。
4. **滚轮对 IDEA 无效** → SQL 面板用点击聚焦 + Ctrl+End；拖滚动条会误选文本。
5. **Win32 剪贴板句柄截断** → SetClipboardData/GlobalAlloc/GlobalLock 显式 argtypes/restype，否则 GlobalLock 访问越界崩溃。
6. **弹窗控件坐标在空态下标不准** → 弹窗是浮层，坐标随位置漂，必须弹窗打开态现抓。
7. **首尾帧不一致循环跳** → 结尾回跳起始行 / 撤回编辑还原现场。
8. **漏「脚本重放+稳定采样」只做截图猜** → 验证启动/结果用剪贴板导出控制台文本，别逐屏翻。
9. **按进程名杀沙盒会误杀日常 IDE** → 2026-09-11 真机实测：`runIde` 启的沙盒 IDE **不是 `idea64.exe`**，而是 gradle 缓存解包目录下的 `<...>\transformed\idea-<版本>-win\jbr\bin\java.exe`（启动参数含 `-Dide.native.launcher=false`），其命令行里**没有**沙盒容器名——`wmic process where "name='idea64.exe'"` 只会列出你日常的那两个 IDE。请按**可执行路径**认（grep `idea-<版本>-win`），或干脆直接关窗口。同族进程还有：该发行版 `bin\fsnotifier.exe`、IDE 的 Maven embedder（java，带 `-Didea.version=<版本>`）、以及 demo 应用的 java（带 `-javaagent:...\idea_rt.jar`，常跑在 demo 工程自带的 JDK8 上——若误判为沙盒本体而 kill，会连带停掉你正在跑的 demo）。

## 九、结论

演示 GIF 录制的工程难点不在「按下录制键」，而在**三点**：①把「画面稳定」作为成片时间轴锚点（帧稳定采样吸收 IDEA 偶发加载抖动）；②让脚本重放的轨迹与节奏像真人（贝塞尔 + 紧凑间隔，光标靠回绘补上 mss 不抓光标的缺口）；③录制前验证每个分镜动作在当前平台版本里真实存在（本批三处分镜偏离都是「计划写了但插件没这个行为」）。这三个障碍一旦用脚本管线消掉，8 张 GIF 从标定到入库可以在一个会话内批量完成，且中间无损 mp4 天然支持反复调参重转制、避免逐张返工。

## 十一、大范围录制补充（2026-10-12）

本轮连拍 A11（EXPLAIN 真实计划）/ wrapper-preview hero / settings.png / A29（MCP 门控）四张成品，
另试录 A13（执行 SQL）未出片。以下按「机制 → 边界 → 陷阱 → 判断失误」分组，原理优先。

### 11.1 机制：裸屏捕获不含光标，纯凝视型 take 转出的成片会被静段裁剪整段吃掉

`Recorder` 采的是裸屏像素，**鼠标移动不产生任何像素变化**；`assemble.py` 的静段裁剪以「帧间像素差 < 阈值」
判静止，于是整段凝视动作被压缩成末尾 hold。实测：纯凝视型 take **转出的成片只有 3.6s**（take 的 mp4 本身约 11s、是完整的），
而同轮有真实 UI 变化的成片能到 7.5s。**推论**：take 必须有真实 UI 变化（浮窗弹出 / 面板展开 /
结果网格出现 / 临时文件执行）；判据是「成片时长明显短于脚本动作时长」先怀疑这条。
这也是「光标靠回绘补上」这一设计的副作用——回绘发生在裁剪之后，所以移动轨迹救不回被裁掉的时长。

### 11.2 边界：设置对话框（Settings）四条硬边界

1. **设置页内容无法滚动**：`pyautogui.scroll` 滚轮、`PageDown`、**拖页面滚动条**三者全无效，
   只有**左树**的滚动条拖动有效。页面高于可视区时底部控件被切（MCP 页高约 750px vs 可视区约 715px，
   底部「全部启用/全部禁用」被切）。**处置＝拉大对话框**：拖标题栏上移 + 拖**右下角精确角点**
   （差几像素就落空、点到后面编辑器上并弹出右键菜单），拉到 981px 即全部入镜。
   ⚠️ 判「滚不动」前先确认目标不在极限位——本轮一度用「树滚不动」断定滚轮全坏，
   其实那次树本就在底部，且 `pyautogui` 正数＝向上滚、方向也搞反了。
2. **对话框是模态的**：开着时对其它窗口的点击**一律无效**。关 SQL 预览浮窗、点编辑器都必须先关对话框；
   本轮在此陷入过「反复点浮窗取消按钮毫无反应」的死循环，白烧数轮。
3. **`Esc` 是对话框的取消键**：拿它关搜索框的补全下拉会**连整个对话框一起关掉**。补全下拉用点别处或方向键收。
4. **对话框不是进程主窗口**：`Get-Process.MainWindowHandle` 看不到 → 须 `EnumWindows` +
   `GetWindowThreadProcessId` 按 PID 过滤再 `GetWindowRect`（实测设置对话框 (399,79)/1125×875，
   与同批静态截图逐像素吻合）。另：设置页搜索框过滤不稳（两词查询报 "Nothing to show"、
   单词查询只自动选中不筛选、补全下拉会吞输入）→ **要树展开到某页，手动展开 + 拖树滚动条比走搜索稳**。

### 11.3 陷阱：三处会毁掉末帧

1. **插件的列文档浮层会「粘住」**：鼠标压编辑器标识符弹出的「Data Source / Schema / Table / Column」
   浮层**鼠标离开也不退**（Esc 可关），末帧右侧被整块挡掉。触发点常是**开文件时坐标扫掠的余点**
   （Go-to-File 弹窗关掉后余点落到代码上）。→ 收尾鼠标停预览左栏 / 原生控制台等空白区；
   **别停代码**（弹文档浮层）、**也别停结果网格**（弹列类型浮层，如 `partitions: MEDIUMTEXT`）。
2. **弹窗按钮行位置要按窗口底边推算**：内容高度可变的弹窗（SQL 预览面板这类），按钮行 y
   **目测写死必错**（实测偏低约 48px，连点三次全落空）。取弹窗 rect 后按钮行恒在**底边上方约 39px**
   （`bottom − 39`）；退一步可用**像素剖面**（逐行取按钮文字所在 x 带的灰度均值，最亮连续段即按钮行，
   实测文字行 47~60 / 背景 26）。
3. **面板展开态跨浮窗保留**：预览面板折叠区（如「预设」行）的展开状态会**跨预览保留**，
   take 前必须归一到确定态，否则那一下点击反而把已展开的收起（末帧仍是收起态）。状态判据用条带灰度
   标准差，**阈值必须按暗色主题定**——Islands Dark 下面板底色均值仅 28、收起态本底噪声就有 13
   （实测收起 13.09 / 展开 34.95 → 阈值取 22），照「空白≈0」的直觉取 8 会把归一化做反、连点三次状态弄反。

### 11.4 陷阱：开文件两条路径各有代价

坐标扫掠（点 Go-to-File 结果行）是可靠路径，但 **Return 打不开结果行**（JBR 吞键）、
行位在 region y 350~366 浮动故须扫掠 3 点，且**弹窗关掉后扫掠的余点会落到编辑器代码上**触发 11.3.1 的粘浮层；
键盘路径（`↓` 选中首条 + Return）能避开浮层却**会开错文件**（实测把 `settings-1.1.0.xsd` 当首条结果打开）。
**取舍**：用扫掠，但把扫掠 y **标定到该文件的空白行**——写死的 350/358/366 只对旧目标有效，各文件排版不同。

### 11.5 判断失误：判「示例坏了」之前先对两处 URL

本轮最贵的失误不在录制本身，而在**由取证越界下结论**：应用 `application.yml` 的 MySQL URL 带
`sessionVariables=sql_mode=ANSI_QUOTES`，而 `.idea/dataSources.xml` 的同名数据源没有 → 同一句
`FROM "user"` 应用能跑、IDE 侧报 `1064`。我据「MP 核心与 MPJ 源码都原样拼接表名」推出「运行时必然报错」，
**漏了连接选项这个变量**（生效 sql_mode = 服务端全局 + 会话覆盖）。A/B 实测（JDBC 直连两条 URL）
才定案。**教训：取证只覆盖你查的那一层，结论别越界；录「执行类」画面前先把两处 URL 逐字对齐**
（改完需重启 IDE 生效）。连带：该数据源 URL 已补齐参数，join demo 的 MPJ 链在 IDE 侧也能跑通
EXPLAIN 与执行 SQL 了。

### 11.6 陷阱：起错的「沙盒」其实是一个日常 IDE（用户定为严重问题）

同一场录制里连栽两次，都是**把日常 IDE 当成沙盒**，而且两次都「看起来很正常」。

第一次是 `Restarter`（许可/插件变更触发）以新进程拉起 IDE，丢掉沙盒的 `-Didea.config.path` 等参数。
第二次更隐蔽：`sandbox_start.cmd` 里把 vmoptions 写成命令行参数
`idea64.exe "-Djb.vmOptionsFile=…\sandbox.vmoptions"`——**启动器不解析这个参数**，静默退回默认配置，
于是起出来的就是一个完整的日常 IDE。

**为什么难发现**：主窗口在、不弹许可弹窗（用的正是日常配置里那份有效许可）、标题也像正常工程。
「有没有主窗口」这条曾经是判断许可是否就绪的判据，在这里完全失效——它反而成了误导。

**唯一可靠判据是日志落点**：起完立刻核沙盒 `build/MPSV-<名>/…/log/idea.log` 的 mtime 是否在刷新，
且日常 `%LOCALAPPDATA%\JetBrains\IntelliJIdea<ver>\log\idea.log` 不动。反了就是起错了。

- 按**命令行**判不成立：正确启动的沙盒命令行可能只是一个裸 `idea64.exe`，路径全在 vmoptions 文件里。
- 按**窗口标题**判不成立：起错的日常 IDE 标题同样像正常工程（只会开出插件仓工程而不是 demo 工程，这是唯一的软线索）。
- 核 `ls` **必须带 `-t`**：不带 `-t` 时 `idea.log` 被 `tail` 按字典序截掉（`i` < `t`），我据此得出过**完全相反**的结论。

**正确姿势（2026-10-13 用户定调，此前本节写的 `IDEA_VM_OPTIONS` 口径已作废）**：统一用

```bash
./gradlew runIde -PgifRecord=true --args=<demo 工程绝对路径>
```

它同时做两件事：**重建并安装插件**（改了插件代码必须走它才生效）+ **合并沙盒 `config/idea64.exe.vmoptions`**
（用户在里面保留的第三方 agent/参数才带得进去，进程命令行可逐字核对）。

理由（两条启动路径读的 vmoptions 不同）：
- `IDEA_VM_OPTIONS` 那条只读 `record/sandbox.vmoptions`（里面只有平台自带的 coroutines agent），
  **沙盒 `config/idea64.exe.vmoptions` 根本不会被读取** → 用户放在那里的 agent/参数被静默漏掉；
  而且它绕过 gradle，插件改动不会被重新安装。**仅作应急备选**（例如不想等构建），用完回到 gradle 命令。
- 命令行 `-Djb.vmOptionsFile=…` 那种写法更要避开：启动器**不解析**，静默退回默认配置＝起了一个日常 IDE。

写 `.cmd` 时**只写 ASCII**：中文注释按 UTF-8 存、cmd 按 GBK 读，`rem` 行会裂出乱命令（实测报
`'r' is not recognized`）。

### 11.7 陷阱：开文件与点弹窗按钮两处「看起来能行」的路径都不行

**开文件（Go-to-File）**：键盘路径 `↓` + Return 在本平台**完全无效**——Down 连选中行都不动、
Return 也不开文件（弹窗仍在、窗口标题不变）。改点结果行后还有第二个坑：**首条结果行的右半被一个
白色浮层 chip（`1 mpjdemo/UserServiceImpl.java`）盖住**，点在它边缘会**穿透到后面的编辑器**，
症状是「弹窗还开着、编辑器却选中了一行、标题不变」——实测 x=777 失效、x=600（落在 chip 左侧的
路径文字上）命中。判据用窗口标题（含文件名），命中即停。

**预览弹窗底部按钮行**：`bright_band_y` 全高扫描会命中**顶部标签行**（SQL / JOIN 图，又长又亮），
最左亮簇就成了「压缩」而不是「执行 SQL」；而底部按钮行的**行**均值只有 40~43（面板底色 26，
按钮是描边样式、文字稀疏），行向阈值法分不出来。正确做法＝按 **`底边 − 39`** 取行，再用
`bright_band_x` 取**列**向亮簇（实测三簇恰为 `执行 SQL` / `复制 SQL` / `取消`，最左簇＝执行 SQL）。
⚠️ **前提是弹窗处于新建态**：停在结果态时按钮行整体上移约 40px，`底边−39` 会落到按钮下方空白处——
所以 prep 里的「关旧窗 + 重开」不是可选项。另：无边框弹窗的**窗口矩形比可见底边低约 40px**，
点「取消」按钮的坐标必错，关窗改走 `locate.close_preview()`（点弹窗体 → Esc，判据＝EnumWindows 里

同场还顺手把两个标准件补进 `record/locate.py`：`sandbox_pid()`（读沙盒 `config/.lock`——
`pid_by_cmdline("MPSV-GifFresh")` 自沙盒改用 `IDEA_VM_OPTIONS` 启动后**恒返回 None**）与

### 11.8 陷阱：IDE 启动气泡污染录制区；盲点坐标会打进别人的窗口

**启动气泡**：`Full Line Code Completion offers an LLM for Java…`（模型下载提示）与
`New/updated database configurations found`（连库建议）都固定在**右下角**，压在预览弹窗与原生
控制台之上，末帧/poster 直接被污染。它们的**关闭按钮只在悬停时才显示、且右缘常被 IDE 窗口边界
裁掉**（本轮照截图目视连点十余次全部落空）。更稳的处置是**重启沙盒**：前者重启后不再出现，后者
可点它自带的 `Do not suggest again`。

**盲点坐标的落点**：清气泡那十余次盲点之后查 z 序才发现——**微信（`Weixin`）在最顶层且是前台**
（其提示框正压在编辑器上），第 5 层还开着 `7-Tool`；这些点击完全可能落进别人的窗口（本轮微信随即

说明情况、让用户腾出屏幕，不抢置顶、不换工具硬试；清气泡这类操作前先 `locate.windows()`
看一眼 z 序与前台 PID，别拿`GetForegroundWindow`之外的直觉当依据。

## 12. 构图对齐与白边（2026-10-25 用户两次指出后定例）

### 12.1 顶部被切：外框与 REGION 错位

`REGION` 的左上角必须**等于** `GetWindowRect(hwnd)` 的左上角。本轮把窗口挪到 `(263,5)` 却没同步 `REGION`（仍是 `(277,25)`），结果顶部标题栏被切 20px、左侧 stripe 被切 14px，成片看起来「IDE 没录全」。

```python
win32gui.MoveWindow(hwnd, 277, 25, 1370, 984, True)

```

### 12.2 四周白边：照外框录进了圆角阴影

外框四边各有 **8px 圆角阴影**，实测均值 214~226（浅色带），录进去就是一圈白边。录制区域要比外框**再内缩 8px**：

```

```

内缩后四边均值降到 40~47（IDE 深色本体），画面铺满。**高度须偶数**——`Recorder.start` 有 `assert w % 2 == 0 and h % 2 == 0`，975 会被拒、974 可以。

a = np.asarray(Image.open(shot_path).convert("RGB"), dtype=int)

### 13.2 推翻一个长期误判：近一半组件只能靠 className 定位

此前多次记「AI 面板、右键菜单 robot 查不到，只能用坐标」。实测推翻：

```
//div[@accessiblename]  → 114 个
//div[@class]           → 225 个
仅靠 className 可定位（无 accessiblename） → 111 个（49%）
```

**近一半组件没有可访问名，只有 className。** 查不到时先换 class 匹配，别急着退回坐标：

| 目标 | XPath | 结果 |
|---|---|---|
| AI 面板输入框 | `//div[contains(@class,'AIAssistantInputEditorTextField')]` | 1 个（332x56） |
| 输入区容器 | `//div[contains(@class,'AIAssistantNewToolbarInput')]` | 1 个（348x108） |
| 右键菜单项 | `//div[contains(@class,'ActionMenuItem')]` | **20 项，几何精确** |

### 13.3 新增菜单原语，替掉 a15 那套像素扫描

`record/robot.py` 增加三个函数（已实测）：

- `menu_items()` — 列出当前弹出菜单全部项（屏幕坐标，按 y 排序；屏幕外残留会被过滤）
- `click_menu_item(index)` — 点第 N 项，`-1` 为末项
- `has_menu()` — 快速判断有无弹出菜单

实测右键菜单 20 项、等间距 26px、首项 (869,177) 末项 (869,1012)，闭合检测正确。

**意义**：a15 曾为「找菜单末项」写了约 100 行像素逻辑（两段式量测、聚簇、边框过滤），
并为此返工五轮。现在等价于一行 `click_menu_item(-1)`。菜单项没有 name/text 字段，
只能按序号取——但这已经比像素扫描确定得多。旧逻辑保留为 robot 不可用时的兜底。

### 13.4 下一个能力：robot-server 的 `/js/execute` 通道（已实证，未启用）

反编译 `robot-server-plugin` 的路由表，发现除了我们在用的 `/xpath/components`、`/screenshot`，
还有一直被忽略的 `/js/execute` 与 `/js/retrieveAny`——底层是 Rhino，classpath 能看到 IDE 完整 API。
沙盒实测 20 项全部通过，关键读数：

| 能力 | 实测 |
|---|---|
| 按 action ID 触发动作（不产生坐标） | `ActionUtil.invokeAction(...)` → toolwindow `isVisible` 26ms 内转 true |
| 进程内截图 | 纯 paint **44 fps**；裁剪 + 内存 JPEG **32.7 fps**；后台连跑 3s ≈30fps |
| 读弹窗内部状态 | 遍历 `Popup$HeavyWeightWindow` → `JBList.getModel().getSize()` 可读 |
| 合成鼠标事件 | JTree 派发 `MOUSE_*` → `selectedRows=1` |

**这解释了 12.4 节那条「气球点不到」**：`BalloonImpl` 是独立 heavyweight 窗口，XPath 遍历不到主窗之外，
但 `/js/execute` 能直接遍历 `Window.getWindows()`。同理也覆盖补全列表这类弹窗。

落地成本约 350 行（`idejs.py` + `ideactions.py`），**不需要改插件、不需要重编译、不需要重启 IDE**。
已列进调研报告 §5 的第二期。
