# 录制沙盒"许可失效"反复踩坑与根治（2026-10-23）

> 背景：文档站动图录制需要 IDEA Ultimate 能力（Database 工具窗、EXPLAIN、CSV 编辑器），沙盒靠 `-javaagent` 补丁维持许可。
> 这个坑从 2026-10-13 到 2026-10-23 反复出现四五次，每次都花掉半小时以上，**直到本轮才认清根因**。

---

## 一、症状（三种表现，其实是同一个原因）

1. 沙盒标题栏右上角出现绿色药丸 **`Start Free Trial`**
2. 启动时弹 **`Manage Subscriptions`** 对话框，显示 `No subscription` / `There are no valid licenses associated with the account ...`
3. 点该对话框的 `Refresh license list` 后，IDE **直接崩溃退出**（`runIde` 报 `non-zero exit value 7`）

第 3 条尤其要记：**绝对不要点 Refresh**。日志显示崩溃前的 SEVERE 栈里有混淆类 `com.intellij.ide.G.z.GG.G`，来自那个第三方补丁 agent；联网刷新会触发它的异常路径。

## 二、曾经的误判（全部走过，别再走）

| 误判 | 当时的处置 | 为什么是错的 |
|---|---|---|
| 以为是 JBA 联网超时 | 反复点 Refresh、等它自己恢复 | 点 Refresh 反而让 IDE 崩；日志里的 `SocketTimeoutException` 是次要噪声 |
| 以为 `idea.key` 丢了 | 检查 / 备份 / 恢复 key 文件 | key 一直在，时间戳正常 |
| 以为是 fallback 启动脚本的问题 | 写 `sandbox-start-full.cmd` 走 `IDEA_VM_OPTIONS` | **`IDEA_VM_OPTIONS` 只被 `idea.bat` 识别，直接启 `idea64.exe` 不会读它**——这条路根本不可能生效 |
| 以为是 gradle 没 merge vmoptions | 手动往 `bin/idea64.exe.vmoptions` 追加补丁行 | 方向对但做法错：gradle 启动会重写该文件，手改的会被覆盖；而且在 IDE 运行时改也无效 |

## 三、根因

**沙盒的许可补丁通过 `-javaagent` 注入，而这个参数必须在 IDE 进程启动命令行里。** 它来自沙盒 `config/idea64.exe.vmoptions` 的那一行：

```
-javaagent:C:\Users\USER\.7t\patch\qwdn-afb.jar
```

`gradle runIde` 启动时会把 `config/idea64.exe.vmoptions` 合并进平台 `bin/idea64.exe.vmoptions` 并传给 JVM——**这个 merge 是有效的**（本轮 18:01 实测：两个文件都在、都含该行、运行进程命令行里确有 `-javaagent:...qwdn-afb.jar`）。

之所以经常"失效"，是因为**中途有别的启动方式把状态搞乱了**：用 fallback 脚本直接启 exe 时，它不带 `-Didea.config.path` 等沙盒参数，会退化成**日常 IDE 配置**启动（日志里 `paths.selector=IntelliJIdea2026.2`，config/plugins 路径却仍是沙盒——混合态），这种进程既不加载沙盒的许可补丁，又占用沙盒目录，表现就是"许可没了"。

## 四、正确做法（唯一推荐）

```bash
cd F:/code/Java/Gitee/SongRenShuo/mybatis-plus-sql-visualizer
./gradlew runIde -PgifRecord=true -PgifRobotServer=true \
  --args=F:/code/Java/Gitee/SongRenShuo/mybatis-plus-sql-visualizer-demo \
  -Pkotlin.compiler.execution.strategy=in-process
```

**验证补丁是否真加载**（不要只看标题栏，要看进程）：

```bash
powershell -NoProfile -c "Get-CimInstance Win32_Process | Where-Object { \$_.Name -eq 'java.exe' -and \$_.CommandLine -like '*MPSV-GifFresh*' } | ForEach-Object { if(\$_.CommandLine -match 'qwdn'){'HAS qwdn'} else {'NO qwdn'} }"
```

期望输出 `HAS qwdn`。

**前置自检**（起沙盒前）：

```bash
cat build/MPSV-GifFresh/mybatis-plus-sql-visualizer/IU-2026.2.1/config/idea64.exe.vmoptions
# 应含 -javaagent:...qwdn-afb.jar
```

若这一行没了，才需要补；补完后**必须用 gradle runIde 启动**（它会 merge），不要用 fallback 脚本。

## 五、绝对不要做的事

1. **不要点 `Refresh license list`** —— 会让 IDE 崩（exit 7），且崩溃后 `idea.key` 会被异常回写。
2. **不要用 `sandbox-start-full.cmd` 这类 fallback 脚本** —— `IDEA_VM_OPTIONS` 对 `idea64.exe` 无效；直接启 exe 会退化成日常配置的混合态。这个脚本是历史产物，应视为废弃。
3. **不要在 IDE 运行时改 `bin/idea64.exe.vmoptions`** —— gradle 启动会重写；且 JVM 参数只在启动时读一次。
4. **不要靠标题栏判断许可状态就收工** —— 录制前必须用上面那条 powershell 验进程命令行。

## 六、崩溃后的恢复步骤

若已经点了 Refresh 导致 IDE 退出：

1. 杀掉残留 java/idea64 进程（`Get-Process idea64 | Stop-Process -Force`，再按 CommandLine 匹配 MPSV-GifFresh 的 java 进程）
2. 检查 `config/idea64.exe.vmoptions` 那行还在不在
3. 用 `gradle runIde` 重启
4. 起来后先跑进程验证命令，再截图确认标题栏无 `Start Free Trial`

## 七、录制前 checklist（并入日常流程）

- [ ] `config/idea64.exe.vmoptions` 含 qwdn 补丁行
- [ ] `gradle runIde` 启动（不是 fallback 脚本）

- [ ] 标题栏无 `Start Free Trial`

## 八、桌面自动化侧的连带坑（本轮一并记）

沙盒窗口被别的应用抢前台时，各种"抬窗"手段会失效，逐级递进：

1. `SetForegroundWindow` 直接调 —— 被系统拒绝（Windows 前台锁定）
2. `AttachThreadInput` + `SetForegroundWindow` —— 有时有效
3. **先模拟一次 Alt 键按放**（`keybd_event(0x12,0,0,0)` 再 `keybd_event(0x12,0,2,0)`）再 `SetForegroundWindow` —— 最可靠，本轮靠这个成功
4. 判定是否成功**必须读 `GetForegroundWindow` 的标题**，不能假设
5. 若某些窗口顽固抢占，可把其它窗口 `SetWindowPos(hwnd, HWND_BOTTOM, ...)` 压到底再抬目标窗
6. 截图验证阶段若窗口仍被遮挡，用 `PrintWindow(hwnd, hdc, 2)`（`PW_RENDERFULLCONTENT`）直接抓窗口内容，不受 z 序影响——但注意它**不含标题栏**，验"无试用横幅"必须用屏幕截图

## 九、后续（2026-10-26）：fallback 脚本已移出仓库根目录

本档第五节第 2 条判「`sandbox-start-full.cmd` 这类 fallback 脚本应视为废弃」。本轮确认并处置：
`sandbox-full.vmoptions` 与 `sandbox-start-full.cmd` 已移入 `record/tmp/`（gitignored 暂存目录），
**不进版本控制、也未删除**，保留追溯。

不进版本控制的三条理由：① `IDEA_VM_OPTIONS` 对直接启动的 `idea64.exe` 无效，这条路不可能生效；
② 脚本硬编码了会被缓存重建清掉的 gradle transform 绝对路径，换机即失效；
③ 正解已是 `-Pmpvs.licenseAgent=<jar>`（走 `jvmArgumentProviders`）。

另有本轮新增的一条硬约束见 `20261025-0830-...-经验总结.md` 第八节：
**重启沙盒必须同时带 `-PgifRobotServer=true`**，否则 `prepareSandbox` 重建 `plugins/` 时
会把 robot-server 清掉，组件定位全线失效。
