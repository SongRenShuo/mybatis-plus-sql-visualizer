## 二、增强捕获面：护栏写死 14 的静默缺口

`DialectCaptureCoverageTest` 是 T-CaptureCoverage 加的反向守卫：按方言逐个要求「语句面 + prepare 面」各有驱动族条目，防的是「方言可选、角标可见、捕获一条不出」。它的方言表**硬编码 14 项**、自检 `size() >= 14`——方言涨到 25 后，10 个新方言（外加更早补入的 GoldenDB）全部落在护栏之外，而测试一直全绿。

补法（四步，已写进 `docs/架构设计/03-开发与测试指南.md` §4.9 第 10 条）：

1. `DriverRegistry` 登记驱动类；
2. `WeaveSpecs` 语句面/prepare 面各登记；
3. 驱动 jar 进 agent 测试 classpath，并在 `gradle/verification-metadata.xml` 按产物的 sha256 登记；
4. `DIALECT_DRIVER_FAMILIES` 加一行、自检下限同步抬到 25。

本轮真正新接线的两族：

- **虚谷 XuGu**（`com.xugu.cloudjdbc.*`）：两类语句 + `Connection`。真实字节层织入通过。
- **崖山 YashanDB**（`com.yashandb.*`）：`YasStatement` / `YasConnection` 是**接口**，织入点在其实现类；`StatementImpl.addBatch(String)` 出口发 `chop_frame`，全套形态会 `VerifyError`，改用不含 `ADD_BATCH`/`CLEAR_BATCH` 的形态（同达梦先例，代价是批文本不累积）。

GBase 8a / 神通 Oscar 的官方驱动在 Maven Central 无 metadata（404），无法做字节层取证 → 写进 `VENDOR_NOT_COVERED` 认领并注明替代路径（8a 真机腿走 MariaDB Connector/J，捕获面命中 `org.mariadb.`）。

**真机端到端捕获**（新装置 `dev-support/agent-capture-repro/DialectCaptureProbe.java` + `fake_receiver.py`）：

| 引擎 | 驱动 | EVENT 帧 |
|---|---|---|
| TiDB | mysql-connector-j 8.0.33 | 7 |
| GBase 8a | mariadb-java-client 3.3.3 | 7 |
| XuGu | xugu-jdbc 12.3.9（本轮新接线） | 8 |
| GBase 8c 代理 | opengauss-jdbc 6.0.0-og | 11 |

过程中的两个假结论（都已入 LESSONS）：

- **EVENT=0 是假阴性**：载荷跑完立即退出，agent 异步 flush 没走完。加 6s 收尾后同链路 7 条。
- **反向探针造错**：护栏按「族前缀」判定，第一次只把类名改成假名（保留 `com.xugu.` 前缀）仍绿；整族换成 `com.xuguprobe.*` 才红。

## 三、OceanBase 环境阻塞：三错连发

现象依次为 `Connection refused` → `Server is initializing` → `Access denied`，真因三层叠加：

1. 整机重启后 observer 未自启（容器 Up ≠ 库在）；
2. 容器 IP 从 `172.17.0.12` 漂到 `.14`，而 `~/.obd/cluster/obcluster/{config,inner_config}.yaml` 钉的是安装期 IP；
3. 为解 obd 锁做过 `kill -9`，把集群状态打断。

sed 对齐 IP + `drop_caches` 过后仍停在 initializing，最终走重建：清数据目录 → 按原参数重跑（5.5g cap / ulimit / bind mount / `MODE=mini`）→ bootstrap 完成 → 补建业务用户（`MODE=mini` 只建 `root@test`）→ 登录名改 `user@tenant`。复跑：**PASS 262 词 / 44s**。

内存全程未触闸门：重建后 OB `1.98GiB / 5.5GiB`，宿主 `available ≈ 8.9GB`。
