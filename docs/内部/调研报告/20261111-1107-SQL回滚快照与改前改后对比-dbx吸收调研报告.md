# SQL 回滚快照与「改前/改后」对比：dbx 吸收调研报告

2026-11-11。来源：用户新需求——UPDATE/DELETE 执行前留一份快照方便回滚，开关可配置、默认关闭；改前与改后要能用 IDEA 原生对比窗口的表格形态看。要求先拉取 dbx（`F:\code\Java\Github\other\dbx`）最新代码并吸收其精华。

> 调研基线：dbx `main` @ `48f3ed1d4`（2026-11-11 拉取）；本仓 `master` @ `cef8545e`。
> 本文只写「事实与可吸收点」，实施拆分见同批计划：`docs/开发计划/20261111-1107-T-RollbackSnapshotPreExec-执行前自动快照与改前改后表格对比-开发计划.md`。

## 一、结论先行

1. **dbx 有「行级回滚 SQL」，没有「执行前自动快照」**。它的回滚 SQL 只在数据网格保存这条通道上生成，且与「查询历史」共生：每条保存历史带一个 `rollback_sql` 文本字段。任意 SQL 执行（含它的 AI/MCP 写路径）都不产回滚。
2. **dbx 的回滚是「文本」，不是「数据镜像」**。它保存的是反向 DML 语句文本（新增→DELETE、删除→整行 INSERT、修改→UPDATE 旧值 + 新值 CAS 谓词），不落盘改前数据行；一旦主键/整行谓词失效，回滚文本就成了废纸。
3. **dbx 的「一致性快照」是备份用的**（`begin_database_backup_snapshot`，REPEATABLE READ READ ONLY），只保证导出期间读同一时间点，不产出任何可回滚物；与本需求要的行级快照不是一回事。
4. **dbx 的对比形态是文本 diff，不是表格 diff**：schema/DDL 用左右双栏文本 hunk（`diffLines` + Splitpanes），数据比对用「按表/行列出 added/removed/modified 清单」，单元格值对比用并排文本弹窗。**全仓没有表格形态的 diff 组件**。
5. **IDEA 侧「原生窗口 + 表格」可行，但入口不是 `DiffContent`**：262 的 `DiffContent` 连 `getComponent()` 都没有，正确做法是自写 `FrameDiffTool` + `DiffViewer`（public API），注册 `diff.DiffTool` EP，让平台的 diff 窗口去渲染我们的双表格视图（详见 §五）。DataGrip 自己的 `TableDiffTool` 就是这个架构，但绑死其内部网格模型，不能借用。
6. 对我们真正可吸收的是三件事：**① 无主键时的整行等值谓词 + `COUNT(*)` 前置守卫（不满足就拒绝，而不是给个模板让用户自己跑）**；**② 行定位不可靠时的诚实拒绝清单**；**③ 回滚产物与「哪次执行」绑定、且「回滚不可再回滚」的元信息设计**。（dbx 的「旧值 SET + 新值 CAS」我们早已实现：`RollbackSqlGenerator.revertUpdateFromSnapshot`，`RollbackSqlGenerator.kt:523-543`。）

## 二、dbx 侧事实（带证据）

### 2.1 回滚 SQL 的生成链路与规则

- 唯一生成入口：`prepare_data_grid_save_for_driver_profile`（`src-tauri/src/commands/query.rs:1154`）→ `crates/dbx-sql-data/src/data_grid_sql.rs:440` → `build_data_grid_rollback_statements`（`data_grid_sql.rs:2085`）。
- 三类动作的反向语句：
  - **新增行 → DELETE**：`DELETE FROM {table} WHERE {主键/整行}`（`data_grid_sql.rs:2114-2133`）；MySQL 在「主键为 NULL / 自增 / 生成列」时**直接不生成回滚**（`build_mysql_insert_rollback_where`，`:2495-2528`）。
  - **删除行 → 整行 INSERT**：`INSERT INTO {table}(cols) VALUES(整行原值)`（`:2138-2203`）；MySQL 合并多行 VALUES（`:2178-2202`）。
  - **修改行 → UPDATE 旧值**，且 WHERE 里同时带主键与新值做 CAS 校验：
    ```sql
    UPDATE SQLUser.PA_PatMas SET PAPMI_ID = 'before'
    WHERE PAPMI_RowId = 51 AND PAPMI_ID = '210101202201016555';
    ```
    证据：`data_grid_sql.rs:2205-2290`，期望样例 `:5712-5716`。
- 行定位来源：`table_meta.primary_keys`；PostgreSQL 系无主键时注入隐藏列 `__DBX_ROWID`（`tableoid:ctid:xmin`，常量 `data_grid_sql.rs:39`，判定 `:1563-1568`）；Oracle/虚谷用 ROWID，Neo4j 用 elementId（`apps/desktop/src/lib/table/tableEditing.ts:4,182-196`）。
- 无主键表：用「所有列 = 值」组整行谓词（`build_row_where`，`:3925-3952`），并额外产出 `keyless_guards`，要求服务端 `COUNT(*)` 确认只命中 1 行（结构 `:394-420`，前端执行 `apps/desktop/src/composables/useDataGridEditor.ts:2010-2031`）。
- 值编码：NULL 统一 `IS NULL`（`:4014-4016`）；二进制走 hex / `BINARY` / `TO_BLOB` / `UTL_RAW`（`:2771-2779`、`:2951-2959`）；Oracle CLOB 按字节分块拼 `TO_CLOB`（`:2803-2830`）；OceanBase BLOB 超 4000 hex 用 `DBMS_LOB.GETLENGTH/COMPARE`（`:4081-4088`）。
- 明确不生成回滚的形态：ClickHouse（`:2098-2100`）、Salesforce（REST 无事务，`data_grid_salesforce_sql.rs:110-113`）、TDengine 复合键新增（`data_grid_tdengine_sql.rs:53-56`）。

### 2.2 回滚产物的持久化

- 载体是**查询历史的一条字段**：`HistoryEntry.rollback_sql: Option<String>`（`crates/dbx-core/src/persistence/history.rs:25`），落在本地 SQLite `history` 表 `rollback_sql TEXT`（`crates/dbx-core/src/persistence/storage.rs:1217-1238`）。没有独立快照表。
- 生命周期寄生在历史保留策略上：默认 `MAX_HISTORY = 1000`（`history.rs:102`），可选 200/1000/5000/10000/0=不限（`:104-108`）；无 TTL、无单条长度上限；剪枝发生在**下一次**写历史时（`storage.rs:3993-4000`）。
- 只在**保存成功**后写入；失败时 `rollback_sql` 为空（`useDataGridEditor.ts:2249,2264`）。
- 回滚动作自身也记历史（`operation: "ROLLBACK"` + `details_json.rollback_of`），但**不写 rollback_sql**——即「回滚不可再回滚」（`apps/desktop/src/components/editor/QueryHistory.vue:443-457`）。

### 2.3 展示与执行

- 历史详情里单块展示 `rollback_sql`（带高亮与复制，`QueryHistory.vue:923-932`）；条目元信息行显示「可回滚 / 无回滚 SQL」（`:403`）。
- 入口：详情面板「回滚」按钮（`:944-946`）与右键菜单（`:568`）。
- 执行前只有一次 `window.confirm`（`:461`）+ 生产库二次确认（`apps/desktop/src/lib/database/productionExecutionGuard.ts:19-38`）。
- **默认非事务**直接 `executeScript` 自动提交（`:476`）；勾选手动事务才 `begin/execute/commit|rollback`（`:466,478-530`）。
- `canRollbackHistoryEntry` 只校验「连接、库、回滚文本都非空」，不校验连接/表/主键是否仍存在（`apps/desktop/src/lib/history/historyAiAnalysis.ts:19-20`）。

### 2.4 一致性快照 ≠ 行级快照

- `begin_database_backup_snapshot`（`crates/dbx-core/src/query/mod.rs:6548`）＝「只读、可重复读快照，供备份导出」，转 `begin_transaction_session(consistent_snapshot=true)`。
- 方言落地：PG 发 `BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ READ ONLY`（`:6558`）；MySQL 先 `SET TRANSACTION ISOLATION LEVEL REPEATABLE READ`（`:6602`）再试 `START TRANSACTION WITH CONSISTENT SNAPSHOT, READ ONLY` / 去掉 READ ONLY / 普通 START（`:6581-6585`）。
- 支持面仅 MySQL / PostgreSQL / openGauss（`crates/dbx-core/src/data/database_export.rs:3291-3295`）；返回只有 `session_id + schemas`，不产任何可回滚物。
- 用途：全库导出（`database_export.rs:3259-3371`）与定时备份（`crates/dbx-core/src/scheduled_backup/engine.rs:315-321`）。
- 生命周期受手动事务 idle 超时约束（默认 300s，`query/mod.rs:54,965-969`）。

### 2.5 对比形态

| 场景 | dbx 形态 | 证据 |
|---|---|---|
| Schema/DDL 正向 vs 回滚 | 左右双栏文本 diff（`diffLines` hunk + 行号 + 字符级高亮 + SVG 连线） | `apps/desktop/src/components/diff/SchemaDiffDdlPanel.vue:360-368,392-451`；`DiffHunkBuilder.ts:1` |
| 表数据比对 | 表/行级清单（added/removed/modified），不是单元格网格 diff | `apps/desktop/src/components/diff/DataCompareDialog.vue:1597-1705`；`crates/dbx-core/src/data/data_compare.rs:146-148` |
| 单元格改前改后 | 并排文本弹窗（超 500k 字符降级） | `apps/desktop/src/components/grid/DataGridValueDiffDialog.vue:5,57` |
| 网格内的行级 before/after | 只有单元格颜色 + undo/redo 栈，**无 diff 视图** | `useDataGridEditor.ts:678` 附近 |

结论：**表格形态 diff 在 dbx 里不存在**，这条得我们自己造。

### 2.6 dbx 自认的局限（我们要引以为戒）

- 无主键整行谓词可能匹配加载页之外的物理行，只能靠 `COUNT(*)` 守卫拒绝（`data_grid_sql.rs:46-47,394-420`）。
- PG `ctid` 行定位在并发修改后失效，靠 `min_matched_rows` + stale 报错兜（`:44-51,2249-2260`）。
- 部分列根本不能做谓词：Oracle 无主键且含 LOB 直接拒绝（`:1638-1653`）、Dameng 二进制 LOB/空间列拒绝（`:1656-1663`）、Doris 聚合态列拒绝（`:1524-1561`）。
- 大字段截断会污染回滚：变更单元格还是 `...` 预览值时，回滚 SQL 会记下截断文本（issue #12964 修复点，`apps/desktop/src/composables/useDataGridLargeValues.ts:717-729`）。
- 条件批量更新明确不生成回滚：「DBX 无法为这些行生成可靠的回滚 SQL」（`apps/desktop/src/i18n/locales/zh-CN.ts:3704`，官方文档 `docs/content/docs/data-grid.mdx:78`）。
- 手动事务里执行完立即记 success，用户随后整体回滚，历史仍显示成功且带回滚 SQL——**历史与最终状态可能不一致**（`useDataGridEditor.ts:2776-2777`）。

## 三、本仓现状（T-RollbackSql 线的真实边界）

以下每条均实读代码，不引旧计划自述。

### 3.1 有的

- **回滚生成器**：`sql/rollback/RollbackSqlGenerator.kt`。INSERT 可推逆向 DELETE；UPDATE/DELETE 一律 `UNABLE` + `snapshotSelectSql = "SELECT * FROM t [WHERE …]"`（`:274-315`）。
- **快照回填三模式**：`generateFromSnapshotRows`（`:372-392`）——`REVERT_UPDATE`（改前值还原）、`BACKFILL_INSERT`（删除后补回）、`REVERT_INSERT`（新增后删除）。评级 `COMPLETE/PARTIAL/UNABLE`，上限 500 语句 / 256KB / 快照 200 行（`:101-107`）。
- **CAS 乐观锁已经在用**：`revertUpdateFromSnapshot` 生成的是 `SET 旧值 WHERE 主键 AND 被改列 = 新值`（`:523-543`）——与 dbx 同一设计，不需要「吸收」，只需要在新链路上继续用。
- **交互式快照查询**：`ui/RollbackSqlDialog.kt` 的「执行快照查询」走只读旁路 `PreviewSideQuery.run`（`:720-745`），结果转 TSV 填进 `pasteArea` 并自动生成回滚（`:728-730`），表格/文本双态展示（`:375-391`），可「在 CSV 编辑器中打开」（`:508-555`）。
- **只读旁路基础设施**：`ui/PreviewSideQuery.kt:28-126`（`McpSelectGuard` + 方言闸 + pooled 线程 + EDT 回调，结果 `Scalar/Table/Blocked/Failed`）——新采集链可直接复用。
- **参数填值**：`sql/ParameterReplacer.kt:77`（`buildExecutableSql`）、`:338`（`buildExecutableSqlWithSlots`）。

### 3.2 缺的（正是本需求要补）

- **执行前不查库**：`SqlPreviewPanelExecution.registerRollbackSnapshotIfNeeded`（`:556-583`）只解析文本 + 写内存 Map。两个调用点在确认之后执行之前（`:473`、`:1299`）。

- **不持久化**：PROJECT 级内存 light service，`LinkedHashMap` LRU 100（`:72-80`、`:188-190`）；IDE 重启即失。
- **改前镜像不落盘**：唯一 before-image 是对话框内 `pasteArea`/表格模型的瞬时内容，弹窗销毁即丢。
- **无开关**：登记对 UPDATE/DELETE 无条件执行（`:561-582`）；`PluginSettings` 全量开关里无任何 rollback/snapshot 项。
- **无改后采集、无双侧对比**：执行回执只改横幅（`RollbackSqlDialog.kt:649-667`）。
- **无表格 diff**：仓内两处原生 Diff 都是文本（`SqlPreviewPanelSqlView.kt:623-646`、`HistorySqlLogPanel.kt:974-993`）；`ui/diff/SqlDiffer.kt:3-4` 自标无调用方死代码。
- **登记失败静默**：`targetTable == null` 直接 return，无日志、无提示（`:581`）。
- **`markRollbackExecuted` 只代表「已交给执行器」**，不代表库端成功（`:155-168`）——新链路的状态机要把它升级为「有回执才落状态」。

## 四、可吸收 / 不吸收

### 吸收（进本仓设计）

1. **无主键 → 整行等值谓词 + `COUNT(*)` 前置守卫**：命中不等于 1 就拒绝生成/拒绝执行。本仓现有 `PARTIAL` + `countCheckSql` 是「给模板让用户自己跑」，dbx 是「不满足就拒绝」——新链路的自动采集应取后者。
2. **诚实拒绝清单**：行定位不可靠（含 LOB 无主键、聚合表、无事务引擎）就明说不能回滚，并给出替代（导出改前数据 / 手工快照）。
3. **回滚产物与「哪次执行」绑定**：dbx 挂历史条目，我们要挂自己的快照条目，并记「已回滚 / 已被后续执行覆盖」。
4. **「回滚不可再回滚」**：回滚执行本身不再生成新的快照条目，避免套娃与状态混乱。
5. **不生成回滚的引擎清单**：ClickHouse / Salesforce / TDengine 复合键这类，直接在采集阶段就标注「该引擎不可回滚」，而不是生成一半。

### 不吸收

1. **不学它的「只有文本、没有数据镜像」**。本需求明确要「留一份快照」，且要能对比改前改后——必须有结构化数据行，不能只有 SQL 文本。
2. **不学它把回滚塞进查询历史**。历史是 APP 级、跨项目、按条数裁剪的；快照需要按项目/连接/表可检索、可过期、容量可控，应独立存储。
3. **不学它默认非事务直跑**。我们执行前已采集改前数据，回滚默认应在事务里跑并逐条报告影响行数。
4. **不学它的一致性快照**。`REPEATABLE READ READ ONLY` 解决的是导出期间的时间点一致，我们的场景是「执行前取一次 WHERE 命中行」，不需要长事务（长事务会持锁/涨 undo）。

## 五、IDEA 原生 diff 的表格形态：平台事实（262 实测）

证据基线：distro `idea-2026.2.4-win`（`build.txt = IU-262.11879.100`）。该 distro 用 JDK25 编译，`javap` 24 读不了（`Unsupported class file version: 69`），签名由 classfile 描述符提取并与 2026.3 distro 逐类比对——`DiffManager / FrameDiffTool$DiffViewer / DiffTool / SimpleDiffRequest / DiffContent / DiffContentFactory / EditorHolder / TwosideDiffViewer` 方法集差异为空。

- **`DiffContent` 没有 `getComponent()`**：262 只有 `getContentType(): FileType`、`getNavigatable(): Navigatable`、`onAssigned(boolean)` 三个方法（`intellij.platform.diff.jar`）。所以「自定义 `DiffContent` 返回 `JBTable`」这条路**不存在**。
- **唯一公开的自定义视图入口**：`FrameDiffTool$DiffViewer#getComponent(): JComponent`；243 实测（P0 探针）`DiffManagerEx.getDiffTools()` 里 **EP 工具不在最前**（探针下标 8/13）——「EP 排在内置之前」不成立，选择正确性由「唯一 canShow 命中」保证（内置工具对非 ContentDiffRequest 全部 say-no）；`DefaultState.init()` 把 `viewer.getComponent()` 放进原生 diff 内容面板。另：243 的静态入口是 `DiffManagerEx.getInstance()`（不是 getInstanceEx），`DiffRequest` 有抽象成员 `getTitle()`。
- **`DiffContentFactory` 没有任何 highlight 参数**：`createEditable(project, text, fileType)` 只是「文本 → DocumentContent」，行内高亮靠平台行级 `RangeHighlighter` + `LineFragment.getInnerFragments()` 的字符级片段，**没有单元格语义**。262/263 也不存在 `DiffViewerType` 类，想强制指定工具只能用请求 userData `DiffUserDataKeysEx.FORCE_DIFF_TOOL`。
- **平台自带的表格 diff 在 DataGrip 里**：`plugins/DatabaseTools/lib/modules/intellij.database.impl.jar` 含 `com.intellij.database.diff.TableDiffTool implements FrameDiffTool`、`TableDiffViewer extends TwosideDiffViewer`、`TableEditorHolder`，注册在 `database-plugin.jar!/META-INF/plugin.xml:535-537`。但它绑死 `GridDataHookUp`/`DasTable`，且本仓对 DatabaseTools 是 optional 依赖（`src/main/resources/META-INF/plugin.xml:106`），**不能当通用底座**。
- **本仓现有 diff 用法两处同款**：`ui/SqlPreviewPanelSqlView.kt:619-645` 与 `log/HistorySqlLogPanel.kt:974-993`，都是 `createEditable` + `SimpleDiffRequest` + `showDiff` 的纯文本形态；仓内无自定义 `DiffContent`/`DiffTool`，无单元格概念。
- **候选路线对比**：

| 路线 | 依赖 | 单元格级高亮 | 风险 | 工作量 |
|---|---|---|---|---|
| A TSV 文本 diff | 本仓现有三件套 | 做不到（只有行级/字符级） | 极低 | S |
| **B 自定义 `FrameDiffTool` + `DiffViewer`（双 `JBTable`）** | 全 public API + `diff.DiffTool` EP | **能** | 低（对齐与渲染自写；无 F7 导航） | M |
| B0 `ComponentDiffRequest` 直塞组件 | 靠 `ErrorDiffTool` 兜底 | 能 | 语义是错误视图、无工具栏，仅验证捷径 | S |
| C 自建 `DialogWrapper` + 表格 | 纯 Swing | 能 | 低，但**不是**原生 diff 窗口 | M |

推荐 **B**：`DiffRequest` 子类 + `FrameDiffTool` 子类 + `DiffViewer` 子类 + `plugin.xml` 注册 `<diff.DiffTool/>`，与 DataGrip 同架构但只用 public 面。取舍是 F7 差异导航与「接受/回退」类平台动作不会自动获得，需自己给工具栏按钮。

**P0 探针订正（2026-11-14，classfile 实测）**：243 与 262 的 `FrameDiffTool` 抽象方法都是 **`createComponent(DiffContext, DiffRequest): DiffViewer`**（本报告早前引用的「`createViewer`」有误）；`getToolType()`/`getIcon()` 均带默认实现（字节码含 Code 属性），`ToolbarComponents` 两版本都有公开 `()V` 构造——按 243 基线编译、262 运行无 AbstractMethodError 风险。`DiffTool` 接口 = `getName()` + `canShow(DiffContext, DiffRequest)`，EP 名常量池实证为 `com.intellij.diff.DiffTool`。

2. 「改后」值能否可靠拿到——执行后按主键反查得到的是库端真值，问题在「改后行还能不能被同一定位键找到」（主键被改、行被删、无主键）；触发器与并发写会让「改前快照」与「真实生效值」产生偏差，UI 上只能声明为「执行前读到的值」。
3. Community 版（无 Database 插件）下采集不可用时，开关应自动降级为「可见但禁用 + 原因」，不能静默跳过。
4. 把采集插进「确认之后、提交之前」是否会打破现有执行链时序（Schema 预检、方言闸、`DumbService.runWhenSmart` 收口）。
