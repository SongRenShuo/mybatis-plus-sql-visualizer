# 🎉 SQL Visualizer v2026.10.28

> 发行说明留档：对应 Gitee 发行版 **v2026.10.28**（标签 `2026.10.28`），附件 `mybatis-plus-sql-visualizer-2026.10.28.zip`。
> 范围＝自 v2026.10.26 正式版发行包之后的全部用户可见增量。

自 v2026.10.26 后的正式版。本轮有 **3 项新增**（Mapper 双向跳转、DDL 类型着色与筛选、方言闸门放行）、**7 项修复**（含一个会让宿主应用起不来的 P0）与 **3 项性能改动**。P0 是增强捕获把宿主连接换成 JDK 动态代理导致的强转异常——达梦工程首当其冲，所有「写死实现类强转」的驱动环境都在影响面内。

## ✨ 新增

**Mapper 接口方法与 XML 语句双向跳转**
- mapper XML 的 `select` / `insert` / `update` / `delete` 标签行与 Mapper 接口方法行各出 gutter 图标，点击互相跳转（XML → 接口方法、接口方法 → XML 语句）
- 目标按 `namespace` + 标签 `id` 解析，解析不到就不显示图标，不猜同名方法
- 该能力来自外部贡献 PR，本版合并

**DDL 语句纳入类型着色与筛选（T-DdlTypeColor）**
- `CREATE` / `ALTER` / `RENAME` 与 `DROP` / `TRUNCATE` 各自成一档 StatementType，可分别勾选筛选；此前 DDL 没有独立类型，勾「只看插入」一类筛选时行为含糊
- 着色复用增删色相，视觉区分靠**色条形态**：DDL 画虚线、DML 实心，不新增设置项

**预览面板执行入口方言不一致改为放行（T-DialectGatePass）**
- 点「执行 SQL」时方言不一致不再弹阻断错误框，改为状态行信息提示、执行继续，与 2026.10.23 定案的「方言不影响最终执行」对齐
- 文案前缀由「已阻止执行：」改为「方言不一致：」；重渲染失败等确实无法继续的路径仍走阻断

## 🛠 修复

**增强捕获把宿主连接换成 JDK 代理，致驱动实现类强转抛 CCE、应用起不来（T-ConnCastSafety，用户 P0）**
- 现象（外部达梦用户报障）：`ClassCastException: com.sun.proxy.$Proxy129 cannot be cast to dm.jdbc.driver.DmdbConnection`，且「以前好好的，今天程序死活跑不起来」。同轮用户环境清单里还有高斯 / openGauss、人大金仓、翰高、海量、Oracle、MySQL、PostgreSQL
- 根因：agent 在驱动 `connect` 出口把真实连接替换成 `java.lang.reflect.Proxy`。动态代理只能实现接口，永远无法伪装成驱动实现类，应用只要写 `(DmdbConnection) conn` 就必然抛 CCE；异常抛在应用自己的栈上，agent 的异常自吞拦不住
- 为什么「今天才坏」：v2026.10.23 起增强捕获默认开启，此前不启用时连接根本不会被替换
- 修复：**增强捕获不再替换应用拿到的任何 JDBC 对象**。连接出口只登记 URL 并原样返回，SQL 采集改由方法级字节码织入完成（只往方法体里插回调，对象身份不变），覆盖 MySQL 家族、PostgreSQL / openGauss、Oracle、SQL Server、H2、达梦
- 绑定参数同步搬进织入通道（`setXxx` 入口插桩），连接代理关闭后参数照常可见、脱敏口径不变；顺带修正织入层把 `execute()` 的 boolean 返回值误装箱成 `Integer`、导致影响行数恒空的问题
- 撤出达梦驱动的 `connect` 面织入：该出口在达梦上是已知的字节码校验失败形态，默认校验下会让驱动类加载失败（`VerifyError`），比 CCE 更早把应用打死；达梦的语句面与 prepare 面覆盖已足够
- 代价（如实说明）：语句实现类不在织入名单的驱动（GBASE 8s、部分 SQLite / HSQLDB 形态）默认不再产出事件；这类环境可显式加 `-Dsqlvis.agent.wrapConnection=true` 恢复旧的连接代理通道，并自行承担实现类强转风险。控制台日志通道不受影响

**执行控制台与预览绑定数据源不一致（T-ConsoleBind）**
- 预览头部显示「已绑定 A 库」，点执行 SQL / 执行计划 / 回滚快照查询却在 B 库的既有控制台上跑（现象是 `Unknown column` 一类只在 A 库存在的列报错），对数据源节点 Close All Sessions 也改不回来
- 根因两层：平台把 exec 文件的「文件→数据源」关联写死并短路 runner 枚举；插件侧的控制台复用只按名字、不按实际绑定身份
- 现复用判定升级为身份制（比对数据源 UUID），全链枚举前把 exec 文件的关联对齐到绑定目标；用户显式换源时清关联，让选择器恢复全源列表

**日志列表头部信息顺序与类名被截断（T-LogListHeader）**
- 恢复 2026.10.23 的头部顺序与形态：来源回到最后、显示完整文件名（带方括号与 `.java` 后缀，不剥不截），超宽时按顺序截断而非按优先级丢片段
- 同时修复「自动滚动关掉后无法恢复」

**时间显示格式严格跟随设置**
- 此前头部行超宽会剥掉日期只留时刻，同一份配置在宽栏与窄栏显示成两种形态；现在完全按设置里的格式输出，不再按宽度偷偷改

**设置页切到具体方言后状态行不刷新（T-DialectLabelStale）**
- 把「数据库方言」从智能推断切到 Oracle 等具体方言时，副标题仍停在旧文案，要等面板重绘或 apply 才追上

**MCP 审计上下文取消残留（T-PerfSweep27-04）**
- 工具协程被取消且 continuation 永不 resume 时审计条目滞留；改为写入点顺带同步清扫（过期窗 10 分钟 + 上限 64 条），不采用 try/finally 包裹挂起调用的方案（会踩平台 `SpillingKt` 校验红线）

**项目打开时的平台慢操作断言（T-SqlDialectPrewarm）**
- 日志工具窗首帧装配在 EDT 上取 SQL 文件类型高亮器，连带触发平台「文件→方言」映射的一次性延迟加载，被平台记为 EDT 慢操作并把本插件归为 blame
- 现日志转 SQL 的结果区改用插件自研 SQL 高亮器，并把这处首查整体挪到后台线程、在装配面板之前完成（有界等待 300ms，超时照常装配）
- 结果区配色随自研词法器变化：关键字按固定词表着色（`WITH` / `INTERVAL` 等方言词降为标识符）、表名与表别名独立成色、逗号点号并入运算符色；「设置 → 编辑器 → 配色方案 → SQL」段的既有自定义不再作用于该区域

## 🔧 改进

**日志头部行渲染缓存（T-PerfSweep27-01）**
- 头部静态片段改条目级缓存，可见格重绘不再重算；单格预算 2.0ms → 1.0ms，实测约 0.08ms/格

**实体解析缓存容量上限化（T-PerfSweep27-02）**
- `EntityResolver` / `JpaEntityResolver` 两处静态缓存加 4096 上限，关闭无上限累积

**补全与 gutter 判定前置（T-PerfSweep27-03）**
- 补全调试日志加开关门控，HqlGutter 的开关判定提到耗时计算之前

## 兼容性

- 支持 IntelliJ IDEA **2024.3+**（Ultimate / Community；EXPLAIN、执行 SQL、表右键入口与 Database 原生图需 Ultimate；MCP 能力需平台 MCP Server）
- 插件 ID 与升级链路不变，v2026.10.26 用户可直接覆盖升级
- 升级后若某工程此前依赖「连接代理」才出事件（即上述 GBASE / SQLite 一类未登记驱动），事件会变少但程序不再可能因插件崩溃；确需事件时按上文加属性

## 📦 安装

1. 下载附件 `mybatis-plus-sql-visualizer-2026.10.28.zip`
2. IDEA：`Settings → Plugins → ⚙️ → Install Plugin from Disk…` → 选择 zip → 重启 IDE
3. Marketplace 用户：市场页直接更新；Gitee 通道用户：设置页「更新」分区检查更新即自动收到本版，自 v2026.9.11 起经该通道更新免重启即时生效
