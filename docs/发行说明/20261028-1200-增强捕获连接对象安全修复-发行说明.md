# SQL Visualizer v2026.10.28

> 发行说明留档：对应 Gitee 发行版 **v2026.10.28**（标签 `2026.10.28`），附件 `mybatis-plus-sql-visualizer-2026.10.28.zip`。
> 范围＝自 v2026.10.26 正式版之后的全部用户可见增量（本轮为单项紧急修复版）。

自 v2026.10.26 后的正式版。本版修一个外部用户真机报障，性质是**插件把用户程序搞崩**：
`com.sun.proxy.$Proxy129 cannot be cast to dm.jdbc.driver.DmdbConnection`，且「以前好好的，今天程序死活跑不起来」。

## 修复

**增强捕获把宿主数据库连接换成 JDK 代理，导致驱动实现类强转抛 ClassCastException（T-ConnCastSafety）**

- 现象（外部用户报障，达梦工程）：开启增强捕获后应用启动即抛
  `ClassCastException: com.sun.proxy.$Proxy129 cannot be cast to dm.jdbc.driver.DmdbConnection`；
  同一轮库里还有高斯/openGauss、人大金仓、翰高、海量、Oracle、MySQL、PostgreSQL 的工程
- 根因：增强捕获 agent 在驱动 `connect` 出口把真实连接替换成 `java.lang.reflect.Proxy` 动态代理再交给应用。动态代理只能实现接口，**永远不可能伪装成驱动实现类**，应用只要写 `(DmdbConnection) conn` 就必然抛 CCE；异常抛在应用自己的线程栈上，agent 那一层的异常自吞拦不住
- 为什么「今天才坏」：v2026.10.23 起增强捕获改为默认开启且不再弹注入确认——此前不启用时连接根本不会被替换
- 修复：**增强捕获不再替换应用拿到的任何 JDBC 对象**。连接出口只登记 URL 并原样返回，SQL 采集改由方法级字节码织入完成（只往 `execute`/`prepareStatement` 方法体里插回调，对象身份完全不变）。覆盖 MySQL 家族、PostgreSQL/openGauss、Oracle、SQL Server、H2、达梦
- 绑定参数同步搬进织入通道（`setXxx` 入口插桩），连接代理关闭后参数照常可见、脱敏口径不变；顺带修掉织入层把 `execute()` 的 boolean 返回值误装箱、导致影响行数恒空的问题
- 同批撤出达梦驱动的 `connect` 面织入：该出口在达梦上是已知的字节码校验失败形态，启动期会让驱动类加载失败（`VerifyError`），比 CCE 更早地把应用打死；达梦的语句面与 prepare 面覆盖已足够，撤出只损失一个粗粒度 URL 兜底
- 代价（如实说明）：语句实现类不在织入名单里的驱动（GBASE 8s、部分 SQLite/HSQLDB 形态），增强捕获默认不再产出事件；这类环境可显式加 `-Dsqlvis.agent.wrapConnection=true` 恢复旧的连接代理通道，并自行承担实现类强转风险。控制台日志通道不受影响
