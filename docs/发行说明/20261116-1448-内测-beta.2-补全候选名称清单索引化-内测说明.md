## 这一版有什么

mapper 补全里的两类跨文件候选——`<include refid="…"/>` 的片段名、以及 `${…}` / `<if test>` 里来自 mybatis-config `<properties>` 的变量名——原本每次弹出补全都把项目内最多 500 个 XML 逐个解析一遍再拼清单。工程越大越慢，而清单内容几乎不变（实测同一清单连续两次调用耗时同量级＝每次都全付）。本版把它们改为项目级服务一次构建、按 IDE 索引状态失效。

### 补全候选名称清单改项目级服务（T-IndexScanSweep2 P1）

- 新增 `ui/highlight/XmlSymbolNameIndexCache`（项目级服务，懒建、后台智能模式构建、随项目释放），清单按「索引代戳 ⊕ 逐文件 modStamp」失效：新增 / 删除 / 保存 mapper 或 config 文件后立即生效，没有原先的 5 秒窗口。
- `MapperNamespaceIndex` 升 v2，新增 `#mapper` / `#config` 文件级标记键与 `rootElementName`（跳过 XML 声明 / DOCTYPE / 注释后取首个元素名，修掉 `<mappers><mapper resource=…/></mappers>` 被老锚误判成 mapper 文件）；既有 namespace 键语义不变，三个消费方（mapper 定位 / 跨命名空间片段 / MybatisXmlTargets）零改动。
- 改造前按**文件身份**排除当前文件，现按**名字集合**排除（病态的同 namespace 重名场景会被一并排除，正常工程逐项一致）。
- 失效以落盘为界：别的文件里未保存的编辑要等保存才进清单；当前文件自身的 `<sql id>` 不受影响（走活 PSI 补齐）。
- 回退：Registry `sqlvis.completion.nameIndexCache=false` 回到旧的「每次现扫」路径（回退通道下一版删除）。
