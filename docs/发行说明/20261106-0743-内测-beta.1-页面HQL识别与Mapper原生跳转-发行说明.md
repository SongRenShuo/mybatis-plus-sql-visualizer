# 🎉 SQL Visualizer v2026.11.6-beta.1（内测版）

> 发行说明留档：对应 Gitee 发行版 **v2026.11.6-beta.1**（标签 `2026.11.6-beta.1`），附件 `mybatis-plus-sql-visualizer-2026.11.6-beta.1.zip`。
> 通道：**Gitee 内测版**（Marketplace 不收内测包，正式版转正时另行上传）。
> 范围＝v2026.11.4 发行包之后的全部用户可见增量：两项新能力（自研框架页面数据源 HQL 识别与转换、Mapper 跳转接入原生快捷键）、两项修复（跨通道重复条目、工具语句误报超时）、一项可选显示改进（类名#方法名）。

这一版的主题是把「看得到但用不了」的两类场景打通：自研框架 `<pages>` 页面里的 HQL 此前只能看原文，现在能转成可执行的 SQL；Mapper 与 XML 之间的跳转此前只有鼠标点图标一条路，现在键盘快捷键全线接通。

## ✨ 新增

**自研框架页面数据源识别 HQL 并转换为 SQL（用户反馈驱动）**

`<pages>` 页面 XML 的 `<datasource>` 此前一律按原生 SQL 直显。真实工程里这段内容常常是 HQL：`FROM BaseLocation location` 原样展示（真执行会报「表不存在」）、`location.updateInfo.beDelete` 这类实体属性路径不映射列名、`:name` / `?1` / `#{...}` 参数一概不提取——看着像已经识别了（表名、列信息都在），实际只是原文加了个壳。

现在按「entityClass 与语句根标识符的关系」判定源语言，命中 HQL 后走与 JPA/JPQL 同一条转换管道：

- 实体名 → 表名（`FROM BaseLocation` → `FROM base_location`），JOIN 副表实体同样映射
- 按别名作用域做属性路径 → 列名映射（`location.updateInfo.beDelete` → 真实列名）
- 命名参数 `:name` / 位置参数 `?1` 自动提取，面板按名回填
- 框架占位符 `#{SESSION_BASE_ORGAN}` 预处理成命名参数走既有参数链；字符串字面量内的 `#{...}` 不动，与 HQL 自带 `:x` 同名时合并为同一参数

判定刻意保守——demo 里 `orderMaintain` 的 entityClass 是 `Order` 但 `<datasource>` 是原生 SQL，这种形态不会误判；判不准时一律按 SQL 处理。设置里新增「自研框架数据源语言（HQL/SQL）」三档：**自动**（默认）/ 仅 SQL / 仅 HQL。

泛化范围：页面标签名不再限定 `maintainPage`（listPage 等任意页面标签都认），`<dataValue>` 这类没有 entityClass 的通用 SQL 载体同样走该判定。gutter 图标与右键预览两条入口都生效。

面板配合：元信息行显示「来源: HQL（已转换）」，新增**「原文」只读页签**随时回看转换前文本；无工程索引、根实体解析不了、转换异常三种情况自动回退显示原文并给提示，不报错。

**Mapper 接口与 XML 语句双向跳转接入 IDEA 原生快捷键（用户反馈驱动）**

此前双向跳转只有 gutter 图标（鼠标专用）：Java 接口方法上 Ctrl+B 没反应，XML 语句标签名上同样没反应（只有 `id` 属性值位置本来就有引用跳转）。

现在接入平台两个原生扩展点：

- **Ctrl+B / Ctrl+Click**：Mapper 接口方法 ↔ XML 语句双向跳转
- **Ctrl+Alt+Home**：弹出「关联符号」，列出对侧的 XML 语句 / 接口方法

键位归平台 action 所有，改 Keymap 自动跟随；非 Mapper 位置的行为零变化。

## 🛠 修复

**同一次执行的 SQL 在日志列表留两条（用户真机报障「部分 INSERT 没有捕获到耗时和执行位置」）**

同一条 INSERT 出现两次：一条无耗时、无库角标、无执行位置（控制台通道），另一条信息齐全（增强捕获通道）。信息其实都在——MyBatis 对 DML 只打 `Updates: N` 不打耗时行，所以控制台条目天生缺耗时；缺的是把两份折叠成一份。

现在 5 秒窗口内按归一化等价键把两条折叠为一条，增强捕获副本到达时融合升级（耗时、影响行数、库角标、可跳转的执行位置补齐），不计入 ⨉N 重复计数。折叠与「SQL 去重」开关解耦——开关关闭时也折叠，因为这不是重复执行，是同一次执行。

顺带：二进制参数（byte[]/Blob/Clob）签名归一为 `<binary>` 不再漏折；agent 参数捕获面补齐（四族 `setObject` 等此前织入点盖到但捕获不到的形态）。沙盒再验收又修掉两处同链路问题——①配置周期性下发会在「清空 → 回执」之间放开一道 0.2~1.25 秒的控制台桥放行窗，每轮都让桥与 agent 各产一条（闸门抖动）；②活性回落判据在两次操作间隔超 10 秒时误解封，解封瞬间的 SQL 又落成一条无耗时条目。①现下发保留上一次确认值、配置未变无窗，②现收窄为「本纪元从未收到过 agent 事件」才回落。

**工具语句/更新语句执行成功却报「超时」提示（用户令）**

不产生结果页签的语句成功完成时，此前仍按「等待结果超时」归因，提示引导用户去排查连接——实际 SQL 早已执行完。现在这类「已完成、只是没有结果页签」的形态给中性提示：SQL 已提交执行并完成，详情见控制台 Output。

## ⚙ 改进

**日志列表可选显示「类名#方法名」（默认关）**

设置开启后，每条 SQL 的来源位置后追加一段方法信息，如 `[OrderServiceImpl.java:41] [UserMapper#selectById]`。控制台桥通道取捕获到的 mapper 语句 id，增强捕获通道取调用栈里的业务方法；无方法信息的条目（Hibernate、JdbcTemplate 等）保持原样。

## ⚠️ 已知边界

- HQL 识别依赖工程索引：索引构建期（dumb 态）或实体解析不了时回退显示原文并提示，不会给错数据
- HQL 转换覆盖命名/位置参数、实体与属性映射、JOIN 副表；隐式关联路径（无显式 JOIN 的 `u.dept.name`）以注释提示、不改写 SQL；`MEMBER OF`、CTE/UNION 内的 SELECT 展开不支持
- 方法名显示：桥通道的方法名是 mapper 语句 id，与来源位置的类可能不是同一个类（MyBatis 动态代理/AOP 场景），所以显示为两段而非一段
- 本版为内测通道版本，Marketplace 稳定通道不上传；正式版转正时合并 beta 日志发布
