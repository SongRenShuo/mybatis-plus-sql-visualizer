这一版的主题是「把不在主流视野里的栈接上」：国产数据库磐维（openGauss 系）现在能被增强捕获直接采到 SQL 与参数；十多年前的 iBatis 2.x 项目，控制台日志里的参数不再被方括号包住、INSERT 不再整片变成 NULL。

## ✨ 新增

**磐维（PanWeiDB）驱动的增强捕获（用户真机报障驱动）**

磐维驱动此前不在采集白名单里，只能靠接口兜底，attach 到运行中应用后常常一条 SQL 都不出。现在按真实驱动字节登记三面——连接面 `org.panweidb.Driver`、语句面 `org.panweidb.jdbc.PgStatement` / `PgPreparedStatement` / `PgCallableStatement`、prepare 面 `PgConnection`：

- 驱动 V1（`panweidb-jdbc-1.0.0.jar`）与 V2（`2.0.0.jar`）**类形一致**，同一套登记覆盖两代；两代 jar 都做了「织入 → 隔离类加载器定义 → 初始化过 JVM 校验」的字节级验收
- 事件带 `jdbc:panweidb://…` 目标库、参数、耗时与源码位置；列表角标显示「Panwei（磐维） · 库名@host:port」
- 方言按 **Oracle** 渲染——磐维的 SQL 兼容模式由建库参数 `DBCOMPATIBILITY` 决定，出厂默认 A（Oracle 兼容）；JDBC 的 `db_compatibility` 只控制列名大小写，不参与推断（PG/MySQL 模式的库请在面板手动改选方言）

**未登记的 JDBC 驱动不再静默零产出**

接口兜底扫到「是 JDBC 实现但不在驱动白名单」的类时，按首次发现顺序记下类名（最多 8 个），随 agent 心跳上报：空态诊断行与 SQL 日志页签底部常驻状态栏会显示「发现未登记 JDBC 实现：…」。上次磐维那个「一条不出」是靠人工猜驱动包名才定位到的，此后同类问题一眼可见。

**MP 写族「空 Wrapper」调用有预览图标与可执行 SQL**

`mapper.delete(null)` / `service.remove(null)` / `mapper.update(entity, null)` 此前既没有 gutter 图标也没有预览入口。现在按「空 Wrapper 精确形态 + MP receiver 家族」双门控挂锚点：`delete`/`remove` → `DELETE FROM 表`（有 `@TableLogic` 时转逻辑删除 `UPDATE`），`update(entity, null)` → `UPDATE 表 SET …`；无 WHERE 时面板给全表删除/更新红字警示。非空 Wrapper 锚点仍在链上，同一语句不出第二枚图标。

**JPA `delete(entity)` / `update(entity)` 调用行预览图标**

`delete`/`update` 与 Wrapper 工厂/链方法撞名，此前 JPA 这条分支被提前返回掉了，`repository.delete(entity)` / `ht.delete(entity)` / `ht.update(entity)` 只有右键能预览。现在补一次 JPA receiver 家族判定，命中才锚；`JoinWrappers.delete/update` 仍归工厂、`service.update(wrapper)` 仍不锚。

## 🛠 修复

**iBatis 2.x 的控制台 SQL 参数被方括号包住、INSERT 整片变 NULL（用户真机报障）**

iBatis 的 JDBC 日志代理打三行一组（`{pstm-N} Executing Statement:` / `Parameters: [v1, null, v2]` / `Types: [java.lang.String, …]`），参数行是 Java 集合的 `toString`，而解析器只认 MyBatis 的「值(类型)」语法：单值会把整段方括号当字面量渲染成 `'[0034…]'`；含 null 的多值只匹配到 null 项、其余值被丢弃并错位填充（36 个占位符只剩前 13 个被填成 `NULL`）。

现在按行内 `{pstm-N}` / `{conn-N}` 标记识别 iBatis 行并优先消费：参数列表剥一层结构方括号、按顶层逗号切分、裸 `null` 记为 null；`Parameters:` 行按 pstm id 挂起，紧随的 `Types:` 行按位置并入类型后闭合。类型必须并入——`00340025002200200006` 这类纯数字串在无类型启发式下会裸出成数值字面量（Oracle 模式语义错误），只有拿到 `java.lang.String` 才按字符串加引号。`{conn-N} Preparing Statement:` 只消费不产条目（与随后的 execute 重复）。

**IDEA 2026.3 上更新插件一律提示「需要重启 IDE」**

2026.3 的平台删掉了 `DynamicPlugins.allowLoadUnloadWithoutRestart(...)`，插件把「旧方法存在」当成热替换的总开关，方法一消失整条动态安装链就降级成重启脚本。现在按**能力族**解析预检入口（旧入口优先，243/262 走原路径；旧入口缺失时才用新的 `validateCanUnloadWithoutRestart` / `checkCanUnloadWithoutRestart`），并连返回类型一起判——2024.3 的同名方法返回的是原因字符串，只按名字匹配会把字符串当布尔。平台否决时把原因原话写进日志，探测失败时列出全部缺失项。

**运行期拼接的 SQL 预览把 Java 源码当活 SQL，括号与引号被吃掉**

JdbcTemplate / 自定义 DAO / Hibernate 三条字符串 SQL 通道此前把静态不可求值的片段输出成 `/*运行时值*/` + 原样 Java 源码 + `*/`——前缀注释当场闭合、源码变成活 SQL、末尾 `*/` 悬空，源码里的引号再把词法器带偏。现在占位收口为单条合法块注释 `/* 运行时值: <清洗后表达式> */`，并补三元分支处理与控制流感知（循环内 append 降级为占位、互斥 if/else 不线性拼接）。

**增强捕获被平台侧停采时现在会说清原因**

agent 有一条保守策略：会话建立后 15s 内收不到 IDE 的 CONFIG 帧就主动停采。此前这条自停完全不可见，用户侧表现成「采集开着，过一会儿就不出 SQL 了」。现在心跳带 `gate` 字段（0=正常 / 1=看门狗自停），宿主控制台留一行点名原因与解除方式。采集语义未改。

## ⚙ 改进

- **attach 之后才懒加载数据源的进程不再漏采**：attach 路径首轮之后补扫 2 轮（默认 5s / 20s，可配），复用已处理去重、每轮开查前重查总开关与熔断；扫描预算从「遍历到的每个类」改为「候选类」，数组顺序不再决定谁被截断（20k 类实测一轮 4~6ms）
- **方言判定按官方指南订正**：磐维的 SQL 兼容模式由建库参数 `DBCOMPATIBILITY`（默认 A/Oracle）决定，JDBC 的 `db_compatibility` 只控列名大小写；`jdbc:panweidb:` 恒映射 Oracle，PG/MySQL 模式的库手动改选

## ⚠️ 已知边界

- 磐维 V2 指南里提到的 `cn.com.panweidb.Driver`（「v 版」另一支制品）尚未登记；用户实际使用的 `panweidb-jdbc-2.0.0.jar` 是 `org.panweidb.*` 整包重命名，已被现有三面覆盖
- 磐维 PG / MySQL 兼容模式的库不会自动切方言（`db_compatibility` 不是 SQL 模式信号），请在面板手动改选 openGauss / MySQL
- iBatis 2.x 批处理（一次性 prepare、多次 `Parameters:`）一期不支持；元素内含逗号或嵌套方括号时按逗号切分（`List.toString` 不可逆，与既有集合参数渲染同口径）
- 磐维 A 内核把 `rowid` 做成系统列，渲染套件的保留字扫描对该实例按 `skipWords` 声明例外（只影响测试套件，不影响产品行为）
- 本版为内测通道版本，Marketplace 稳定通道不上传

1. 下载 `mybatis-plus-sql-visualizer-2026.11.6-beta.2.zip`
2. IDEA → Settings → Plugins → 齿轮 → Install Plugin from Disk… → 选择该 zip
3. 重启 IDE
