# 🎉 SQL Visualizer v2026.10.31-beta.2

> 发行说明留档：对应 Gitee 发行版 **v2026.10.31-beta.2**（标签 `2026.10.31-beta.2`），附件 `mybatis-plus-sql-visualizer-2026.10.31-beta.2.zip`。
> 通道：**Gitee 内测（抢先体验）**，不上架 Marketplace。
> 范围＝v2026.10.31-beta.1 之后的增量：**一处用户真机报障的修复 + 一处控制台噪音收敛**。

这一版没有新能力，修的是 beta.1 带出来的两个问题。

## 🛠 修复

**方言为 GaussDB / 达梦 / 瀚高 / 海量时，预览恒降级、表与列补全不可用（用户真机报障）**
- 现象：预览面板顶部常驻黄色横幅「预览以简化模式打开——临时文件解析失败；表/列补全暂不可用」，一个下午 10 次预览 10 次降级；预览本身、参数替换、执行都还能用，唯独补全没了
- 根因：这四个方言是本插件自己注册给平台的（平台原生列表里没有），此前只注册了「方言」这一半、**漏了「语法解析器」那一半**。平台在建文件 PSI 时会去取该语言的解析器，取不到就回落到基础 SQL 那份，而基础那份里的类型强转必然失败——真机日志里是一条被平台「频繁异常抑制」掩盖的 `ClassCastException`，一个下午 9 次，其中 3 次以 SEVERE 记录并点名本插件
- 修复：给四个方言补齐解析器注册；映射前先探一次「这个语言能不能建 PSI」，探不到就不映射（补全退到通用 SQL，不再拖垮整条预览）；取 PSI 的两处调用加防御，平台契约异常降为一条带堆栈的 WARN，不再以 SEVERE 记到插件头上
- 顺带修掉一处跨版本隐患：初版实现用了平台 SQL 侧的 `SqlFileElementType`，那个类只在 2024.3 存在、2025.3 与 2026.2 已移除（Plugin Verifier 会判「运行期可能 NoSuchClassError」），已改用三版本都在的核心 `IFileElementType`
- 守卫：新增静态配对守卫（每个方言必须有配套解析器注册，将来加第五个方言时会先红），并在 DB 集成通道加了一条「四种方言真的能建出 PSI」的用例——摘掉任一条注册该用例即红，实测能精确复现上面的 `ClassCastException`

## 🔇 变更

**增强捕获在应用控制台的输出默认静默**
- 此前每次运行会给宿主应用控制台打四五类诊断行：attach 汇总、premain 候选类数、逐轮补挂计数、首条事件取证。日常排查用不上，噪音大于信息量
- 现在分两级：诊断与进度行默认不打，需要时在 agent 参数里加 `logLevel=debug` 即可全部恢复；**真实降级与熔断永远输出**，与日志级别无关——预算耗尽、kill switch 触发、类扫描失败、注册盲区（仅一次）、端口放弃、安装降级、驱动名单预载失败
- attach 汇总行额外保留「有问题就打」：失败数非零时照常打印，全零时静默（「本次 attach 命中多少」在插件侧诊断行里已有）
- 采集与上报链路零变化：静音只作用于宿主 stderr 的诊断输出，SQL、参数、耗时、调用点照常采集

- 全量分片 `testShards`：**8496 / 0 / 0 / 9**（tests / failures / errors / skipped，795 个套件全有结果 XML）
- 真机级探针 `e2eFakeIde`：**26 PASS / 0 FAIL**（含在 `releaseGate` 同一条命令内）
- 在线口径复验 `verifyMarketplace`：IU-243 / IU-253 / IU-262 同样 **Compatible**，零未覆盖问题块

## 兼容性

- 支持 IntelliJ IDEA **2024.3+**（Ultimate / Community；EXPLAIN、执行 SQL、表右键入口与 Database 原生图需 Ultimate；MCP 能力需平台 MCP Server）
- 插件 ID 与升级链路不变，beta.1 用户经 Gitee 通道可直接收到本版
- 行为变化仅一处：装了增强捕获的用户，应用控制台不再有 `[SqlVisAgent]` 诊断行；需要排查时把 agent 参数改成 `logLevel=debug`
- 方言总数与设置项数量不变
