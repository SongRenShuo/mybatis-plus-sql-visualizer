# v2026.11.11 正式版发行说明（捕获可见化与「整类 SQL 消失」根治）

- 版本：`2026.11.11`（正式版；同日内测线 `2026.11.11-beta.1` / `beta.2` 连同转正前两笔收口修复一起转正为纯数字版本，装了内测版的用户会正常收到这次更新）
- 发布日期：2026-11-11
- 提交范围：`v2026.11.10`（`8561fafc`）之后全部用户可见增量
- 兼容 IDE：2024.3（243）/ 2025.3（253）/ 2026.2（262）/ 2026.3（263）

本版主题是把上一批真机报障的两条主线收掉：**「抓不到 SQL 时完全零信息」与「一条语句抛异常之后整类 SQL 消失」**。逐条根因、提交哈希与反向验证读数见两篇内测说明（`docs/发行说明/`：`20261110-1651` 捕获静默路径可见化、`20261110-1755` 整类 SQL 消失的根治），此处按能力面合并。

## 新增

- **状态栏「门禁陈旧 N」确诊读数（T-NestGateObserve，8e85d397）**：嵌套门禁出现深度泄漏时（链龄超过阈值仍有新帧进入即计），状态栏直接给出读数；debug 档另在宿主 stderr 打一次陈旧链摘要与调用栈（只一次、不含 SQL 原文），心跳带出 `nestStale` / `nestMaxDepth` 供现场判读。
- **抓不到某类 SQL 时不再只有空白（T-PanweiInsertCapture，e2b0b581）**：SQL 日志页签底部状态栏新增四段读数，全部「非零才显示」——`让位丢弃 SQL 行 N`（增强捕获接管期间控制台通道按设计让位、此前零留痕）、`组装失败 N`（agent 出口组装异常此前被自吞）、`门禁抑制 N`（嵌套门禁抑制的外层帧数）、`登记盲区 N 次（类名…）`（按 PS 实现类点名）。配合既有的「已收事件 N / 未登记 JDBC 实现」，现场一眼分出三种形态：**没产事件**、**产了被丢**、**让位吃了**。

## 修复

- **iBatis 链「全选 / 清除」按钮不生效（T-IbatisSelectAll，e1cf3872）**：点「全选」后动态条件复选框全部勾上但 SQL 预览不重渲染，「清除」同样无反应（单框切换正常）。根因是两条批量路径只枚举 Wrapper 与 MyBatis XML 两份条件视图清单，iBatis 条件行持有在 `PreviewResult.ibatisParamModel`，两条路径都枚举不到——勾选态只改了 UI，`enabledIds` / `paramValues` 一处未动。现在两条路径一并枚举 iBatis 条件行：全选落齐 `enabledIds` 并实时重渲染；清除同时清参数值与可见字段文本（iterate 值同语义清空），勾选态保留。这也收掉了 v2026.11.10 发行说明登记的已知问题「selectByCondition 勾选联动」。
- **「一条语句抛异常之后，同一线程后续的 SQL 整片消失」已根治（T-NestGateFix，0fc3836c）**：根因在增强捕获的语句织入——原实现只在方法体**显式出现**的返回点前插出口回调；语句执行抛异常、而异常从被调方法逃逸时（方法体自身没有 try/catch），字节层根本没有出口点，嵌套门禁的入口计数了、出口没执行，线程深度永久 +1，此后该线程每条语句都被静默抑制（现场形态正是「前几条正常，之后整类不上屏」，且「门禁抑制」计数恒为 0）。现在 timed 语句面（`execute` / `executeQuery` / `executeUpdate` / `executeLargeUpdate` / 批处理）的方法体统一包一层 catch-all 出口：异常也走一次出口回调**再原样重抛**，链深度立即归零。附带改善：**失败的那条语句本身现在会产一条带错误信息的事件**，不再是「报错了但列表里什么都没有」。磐维 A 模式真机验证：失败 DROP 之后 INSERT/SELECT 照常产出，心跳连续三拍 `nestSuppressed=0 / nestStale=0 / nestMaxDepth=1`；`-Dsqlvis.agent.nestGate=false` 不再是必需。
- **Mac / UOS 上点「执行 SQL」恒报「创建临时 SQL 文件失败：findPsi」（T-ExecPsiGate，87226496）**：执行用临时 SQL 文件的 PSI 语言由插件的文件级方言映射决定，映射失败时（自注册方言 parser definition 未生效、平台缺该方言、历史坏映射）平台拿不到 PSI，而 exec 链过去对映射失败既没有闸门也没有日志。现在预览与执行两条链共用同一道「可建 PSI 门」：不建 PSI 就不写映射并清掉历史映射，`findFile` 仍失败时重定位 VFS 条目再重建一次；失败文案带 vf 有效性、文件类型、映射语言、该语言能否建 PSI 与绝对路径五项，映射没落地也一定有日志。
- **预览执行 INSERT/UPDATE/DELETE 成功却被报「等待结果超时」（T-PreviewDmlResult，67a574ab）**：数据库控制台对写语句**不建结果页签**，影响行数只写进 Output 视图；插件原完成态判据只读历史文档，40 拍窗口到期后把成功误归成超时。现在按 DML/DDL 首关键字识别「结构上没有结果页签」的语句：提交后 8s、连接已就绪即给中性提示「已提交执行（更新/DDL 语句不产生结果页签），影响行数与耗时见下方控制台 Output」，措辞刻意不宣称「完成」，长事务仍在跑时不误导。
- **两种真实存在的日志形态此前整条丢失（e2b0b581）**：MyBatis `statementType="STATEMENT"` 只打 `==>  Executing: <sql>`（无 `Preparing:` / `Parameters:`）；iBatis 2.x 普通 `Statement` 打的是 `{stmt-N} Statement: <sql>`。两者现在都能产出条目（后者来源标记为 IBATIS）。严格前缀模式仍按原契约，未识别形态计入解析诊断增量。
- **iBatis 批处理不再无声消失（e2b0b581）**：iBatis 2.x 批处理在框架层一行日志都不产生，控制台通道结构性看不到。现在「已识别到 iBatis 形态且增强捕获未开启」时状态栏给出具名提示，不再像插件坏了。
- **三方数据库增强捕获登记缺口补齐（e2b0b581，横向审计）**：按真实驱动 jar 逐个反编译核对——pg 家族 `PgCallableStatement`（7 个包名）、MySQL 5.1 `CallableStatement`、华为两族兼容模式 `MPreparedStatement`（`addBatch(String)` 覆盖父类不回调）、海量/社区 openGauss 读写分离包装语句与其连接类、SQLite 四参 `prepareStatement` 重载实现类、华为两族 connect 面驱动类。

## 改进

- **「门禁陈旧」判据收口（70048a12）**：原判据「链龄超 5s 仍进入即计一次」会把长事务合法嵌套误报成泄漏。现改为「链龄超 30s **且**同一链连续 3 次超阈值进入才计，同一链只计一次」；两个门槛可经 `sqlvis.agent.nestStaleMs` / `sqlvis.agent.nestStaleStreak` 覆盖，不改任何抑制语义。
- 心跳新增 `assembleFailures` / `nestSuppressed` / `unresolved` / `blind` 四个诊断键（键序固定、无空格；旧版 IDE 宽容扫描零影响）。

## 已知边界

- 嵌套门禁的**判定语义未改**（仍靠「同线程只报最内层」去重），本次修的是出口配平不是门禁策略；一条语句在同一线程内**真正嵌套**执行（存储过程里再执行语句）时，外层那条仍不产事件——既有取舍。
- `ADD_BATCH` / `CLEAR_BATCH` / `PREPARE` 三面未包 catch-all：异常时可能少一次登记，但不影响链深度，不会造成整类丢失。
- 让位策略未改（仍是有事件即让位）；「agent 半活」时控制台通道不会自动回来，这是设计选择，本版只把它变成可见事实。
- MySQL 5.1 `CallableStatement` 的字节层与行为未验证（本机无该版本 jar，只做了谓词层与登记）。
- 上一版（v2026.11.10）登记的已知问题 iBatis `selectByCondition` 勾选联动已在本版修复（见修复段第一条）。

## 兼容性

- 最低 2024.3（243），`sinceBuild=243`；无平台 API 面新增，不改用户既有配置。
