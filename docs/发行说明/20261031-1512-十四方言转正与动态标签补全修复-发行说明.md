# 🎉 SQL Visualizer v2026.10.31

> 发行说明留档：对应 Gitee 发行版 **v2026.10.31**（标签 `2026.10.31`），附件 `mybatis-plus-sql-visualizer-2026.10.31.zip`。
> 通道：**正式版（Gitee + Marketplace 双通道）**；内测期 v2026.10.31-beta.1 / beta.2 两轮的内容全部并入本版。
> 范围＝自 v2026.10.30 正式版发行包之后的全部用户可见增量。

本版是方言与采集能力的一次大版本。**主线一：方言从 11 种扩到 14 种**——GaussDB 拿到独立身份（不再藏在 openGauss 后面）、新增瀚高 HighGo 与海量 Vastbase、补掉 PostgreSQL 系与人大金仓的长期缺口。**主线二：增强捕获不再受方言限制**——从「驱动类名白名单」改为「JDBC 接口匹配兜底」，没登记过的数据库也能采到 SQL，兜底自带扫描上限、耗时预算与连败熔断，红线仍是「不能让用户服务受影响」。

修复面覆盖五个真实缺陷，其中两个来自用户真机报障：四种自注册方言下预览恒降级（补全不可用）、mapper XML 嵌套动态标签体内 `#` / `$` 不自动补花括号。

## ✨ 新增

**GaussDB 独立方言**
- 设置页方言下拉、日志库角标、MCP 方言名此前全部显示 `openGauss`——连接能认、SQL 能渲染，但用户看不到 GaussDB 这个名字。现拆出独立的 `GaussDbDialect`：同形不同名（六项渲染能力与 openGauss 一致），保留字单独用 GaussDB 官方口径
- 顺带修掉两个真实缺陷：`PG_RESERVED` 缺 `is` / `procedure`（PostgreSQL 方言同样受影响，合法列名会被判成语法错）；openGauss 保留字原先直接复用 PG 表，比真机 `pg_get_keywords()` 的保留类少 17 词，`rownum` 一类列名在真机上直接「cannot be used as an alias」
- 增强捕获补齐华为两族驱动（`com.huawei.gaussdb.jdbc` / `com.huawei.opengauss.jdbc`）登记——此前三面全未登记，attach 后 `matched=0`、零事件零角标，宿主侧还完全没有报错

**瀚高 HighGo 与海量 Vastbase**
- 两种新方言（形态复用 PG 族，模板照 `GaussDbDialect`）：保留字分别 153 词 / 201 词，取「官方附录 ∪ PG 基础 ∪ 引擎实读」并集——只取单一来源会漏掉类型名与函数名
- URL 与方言链登记 `jdbc:highgo:`、`jdbc:vastbase:`、`jdbc:dws:iam:` 三个子协议，MCP 中文别名收 瀚高 / 翰高 / 海量
- 平台 `sql.dialect` 注册 2 → 4（HighGo / Vastbase 照 DM 先例），插件设置页的方言下拉与 IDE 原生 SQL 方言映射对得上

**人大金仓三处缺口补齐**
- 保留字补 `enckey`（官方文档标非保留，但引擎 `pg_get_keywords()` 标 R、列引用实测报 `syntax error at or near "enckey"`，以引擎为准）
- 金仓 PG 协议版驱动 `postgresql-for-kingbase` 排在 `org.postgresql:postgresql` 之前匹配——此前被误判成 PostgreSQL
- 增强捕获语句面 / prepare 面登记此前为零，金仓用户「有库角标、零 SQL」；现已登记

**增强捕获按 JDBC 接口匹配兜底（采集面与方言解耦）**
- 根因是「未命中白名单」不等于少一条通道，而是**两条都没有**：agent 在线并 ACK 后控制台桥被置为暂停，白名单没命中就整链静默。现在 attach 轮用反射对已加载类做 `isAssignableFrom` 匹配（零字节解析），命中 `Statement` / `PreparedStatement` 即登记织入
- 兜底带三道闸：扫描类数上限 5000、transformer 兜底累计耗时预算 300ms、连败 3 次整体退回纯白名单；全部可经系统属性覆盖，非法值回落默认——注入失误不得改变生产行为
- 嵌套调用只报最内层（Hikari + MyBatis 双层不再双报）；接口对象引用改 `ClassValue`（防热部署钉住旧 classloader）
- premain 阶段**不内联未知形态**，只记候选、attach 后 daemon 补挂——premain 织入失败等于宿主 JVM 起不来，宁可晚一点
- IDE 侧新增活性回落：`paused` 满 10 秒、窗口内零 agent 事件、且控制台确实解析出 SQL 时自动解封控制台通道并披露，带滞回与去重（出厂开）；心跳带出 attach 命中 / 织入 / 版本闸跳过 / 熔断计数，诊断行直接显示「本次 attach 到底命中多少」，不再靠面板零条目反推

**增强捕获覆盖补齐：OceanBase / MariaDB / SQLite**
- OceanBase 三面全补（此前三面全空）；MariaDB 语句面 3 类 + prepare 1 类（3.x 起全部重写为自有类，不复用 MySQL `StatementImpl`）；SQLite 语句面 2 类 + prepare 1 类
- 新增 14 方言三面对账守卫 `DialectCaptureCoverageTest`——它反衬出既有厂商对齐守卫是**前缀级判定**，挡得住整族静默、挡不住「只补 prepare 面」的半覆盖

## 🛠 修复

**GaussDB / 达梦 / 瀚高 / 海量四种方言下预览恒降级、表与列补全不可用（用户真机报障）**
- 现象：预览面板顶部常驻黄色横幅「预览以简化模式打开——临时文件解析失败；表/列补全暂不可用」，一个下午 10 次预览 10 次降级；预览本身、参数替换、执行都还能用，唯独补全没了
- 根因：这四个方言是本插件自己注册给平台的（平台原生列表里没有），此前只注册了「方言」这一半、**漏了「语法解析器」那一半**。平台在建文件 PSI 时去取该语言的解析器，取不到就回落到基础 SQL 那份，而基础那份里的类型强转必然失败——真机日志里是一条被平台「频繁异常抑制」掩盖的 `ClassCastException`，一个下午 9 次，其中 3 次以 SEVERE 记录并点名本插件
- 修复：给四个方言补齐解析器注册；映射前先探一次「这个语言能不能建 PSI」，探不到就不映射（补全退到通用 SQL，不再拖垮整条预览）；取 PSI 的两处调用加防御，平台契约异常降为一条带堆栈的 WARN，不再以 SEVERE 记到插件头上
- 顺带修掉一处跨版本隐患：初版实现用了平台 SQL 侧的 `SqlFileElementType`，那个类只在 2024.3 存在、2025.3 与 2026.2 已移除（Plugin Verifier 会判「运行期可能 NoSuchClassError」），已改用三版本都在的核心 `IFileElementType`
- 守卫：新增静态配对守卫（每个方言必须有配套解析器注册，将来加第五个方言时会先红），并在 DB 集成通道加了一条「四种方言真的能建出 PSI」的用例——摘掉任一条注册该用例即红

**mapper XML 动态标签体内敲 `#` / `$` 不再自动补花括号**
- 现象：`<where>` 下的 `<if>`、`<choose>` 下的 `<when>` 等真实 mapper 主流排版里，敲 `#` 只落裸字符，自动补全功能等于失效；光标落在语句标签自身属性区（`<select id="a|">`）时还会误插
- 根因：判定只看一层父节点，且把「子标签体内正文」与「子标签标记区」混为一谈
- 修复：改为「最近语句标签祖先（任意深度）+ 体内容孩子推导标记区」——体内正文与 `</if>` 右侧接管，起始标记区（含属性间隙）与结束标记区不接管
- 用例：`ParamBraceTypedHandlerTest` 新增 5 例（嵌套 if/when 体内、单层 if 体内、语句属性区、自闭合子标签之后）全绿，原 6 例回归绿

**OceanBase 执行计划改按文本档位呈现**
- 此前按表格档位解析，真机返回的其实是文本形态；现改为文本档位，结构化渲染不再拿不到内容

**SQL Server 无排序分页渲染出非法 T-SQL**
- `OFFSET … ROWS FETCH NEXT … ROWS ONLY` 在 SQL Server 上**必须**跟在 `ORDER BY` 之后，而 `SqlGenerator` 只在 `orderBy` 非空时才输出 `ORDER BY`、`limit` 无条件拼接——「无排序 + 分页」的预览产物在真机直接报 `Incorrect syntax near '0'.`
- 现新增 `Dialect.limitRequiresOrderBy` 能力位（仅 SQL Server 覆写 true），无排序且带分页时补语义中性的 `ORDER BY (SELECT NULL)` 占位，位置在分页子句之前
- 旧用例为什么没抓到：`DialectH2VerificationTest` 用 H2 的 `MODE=MSSQLServer` 跑兼容面，H2 不强制这条规则——与 OceanBase 档位误登同型，「兼容模式」不等于「引擎现实」

**premain 补挂线程永不执行**
- `msProp` 统一返回纳秒（预算比较需要），但 premain 首轮延迟与轮间隔也被它处理，随后直接当毫秒喂 `Thread.sleep`：默认 10 秒变成约 317 年，补挂线程从未跑起来。白名单驱动不受影响（靠类加载期织入），但未知驱动的 premain 形态 100% 静默，正是本轮兜底要解决的场景
- 现拆出 `rawMsProp` 只服务两个延迟字段，并加源码扫描守卫钉住量纲（行为断言永远绿——`resetForTest()` 会把字段覆盖回正确默认值，这正是缺陷潜伏的原因）

## 🔇 变更

**增强捕获在应用控制台的输出默认静默**
- 此前每次运行会给宿主应用控制台打四五类诊断行：attach 汇总、premain 候选类数、逐轮补挂计数、首条事件取证。日常排查用不上，噪音大于信息量
- 现在分两级：诊断与进度行默认不打，需要时在 agent 参数里加 `logLevel=debug` 即可全部恢复；**真实降级与熔断永远输出**，与日志级别无关——预算耗尽、kill switch 触发、类扫描失败、注册盲区（仅一次）、端口放弃、安装降级、驱动名单预载失败
- attach 汇总行额外保留「有问题就打」：失败数非零时照常打印，全零时静默
- 采集与上报链路零变化：静音只作用于宿主 stderr 的诊断输出，SQL、参数、耗时、调用点照常采集

## ⚡ 性能

- **日志列表多行模式取源惰性化**：脱敏开时 `displaySqlForList` 内部付 O(SQL 长) 全量词法打码，而缓存命中路径每帧重取源后整段丢弃——现改为只在缓存未命中时取源

## 兼容性

- 支持 IntelliJ IDEA **2024.3+**（Ultimate / Community；EXPLAIN、执行 SQL、表右键入口与 Database 原生图需 Ultimate；MCP 能力需平台 MCP Server）
- 插件 ID 与升级链路不变，v2026.10.30 用户可直接覆盖升级（Marketplace 通道与 Gitee 通道均收到本版）
- 方言总数 11 → 14；已装用户的方言设置不受影响（新增三项需手动选择，智能推断会按数据源自动认）
- 增强捕获的接口匹配兜底**默认开**；transformer 侧兜底分派**默认关**（需更多真机验证后再考虑打开）
- 行为变化两处：装了增强捕获的用户，应用控制台不再有 `[SqlVisAgent]` 诊断行（需要时 `logLevel=debug` 恢复）；mapper XML 嵌套动态标签体内 `#` / `$` 现在会自动补花括号
- 设置项数量不变，无需重新配置

## ⚠️ 已知边界

- 瀚高 / 海量均为社区第三方镜像实例（瀚高 V6.0.1 非 V9 线），非厂商官方版本；增强捕获 attach 端到端对瀚高、海量、金仓三族尚无读数，**「14 方言全部真机验证」不可写**
- 十四方言渲染套件真机矩阵：达梦 DM8 **PASS 254/254 词**、openGauss **PASS 186/186**、GaussDB **PASS 197/197（与 openGauss 同实例）**、MariaDB 10.11.11 **PASS 281/281**；openGauss 读数取自 **GaussDB Kernel 503** 实例（老命名 A/B/C/PG，不等于商用 5.x/6.x 的新命名与关键字表），官方 openGauss 5.0.0 实例权限不足建不了夹具表
- SQLite / HSQLDB 的增强捕获只到驱动字节层；GaussDB 商用版无可自行安装来源（需华为授权或云实例），渲染按同形推定 + 官方文法级验证
