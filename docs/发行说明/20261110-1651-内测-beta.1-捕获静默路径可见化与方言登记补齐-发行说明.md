- 版本：`2026.11.11-beta.1`（内测，Gitee 抢先体验通道；Marketplace 不收内测包）
- 发布日期：2026-11-10
- 提交范围：`4c6294c2`（含本版全部功能与文档提交 `e2b0b581` / `151e4d5b` / `7537a4cd` / `99b816d5` / `918871e9`）
- 兼容 IDE：2024.3（243）/ 2025.3（253）/ 2026.2（262）/ 2026.3（263）

## 新增

- **抓不到某类 SQL 时，面板不再只有空白。** SQL 日志页签底部状态栏新增四段读数，全部「非零才显示」：
  - `让位丢弃 SQL 行 N`：增强捕获接管期间，控制台通道按设计让位；此前被丢弃的行**没有任何读数**，就会出现「控制台明明有 SQL、面板就是没有」。现在按语句计数。
  - `组装失败 N`：增强通道出口组装异常此前被自吞，现在计数。
  - `门禁抑制 N`：嵌套门禁抑制的外层帧数（正常嵌套会有少量，持续增长才是异常信号）。
  - `登记盲区 N 次（类名…）`：按 PS 实现类点名——「哪个语句类一直取不到 SQL」从此不用猜。
- 配合既有的「已收事件 N / 未登记 JDBC 实现」，现场可以一眼分出三种形态：**没产事件**、**产了被丢**、**让位吃了**。

## 修复

- **MyBatis `statementType="STATEMENT"` 的语句此前整条丢失**：这类语句日志是 `==> Executing: <sql>`（没有 `Preparing:`、也没有 `Parameters:`），旧解析器接不住。现在能识别；关掉「启用混合前缀」时仍按你的严格前缀契约执行，未识别的 SQL 形态行会计入解析诊断增量。
- **iBatis 2.x 普通 `Statement`（`createStatement()`）此前整条丢失**：它打的是 `{stmt-N} Statement: <sql>`，标记前缀与关键字都与 PreparedStatement 那档不同，旧解析器当噪声丢掉。现在能识别，来源标记为 IBATIS。
- **iBatis 批处理不再无声消失**：iBatis 2.x 的批处理（`executeBatch`）在框架层一行日志都不产生，控制台通道结构性看不到。现在「已识别到 iBatis 形态且增强捕获未开启」时，状态栏会给出具名提示——不再像插件坏了。
- **三方数据库的增强捕获登记缺口补齐**（按真实驱动 jar 逐个反编译核对）：
  - pg 家族存储过程（`PgCallableStatement`，7 个包名）：函数模式 `executeUpdate` 走 `executeWithFlags` 分支，父类织入盖不到；
  - MySQL 5.1 `CallableStatement`（与 GoldenDB 对称补登）；
  - 华为 GaussDB / openGauss 品牌两族的兼容模式 `MPreparedStatement`：`addBatch(String)` 覆盖父类不回调，批文本漏记；
  - 海量 Vastbase 与社区 openGauss 的**读写分离**包装语句及其连接类：该模式下整条连接的语句进不了登记表；
  - SQLite 四参 `prepareStatement` 重载的实现类 `JDBC4Connection`；
  - 华为两族的 connect 面驱动类。

## 改进

- 心跳新增 `assembleFailures` / `nestSuppressed` / `unresolved` / `blind` 四个诊断键（键序固定、无空格；旧版 IDE 宽容扫描零影响）。

## 测试

- 根项目定向：`MyBatisLogParserTest` 32 / `IbatisLogParseTest` 14 / `CaptureStatusBarTest` 28 / `LogParseConcurrencyTest` 11 / `CaptureDiagnosticsTest` 27 / `CaptureActivityFallbackTest`（含新增让位计数用例）全部 0 失败。
- agent 子项目：`287 例`（1 skip）；唯一红点 `SenderLoopBackoffTest` 为端口/时序 flake，单跑复现不出。
- 反向验证成对：摘除 MyBatis `Executing:` 分支 → 恰 4 红；摘除 iBatis `{stmt}` 分支 → 恰 2 红；恢复后复绿。
- 守卫：`convention` 整包（含 `BundlePlaceholderArityTest`、`ChangeNotesRatingLineGuardTest`、`GuardSelfTestCoverageMetaGuardTest`）通过。
- **真机复现**（本版最重要的一条背景）：香港独立部署的磐维 PanWeiDB V3.0-S3.4.0（A 模式）上复现了用户报障，并用开关判别定位到 `NestGate` 深度泄漏；本版交付的是**可见化**，泄漏本身的自愈修复未进这一版（见「已知边界」）。

## 已知边界

- **磐维 A 模式下「某线程后续语句整类消失」的根因已定位但未修**：增强捕获的嵌套门禁在该形态下出现深度泄漏。现场可用的规避手段是给应用加 `-Dsqlvis.agent.nestGate=false`（关闭嵌套门禁，代价是嵌套链可能双报，列表去重会折叠成 ⨉N）。自愈修复会动采集语义红线，需先完成观测取证再落，不在本版。
- 让位策略未改（仍是有事件即让位）。「agent 半活」时控制台通道不会自动回来，这是设计选择，本版只把它变成可见事实。
- MySQL 5.1 `CallableStatement` 的字节层与行为未验证（本机无该版本 jar，只做了谓词层与登记）。

## 兼容性

- 最低 2024.3（243），`sinceBuild=243`；无平台 API 面新增，不改用户既有配置。
- 旧版 agent 上报的心跳不含新键，状态栏那四段不显示，其余行为不变。

## 安装

1. Settings → Plugins → ⚙ → Install Plugin from Disk，选本版 zip；
2. 重启 IDE（本版不涉及动态卸载面）；
3. 打开 SQL 日志页签，底部状态栏即可看到新增读数。
