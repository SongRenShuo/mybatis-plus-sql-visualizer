# v2026.11.14-beta.1 内测说明（预览首开再提速与重索引根治）

- 版本：`2026.11.14-beta.1`（内测，Gitee 抢先体验通道；Marketplace 不收内测包）
- 发布日期：2026-11-14
- 提交范围：`2026.11.13-beta.2` 之后到 `de8a6027c`（预览打开与反查索引链路 20 余笔，另含补全大小写形态与数据源按钮告警修复）
- 兼容 IDE：2024.3（243）/ 2025.3（253）/ 2026.2（262）/ 2026.3（263）

## 这一版有什么

- 打开 mapper 时后台就预热预览，点开更快
- 打开预览不再把整个工程短暂拖进重索引，补全不再跟着短暂失灵
- 执行控制台改为第一次执行时才准备，设置页可调三档口径
- 表名反查索引大幅提速，启动期不再重复建 7 次
- 表名反查按 ORM 分源，JPA 工程同样适用
- 敲 `DEL_F` 能补出 `DEL_FLAG`，列名补全支持大写蛇形别名
- 数据源切换按钮不再刷 IDE 日志告警，退出 IDE 不再报插件内存泄漏

## 按能力面展开

### 打开 mapper 就在后台预热装配（T-PreviewAssemblyWarm，`da6ccb982` / `589be7dcd`）

本会话第一次打开预览要等约 700ms，其中装配那一段含着首次类加载与 JIT。现在打开 mapper XML 时就在后台把装配算一遍——只算不建界面，结果丢弃，把冷启动成本挪到用户点击之前。每文件只预热一次、每项目至多 2 个文件（一个 mapper 常有十几条语句，按语句去重会一次预热十几遍）；可在 Registry 里关掉（`sqlvis.preview.assemblyWarm`，默认开），关掉即回到点击时才装配。

### 打开预览不再把工程打进重索引（T-PreviewNoReindex，`02bccd045` / `cc6745550` / `70694995d` / `bcf1529da`）

现象：预览打开时会写一份带方言映射的临时 SQL 文件并把控制台准备好；给这份频繁重写的文件设方言映射，会让 IDE 在每次写入后重算「语言替换」并推文件属性——实测整个工程短暂进入索引态，补全也随之短暂失灵。

修法：预览打开只显示 SQL，执行控制台在你第一次执行（或切换数据源）时才准备，不再预写带方言映射的 exec 文件（`02bccd045`）。惰性口径下预览面板补了「显示执行控制台」入口，换源仍走控制台自带菜单（`70694995d`）；「执行控制台」三档口径（惰性带入口 / 惰性无入口 / 打开即准备）进了设置页（`bcf1529da`），想恢复旧行为不必再去 Registry 手改 `sqlvis.preview.eagerConsole`。

### 方言映射不再每轮重写（T-PreviewNoReindex 前置轮，`e6d26cca7` / `32d58ad6e`）

预览用的 SQL 文件需要设方言映射，探测拿不到结果时旧逻辑会每轮重写一次，而平台的方言推送会让整个工程重算文件属性。现在写入成功会记一条本地备忘，探测不可用时凭它跳过；探测可用时仍以 IDE 自己的配置为准，你手动改过映射插件不会拦。

### 表名反查索引提速（T-StartupReadLockFreeze §二十二收尾，`c96759946` / `e99750f53` / `ee8c69e9a` / `59e58ab93` / `589be7dcd`）

真机日志里「SQL 表名 → 实体类」的反查反复出现 3.7~4.0 秒，且因为缓存挂在 PSI 版本上、预览自己写文件就会把它顶掉，每次打开都在重扫全工程（16804 个类）。这轮连做四步：

- 一次扫描建「表名 → 类」全表索引，任意表名 O(1) 命中，失效基准换成项目结构版本 + 5 分钟 TTL（`c96759946`）
- 建索引挪到后台线程，点击链至多有界等 800ms，等不到就本次降级、下次命中（`e99750f53`）
- 候选源改用平台注解索引直接取带 `@TableName` 的类，实测 16804 类 → 812 类、稳态重建 4737ms → 187ms；联表候选改「缓存优先 + 后台预热」，实测点击链 0~2ms（`ee8c69e9a`）
- 补全路径只派发不等待，扫描在平台要写权限时被撤销、撤销后 10 秒冷却，连续输入不再把一次扫描打成反复重试白烧 CPU（`59e58ab93`）

启动期还抓出反查索引被重复建 7 次（只 1 次建成）的问题——工程结构版本抖动会换掉缓存条目，已完成的扫描结果被丢弃后在新条目上重扫。现在结果落到当前条目，跨 ORM 回补的全项目扫描也改按结构版本缓存（`589be7dcd`）。

### 表名反查按 ORM 分源，JPA 工程适用（`231cd2065` / `47634d4c5`）

上一版把反查候选源收窄到 `@TableName` 后，JPA 实体（`@Table(name=…)`，`javax` 与 `jakarta` 两代都认）会整片漏掉。现在按 ORM 分源查注解索引，注解索引没命中时再退回一次全项目推断，覆盖 MBG / iBatis / Kotlin / 自定义映射这些没有表名注解的工程。顺带修了 `@TableName` 注解索引兜底恒空的问题——兜底把全限定名传给了以简单名为键的注解索引，从未命中过；改传简单名并按注解原文筛同名（`47634d4c5`）。

### 补全支持大写蛇形别名与大小写跟随（`3813d832c` / `c5646b239`）

敲 `DEL_F` 此前补不出 `DEL_FLAG`——列名候选现在支持大写蛇形别名；插入形态跟随输入大小写风格，习惯敲全大写或驼峰都能对上。

### 改了实体注解立刻生效（`ad292a169`）

实体解析结果按「类名 + 60 秒时间窗」缓存，命中条件写成「60 秒内一律命中」，改了 `@TableName` 或字段后预览与补全最多一分钟还在用旧值。现在改按类正文指纹判据：内容没变就复用，真改了立刻生效。

### 日志清净：告警与内存泄漏消除（`be43c4bf6` / `a02ad51cf`）

- 预览控制台顶部的数据源按钮内部镜像界面状态时用了平台点名的反模式写法，IDE 日志里每次刷新记 2 条带堆栈的 WARN，一个会话能攒几十条。改走平台自家的批量复制通道后告警消失，按钮显示不受影响（`be43c4bf6`）
- 预览面板的编辑器与补全监听只在「组件移除」路径上释放，IDE 直接退出时平台按 `Memory leak detected … Plugin to blame: SQL Visualizer` 记账四条。现在面板销毁时兜底释放（幂等），退出不再刷这几条（`a02ad51cf`）

### 上一版已知问题解除（`29e872abe`）

beta.2 发行说明里登记的「从本地安装包热更新后，设置页可能报一次 Cannot create configurable」已修：现在更新前一刻自动关掉正开着的设置窗口（只关设置窗口，不碰预览面板等可能有未保存内容的对话框），并弹一条提示说明更新已生效、若「确定」无反应请重启 IDE——气泡里带重启入口。本期无新增已知问题。
