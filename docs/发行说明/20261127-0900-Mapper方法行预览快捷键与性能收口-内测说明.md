## 这一版有什么

按新功能 → 修复 → 优化排序。

### 新功能

1. **Mapper 接口方法行也能按快捷键预览（T-MapperMethodSqlPreview，`3d6bb9b57`）**：光标停在 Mapper 接口方法名/参数/返回类型上按 `Alt+Shift+Q`（右键菜单同一入口）即可直接预览该方法绑定的 XML 语句。此前只能点行号旁的预览图标，快捷键会落到「未找到可转换的 Wrapper」。走与图标点击、XML 语句行点击同一条渲染链（参数表、`<include>`、`${}` 注入一致）；同名多方言（`databaseId`）变体弹选择器；没有 XML 语句的方法（含 MP 内置 CRUD）仍回落原有链，不出错源提示。

### 修复

2. **方法行两枚图标固定为「预览在左、跳转在右」（T-MapperPreviewOrder，`031fb9089` + `6c1dc40a6`）**：第三次报障。此前预览与跳转在同一个 provider 里产出，首次渲染偶发「预览在右、过一会跳到左边」。前两版修法（同 provider 双 marker、锚点 offset 小一档）都只让收集顺序偏向自己，真机多轮 daemon 复用下仍会翻转。现在改用平台的分列机制：预览固定 `Alignment.LEFT`、跳转保持 `CENTER`，`EditorGutterComponentImpl.processIconsRowForY` 按 alignment 分列排布（先排完所有 LEFT，再把 CENTER 整体放其右侧），左右序与收集顺序、daemon 增量复用、provider 注册顺序全部无关。
3. **Mapper 接口方法的 Wrapper 参数不再多出一枚预览图标（T-MapperPreviewDedupAndAnnotationShortcut，`0263bf788`）**：`List<Order> selectByXxx(@Param("ew") Wrapper<Order> ew)` 这种签名里，参数名上曾经也出 Wrapper 预览图标，与方法行的 SQL 预览图标同款同行，看着像「图标重复」。参数在无方法体的接口/抽象方法里只是 `${ew.customSqlSegment}` 占位符、不是可预览的链起点，现在不标；实现类与接口 `default` 方法（有 body）的参数照旧。
4. **注解 SQL 的快捷键按方法定位，不再弹全文件列表（T-MapperPreviewDedupAndAnnotationShortcut，`0263bf788`）**：光标停在 `int createDemoTable();` 这类方法声明行（注解在上一行）时按 `Alt+Shift+Q`，此前会列出整个文件的注解 SQL 让人挑；现在直接预览该方法自己的 `@Select`/`@Update` 等注解 SQL。光标在类体空白处时仍保留文件级列表兜底。
5. **Mapper 接口方法上按快捷键预览时不再在 EDT 查索引（T-PreviewFallbackEdtSlowOps，`c5685aee8`）**：`Alt+Shift+Q` 落在 Mapper 接口方法、且 Wrapper 链没有命中时，兜底要按 namespace 找同名 XML 语句，这步原先跑在 UI 线程的预览回调里——`idea.log` 每次留两条 `SEVERE Slow operations ... Plugin to blame: MyBatis SQL Visualizer`，索引要追平时界面还会卡一下。现在锚点解析放回后台线程的读动作里完成，回调只做分发与渲染；预览行为不变。
6. **Repository 接口方法声明行的预览不再卡一下（T-PerfSweep34 券01，`3e434734f`）**：光标停在 `deleteAllInBatch()` 这类 Repository 声明行按 `Alt+Shift+Q` 时，「按接口泛型找实体」这一步会去查文件名索引并读工程的 Hibernate/Spring 配置文件，原先跑在 UI 线程上——首次点击（以及任意文件编辑后缓存失效时）会短暂卡顿。这是修 `Alt+Shift+Q` 卡顿时（`c5685aee8`）同一处兜底链漏掉的第二条分支；现在解析也放到后台线程。
7. **缺失片段框「从文件选择」选完没反应（T-PerfSweep34 券05，`3e52b138f`）**：预览里遇到未解析的 `<include refid>` 时，弹框里点「从文件选择」、选好 XML 后文本框没有任何变化。原因是回填动作被排在一个「等模态框关掉才执行」的队列上，而那时框已经关了、结果被丢弃。现在选完即回填。

### 优化

8. **切换「同类插件共存让位」不再拖慢整个项目（T-PerfSweep34 券02，`56162eaf6`）**：这个开关只影响行号旁的图标，但原先切换后会让所有已打开项目重新做一遍全量代码分析，大工程下要等一会儿才恢复。现在只重算当前打开着的那些文件。
9. **gutter 图标判定顺序微调（T-PerfSweep34 券04，`a33d99a4a`）**：4 个图标 provider 原先对每个语法元素都先读一次插件设置再判断「这个元素是不是我的目标」，现在先做那个几乎零成本的判断。纯内部重排，无行为变化。
10. **补全上下文预热加了每项目次数上限（T-PerfSweep34 券03，`0b581d5b1`）**：冷启动后连续打开很多 mapper 文件时，原先每个文件都会触发一次较重的实体解析预热；现在每项目最多 2 个文件（与同批的装配预热同口径）。首次点击预览/补全仍命中热缓存。

- **`CHANGELOG.md` 结构损坏**：`9c1a1b724`（11-26 灾后恢复）把早已归档进 `docs/变更记录/发行-2026-08.md` 的 2026.8.13 段整段重复插回（M15 段在文件里出现 3 次），`4594a54d5` 又在其上方新加了一个空 `[Unreleased]`，导致原有 5 条 beta 期条目被顶到无版本标题的位置。本轮从 `9c1a1b724^` 取回干净结构，把 PerfSweep 五券条目按原内容放回 `[Unreleased]` 的正确位置。8.13 段在归档分册里内容齐全（M15/M14/M13 均在），未丢信息。
