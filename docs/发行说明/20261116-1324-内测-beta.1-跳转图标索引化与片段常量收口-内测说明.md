## 这一版有什么

本版沿一条主线收口：把 Mapper 与 iBatis 的跳转图标从「运行期全项目扫清单」改为「IDE 索引期摊平」，并补齐三件同源能力——图标不闪没且目标没了会收回、公共片段即时生效且片段里的常量能认出、打开 mapper 的后台预热不再刷日志告警。

### 跳转图标：统一索引化，冷开不闪没、目标没了会收回、iBatis 不误跳

这一带把 MyBatis 与 iBatis 的双向跳转图标做了一次体系化收口：

- **定位改走自定义索引**：大工程（数千 mapper XML / sqlMap）里「跳到 XML 语句」原本每次全项目扫清单，出现慢甚至长期缺席。参照竞品反编译调研（`docs/调研报告/20261115-0202`）的头部设计，MyBatis 注册 `MapperNamespaceIndex`（T-GutterFirstOpenDelay F1'''，`7dc6c1c73`）、iBatis 注册 `SqlMapNamespaceIndex`（T-IbatisGutterPerf，`b5ccf14c7`），把 namespace / 语句 id 在 IDE 索引期摊平成键，运行时一次查询毫秒级出答案，文件变更由平台增量管理，热更新（免重启装）不受影响。iBatis 只认 `<sqlMap>` 根标签，与 MyBatis 的 `<mapper>` 互斥，其它 ORM 不受影响。
- **解析瞬时失败不摘图标**：索引未就绪时的那次解析失败不再被当成「真没有」——XML→Java（F1 `d3eb65079`）与 Java→XML（F1' `6bc12e9c8`）都改成会话级正缓存 + dumb 窗乐观产出。本会话确认过存在的语句不再闪没或长期缺席；此前为缓解饿死做的头扫化 / 异步构建 / serve stale（F1'' `81884a539` / `588d64604`）也由索引化取代，索引 version 升级会触发一次全量重索引。
- **目标确定不存在则收回**：与「暂时查不了」分开判断，mapper 接口方法删除、`<mapper namespace>` 改名后，图标立即消失并清掉记忆（T-MapperGutterEvict `c0bc9b043`，iBatis 侧 `8eca5211f` 同族收口）。iBatis XML 语句行的箭头还加了「有调用点才出」的门槛（T-IbatisXmlArrowCallerGate `e4b3fdd27`），且只认裸 `id` 或「本文件 `namespace.` + `id`」两种精确形态（`2eecbdcba`），不再跨命名空间认领同名语句；想恢复旧行为可置 Registry `sqlvis.gutter.ibatisXmlArrowRequiresCaller=false`。

### 打开 mapper 的后台预热：延后到工程就绪后在正确读权限内执行

首次渲染图标时顺带做的三件预热（调用点预取 / 补全上下文 / 预览装配）原本和索引重建挤在一起（实测首开后台扫描累计 3.3s + 15s），既拖慢图标落地也让闪没更容易发生（F2 `7ad1d1a5d`）。现在由 `GutterWarmScheduler` 统一延后到工程就绪后数秒再做，Registry `sqlvis.gutter.warmDelayMs` 可调、置 0 回旧行为。到点执行时那批预热曾跑在后台线程池、没有读权限却读 PSI，往 IDE 日志刷 SEVERE（`e4b3fdd27`）；现在这一步在正确的读权限内完成，时机与内容不变。

### 公共片段与常量：跨命名空间即时生效、片段里的 bind 常量能认出

`<include refid="其它命名空间.片段名"/>` 复用公共片段原本靠「5 秒缓存 + 全项目 XML 扫描」找目标，刚改完片段再预览可能还是旧 SQL；带命名空间的引用解析也每次重筛全项目 XML（T-MechanismSweep `501db7d89`）。现在两处都改按 namespace 查 IDE 索引，改了片段立刻生效、也不再随项目 XML 数量变慢，并删掉了 iBatis 定位里那个内部 A/B 用的全项目扫描回退开关（从未对外承诺）。配套地，被 include 进来的跨命名空间片段里的 `<bind value="@com.x.DicConstants@常量"/>` 此前一律求值为空（同一条语句里本文件自己的 bind 却正常），现在常量扫描覆盖这类片段，常量声明在父类或接口上时也支持按 `@子类@常量` 解析（T-BindStaticRefCrossNs `ad1deacb0`）。

### 日志清净：SQL 日志工具窗少一条无害告警

工具窗第一次打开时，排序按钮那组工具栏会在真正显示前被手动刷新一次，IDE 忽略这次刷新并记一条带堆栈的 `toolbar manual update is ignored` 告警；这次刷新本就不起作用（显示时会按当前排序自行更新），去掉后按钮外观、排序提示与菜单勾选态都不变（T-DebugLogNoise `c79026ea9`）。
