## 这一版有什么

### MBG 生成的 Example mapper 预览从残缺骨架变成可读 SQL（T-MbgExamplePreview，`2d8798a9` / `6fb76205` / `6212f24e0`）

用户报 `selectByExample` 预览出来是 `WHERE (AND OR (AND … ORDER BY 1`。四条成因逐条收掉：

1. `${criterion.condition}` 在模拟参数下求值为空，`and` 后面什么都不剩——预览现在把求值为空的 `${}` 写成 `{{表达式}}` 占位（**真实 SQL 产物路径不受影响**，renderer 默认参数仍输出空串），执行前另有更强的确认文案。
2. foreach 两轮迭代的 `and` 拼成单词 `andand`、separator 粘成 `)or(`——trim 缓冲现在**只在「粘起来会拼成一个词」时补空格**（左侧收尾是操作数、右侧起笔是标识符）；`(`、`,`、`)` 与 `?` 之间不再被撑开，`<where>` 里的 `IN (?,?)` 保持紧凑，与真实 MyBatis 的 trim 缓冲裸 append 行为一致。
3. `choose` 四个互斥分支默认全开、永远短路到唯一不带参数的 `noValue`——同组现在只默认启用含 `#{}` 的分支。
4. `parameterType` 是 MBG Example 时 `distinct` 与 `orderByClause` 默认不展开、集合按 1 项（`order by 1` 这种能执行、但语义被改写的产物不再出现）。

另外，MBG 的 `andXxxYyy(...)` 方法体固定是一句 `addCriterion("cust_id =", value, "custId")`——`condition` 是常量、分支语义写在方法名后缀里。预览现在会从 mapper 方法的调用点找到 example 变量，在同一方法体里逐个解析 `and*` / `or*` 调用并读那个常量，于是 `${criterion.condition}` 拿到真实列名与操作符：产物从 `WHERE ( {{criterion.condition}} ? )` 变成 `WHERE ( cust_id = ? )`。拿不到调用点（跨模块、无索引、非链式写法）时退回占位，不报错。告警行也不再混排「基线渲染错误」与「当前勾选的错误」。

### iBatis DAO 调用行直接预览 SQL（T-IbatisCallPreview，`8ad491b8`）

`client.queryForList("User.selectAll")` 这类 `SqlMapExecutor` 调用行，在原有跳转箭头旁新增预览图标，点开直接渲染对应 `<sqlMap>` 语句（`#name#` 参数、动态条件、`<iterate>`、`<selectKey>` 与 XML 语句行预览一致）；`Alt+Shift+Q` 在调用行与方法定义行同样可直接预览——此前这类位置会被 JDBC 模板通道先认领再拒绝，只得到「未找到」提示。MCP `sqlv_render_sql` 同步支持 iBatis DAO 调用行与 `<sqlMap>` 语句行（`sourceType` 以 `iBatis` 起头）。

### iBatis 预览里裸 `#name#` 参数按 parameterClass 定引号（T-IbatisParamClassQuote，`cb4ec1ed3` / `5a2e0419d`）

`WHERE USER_NAME = #username#` 填 `1213` 曾经预览成 `= 1213`——链路唯一的类型来源是占位符自带的 jdbcType（`#x:VARCHAR#`），裸 `#name#` 只能落面板「按值形态猜」，纯数字就不加引号。而 iBatis 引擎是按 `parameterClass` 的字段类型反射决定 `setString` / `setInt`，与值的形态无关。现在预览解析 `parameterClass`（类名或 `<typeAlias>` 别名）→ 字段类型 → 引号提示；短名解析按语句所属模块收窄（多候选不再一律弃权）。占位符自己写了 jdbcType 的仍以 jdbcType 为准，解析不到时维持原启发式不变。

### 复制可执行 SQL 的占位说明（T-CopyPlaceholderMarker，`2e553316`）

`{{表达式}}` 是预览占位、不是 SQL 注释，复制链原本原样把它带出去，粘到库里只报语法错、看不出原因。现在产物头部加一条带计数的注释（`-- contains N unresolved ${} placeholders shown as {{...}}; replace them before executing`）；有占位时不再叠加原来那条「已用模拟值填充」。分享面板的「复制可执行 SQL」此前一条标记都没有，这次一并接上。复制仍不弹确认——弹窗克制只留给执行。

## beta.1 验收失败的两处修复（F3/F4）

用户在**日常 IDEA 2026.3** 上验收 `2026.11.12-beta.1` 时看到两处异常：预览一直停在「以简化模式打开 · 临时文件解析失败」，点「执行 SQL」只报「创建临时 SQL 文件失败：**unknown**」——两条蓝字修复入口也没有出现。

两处都是上一版引入的缺陷，与用户环境无关：

**F4：落点判定被会话级缓存钉在旧结论上。** 「这个目录能不能建 PSI」原来按目录路径记忆到 IDE 关闭，而它其实取决于内容模型与 Registry——用户在排查过程中勾过 `ide.hide.excluded.files`、把 `.idea` 标成 Excluded，旧结论（当时判定为「能建」）就一直生效，于是预览仍然写 `.idea`、仍然拿不到 PSI，备用目录根本没被用上。现在每次现探，成本只是一次 VFS 查找加一次 `PsiDirectory` 查找，不在键盘热路径上。

**F3：失败原因被预热链并发清空。** 失败阶段原因原靠 `DataSourceSelector.lastTempFileFailure` 这个跨线程共享字段传递，「临时文件 + 备用落点」的失败在池线程记录、续接链在 EDT 读取；而预热链（预览打开时就会跑）在入口把同一个字段清空。两者并发时，EDT 读到的就是 null，文案退化成 `unknown`，连按原因挂的两颗蓝字也一并没了（它们依赖同一次失败记录）。现在原因**在失败现场就地捕获**、随异步回调带回续接链；预热链不再动这两个字段。

## 第三处：文件级判据看不见父目录，而落点本身就没得改（F5/F6）

同一轮验收连着报两次：一次是「面板上没有任何蓝字入口」（用户原话「执行sql错误，没有引导用户调整配置信息」），补上目录级读数后再报一次「问题还是没解决呀」。两轮的报文把成因钉死在**落点目录**上：

```
四次验收的读数对比
第一次：excluded=false underIgnored=false regHideExcluded=false psiLang=GenericSQL   ← 四项全绿，判成 UNKNOWN
第二次：dir=F:/…/mybatis-plus-sql-visualizer-demo/.idea/sql-visualizer/exec,
        dirPsi=false, inContent=false, dirExcluded=true, dirUnderIgnored=true, regHideExcluded=false
```

反编译本机 2026.3 平台确认了粒度差：闸门 `shouldCreatePsi()` 问的是**父目录**（`findDirectory(vFile.getParent())`），而失败文案里的四项判据是在**文件**上取的——「文件在内容根的文件集里、目录本身被记为 ignored」时文件级全绿、目录级判否，两者同时成立。所以第二行那两个 `false` 才是真相：**这个目录拿不到 PSI，平台永远不会为它建**。

而这类项目的成因是 `.gitignore` 里有一行 `.idea/`——那是**正常设置**，不是配错。也就是说「报错引导用户改配置」在这个形态下没有可改的东西；上一版把默认落点选在 `.idea` 下，却要用户去收拾，方向本身错了。

现在：

- 归因来源从「文件级四项」扩到**文件与父目录取并集**，并把目录级四项（`dirPsi / inContent / dirExcluded / dirUnderIgnored`）打进诊断串——这类成因以前在文件级全绿，只能判成「未知」。
- 新增成因「落点目录不被内容模型接管」，失败行给三条东西：原因说明 + 蓝色「改用项目根落点重试」+ 蓝色「打开文件类型设置」。
- **失败信息不再走共享可变字段**：成因与它所属的阶段成对记录，**且读方不清空**——同一次失败会被投递两次（abort 持有者 + complete 排队意图），原来「读一次就清」让第二次渲染退化成纯红字、把蓝字覆盖掉；你观察到的「切换数据源那条正常、直接执行那条丢」正是两条链路一个单投递一个双投递。
- `UNKNOWN` 不再只丢红字，兜底落点照给。
- **落点不改写**：你两次定案「兜底要用户点」「不能偷偷换落点」，所以 `.idea/sql-visualizer/exec` 仍是默认，失败就报错等人点；**也不再引导改 `.gitignore`**——忽略 `.idea/` 是正常设置，忽略模式的入口统一指向 设置 → 编辑器 → 文件类型。
