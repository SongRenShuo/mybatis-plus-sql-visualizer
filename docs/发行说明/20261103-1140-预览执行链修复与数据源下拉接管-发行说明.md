# 🎉 SQL Visualizer v2026.11.3

> 发行说明留档：对应 Gitee 发行版 **v2026.11.3**（标签 `2026.11.3`），附件 `mybatis-plus-sql-visualizer-2026.11.3.zip`。
> 通道：**Gitee 正式版**（Marketplace 侧由作者单独上传）。
> 范围＝v2026.11.2 发行包之后的全部用户可见增量：主体是预览窗「执行 SQL」链路的整批修复与原生数据源下拉接管，另有预览打开速度优化与增强捕获告警降噪。

这一版的主角是预览窗的执行链。v2026.11.2 之后，用户连续报了三个相互独立、却都落在同一条链路上的问题：点「执行 SQL」后预览面板下半区空白、连原生控制台工具栏都不出现；方言冲突时点了「放行」反而报「数据库控制台准备超时」，预览窗里还找不到「切换数据源」；注解预览打开后一直显示「未绑定数据源」，必须点一次执行才挂上控制台。三处都已定位到根因并修复，其中第一处是五个独立缺陷叠在一起，逐层拆完才修透。

同一批还补了一项能力：控制台工具栏最右侧的原生数据源下拉，现在由插件接管为「只换源、不执行」。原生动作点选后会换源、立刻执行、再重挂一个新控制台——新控制台并不在预览面板里，而且绕过了 DML 二次确认、`${}` 原文段确认、未知参数确认、方言闸与留痕。接管后点选只走插件的换源链，不提交 SQL；其它文件与 DataGrip 原生控制台的行为逐字不变。

## ✨ 新增

**控制台工具栏原生数据源下拉接管（只换源、不执行）**
- 预览窗内嵌控制台后，工具栏最右侧的数据源下拉改为插件接管：子项是每个已配置数据源一项，点选只换源并重建控制台，不自动提交 SQL
- 非本插件执行文件（如 DataGrip 自己的控制台）逐字委托原生组，行为不变；插件卸载或预览面板关闭时自动换回原动作
- 顺带修好下拉本身的三个显示问题：按钮只剩图标没有数据源名、弹层不贴着按钮弹出、数据源名里的下划线被当成助记符吃掉
- 数据源枚举改为两条来源取并集（全量在册源 + 原生「所有」集合），任一来源有时序或方言过滤问题都不会再整体退回原生列表

**「更多」菜单常驻「切换数据源」**
- 状态行里那两段可点的蓝字只在方言冲突时出现，执行失败后错误行会把它们顶掉，而「想换源」最常发生在执行失败之后。现在「更多」菜单里始终有「切换数据源」，点开就地弹原生数据源列表，只换源不自动提交

## 🛠 修复

**执行 SQL 后预览面板下半区空白，连原生控制台工具栏都不出现（T-PreviewConsoleOwnership，用户真机报障）**
- 现象：在预览弹窗点「执行 SQL」后面板没有变化；结果只出现在 IDEA 的 Database 工具窗；多数情况下连 ▶ / Tx / Playground / 数据源下拉都不出现；改用「切换数据源」重建控制台后才正常
- 根因是五个独立缺陷叠加：
  1. 预览编辑器与原生控制台共用同一个显示槽。冷启预热超预算时，降级装配与迟到换装都落在控制台嵌入之后，各自清空显示槽再挂自建编辑器，原生控制台整块被挤出显示链；而两个「控制台还在不在」的判据都只查组件与宿主的关系，宿主被摘下仍恒真，谁都不会把它修回来
  2. Database 工具窗对同一个执行文件复用同一个结果面板，新建控制台时没有清场，旧 Result 页签跨预览残留，预览还没执行就先出现结果栏
  3. 接管组没有覆写 `displayTextInToolbar()`，平台因此把工具栏按钮渲染成纯图标
  4. 结果区为「执行后不被压回 84px」设了 160px 最小高度，折叠时把分隔条钳住，推到底仍留约 165px
  5. 折叠生效后，结果区回收守卫无条件把 160px 最小高度写回去；窗口放大时分隔条停在旧的绝对位置，新增高度全给了结果区
- 修复：新增 `mountEditorHolderContent` 作为显示槽唯一装配口，控制台在位时保留宿主，预览编辑器只作文档/状态载体；归属判据补「宿主仍在显示槽上」；预览路径补 `clearResultContents` + `clearConsoleHistory`（执行路径不清）；覆写 `displayTextInToolbar()`；折叠时同时清零最小高度并打折叠标记，回收守卫与分隔条校正都读该标记让路；折叠态挂常驻 resize 监听重新贴底
- 顺带修掉一处 262 文档写断言：清空控制台历史改用带类型的 Document + 写命令，不再裸反射 `setText`

**方言冲突「放行」把控制台准备链静默卡死（T-DialectGatePassDeadChain，用户真机报障）**
- 现象：执行 SQL 报「数据库控制台准备超时，未提交 SQL」，预览弹窗里找不到「切换数据源」；日志里 session 创建后 6ms 就打出 `runRunner invoked OK`，`attachConsole` 一次都没到，既无失败也无中止；随后点击全部排队，直到 60 秒逃生才自愈
- 根因：放行分支仍按「非 MATCH 一律投 BLOCKED」处理，而准备链收到的回执一投就把本次执行意图标成已完成，下游「准备是否进行中」立刻为假，准备链在挂控制台之前静默早退——既不挂控制台，也不释放单飞门
- 修复：先算出放行结果再投回执，BLOCKED 只用于真阻断；准备链 7 处早退改为「结算门 + 返回」，门不再悬挂 60 秒；放行态状态行保留「切换数据源」「方言设置」两段可点蓝字；换源改就地弹平台原生列表，单源也弹、只换源不自动提交；排队超时与「被新请求取代」拆成两条独立文案，不再复用「准备超时，请重新选择数据源」

**方言冲突状态渲染实例化整棵设置树，EDT 卡顿且面板停在「执行中」转圈**
- 根因：判断「方言设置」链接显隐时调用了会把整棵设置树实例化的平台 API，第三方插件的设置页在构造时抛异常（日志三条 SEVERE），单次 1.2 秒级 EDT 卡顿；异常还会把状态行渲染整段吞掉，面板停在转圈
- 修复：去掉该探测，链接恒显示，点击时按 id 打开并兜底失败；状态行渲染整段包兜底，失败至少退回纯状态行，不再停在旧态

**注解预览打开后一直「未绑定数据源」，要点一次执行才挂上控制台**
- 根因：注解预览链里的回退编辑器是异步创建的，准备默认控制台时编辑器还没建好，旧实现直接提前返回
- 修复：SQL 源改为三级回落（原生文档 → 回退编辑器 → 本次预览结果），并补入口锚点日志，两条静默提前返回的路径从此在日志里可见

**折叠结果区后约 2.5 秒又自己长回来；放大窗口时结果区反而被撑大**
- 修复：回收守卫读折叠标记，折叠态保持零兜底并重新贴底，展开态才恢复 160px；折叠态挂常驻 resize 监听；准备与复用两处折叠加高度守卫；无条件的 0.6 分隔条监听读标记跳过

**增强捕获「登记盲区」单条告警平时也出现，看着像常规噪声**
- 修复：单条盲区降为诊断，默认静默（`logLevel=debug` 时可查）；累计达到 5 次才判为系统性盲区，任何级别必报一次，文案改为可行动提示

**Marketplace 描述里的二维码卡片两列不等宽、交流群码部分客户端不显示**
- 描述区样式会覆盖图片的 width 属性，两个单元格都不写宽度时列宽由说明文字长度决定，两张码一大一小；站点上的 `group-qr.png` 内容实为 JPEG，按扩展名却返回 `image/png`，配合 nosniff 在部分客户端被拒渲染。现两个单元格显式等宽，交流群码改引 `.jpg`，原 `.png` 保留不删

## ⚡ 优化

**预览打开速度：每次省 1.7–2.0 秒**
- 根因：执行文件的有界等待放在写锁内，后台预热线程先持锁等 EDT，EDT 随后阻塞在同一把锁上，形成自锁，每次稳定烧满 2000ms 超时；超时后 12–18ms 立刻写完，证明 EDT 不是忙，是被锁挡住
- 修复：临界区收缩为「存在性 + 内容判等 + 首建裸写」，EDT 派发移到锁外；等待失败后重进锁复核，内容仍不一致时不裸写。六次真机预览逐次复核，超时告警消失

## 兼容性

- 支持 IntelliJ IDEA **2024.3+**（Ultimate / Community；EXPLAIN、执行 SQL、表右键入口与 Database 原生图需 Ultimate；MCP 能力需平台 MCP Server）
- 插件 ID 与升级链路不变，v2026.11.2 用户可直接覆盖升级
- 数据源下拉接管只作用于本插件执行文件，其它控制台与 DataGrip 原生行为不变；预览面板关闭或插件卸载时自动换回原动作
- 设置项数量不变，无需重新配置

## ⚠️ 已知边界

- 本轮预览链修复的真机验证集中在 IDEA 2026.2.4（用户日常环境），2024.3 / 2026.1 上走的是同一套代码路径，但未逐版本重跑真机
- 数据源下拉接管依赖平台动作 ID `Console.Jdbc.ChooseDataSource`；若后续 IDE 版本改名，接管会静默不生效并回落原生行为，不会阻塞执行
- 折叠标记与结果区回收守卫只覆盖预览面板内嵌的持久控制台；独立 Database 工具窗不受影响
