## 这一版有什么

**SQL 预览独立工作台（T-SqlPreviewStandalone 系，内测 beta.1/beta.2 已含）**：主侧边栏新增「SQL 预览」页签——粘贴一段 SQL 或 mapper XML 片段就能快速格式化、填值、复制可执行 SQL（Tools 菜单与 `Alt+Shift+P` 直达，剪贴板里疑似 SQL 时自动预填）。XML 片段识别复用插件自研 XML 引擎：动态条件勾选、foreach 重放、bind 回填都可用；网页复制的 `&lt;/&gt;` 转义形态与 markdown 代码围栏也能识别；iBatis 2 条件标签（`<dynamic>` / `<isNotNull>`）与 `#id#` / `$name$` 占位语法同样可识别可填值。可直接执行（D233/D234）——复用语句预览那套完整执行链（Schema 校验、DML 二次确认、`${}` raw 确认门、方言闸、控制台内嵌），解析成功后自动跑静态性能检查（`SELECT *`、缺 WHERE 直接出现在性能建议行）。

**工作台底部动作行（T-PreviewActionRow，内测 beta.1 已含）**：页签底部新增「执行 SQL / 复制 SQL」两个产物出口——此前页签里没有复制 SQL 的入口，想取走去注释的可执行 SQL 只能先进弹窗或手工全选；顶部图标区保留解析预览 / 格式化 / 从文件加载 / 清空 / 在弹框中打开。预览缺 `<sql>` 片段时结果区直接给「缺少片段 —— 点此补上内容」入口，从工作台打开的弹窗里点了当场用原文重解析、就地看到展开后的 SQL（gutter 图标 / 日志 / 历史打开的弹窗没有原文可重解析，不出现该入口）。

**结果区信息分区（T-PreviewInfoLayout，内测 beta.1 已含）**：警告只在黄色横幅承载（含悬停全文、点正文弹完整信息对话框），meta 行不再重复贴一遍警告正文、表名与判型依据不再被挤掉；性能建议整行展示，不再被挤成半句。顺带修复补齐片段框的「从文件选择…」没有反应（选择器父组件传空，被模态框压住或不显示）。

**「从文件加载」移到独立工作台（T-LoadFilePlacement，内测 beta.1 已含）**：预览弹窗是全插件 21 处入口共用的展示层（gutter 图标、日志、历史、语句预览），在里面换文件会静默改掉「这条 SQL 从哪来」。现在该入口只出现在独立工作台的输入工具栏——选中 mapper XML 后替换输入并直接解析，状态行标注「已从 <文件名> 加载」，超长文件不写入。

**吸收 Hibernate Debugger 精华五项（T-HdAbsorb D215~D219，内测 beta.2 已含）**：SQL 日志耗时按测量来源分档（agent 精确计时原样、控制台解析的近似耗时带 `~` 前缀）并补偿调试器挂起时段；同模板 60 秒滑动窗判定「疑似 N+1」红色徽章，点开按模板过滤成一组；调用栈里的 JDK/CGLIB 代理帧反解为业务类型；数据源改名后按「URL+用户+库名」指纹兜底恢复记忆；MCP 工具输出可选摘要档（`detail=false`）。其后聚合摘要行排版重做（红色只给短标签、详情转次要灰、退出口链接化）与「关掉 SQL 去重不再让 N+1 检测失效」（D237）一并修掉。

**MCP 结构性免疫（T-McpGlobalBreakHardening，内测 beta.2 已含）**：平台过滤器契约再变也不会拖垮内置 MCP Server（未知契约自动不注册、运行期调到未知方法熔断摘除）；关掉插件 MCP 总开关后完全不碰平台过滤链、重新打开无需重启生效；设置子页改动无需重启生效；设置页 MCP 区新增只读门控状态行与 Registry 逃生开关 `sqlvis.mcp.gateFilterEp`。

**D239：2026.3 / 2025.3 / 2026.2 上 MCP 工具清单只列一两个的根治（内测 beta.2 已含）**：运行期生成的工具集壳类补齐元数据、自己声明工具方法并带上注解，11 个工具集在 2026.3 元数据扫描下都能正常展开；顺带修平台工具清单缓存不刷新。真机三轮读数：165 个工具（含 11 个 `sqlv_*`）/ 154 个（0 个）/ 165 个。

**本版新增：设置页「公开的工具」灰字描述双语化（T-McpToolDisplayDesc）**：此前该行只重复工具名（根因＝工具集描述钩子把平台兜底值原样透传，平台给的兜底恰好是工具名）；现在与插件设置页 MCP 工具开关列表同一组双语简述——插件语言中文显示中文、英文显示英文，外部 AI 客户端看到的工具长描述不受影响。

**本版新增：增强捕获修复批（beta.1 之后增量）**：
- **多模块并行时，没挂 agent 的模块 SQL 不再被控制台让位吞掉（T-MultiModuleConsoleYield，`eb9711735`）**：让位原是项目级全局闸——agent 在任一进程在线，所有控制台的 SQL 行都丢（两模块只挂一个 agent 时另一模块全灭）。现在按控制台行前缀的进程 PID 归属：挂了 agent 的进程照旧让位防双报，没挂的模块照常从控制台解析。
- **老驱动建连接时自执行的内部语句不再混进增强捕获日志（T-DriverInternalSqlFilter，`8ef85fe56`）**：mysql-connector 5.1 每次建连接会自己执行一批 `SELECT @@session...` 系统变量查询（带驱动版本注释），此前被当业务 SQL 占满日志头部。现在识别为驱动内部语句默认过滤，业务 SQL 照常入列。
- **增强捕获状态行会如实说明「目标 JDK 低于 8，已跳过注入」（T-AgentStatusOldJvm，`05fd3dff1` + 优先级收口 `95ecbea44`）**：此前这类项目错过一次性提示后，设置页会一直显示「等待应用进程启动后挂载」，而它永远挂不上——现在改说已跳过并回落控制台捕获，不再像坏了；且状态行以本次运行的事实为准（真实挂载 > 本次跳过 > 上次会话结局），先跑高版本再跑低版本时不会再拿上次的「连接中断」遮住本次的跳过说明。配套 JDK 6/7 项目开启增强捕获后直接起不来的根治（T-OldJvmPremainGuard，`79cafe2a6`）也在本版内。

**修复与优化（内测 beta.1 已含，T-PerfSweep33 / T-Perf33MergeAlign）**：独立预览的识别链与读盘全部移出界面线程——弹窗贴入识别改池线程解析，大 XML 片段（上限 100k 字符、最坏 8 次候选解析）不再停在界面线程；工作台「从文件加载…」与补齐框「从文件选择…」的读文本移入后台，读取前按文件长度粗筛、超 100k 不再读进来；EXPLAIN 前置预热补 cache-only 判等；N+1 嫌疑戳登记加双帽兜底——日志面板长期不打开时不再随捕获速率无界累积。同批新增源码守卫钉住「识别不在 EDT 直跑」形态。

**更早的稳定性修复（内测 beta.2 已含，摘要）**：IDE 被第三方长读锁卡住时插件不再跟着卡（有界派发，`7e470a9e4`）；首开不再误报「简化模式/完整编辑器尚未就绪」；长警告可悬停/弹窗看全；预览参数已带引号的值不再被二次转义；iBatis 别名表索引化、索引构建期点预览自动重试等一批提速项（T-PerfSweep31/32）；交流群二维码改引站点 .jpg 版（`d6d34c3dd`）。
