> 版本号说明：今天的 `2026.11.7` 正式版已经发出，按「同日再发并入次日」的规则本次用 `2026.11.8-beta.1`；这样内测清单里的版本才高于正式版，装了正式版的用户也能正常收到推送。

这一版是 v2026.11.7 的补丁版，只做一件事：把日期时间参数的回填形态改对。用户在 Oracle 上执行带 `UPDATE_TIME` 之类时间戳条件的 SQL 时，预览里明明是好的值，一点执行就 `ORA-01843: 无效的月份`——原因是参数被包成了单引号串，Oracle 对 TIMESTAMP 列的隐式转换按 `NLS_TIMESTAMP_FORMAT` 解析，而捕获到的 `LocalDateTime` 打印出来是 ISO 的 `2026-11-07T13:20:14.417`，那个 `T` 分隔符不被接受。

## 🛠 修复

**日期族参数改用 ANSI 类型字面量，Oracle 预览执行不再报 ORA-01843 / ORA-01861（T-DateLiteralBackfill，`9779d173`）**

捕获到的 `LocalDateTime` 值按 `toString()` 是 ISO `T` 形态（`2026-11-07T13:20:14.417`），参数行此前只把它包成单引号串：`'2026-11-07T13:20:14.417'`。Oracle 对 TIMESTAMP 列的隐式转换按 `NLS_TIMESTAMP_FORMAT` 解析，`T` 分隔符不被接受 → 执行报 ORA-01843。

把 `T` 换成空格同样不够——`'2024-01-01 10:00:00.0'` 在 Oracle 11g 与 23 上都实测报 **ORA-01861**（字面量与格式串长度不匹配，末尾那个 `.0` 是主因）。所以这次不再修修补补字符串，而是按 SQL 标准产出**类型字面量**：

| 值形态 | 产出 |
|---|---|
| 纯日期 | `DATE '2024-01-01'` |
| 时间戳 | `TIMESTAMP '2024-01-01 10:00:00'` |

归一规则：ISO 的 `T` 换成空格、缺秒补 `:00`、保留毫秒。产出点收在一个共享渲染器 `SqlDateLiteral` 里，四条渲染链与模型链同口径：

- **面板参数行**：参数区显示的就是最终形态，点执行不再与显示不一致
- **复制可执行 SQL**：复制出去能直接贴进客户端跑
- **导出 / 分享**：导出文件里的参数同样是字面量
- **增强捕获列表**：未打开预览时列表里的 `restoredSql` 也是字面量
- **模型链**：MP 批量 / JPA（`QueryByExample`、`Specification`）/ 自研框架 XML 回填统一走同一条规则

**回落与门禁**：形态不匹配或类型未知时仍按原来的引号渲染，不会产出非法字面量；SQL Server 与 SQLite 因 T-SQL 与 SQLite 本身不支持 ANSI 类型字面量，按方言门禁保持引号形态（SQL Server 的 ISO 8601 引号串本来就能隐式转换，无需改动）。

这条修复同时给 R3 验证报告里挂起的「面板参数行要不要一起 ANSI 化」定了案（决策点 D1）：统一 ANSI 化，不再分链。

## ⚠️ 已知边界

- **非补零日期仍回落引号**：`2026-1-1` 这种形态只有 Oracle 实测过，MySQL / 达梦等引擎未验证，本版不扩；面板只做提示、不阻塞
- **控制台还原路径在 SQL Server 上仍产字面量**：`LogSqlRestorer` 没有方言入参，SQL Server 控制台还原出来的仍是 ANSI 字面量（既有缺口）；增强捕获侧已按连接 URL 判方言，因此同一语句跨通道在 SQL Server 上可能一处引号、一处字面量
- **JdbcTemplate 的 `:name` 命名参数维持引号**：该通道没有类型信息，不做猜测
- 本版为内测通道版本，Marketplace 稳定通道不上传

1. 下载 `mybatis-plus-sql-visualizer-2026.11.8-beta.1.zip`
2. IDEA → Settings → Plugins → 齿轮 → Install Plugin from Disk… → 选择该 zip
3. 重启 IDE

内测通道用户也可以在设置页点「检查更新」直接升级。
