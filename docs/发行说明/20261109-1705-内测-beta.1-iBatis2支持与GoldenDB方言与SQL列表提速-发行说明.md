# 🎉 SQL Visualizer v2026.11.9-beta.1（内测版）

> 发行说明留档：对应 Gitee 发行版 **v2026.11.9-beta.1**（标签 `2026.11.9-beta.1`），附件 `mybatis-plus-sql-visualizer-2026.11.9-beta.1.zip`。
> 通道：**Gitee 内测版**（Marketplace 不收内测包，转正时另行上传）。
> 范围＝`v2026.11.8` 正式版之后的全部用户可见增量：iBatis 2.x 全面支持、中兴 GoldenDB 第 15 方言、SQL 列表追赶与风暴期刷新优化，以及两条真机缺陷修复。
> 版本号说明：上次发行是 11-07 的 `2026.11.8`，按日期版本号规则本次基号用 `2026.11.9`，内测加 `-beta.1`。

这一版块头最大的三件事都在「平时没人夸、出事才被骂」的位置：iBatis 2.x 的老工程终于能像 MyBatis 一样预览和跳转；GoldenDB 接上了第 15 种方言；高并发抓取时 SQL 列表不再卡顿丢数据。另外修掉两个真机上一定会撞到的缺陷——PostgreSQL 执行预览 SQL 只发出 `TIMESTAMP` 一个词，以及 Oracle 驱动连接层被反复提示「未登记 JDBC 实现」。

## 🛠 新增

### iBatis 2.x：预览、着色、补全、跳转全部接上

此前 `<sqlMap>` 文件只能靠「通用内嵌 SQL」兜底通道碰运气：叶子语句能出预览图标但 `#name#` 原样输出、参数面板显示「无参数」，含 `<dynamic>` / `<isNotNull>` 的语句**一个图标都没有**。现在走独立的 iBatis 2 渲染链（`29a4a4be` / `0fa46b44`）：

- **占位四态**：`#p#` / `#p:jdbcType#` / `#p:jdbcType:nullValue#` / `#p,jdbcType=?`，另有 `$p$` 字符串直替与 `##` / `$$` 转义
- **条件标签**：14 个 `<isXxx>`、`<dynamic prepend>` 的 prepend 消费、`<iterate>` 的 `open`/`conjunction`/`close` 与 `#ids[]#` 下标、`<sql>`/`<include>` 配置期内联、`<selectKey type="pre|post">`
- **保真口径**：以 iBatis 官方 2.3.4.726 引擎做黄金对照（不连库直取真值，20 种形态逐字节一致），包括「`prepend` 逐字拼接不补空格」这类反直觉行为——真实输出会出现 `ANDORG_NAME` 这种粘连，我们原样复现、不做美化
- **文件识别**：按「根元素 `<sqlMap>` / DOCTYPE 的 8 条标识 / classpath 上的 `com.ibatis.sqlmap.client.SqlMapClient`」三选二判定，避免把 MyBatis 3 的 `<mapper>` 误判成 iBatis（`763885f6`）

编辑器侧（`e8553325` / `ac918146`）给语句文本加了注入着色、折叠与关键字补全：`#name#`、`#name:TYPE#`、`#name:TYPE:nullValue#`、`$name$` 四态按配对闭合识别（未闭合不吞后续文本），`##` / `$$` 判为字面量而非参数。iBatis 属性值（`property` / `compareValue` / `refid` …）**不做**注入，属性名与 MyBatis 高度重叠，强行注入会改变 `<mapper>` 文件的既有行为。

两份 DTD 随包分发（`56d2ba18` / `ce3ab462`）：iBatis 配置期从 classpath 读 DTD、不联网，但 IDE 会按 `DOCTYPE` 外链去取，而 `www.ibatis.com` 域名早已失效——现在 `sql-map-2.dtd` / `sql-map-config-2.dtd`（取 2.3.4.726 jar 内的权威副本）内置，8 条标识全部映射到随包副本，离线可用，发行包增量约 9 KiB。

跳转（`e744b9d6` / `75b84d7a`）两条链路：

- **XML 内部 id 引用**：`<include refid>` → 同文件 `<sql id>`；`resultMap=` / `parameterMap=` / `<resultMap extends=>` → 同名定义
- **Java DAO → XML 语句**：`SqlMapExecutor` 的 statementId 入口（`queryForObject` / `queryForList` / `queryForMap` / `queryWithRowHandler` / `queryForPaginatedList` / `insert` / `update` / `delete`）的首个字符串实参 → 对应语句的 `id` 属性

全部是 soft 引用：目标不存在时零报红，不注册任何校验器形态。SQL 列表里 iBatis 条目也拆出了独立的 `IBATIS` 来源（`4ac11547`），按来源展示/筛选可区分。

### 中兴 GoldenDB（第 15 方言）

渲染形态依据《GoldenDB 开发支持 V6.1.03.10》：分页 `LIMIT [offset,] count`、反引号标识符、upsert `ON DUPLICATE KEY UPDATE`、`DELETE ... LIMIT` 文法级支持；保留字词表按 p351-355 三表并集落 384 词（含 `storagedb`/`chgdiskey`/`gdb_nolock` 等 GoldenDB 自有词与 `rownum`/`varchar2` 等 Oracle 兼容词，与 MySQL 词表差 147 词）。连接面接全：`jdbc:goldendb://`（含 loadbalance 形态）URL→方言、列表角标 `GoldenDB`、MCP 识别（含中文名「金篆」归一）、执行目标路由（`7c5788fb` / `7630fd0a` / `e2051bca`）。

增强捕获按 `gdb_mysql-connector-java-oracle-5.1.46.99.jar` 真实字节登记三面：连接面 `com.goldendb.jdbc.NonRegisteringDriver`（`Driver` 自身不声明 `connect`，只登记 `Driver` 会零命中）+ `Driver`、语句面四个类、prepare 面 `ConnectionImpl`；日志来源定位的框架帧跳过前缀同步补 `com.goldendb.`（`acc522cf` / `bb987110`）。

### 其他

- **捕获状态栏显示「追赶中：落后 N 条」**（`5bdefafc`）：高并发抓取期间实时显示缓冲区尚未呈现的变更数，追平自动消失，归零防抖一拍不闪烁；同批接入面板刷新逐拍耗时探针
- **捕获高峰期的事件不再静默消失**（`bb5652ed` / `2521991a`）：agent 事件队列丢弃数随心跳上报，状态栏增强段显示「已丢弃 N 条」；队列满时同语句模板聚合为最新一条并累加计数，异模板才逐出最旧

## 🔧 修复

- **PostgreSQL 执行预览 SQL 只提交了 `TIMESTAMP` 一个词，报 42601**（`f0a4db4f`，用户真机）：日期族改 ANSI 类型字面量后，`AND 列 >= TIMESTAMP '…'` 这类长行被控制台折行，DBN 默认按光标所在语句提交，光标正落在以 `TIMESTAMP` 开头的片段上。现在单语句预览**整批提交**（拆句数 ≤ 1 即整批），绕开光标/选区变量；多语句预览与 SQL Server identity 包装产物维持原逻辑，EXPLAIN 与回滚脚本同口径
- **控制台清屏后 SQL 捕获静默数分钟**（`cc2d3606`）：平台清屏是同一文档实例原地删除、偏移从头重计，而重放守卫的水位还停在旧长度，新行被持续误判为「重放」丢弃，直到长度追平才恢复。现在守卫先核对文档总长度，发现被缩小即核销陈旧水位
- **Hikari 等连接池代理被提示「未登记 JDBC 实现」**（`886a0d33`）：池包装类是代理层不是驱动，按六前缀表（Hikari/c3p0/DBCP 1.x+2.x/Tomcat-JDBC/Druid）从曝光排除，捕获路径与织入面零变化
- **Oracle 驱动的连接继承链被提示「未登记 JDBC 实现」**（`4fdd7d5e`）：Oracle 把 `java.sql.Connection` 摊在五层继承链上，白名单只登记真正声明 `prepareStatement` 的 `PhysicalConnection`，链上其余类被当成漏登记驱动，占满了 8 条上报上限、可能挤掉真正未知的驱动。现在与白名单类同族的类不再进该清单（照旧兜底匹配、照旧织入，只是不占取证位）
- **iBatis 文件点预览图标打开很慢**（`04522885`）：慢的根因不在渲染，而在预览前的源语言判定——它拿 SQL 的 FROM 根标识符反查实体类，iBatis 语句必然不带 `entityClass`，于是每次都落到全项目类短名的有界扫描。现在两条 XML 预览链的同步判定只做「直查 + 只读别名缓存」
- **`<sqlMap>` 文件里 Alt+Shift+Q 空候选**（`c587e911`）：兜底通道让位后，快捷键的 XML 候选集只剩 MyBatis 语句与兜底载体两路。现在三路来源收敛成单一判据并让三处消费点共用
- **风暴末尾最后几条 SQL 要等下一次执行才上屏**（`47f762ef`）：不足一批且落在通知节流窗内的变更，旧机制下再没有触发点。现由面板诊断拍（2s）发现悬挂并补发通知，最迟 2 秒上屏
- **去重开启时同一次执行出现两行**（`f7c20f7b`）：跨通道折叠窗只有 5 秒，控制台副本经平台冲刷延迟 >5s 才到时两行并存。现在折叠索引取消时间清除，越窗到达的同源控制台行按 60s 兜底窗折回 agent 行（保耗时/角标全的字段，不计 ⨉N）
- **高并发期事件投递速率被钉死在约 64 条/秒**（`0d50931d`）：agent 排水循环每轮最多 64 条，随后读一次带 1 秒超时的阻塞帧——平时没有入站流量，等于每排 64 条干等 1 秒。现在 burst 达上限时先 `available()` 探测，无数据零等待继续排水；排水 512 条从 726ms 降到 31ms（约 23 倍）
- **尖峰时被挤出的事件不再丢失「执行了多少次」**（`27ec0173`）：队列满且没有同模板可合并时，此前直接逐出并计入丢弃。现在逐出时把模板与次数记进溢出账本（512 个模板封顶，内存 <1MB），排空后转成聚合事件补发；实测 520 种模板灌爆场景真丢失从 586 条降到 74 条

## ⚡ 改进

- **列表刷新加 150ms 时间窗下限**（`7be82118`）：旧机制只在上一拍在途时合并，EDT 一空就刷下一拍，压测实测风暴期退化成每秒几十拍高频小刷新。窗口内通知挂 Alarm 补刷一拍，窗口外（含风暴后第一条）仍立即刷，单条 SQL 秒显不变
- **⨉N 计数与同模板计数改增量维护**（`5a32e33d`）：保留六类兜底点自动回退全量，等价性由 3 种子 × 600 操作随机序列与全量重算逐键对账钉住
- **刷新单拍从 102~232ms 降到 7~9ms**（`c1764eaa`）：真凶不在计数（增量计数仅 0.6~1.4ms）而在贴底滚动触发 Swing 列表整表布局重扫，每拍 27~31ms 重算全部行高。现在给渲染器加条目级 preferred size 缓存（按行身份键控，宽/模式/字体变化才作废）
- **淘汰条目的 ⨉N 核销改确定性增量**（`4703ed64`）：不再每拍全量回退

## ⚠️ 已知边界

- **GoldenDB 未经 GoldenDB 引擎验证**：渲染形态来自厂商文档 + 驱动级对照；EXPLAIN 能力矩阵显示 `false`（PDF 有专章但输出格式未逐字取证，不登记模板）
- **iBatis 本期不做**：跨文件 id 清单（需解析 `sqlMapConfig` 的 `<sqlMap resource>`）、XML → Java 反查、`<selectKey>` 隐式 id（`<insertId>-SelectKey`）、Kotlin DAO 调用形态
- **iBatis 跳转是语法级识别**：方法名 + 首参是字符串字面量，不做接收者类型解析。若工程里另有非 iBatis 的同名方法、且项目内恰有同名 sqlMap 语句，可能出现一次跳转；无目标时不产生任何效果
- **`<sql>` 片段前向引用**：iBatis 引擎要求片段声明在引用它的语句之前，本仓渲染器是「先收全表再展开」、支持前向引用但不告警（缺省方向安全）
- **iBatis 参数行含逗号时按逗号切分**：`List.toString` 不可逆，元素内含逗号或嵌套方括号时会切错；iBatis 批处理一期不支持
- **同模板聚合的计数只降精度**：面板侧逐条聚合计数消费尚未实现
- **iBatis 属性值不注入**：`property` / `compareValue` / `refid` 等属性与 MyBatis 高度重叠，接了会给错语义
- 本版为内测通道版本，Marketplace 稳定通道不上传
