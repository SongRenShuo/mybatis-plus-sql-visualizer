## 这一版有什么

- iBatis 自研语句名里的 `@` 不再让快捷键预览误报未找到
- JDBC 通道认领却渲染为空时，会自动再按 iBatis 语句解析一次

## 根因与修复（T-IbatisAtShapeGate）

真机上报：iBatis DAO 调用行上点左侧 gutter 预览图标正常，但按 `Alt+Shift+Q`（转换为 SQL）却弹「未在光标处找到可预览的 SQL 源」。语句名形如 `cQAccountTypeByAccountType@custmg.qAccountTypeByAccountType`（组名@命名空间.语句 id）。

根因是快捷键回落链的 iBatis 形状正则不接受 `@`，把这次调用让给了 JDBC 通道；JDBC 认领后 `isLikelySql` 拒绝，但通道已经返回认领成功，用户只拿到错源提示。gutter 侧没有这道正则，所以图标与点击一直正常。

修复：
- 形状门 `STATEMENT_ID_SHAPE` 的段字符集放行 `@`（段首字符集不变，SQL 文本、空格、括号、数字开头等负例照旧拒绝）。一处改动覆盖 JDBC gutter 让位、字符串方法 gutter 让位、快捷键与 MCP 认领四个消费面。
- 错源兜底：JDBC 通道认领但渲染为空时，在同一读锁内再判一次 iBatis（新增 `resolveIgnoringShape` 跳过形状正则、`previewResolvedOrNull` 未命中返回 null）——命中才接管，未命中保持原提示，非 iBatis 工程不受影响，也为今后第三种自定义字符兜住同一错源。
