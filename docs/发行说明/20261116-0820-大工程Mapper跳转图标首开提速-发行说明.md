## 这一版有什么

本版只做一件事：让大工程里 Mapper 双向跳转图标在冷打开时又快又稳。上一版（2026.11.14）真机反馈是「冷打开 mapper XML 后图标晚约 5 秒才出现、出现后我方图标消失几秒再回来」「Java 接口方法行的图标长期缺席」；本轮按 F1 → F1' → F1'' → F1''' → F2 五刀收口，最终把运行期全项目扫清单换成 IDE 索引期的自定义文件索引。

### 冷打开时 XML→Java 图标不再闪没（F1，`d3eb65079`）

图标是否显示原本只取决于「接口方法此刻能不能解析到」。索引未就绪或重建中的那一次解析会瞬时返回 null，而慢趟 pass 按整趟结果换装，就把先前已渲染的图标摘掉了；几秒后索引就绪、下一趟解析成功，图标又回来。现在改成四段判定：解析成功就产出并记入会话级正缓存（`namespace#id`）；解析失败但正缓存命中仍照常产出；解析失败且落在 dumb 窗乐观产出且不入缓存；其余失败不产出。不变式是「图标只在确认真没有时缺席，不在还没查到时缺席」——真没有对应方法的语句依旧不显示图标。定向 17 例全绿，反向摘掉「失败但缓存命中仍产出」分支恰 2 红、恢复复绿。

### Java→XML 图标不再长期缺席（F1'，`6bc12e9c8`）

大工程刚打开头几秒，慢趟首跑 `MapperXmlLocator.locate` 时 XML 文件清单还没就绪，这次「暂时的失败」被当成结果记住，而 daemon 不会自动重算慢趟，图标就一直缺席到文件改动触发重分析。修法与 F1 同构：成功入的是共享正缓存 `resolvedStatementKeys`，XML 侧确认过的语句双向受益。定向 31/31 绿、反向恰 3 红后恢复复绿。

### 根工程 scope 下图标不再饿死（F1''，`81884a539` / `588d64604`）

真机实证：根工程约 4841 个 XML 时图标长期缺席，单工程约 2100 个尚可自愈。根因是清单首扫在慢趟 ReadAction 内被 JPS 写盘反复以 `ProcessCanceledException` 取消，慢趟饿死。`81884a539` 把清单构建移出慢趟关键路径（无槽只踢后台异步构建并立即返回 null，不写 MISS；落地后一次性 restart），TTL 过期改 serve stale 加后台刷新；`588d64604` 续刀把清单扫描从「4841 个 XML 全量 PSI 解析 rootTag」改为「VFS 原始头扫 16KB 提取 namespace」，慢趟定位只对 namespace 命中的 1~2 个候选付 PSI，并保留文件名兜底（头扫盲区回退一次 PSI），覆盖面不收窄，iBatis sqlMap 仍由独立链负责。顺带修了静态槽跨用例污染导致的「单跑绿、全套件红」。前刀定向 56/56 绿、续刀 60/60 绿。

### 改用自定义文件索引替换清单状态机（F1'''，`7dc6c1c73`）

前三刀都在补自建缓存的补丁。参照竞品反编译调研的头部设计，改用自定义 `ScalarIndexExtension`：每个 mapper XML 的 namespace 在**索引期**摊平成键，运行时一次 `FileBasedIndex.getContainingFiles` 就是答案，失效全交平台增量管理，零 TTL、零自建监听器。采纳前先核屏障风险——平台 `fileBasedIndex` 扩展点声明 `dynamic="true"`，不是动态卸载屏障，热更新（免重启装）不受影响；`042cf6572` 补跑 verifyPlugin（243/253/263）BUILD SUCCESSFUL，验证器判定插件可免重启启用/禁用。`MapperXmlLocator` 瘦身重写为「索引查询 + PSI 校验」，单槽 TTL、头扫异步、pending→restart 整套状态机退役（净减 229 行）；provider 层 F1' / F1-b 的失败分支兜底保留，正确性闸门仍在 PSI 侧（根 namespace + id 精确匹配）。定向 84/84 绿。收益预估是 4800 XML 下 Java→XML 首跳从「秒级全扫」降到毫秒级。

### 首渲染预热延后，不再和索引重建抢资源（F2，`7ad1d1a5d`）

首次渲染图标时会顺带在后台踢三件预热（调用点预取、补全上下文、预览装配），冷打开时它们和索引重建挤在一起（实测首开后台扫描累计 3.3s + 15s）。现在收拢到 `GutterWarmScheduler` 一个调度点：判定内核抽纯函数 `shouldKickNow(dumb, msSinceProjectSmart, delayMs)`，dumb 不踢、到点才踢、未到延迟派发；延迟锚点是本会话内最近一次观察到工程 smart 的时刻。Registry `sqlvis.gutter.warmDelayMs` 默认 5000，置 0 回到旧行为。定向 `GutterWarmSchedulerTest` 7/7 + `PreviewAssemblyWarmTest` 7/7 绿，反向把 `getLineMarkerInfo` 改回直踢恰红、恢复复绿。
