# v2026.11.10-beta.1 发行说明(内测)

- 发行:2026-11-10
- 版本:`2026.11.10-beta.1`(内测通道，Marketplace 不上架)
- 范围＝`v2026.11.9-beta.1` 发行包之后的全部用户可见增量:**iBatis 交互补全**(T-Ibatis2Gap 券 A/B/C/D，即用户真机反馈「参数没正常识别、左侧没有跳转图标」的正面解法)。

## 主要增量

### iBatis:sqlMap 语句行与 Java DAO 调用行双向跳转箭头

- 此前 iBatis 文件只有预览图标，跳转只能 Ctrl+B / Ctrl+Click；现在与 MyBatis mapper 文件同款的双向箭头:语句行箭头落到 Java DAO 的调用实参，调用行箭头落到 XML 语句的 `id` 属性。
- **不受 MyBatisCodeHelperPro 影响**:竞品没有 iBatis 能力、不存在图标冲突，让位门已解耦——竞品在位时箭头照常显示(有竞品在位用例与反向验证钉住；典型用户环境两者同装，这是本次验收特意盯住的一条)。

### iBatis:预览参数可填值，SQL 随值变化

- 此前预览固定按无参基线渲染:`<dynamic>` 条件全部不成立、参数面板为空——用户看到的「参数没正常识别」即此。
- 现在按语句生成参数行与条件行:动态条件按行勾选(`isNotNull` / `isNotEmpty` / `isEqual` / `isGreaterThan` 等 14 种)、值可填、`<iterate>` 填值列表(逗号分隔，按长度展开 `ids[0..n-1]`)，SQL 随填值变化。
- 数值比较修正:`compareValue="18"` 与值 `"9"` 按数值比较(此前字典序会误判 `"9" > "18"` 成立)。
- `$x$` 字符串直替仍走既有注入确认闸门，未绕过。

### iBatis:parameterMap 语句参数名按位对齐

- 声明了 `<parameterMap>` 且体内手写 `?` 的语句，此前因「名字数 ≠ 占位符数」回落成 `param1..N`；现按位置取前 N 个声明映射，显示真实属性名(如 `username` / `email` / `age`)，未消费的声明单独提示。

### iBatis:预览降级可见、横幅如实

- 某段无法渲染时明确标注哪个标签、什么原因(如 `<iterate property='ids'>` 需要集合取值)，不再静默产出半截 SQL 配一句与事实不符的「按原文保留 # 直替」。
- 横幅跟随重渲染结果:填值展开后自动消失、清空后以信息级回归；信息性说明(ℹ 说明)与失败(⚠ 预览未完整还原)分档，不再与「无未解析参数」自相矛盾。

## 已知边界

- `<sqlMapConfig>` 全局 id 表(跨文件跳转、`useStatementNamespaces` 解析)未做；跨文件 `<include>` 仍只支持同文件 + namespace 回退。
- iBatis 属性值(`property` / `compareValue` 等)不做注入着色——与 MyBatis 属性名高度重叠，注入会误伤 `<mapper>` 文件(刻意不做，非遗漏)。
- `<statement>` 手写 `?` 的语句参数名来自 `<parameterMap>` 按位对齐；无 `<parameterMap>` 时仍为 `param1..N` 并提示「参数名不可知」。
- 竞品同装场景(MyBatisCodeHelperPro 3.6.8)的箭头显示已由机器用例钉住，沙盒无竞品、GUI 未重演——真机以用户环境为准。
