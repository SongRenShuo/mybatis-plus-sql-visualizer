## 这一版有什么

### MBG 预览左栏没有可填的参数行（D11，`c33f9542c`）

现象：MBG Example 预览打开后，左栏参数区一行都没有，用户没有任何地方可以填值。

根因：条件对象注入之后，语句里占位符的来源全是 `__frch_criterion_N.*` 这一类展开项键，而参数区按「foreach 展开项不单独建行」的既有规则把它们全部滤掉了——规则本身没错，错在注入后的语句已经没有普通占位符可建行。

修法：按条件文本为这类键生成可填行，标签直接给条件摘要，例如 `staff_login LIKE 值`、`create_time between 值/结束值`。用户不必再钻进 foreach 值框里间接填值。

### 点「清除」后产物里还留着旧值（D10，`c33f9542c`）

现象：填过值后点「清除」，预览产物里仍残留上一次的值，例如 `BETWEEN '11' AND ?`。

根因：清除只清了 foreach 的权威值，已播种到展开项键上的值没有回收；而回收路径以「值 map 非空」为前提，清空权威值后 map 恰好为空，回收整条被跳过。

修法：清除时显式回收展开项键，产物与左栏填值重新一致。

### foreach 值框冲掉还原出来的条件对象（D9，`89c74c663`）

现象：条件对象已经还原出元素内容时，在 foreach 集合的值框里填值会把还原结果覆盖成半填形态，产物随之中断。

根因：值框与条件对象注入是两条写同一处数据的路径，前者没有感知后者已经生效。

修法：已还原元素对象的集合，值框改为只读并给出说明，只保留「未还原时手工填值」这一条路径。

### 每次打开预览都重扫全部数据源做 schema 预热（`20cc719dd`）

现象：真机日志里一次预览打开跑了两遍预热，每遍把 15 个数据源全遍历且全部没有结果，下一次打开原样重来；打开变慢，日志也被刷满。

根因：预热这条尽力链没有记忆，同一张表在极短间隔内被重复尝试。

修法：预热链加 60 秒去重窗口——同一张表在窗口内只尝试一次，窗口外放行，保留「数据源晚连接后自愈」的既有行为；跳过时在日志打一行 `prewarm window skip: skipped=N` 便于核对。
