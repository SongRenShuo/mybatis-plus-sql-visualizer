# 🎉 SQL Visualizer v2026.11.7（正式版）

> 发行说明留档：对应 Gitee 发行版 **v2026.11.7**（标签 `2026.11.7`），附件 `mybatis-plus-sql-visualizer-2026.11.7.zip`。
> 通道：Gitee（主仓）+ GitHub 镜像；Marketplace 由作者单独上传。
> 范围＝`v2026.11.4` 发行包之后的全部用户可见增量，由四个内测版（11.6-beta.1 / beta.2、11.7-beta.1 / beta.2）合并转正。

这一版把「看 SQL」推进到「改 SQL」：运行期拼接的语句不再是只能看的注释占位，参数区可以逐项填值，填完就是可执行 SQL；同时补上磐维 PanWeiDB 的方言与增强捕获、自研框架页面的 HQL 识别、Mapper 双向跳转的原生快捷键，以及空 Wrapper / JPA 删除更新的预览入口。

## ✨ 新增

**自研框架 `<pages>` 页面数据源识别 HQL 并转换为可执行 SQL（T-PagesHql）**

`<pages>` 页面 XML 的 `<datasource>` 此前一律按原生 SQL 直显——`FROM BaseLocation location` 原样展示（真执行会报「表不存在」）、实体属性路径不映射列名、`:name` / `?1` / `#{...}` 参数一概不提取。现在按「entityClass 与语句根标识符的关系」判定源语言（demo 的 `orderMaintain` 反例保证「有 entityClass」不会被误判成 HQL），命中后走既有 JPA/HQL 转换管道：实体名→表名、属性路径→列名、JOIN 副表实体映射、命名/位置参数提取，`#{SESSION_BASE_ORGAN}` 这类框架占位符预处理成命名参数。设置新增「自研框架数据源语言」三档（自动 / 仅 SQL / 仅 HQL），面板加「来源: HQL（已转换）」与「原文」只读页签。

**Mapper 接口与 XML 语句跳转接入 IDEA 原生快捷键（T-MapperNavShortcut）**

此前双向跳转只有 gutter 图标（鼠标专用）。现注册平台 `gotoDeclarationHandler` 与 `gotoRelatedProvider`：Ctrl+B / Ctrl+Click 在 Mapper 接口方法与 XML 语句间双向跳转，Ctrl+Alt+Home 弹出「关联符号」。handler 优先于 reference 且返回 null 即回落原生，非 Mapper 位置行为零变化，键位归平台 action 所有（改 Keymap 自动跟随）。

**空 Wrapper 与 JPA 的删除、更新调用也有预览图标（T-WriteFamily / T-JpaDeleteAnchor）**

`mapper.delete(null)` / `service.remove(null)` / `mapper.update(entity, null)` 此前既没有 gutter 图标也没有预览入口；`repository.delete(entity)` / `ht.update(entity)` 因方法名与 Wrapper 工厂撞名同样不锚。现在按「空 Wrapper 精确形态 + MP receiver 家族」与「JPA receiver 家族」两套门控挂锚点，无 WHERE 时面板给全表删除/更新红字警示；非 MP/JPA receiver（如 `redisTemplate.delete(null)`）不亮。

**磐维 PanWeiDB 的方言与增强捕获（T-IbatisPanwei）**

- **增强捕获**：按 `panweidb-jdbc` 真实字节登记三面（连接面 `org.panweidb.Driver`、语句面 `PgStatement` / `PgPreparedStatement` / `PgCallableStatement`、prepare 面 `PgConnection`），V1 1.0.0 与 V2 2.0.0 类形一致、同一套登记覆盖两代
- **方言与角标**：`jdbc:panwei:` / `jdbc:panweidb:` 两种子协议都登记，角标显示「Panwei（磐维） · 库名@host:port」，渲染方言**恒按 Oracle**——磐维的 SQL 兼容模式由建库参数 `DBCOMPATIBILITY` 决定（出厂默认 A＝Oracle），JDBC 的 `db_compatibility` 只控列名大小写、不参与推断（PG/MySQL 模式的库请在面板手动改选）
- **未登记驱动点名**：接口兜底扫到「是 JDBC 实现但不在白名单」的类时，空态诊断行与日志页签底部常驻状态栏会列出类名，同类问题不再靠人工猜驱动包名
- **attach 补扫**：attach 之后才懒加载的驱动，首轮之后补挂 2 轮（默认 5s / 20s，可配），扫描预算只计候选类

**运行期拼接的 SQL 可以自己填值（T-RuntimeSlotFill）**

参数区为每个运行期占位建一行「运行时值 #N · 类型」，按语义给不同控件：单值（字符串 / 数字 / 布尔 / NULL）、循环（填一组值，按你代码里的模板展开）、三元（选真 / 假分支）、可选片段（勾「包含这段」）。填值后**预览 / 复制可执行 SQL / 导出回放脚本 / 直接执行四条链路取同一份文本**；值按字面量渲染（`O'Brien` → `'O''Brien'`），循环与命名参数、`?` 混排时一次扫描 + 区间记账，避免值里的 `:nm` 被二次替换。**留空即原样**，不填不影响任何既有行为。

**开发者模式：预览更新通道（T-DevUpdateChannel）**

设置页构建号连点 7 次后，更新区多出「检测更新（开发版）」，读 `update/preview.update.json`；正式「检查更新」仍读 `update/update.json`。状态行标「（开发版通道）」、tooltip 写实际 URL，`-Dmpvs.update.previewManifestUrl` 可换源，`-Dmpvs.update.devMode=true` 可直通；解锁只在当前会话内存里，切语言重建面板后按钮仍在。

**日志列表可选显示「类名#方法名」（T-LogMethodName，默认关）**

开启后在每条 SQL 的来源位置后追加一段，如 `[OrderServiceImpl.java:41] [UserMapper#selectById]`。控制台桥通道取捕获到的 mapper 语句 id，增强捕获通道取调用栈里的业务方法；无方法信息的条目保持原样。

## ⚙ 改进

- **循环内拼接的降级占位带上「追加的是什么」（T-RuntimeConcat-Polish）**：占位不再只说「运行时重复执行」，而是带循环体的模板摘要（只取 `append` 的字符串字面量，变量/调用/三元条件替 `…`），并走同一套清洗（注释结束符拆开、引号换安全同形字符、长度上限）
- **同一次执行的 SQL 不再在日志列表留两条（T-CrossChannelDedupe）**：控制台通道与增强捕获通道对同一条语句各出一条，前者天然没有耗时与执行位置。现按归一化等价键在 5 秒窗内折叠为一条，agent 副本到达时融合升级（耗时、影响行数、库角标、可跳转位置），与「SQL 去重」开关解耦

## 🛠 修复

- **运行期拼接的 SQL 预览把 Java 源码当活 SQL，括号与引号被吃掉（T-RuntimeConcatAndDeleteNull）**：占位收口为单条合法块注释 `/* 运行时值: … */`，并补三元分支处理与控制流感知（循环内降级、互斥 if/else 不线性拼接、可选片段带标记）
- **运行期占位回填的两处错位（T-RuntimeSlotOptionalFill）**：三元占位注释里的 Java 问号不再被朴素 `count('?')` 当成 JDBC 占位符（治面板多出的 `#param1`）；可选 if 片段改为「整段一个 slot」，填值不再重复静态前缀、取消包含不再残留前后缀
- **被括号包住的三元不被识别（随 T-RuntimeSlotFill 修复）**：`(status == null ? "" : " AND status = " + status)` 此前整段退化成普通运行时值，现在能拿到「两支」信息
- **iBatis 2.x 的参数被方括号包住、INSERT 大片变 NULL（T-IbatisPanwei 券 A/B）**：按 `{pstm-N}` 三行组识别 iBatis 日志，参数列表剥一层结构方括号、`Types:` 行按位置并入类型（纯数字串不再裸出成数值），`{conn-N} Preparing Statement:` 只消费不产条目
- **IDEA 2026.3 上更新插件一律提示重启、热替换失效（T-DynUpdate263）**：平台删掉了旧预检入口，改按能力族解析（validate / check / legacy，连返回类型一起判），2026.3 恢复免重启
- **更新被平台拒绝时日志只说「平台没给原因」（T-HotSwapUnloadSafety）**：按「非动态 EP 事实表」补位，直接写出拒绝项与后果。**平台边界**：`com.intellij.sql.dialect` 在 243 是非动态 EP（扩展它的插件不可动态卸载，更新只能重启），253 / 262 / 263 已是 `dynamic="true"`，免重启可用
- **下载更新包遇到 404 / 410 甩出一串 HTTP 异常（T-DevUpdateChannel）**：单独判为「该更新包还没有发布」并给发布页兜底链接，日志只记一行 info
- **增强捕获被保守策略停采时完全静默（T-AgentSilentAfter16s）**：会话建立后 15s 内收不到 CONFIG 就自停，现在心跳带 `gate` 字段并在控制台留一行点名原因，采集语义未改
- **工具语句 / 更新语句执行成功却报「超时」（T-TestGapSpeed T8）**：不产生结果页签的语句成功完成时给中性提示，不再引导用户排查连接

## ⚠️ 已知边界

- **循环值的分隔符**：逗号与换行都是分隔符，项内含逗号会被拆成两项，这类值请每行一个
- **一个 if 片段含多个运行期值**：回退为「值位置」模式，取消包含只移除当前值、静态前后缀保留，面板会给提示
- **占位值不进参数历史与参数预设**：切预设时占位值会丢；「导入参数」按 `paramValues` 来源匹配，占位 id（`rtN`）会被报成未匹配
- **互斥 if / else 两支都追加的形态（PAIRED）**：只有说明性注释，没有可填的值对象
- **模板里的 `%s` 是字面标记**：源码本身含 `%s`（如 `LIKE '%s%'`）时按「模板 `%s` 个数 = 预期值个数」校验并明确报出
- **iBatis 批处理一期不支持**：元素内含逗号或嵌套方括号时按逗号切分（`List.toString` 不可逆）
- **磐维 PG / MySQL 兼容模式需手动改选**：`jdbc:panweidb:` 恒按 Oracle 渲染（建库默认 A 模式）
- **243 上热替换只能重启生效**：`com.intellij.sql.dialect` 在 2024.3 是非动态 EP；253 / 262 / 263 可免重启
- **开发者模式按钮只在当前会话可见**：重启 IDE 后需重新连点 7 次，除非用 `-Dmpvs.update.devMode=true`
