这一版是 beta.1 的补丁版。beta.1 把运行期占位从「只能看」变成「能填」，但真机走查发现两条路径填不对：三元那一行会凭空多出一个 `#param1`，可选 if 片段填了值反而出现重复的前缀或悬空的条件。这一版把这两条收干净，其余行为不变。

## 🛠 修复

**三元占位注释里的 `?` 不再被当成 JDBC 占位符（T-RuntimeSlotOptionalFill，`bd641efe` / `f8adf101`）**

`listByTernaryBranch` 这种写法在面板上会多出一行 `#param1`，填了也没地方落。根因是 JDBC 字符串预览用朴素的 `count('?')` 数占位符，把三元占位注释里的 Java 问号（`status == null ? "" : …`）也算成了 JDBC 占位符。现在改用 string-aware 位点扫描——注释与字符串里的 `?` 不计，参数行只保留真实占位符；复制可执行 SQL 与命名参数来源判定同口径（`CopyExecutableSqlAction` / `SqlPreviewService.usableNamedPlaceholderSources`），顺带删掉没有调用点的旧 `extractPlaceholders`。

**可选 if 片段填值不再重复静态前缀、不再留下悬空条件（`bd641efe` / `f8adf101`）**

`listByOptionalIf` 的两条路径都错在「slot 只覆盖值位置、模板却覆盖整段片段」：

| 填法 | 改前 | 改后 |
|---|---|---|
| 填 `keyword` | 占位留在字符串里不被替换（`LIKE '%/* 运行时值: keyword · rt1 */%'`） | 值填进引号内 |
| 填 `minAmount` | 出现 `AND amount >=` 悬空行 + `AND amount >= 111` 重复行 | 只有一条 `AND amount >= 111` |
| 取消「包含这段」 | 静态前缀/后缀残留 | 整段干净移除 |

现改为**整段一个 slot**（token 与模板同覆盖整段），填值 / 取消包含 / 留空三条路径一致。一个 if 片段里含多个运行期值时回退为「值位置」模式，并在面板提示这一限制（整段多值模型另券）。

## ⚙ 改进

- **未填值时的可选片段预览形态有变化**：以前显示「静态片段 + 值占位」，现在显示一条整段占位。这是「整段一个 slot」的必然结果，填值后的结果与以前一致；留空行为与 beta.1 的「留空即原样」口径不变（该片段仍是运行期才决定的内容）
- **`inferHint` 增加模板感知**：占位 token 在字符串外、但模板里的值位在引号内时，仍标记为需要引号（面板自动类型更准）

## ⚠️ 已知边界

- **循环值的分隔符**：逗号与换行都是分隔符，项内含逗号会被拆成两项，这类值请每行一个
- **可选片段没有可填位置时**：需填任意非空文本（不影响产物），或显式取消勾选；只有「填了值」或「显式取消勾选」才算一次动作
- **一个 if 片段含多个运行期值**：回退为值位置模式，取消包含只移除当前值、静态前后缀保留，面板会给提示
- **占位值不进参数历史与参数预设**：切预设时占位值会丢；「导入参数」按 `paramValues` 的来源匹配，占位 id（`rtN`）会被报成未匹配，不静默失败
- **互斥 if / else 两支都追加的形态（PAIRED）**：当前只有说明性注释，没有可填的值对象
- **模板里的 `%s` 是字面标记**：源码本身含 `%s`（如 `LIKE '%s%'`）时回填会多认一个占位，此时按「模板 `%s` 个数 = 预期值个数」校验并明确报出
- **243 上热替换只能重启生效**：`com.intellij.sql.dialect` 在 2024.3 是非动态 EP，扩展它的插件不可被动态卸载；253 / 262 / 263 上该 EP 已是 `dynamic="true"`，免重启可用
