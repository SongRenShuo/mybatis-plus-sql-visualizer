# 🎉 SQL Visualizer v2026.10.16

> 发行说明留档：对应 Gitee 发行版 **v2026.10.16**（标签 `2026.10.16`），附件 `mybatis-plus-sql-visualizer-2026.10.16.zip`。
> 范围＝自 v2026.10.13 发行包之后的全部用户可见增量。

自 v2026.10.13 后的正式版。本版把 SQL 日志与历史列表的交互与观感整体重做（单击只选中、按需底部快速预览、尾部跟随、同结构聚类与按库分组排序、只看慢查询），补齐调用栈业务帧折叠与交流群入口，并修掉两处会直接影响使用的问题：**预览准备期写意向锁自锁导致 IDE 无响应**、**日志与历史列表的正常耗时颜色被灰色覆盖**。同时收敛实体解析：同名实体按查询宿主模块可见性解析，依赖 JAR 内实体与嵌入类的反查与命名约定探测得到覆盖。

## ✨ 新增

**SQL 日志与历史列表更易读（T-SqlListNativeVisual，O-146）**
- SQL 语法色改为跟随 IDEA 编辑器配色，列表、底部预览与自建 SQL 预览使用同一组高亮键
- 默认显示仍是关键字换行（与以往一致，最多三行并标注剩余行数，便于扫读 SQL 大致形态）
- 长来源与 SQL 按窗口宽度省略，列表不再横向滚动；格式化模式仍可看完整 SQL，复制与预览不受省略影响
- 工具栏动作全部直达（不设自建「更多」菜单，窄侧栏由平台自动折叠、悬停即可看到全部动作）
- 排序方式并入左侧按钮组并以排序图标呈现，窄侧栏下随组一起折叠，当前方式见悬停提示与菜单选中态

**调用栈业务帧优先与摘要入口（T-StackFramesFold）**
- 静态调用栈优先呈现可识别的业务帧，相邻内部调用折成可展开的段；采集时省略的帧明确标示，不伪装为可展开内容
- 改进深栈采样对部分业务入口帧的保留；调用栈摘要也可单击打开弹层，原文复制与逐帧跳转保留
- 边界声明：跨线程或原快照未采到的帧不能凭展示恢复

**SQL 日志交流群入口（T-SqlLogCommunityDialog）**
- 工具栏新增「加入交流群」，原生弹框并排展示作者微信与交流群说明
- 二维码在打开时异步从官网获取，加载失败可从弹框打开官网交流页

**依赖库内实体与嵌入类的反查（T-JarEmbedded W1/W2 · 优化方案 1+2）**
- 表名→实体反查补**库兜底**：项目源码 0 命中后，再按候选类名在依赖库范围查找并按表名精确校验（源码命中时行为逐字不变）
- 库内「非常规命名」实体（类名与表名约定不符）的后台扫描：结果落项目级缓存、每项目结构版本一次；**只认 `@TableName`**，不再回落「按类名推断表名」（那会把整条 classpath 建成表，实测只挂 JDK 就有 2 万条目）
- 扫描按每 500 个短名一片、每片一个独立读动作，**片间真正释放读锁**（实测写动作最大等待 5.5 秒 → 158~286 毫秒），不会冻住打字
- 设置页「代码生成」新增「后台扫描依赖库以反查实体」（默认开，可关）；关掉后可在实体选择弹窗用「在依赖库中查找」显式触发一次
- 嵌入列命名策略探测扩到工程级信号：`persistence.xml` / `orm.xml` / `hibernate.cfg.xml`（含 `META-INF/`）与代码式配置（源码里找命名策略类名）；模块已知时仍只看该模块，防兄弟模块配置外溢

## 🛠 修复

**预览准备期写意向锁自锁导致 IDE 卡死（T-PrewarmWilDeadlock）**
- 后台预热执行临时文件时，原逻辑持写意向锁同步等待 VFS 刷新会话，而会话推进又需要该锁——预览停在「正在准备预览...」并拖住整个 IDE（EDT 也随之排队等锁）
- 修复：后台刷新移除写意向锁包装（EDT 冷路径的保护保留）；投机性执行预热增加 30 秒预算，超时放弃并照常释放在途标记，一次挂死不会让后续预热全部跳过
- 新增 `SyncRefreshWriteIntentGuardTest`（BGT 链禁 WIA / EDT 冷路径保 WIA / 全仓扫描白名单），反向验证摘掉修复恰 2 红；262 真机冷启动复验仍待完成

**日志与历史列表的正常耗时颜色被灰色覆盖**
- 列表元信息展示层原先把低于半阈值的耗时片段二次覆盖为元信息灰，用户看到 `1ms` 这类正常耗时不再有分档颜色
- 移除该覆盖后恢复：正常绿、≥半阈值橙、≥慢查询阈值红、未知耗时灰、选中白；分档颜色断言已补进测试

**同名实体跨模块误选：预览改为按查询宿主模块可见性解析根实体（T-EntityNameScope）**
- 工程里两个模块各有同名实体时，此前按短名**取第一个**，预览会认成另一个类：FROM 表名与 SELECT 列清单全按它渲染，找不到映射的属性路径原样透传
- 现统一由 `EntityClassResolver` 收口：查询宿主模块已知时只查该模块及其依赖与库；`@Entity(name)` 与默认实体名同一命名空间、大小写精确匹配；**同级多候选即判歧义——不选、返回未解析并提示一次**，不再静默挑一个
- 顺带修掉「预览的弱提取压过转换链的强提取」不一致；已声明但解析失败的副表别名不再借用根表列名

**插件校验报告中的三项 override-only API 用法**
- SQL 日志面板里两处直接调用 `AnAction.update` 和一处直接调用 `DefaultActionGroup.getChildren` 的测试访问器被打入生产包，导致 IDEA 243 / 253 / 262 校验报告各出现三项违规
- 移除无调用方的访问器，排序 tooltip 断言改留在测试侧；正常工具栏更新与动作分组不变。修复后离线与在线报告均为零项 override-only

**其它修复**
- 依赖库扫描的后台投递线程里的 `catch (Throwable)` 原来用 `if (t is Error) throw t` 判致命，不符合本仓「fatal 透传」守卫的判据（只认 `FatalErrors.isFatal`）：改为标准形态，JVM 级致命错误（`VirtualMachineError` / `LinkageError` / `ThreadDeath`）照常透传，其余异常仍按「本次作废、允许重投」降级
- 同名实体的别名慢路径把**触顶（未扫完）结果也落缓存**：真实工程的短名空间含 JDK 恒大于预算，触顶是常态，原实现不缓存会让同一个名字每次预览都重扫一整段预算（约 1 秒，且扫描在预览的读动作里持读锁）；缓存不改变结果（触顶本就恒为未解析），只去掉重复代价，缓存随 PSI / 依赖版本失效，直接命中的路径在查缓存之前就已返回
- SQL 历史首次真正进入时不加载已有文件：补幂等扫描，不再需要点刷新才看到已保存的 SQL
- SQL 日志工具窗页签在窄侧栏下折成两行：页签改用平台 JBTabs，窄侧栏保持单行，空间不足由平台压缩或提供溢出入口
- 底部快速预览分隔条跟随 IDE 主题，深色主题不再出现白边

## 🔧 改进

**SQL 日志与历史列表预览交互（T-SqlListPreviewInteraction）**
- 单击只选中，不再弹出遮挡列表的轻预览；双击完整预览、列表多选复制保持原样
- 日志与历史二级列表通过「快速预览」图标开启默认收起的底部预览区，选中下一条即可连续查看
- 临时修改 SQL 时保留当前编辑内容，恢复原文后继续跟随；首次单击会出现一次不抢焦点的入口提示

**SQL 日志尾部跟随、排序与筛选（T-SqlLogTailFollow · O-148）**
- 默认仍跟随最新 SQL；手动滚轮、拖动滚动条或键盘浏览后暂停自动滚底，点击「滚动到底部」恢复，清空列表也开始新一轮跟随
- 排序菜单新增「同结构聚类」（同形状 SQL 相邻，排查 N+1 用）与「按目标库分组」（多数据源 / 多模块定位用，未知库沉底）
- 类型过滤弹窗新增「只看慢查询」勾选（耗时未知的条目不占慢查询）

**仓库首页与市场展示文案**
- README 按官网首页的八模块顺序组织演示（Wrapper 预览、SQL 日志、源码溯源、SQL → Java、CRUD、XML、JPA / Hibernate、MCP），动图与联系二维码改用官网稳定 URL，避免维护两份素材；补齐新版日志交互、历史检索与导出、参数预设、XML 编辑辅助与 11 个 MCP 工具，纠正回滚预案、热挂载、离线通信与外部 AI 数据流的能力边界
- Marketplace 自定义页（HTML 与 Markdown 两版）同步当前交互：快速预览入口、显示模式落在设置页「列表显示」、调用栈业务帧折叠

## 🧪 测试

- 本版按用户要求只跑全量测试与打包，**未重跑兼容门禁**，故不宣称兼容结论。最近一次兼容读数基线为 `90fef0bb`：`verifyGate` 与 `verifyMarketplace` 对 IDEA 243 / 253 / 262 均 `Compatible`、override-only 均为 0（待移除 4 / 5 / 7，弃用 30 / 38 / 100，实验性 96 / 94 / 94）；该基线不含其后合入的实体解析与别名慢路径改动
- **最终全量测试：`testShards` 7255 / 0 / 0 / 9**（tests / failures / errors / skipped，含 `testExternal`），664 个计划测试类均有结果 XML，BUILD SUCCESSFUL（11 分 51 秒）；agent 子项目测试 **162 / 0 / 0 / 0**
- 9 个跳过项：`DialectDockerVerificationTest` 六项（五种 Docker 数据库与外部实例）、`ExecWholeScriptOptionTest` 两项、`AcpSignatureCrossVersionTest` 一项。Docker 本轮不可用，这些项目不计作实测通过
- 全量测试在收口前先后抓到**三处主分支真实红灯**（均随本版实体反查／别名作用域改动引入，与文档改动无关），逐一修复后复跑：
  1. 元守卫 `GuardSelfTestCoverageMetaGuardTest` 报「磁盘上存在未登记的守卫类 `psi/FullScanCancelGuardTest.kt`」——该守卫类加入时漏登记，已在 `GUARD_CLASSES` 补登（判定内核内联于用例、`decisionFns` 留空并写明依据）
  2. `BannedApiScanRuleTest` 报 `EntityClassFinder.kt` 的 `catch (Throwable)` 未判 fatal——原用 `if (t is Error) throw t`，不满足守卫判据，已改为 `FatalErrors.isFatal(t)` 标准形态
  3. `PluginSettingsPersistenceTest` 报设置页复选框总数不符（期望 43、实际 44）——新增「后台扫描依赖库以反查实体」开关未同步计数，已按既有登记注释格式更新为 44
- 端到端探针（假 IDE + `-javaagent` 注入真 Spring Boot / MPJ 应用）：**26 PASS / 0 FAIL**（读数为前一轮验证结果，本轮未重跑）。脚本已支持应用端口占用时自动回退，并按本轮 agent HELLO 的 Windows PID 收尾，不再按端口误杀其他进程；受控进程占住 19080 时脚本自动切到 19081、探针 26/0，占用者保留
