## 这一版有什么

按新功能 → 修复 → 优化排序。

1. **Mapper 接口方法行也能直接预览 SQL（T-MapperMethodSqlPreview，`12f3232b8`）**：方法名行新增预览图标，点击弹出该方法对应语句的动态 SQL 预览，装配与渲染和 XML 语句行点击完全一致（参数表、`<include>`、`${}` 注入同一条链）。该方法行因此有两枚图标——左预览、右既有跳转箭头。开启同类插件共存让位时只让跳转、预览保留（三家竞品 Java 侧都只有跳转箭头，无预览能力），只装 MyBatisCodeHelperPro 时开让位该行不再为空。不加新设置项，随「MyBatis mapper XML」组开关与总闸。
2. **两个应用同时开着时，先启动的那个不再丢 SQL（T-EpAttachBeforeCapture，`ad4f5994b`）**：控制台捕获通道原先只在控制台创建那一刻装配，先启动应用、之后才点「开始捕获」时，这个控制台拿不到 EP 通道；后启动应用的控制台一旦捕获到 SQL，会把进程级的接管标志置位，前一个控制台的兜底解析也随之中止——表现为「两个应用单独跑都能看到 SQL，同时跑只剩后启动的那个」。现在捕获通道对任何控制台都先装配、捕获开启后自动生效，两边各收各的。该修复落在 beta.1 tag 之后，beta.1 发行包内不含它；此前误落进 beta.1 的 CHANGELOG 段，本版已归位。
