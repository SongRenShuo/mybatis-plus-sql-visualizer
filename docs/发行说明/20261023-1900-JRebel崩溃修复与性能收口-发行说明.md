# 🎉 SQL Visualizer v2026.10.23-beta.2（内测版）

> 内测版留档：Gitee 抢先体验通道发行版，标签 `2026.10.23-beta.2`，附件 `mybatis-plus-sql-visualizer-2026.10.23-beta.2.zip`。
> 基线为内测版 v2026.10.23-beta.1，本版承载其后的全部增量；对外更新清单只保留最新一个 beta 版，内容为全系列累计。

自 v2026.10.23-beta.1 后的同日内测第二轮。本版是**单项急救 + 小修**：修掉一处会让用户应用直接起不来的问题——同时开启增强捕获与 JRebel 启动器时，目标 JVM 以 `FATAL ERROR in native method: processing of -javaagent failed` 中止启动；顺带修正设置页能力矩阵里停留已久的工具数。beta.1 引入的全部能力仍在本版包内（累计口径），详见下方「随本版交付的 beta.1 能力」。

## 🐛 修复

**增强捕获与第三方 agent 共存导致目标 JVM 无法启动（T-JRebelPremainCrash）**

- 现象：用户同时开启增强捕获与 JRebel 启动器后，目标应用直接起不来，控制台只有一行 `FATAL ERROR in native method: processing of -javaagent failed, processJavaStart failed`。已核实用户所装 2026.10.16 的内嵌 agent 产物完整（137 条目、asm/Opcodes 在位），即问题出在加载时序而非打包缺失
- 根因：`retransformLoadedDrivers` 的名单谓词位于 try 之外。第三方 agent 接管 premain 类加载后，重定位后的 ASM 对插件不可见，谓词触发织入器类初始化时抛 `NoClassDefFoundError`（另一种加载器形态为 `ClassCircularityError`）。异常穿出 `premain` 对 JVM 是致命的，直接中止宿主启动
- 止血：premain / agentmain 双入口统一做失败兜底（捕 `Throwable`，含 `Error`），任何异常都不再外抛；降级时不写在线标记、不置 installed，使运行期 attach 仍可重试，并在 stderr 留一行降级说明。三连谓词移入单类 try 并新增 `predicateFailed` 计数，与 retransform 失败区分开
- 结构性修复：登记表与形态标注上提为零 ASM 依赖的独立类，「查名字」不再要求 ASM 可解析——异常场景下增强能力不丢，真正的 ASM 需求只落在 `weave()`，已在 transformer 的 try 内
- 体验：新增 premain 未按时回连的降级感知，每项目会话提示一次并回落运行期挂载，不再静默
- 验证：Corretto 21.0.12.1 上用真实 agent 产物做修复前后对照——修复前同形态必然致命，修复后进程正常启动、逐类失败被计数拦下（自定义 system loader 形态读到 `predicateFailed=949`，即逐类兜底生效的直接证据）；demo 仓配套复现子工程 8 格全绿
- 边界如实声明：未复刻用户 JRebel 的具体转发路径（本机 JRebel 为 native agent，走不到用户栈里的纯 Java 转发路径），也未在真实 IDE 工程 + 真实 JRebel 端到端验收

**设置页能力矩阵的 MCP 工具数（文案）**

- 落地页能力矩阵仍写着「MCP 十工具」，实际为十一个；只改文案，工具注册与门控不变

## 🔧 改进

- **性能二十六轮收口（T-PerfSweep26）**：日志缓冲区淘汰回扫改键级计数、mapper XML 折叠尊重 `quick` 并加体量熔断、停靠预览同一性短路前置、EXPLAIN 数据源绑定等待上限由 120 秒收紧到 30 秒、若干处现场正则提常量与引用解析加 memo。均为内部等价改动，用户侧体感为长日志与大文件下更稳；无新增开关、无行为变化
- **Mapper 配对跳转图标资源**：新增 Mapper 接口方法侧与 XML 语句侧两张 16×16 图标并注册到图标表，为后续配对跳转入口做准备；本版尚未挂到 UI，用户侧暂无可见变化

## 🧪 测试

- 权威全量：`testShards` **8116 / 0 / 0 / 9**（tests / failures / errors / skipped），742 个计划测试类均有结果 XML，BUILD SUCCESSFUL（17 分 24 秒）；agent 子项目 **178 / 0 / 0 / 0**
- 9 个跳过项：`DialectDockerVerificationTest` 六项（五种 Docker 数据库与外部实例）、`ExecWholeScriptOptionTest` 两项、`AcpSignatureCrossVersionTest` 一项。本机 Docker 引擎不可用，这些项目不计作实测通过
- 收口过程修掉两处**测试间污染**（都不是产品缺陷，单类跑全绿、同 JVM 全跑才红）：
  1. `PremainSingleClassFailureTest` 用 `Class.forName("org.h2.Driver")` 取 code source，会把 `org.h2.Driver` 装进系统加载器，破坏 `ZeroLoadClassWriterWeaveTest` 的「h2.Driver 未装载」红线前提（3 例误红）。改为 `getResource("org/h2/Driver.class")` 定位 jar，不加载任何 H2 类
  2. `AgentManagerAttachAfterDegradeTest.test真实入口` 的会话工厂无条件累加计数，而同 JVM 内其他测试类在真实 dispatcher 上排队的迟到任务会带着自己的 pid 打到该工厂缝上（稳定 `expected:1 but was:2`）。改为只统计目标 pid，并把观测到的全部 pid 写进断言消息
- 修复后 agent 包 204/0/0/0，两类同批 7/0/0/0，全量复跑 8116/0/0/9
- 产物：`mybatis-plus-sql-visualizer-2026.10.23-beta.2.zip`，7,136,893 字节，SHA-256 `a0dc334a134c1cb24f3e50597173d1638068491ffb318dd026c9156dda7f8b91`；`inspect-plugin-zip.py` 全项 PASS（内层 jar 名、`plugin.xml` 版本、`MANIFEST` 版本、changeNotes 首块 19 条与文案零违规）

## 📦 安装（内测通道）

1. 下载附件 `mybatis-plus-sql-visualizer-2026.10.23-beta.2.zip`
2. IDEA：`Settings → Plugins → ⚙️ → Install Plugin from Disk…` → 选择 zip → 重启 IDE
3. 已装 v2026.9.11+ 用户：设置页「更新」分区检查更新即自动收到本内测版（Gitee 抢先体验通道），经该通道更新免重启即时生效

## 附：随本版交付的 beta.1 能力（累计）

以下能力自 v2026.10.23-beta.1 起随内测包交付，本版继续包含：

- 预览执行按目标数据源方言出 Runner（达梦等方言的数据源可直接执行）；真实执行前核对来源方言与执行目标，冲突时阻断并给出「切换数据源」「方言设置」两个就地入口
- 只读旁路：预估影响行数、EXPLAIN 与回滚快照查询不再替换预览编辑器里的 SQL；影响行数结果改为顶部横幅；预览面板底部新增「复制 SQL 并关闭」
- 回滚快照表格 / 文本双态与 CSV 编辑器打开；无数据源时直接弹选择器并自动重试
- 参数预设与参数历史按声明方法隔离，预设永久绑定方法，改 SQL 不再丢参数
- 跨会话 EXPLAIN 计划历史与跨次对比；预览可标注无法解析的列
- AI 上下文复制新增「含表列名」出口；日志与导出支持选择性脱敏
- FieldFill 字段填充安全模拟（不执行用户 Handler）
- 执行前 Schema 预检、方言能力自检、DML 影响面试算、一键诊断报告
- 增强捕获默认开启、打开即授权；SQL 转 Java 条件组不吞 OR、保留子组 NOT、逻辑删除条件不重复生成
- 历史检索与日志列表性能优化；分发包补齐 LICENSE 与第三方声明，体积减少约 20%
