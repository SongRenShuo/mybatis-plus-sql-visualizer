# v2026.11.10-beta.2 发行说明（内测）

- 发行：2026-11-10
- 版本：`2026.11.10-beta.2`（沿用 11.10 内测线；内测通道允许 `-beta.N` 后缀，`beta.2 > beta.1` 可被 IDE 更新检查识别）
- 范围＝`v2026.11.10-beta.1` 发行包之后的全部用户可见增量：**iBatis 预览四项真机缺陷修复**（用户 2026.3 验收反馈）

## 修复

### 1. `<selectKey>` 子语句在预览里完全不可见

`insertUser` 的 `SELECT SEQ_USER_ID.NEXTVAL FROM DUAL` 此前根本不出现在预览里——渲染器有 `renderSelectKey`（保真对照 4/4 通过），但服务层从未调用它。

现在按引擎语义组装：`type=pre` / `post` 的时序在块注释里标明（`-- [selectKey type=pre → id]`），selectKey 内的 `#x#` 照常转 `?` 并按 pre/主/post 顺序拼进参数名序。

**主语句恒在最前**：执行链按首条语句判类型（`SqlTypeClassifier.getFirstKeyword`）与写安全闸（`ExecutionScriptScope`），把 selectKey 的 `SELECT` 放前面会让带上键的 INSERT 被误判成只读查询——这条有钉死用例（预览 SQL 必须以 `INSERT` 开头）与反向验证。

### 2. 格式化把占位符拆散

`# username #` 此前被格式化成三段。iBatis 的 `#x#`（含 `#x:TYPE:nullValue#` 三段形态）在**格式化 / 关键字换行 / 竖向排列**三条路径下都被当普通字符断开了。现统一把占位符当原子段保留（未闭合残段不合并）；MyBatis 的 `#{x}` / `${x}` 同病同修（此前同样被拆成 `# { x }`）。

### 3. 勾选填值后重渲染失败被静默吞掉

2026.3 上部分用户勾选条件并填值后 SQL 始终停在无参基线——rerender 回调内抛出的异常被面板吞掉、保留旧结果，用户看不到任何原因。

现整条回调捕获失败（`FatalErrors` 直传）后：面板显示失败档结果（「重渲染失败：<原因>」）并在 `idea.log` 记带堆栈的 warn，不再静默回落。**这条同时是取证手段**——下次若仍失败，面板会直接告诉你异常内容。

### 4. 信息性说明混进红色失败行

parameterMap 的「引擎行为」说明此前与「方言未验证」等真失败拼在同一行、下方 ℹ 行又重复一遍。现按档分开收集：混合时 ⚠ 行只留真失败，纯信息级整行走 ℹ（内容不丢）。

## demo 侧配套（同批）

`ibatis2-demo` 从「只有 XML 语料 + 离线渲染自检」扩成可真实调用的模块：新增 `UserDao` / `UserDaoImpl`（20 条语句，语句 id 字样是跳转箭头锚点）、`Ibatis2ExecMain`（真实执行入口，逐步 try/catch 打印 `[OK]` / `[EXPECT-FAIL]`）、`log4j2.xml` + `log4j-jcl`/`log4j-core`（iBatis 的 `LogFactory` 探测序是 commons-logging → log4j 1.x → JDK14 → nop，给上桥接后 `java.sql` 的 DEBUG 才进控制台，插件捕获从这里采样）。`User.xml` 17 → 20 条（新增可执行的 `selectPrependWithSpace` 与 `updateUser`/`deleteUser`）。离线自检：`已注册语句（20）`、`渲染成功 20 条，失败 0 条`。

## 已知边界

- `ANDUSER_NAME`（`selectPrependNoSpace`）**执行必然报语法错**——这是保真样本（钉住 iBatis 的 `prepend` 逐字拼接不补空格）；可执行对照用 `selectPrependWithSpace`。
- `<selectKey>` 内的 `#x#` 参数会进参数名序（保证 `?` 位点对齐），但**没有输入行**（`keyProperty` 回写目标不是 `?` 参数）——需要给它填值时当前无入口。
- 预览 SQL 变成多语句后，「执行 SQL」按首语句走（主语句在前，所以类型与写安全闸判定正确）；需要整脚本执行时用「执行整个脚本」选项。
- 竞品同装（MyBatisCodeHelperPro）场景的箭头显示由机器用例钉住，沙盒无竞品、GUI 未重演。
