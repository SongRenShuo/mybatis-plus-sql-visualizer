这一版修两个「看着像插件坏了、其实是参数形态与平台 API 变更」的问题：一个是 Oracle 上带时间戳条件的 SQL 一执行就 `ORA-01843`，一个是 IDEA 2026.3 上「切换数据源」只剩当前一个源、点了还静默跑到原来那个库。

## 🛠 修复

**日期族参数改用 ANSI 类型字面量，Oracle 预览执行不再报 ORA-01843 / ORA-01861（T-DateLiteralBackfill，`9779d173`）**

捕获到的 `LocalDateTime` 值按 `toString()` 是 ISO `T` 形态（`2026-11-07T13:20:14.417`），参数行此前只把它包成单引号串。Oracle 对 TIMESTAMP 列的隐式转换按 `NLS_TIMESTAMP_FORMAT` 解析，`T` 分隔符不被接受 → 执行报 ORA-01843。把 `T` 换成空格同样不够，`'2024-01-01 10:00:00.0'` 在 Oracle 11g 与 23 上都实测报 ORA-01861（末尾 `.0` 导致字面量与格式串长度不匹配）。

现在不再修字符串，而是按 SQL 标准产出**类型字面量**：

| 值形态 | 产出 |
|---|---|
| 纯日期 | `DATE '2024-01-01'` |
| 时间戳 | `TIMESTAMP '2024-01-01 10:00:00'` |

归一规则：ISO 的 `T` 换成空格、缺秒补 `:00`、保留毫秒。产出点收在共享渲染器 `SqlDateLiteral`，覆盖四条渲染链（面板参数行 / 复制可执行 SQL / 导出分享 / 增强捕获列表）与模型链（MP 批量 / JPA `QueryByExample`、`Specification` / 自研框架 XML 回填）。形态不匹配或类型未知时仍回落原引号渲染，不会产出非法字面量；SQL Server 与 SQLite 因 T-SQL 与 SQLite 不支持 ANSI 类型字面量，按方言门禁维持引号形态（SQL Server 的 ISO 8601 引号串本来就能隐式转换）。R3 报告里挂起的「面板参数行要不要一起 ANSI 化」（决策点 D1）由此定案为统一 ANSI 化。

**IDE 2026.3 上换源不再退化为单源、不再静默跑到旧库（T-ConsoleBind263，`bd4eff85` / `151573f2`）**

2026.3 移除了 `DataSourcePerFileMappingsImpl.setMapping(VirtualFile, LocalDataSource)`，插件清平台「文件 → 数据源」绑定的那一步恒抛 `NoSuchMethodException`。后果是两张脸：绑定清不掉 → 平台的 forced 关联把可选数据源短路成单条，「切换数据源」只列出当前源；工具栏挑了 `mpj_demo@localhost` 却在原来钉住的源上建会话，看起来「点了没反应」，实际跑到了另一个库。

修法是把写入口改成能力族探测——`setMappingWithWriteAction`（2026.3）→ 旧重载 → `setMapping(VirtualFile, String)` → 静态只写入口，每写完都用平台接口回读核对；2026.3 的写动作入口是异步协程（字节码实证），由同步写兜底并在日志里给出实际生效的策略名。日志分型改为 `setMapping FAILED strategy=… reason=…` / `setMapping UNAVAILABLE …`，首次换源打一行平台契约读数，将来平台再收走入口时一眼可见。

同时补两道防护：**显式选了数据源但平台可选集合里没有它时直接阻断并说明原因**（不再静默用另一个源执行），**平台绑定改不动时面板就地提示实际目标与请求目标**（并给出关闭该文件控制台的操作路径）。两条新增文案都已进双语语言包。

## ⚠️ 已知边界

- **非补零日期仍回落引号**：`2026-1-1` 这种形态只有 Oracle 实测过，MySQL / 达梦等引擎未验证，本版不扩；面板只做提示、不阻塞
- **控制台还原路径在 SQL Server 上仍产字面量**：`LogSqlRestorer` 没有方言入参，SQL Server 控制台还原出来的仍是 ANSI 字面量（既有缺口）；增强捕获侧已按连接 URL 判方言，因此同一语句跨通道在 SQL Server 上可能一处引号、一处字面量
- **JdbcTemplate 的 `:name` 命名参数维持引号**：该通道没有类型信息，不做猜测
- **平台绑定改不动时只能就地提示**：2026.3 的写动作入口是异步协程，插件走同步写兜底；若某次仍未写落地，面板会提示实际目标并建议关闭该文件控制台重试，不做无限重试
- **T-ConsoleBind263 只做了本链路所需的反射点方法级取证**：全仓 30 处平台反射点的逐点在 263 上的方法级体检登记为专项（同批发现 `DialectPreMapping.getConfiguredDefaultSqlDialect` 在 263 上已失效，走既有降级路径，未在本版改）
- **243 上热替换只能重启生效**：`com.intellij.sql.dialect` 在 2024.3 是非动态 EP，扩展它的插件不可被动态卸载；253 / 262 / 263 上该 EP 已是 `dynamic="true"`，免重启可用

3. 重启 IDE
