> 🔴 **多会话并行开发必读（重点）——并行测试协调登记表**：
> 场景原因：2026-08-15 T-M26.1 验证时两个并行会话同仓库跑测试，测试沙盒互锁 + 互相误杀对方测试 JVM（误判残留进程），导致索引/test-results 损坏、1.3GB hprof 垃圾的「互锁互杀」循环；此后落地共享登记表机制，**任何会话跑 Gradle 测试前必须查表**。
> - 脚本（本机工具，不在仓库）：`C:\Users\USER\.zcode\cli\parallel_tasks.py`；数据文件 `parallel-tasks.json` 同目录（全局共享）
> - 用法：`python parallel_tasks.py check`（无活跃任务 exit 0 / 有活跃任务 exit 1 并列出对方）→ 有并行活动时 `register --name <任务名> --sandbox <独立沙盒>` 登记 → 跑完 `done` 注销；`prune` 清超时残留
> - kill 白名单：kill java/idea 进程前查表——命令行含**自己登记的沙盒名**才允许 kill
> - **沙盒本身也会冲突**：① `prepareTestSandbox` 目标文件互锁（「用户映射区域」错误——对方/残留测试 JVM 把沙盒内 jar 映射锁定，复制必失败）；② SDK 解压目录（`~/.gradle/caches/.../transforms/idea-2025.3.5-win`）两会话共享，沙盒 system 索引（`records.dat`）互锁会强制重取；③ 已隔离的沙盒也可能被**自己早前运行的残留测试 worker** 锁住——按白名单杀（命令行含自己沙盒名）或直接删沙盒目录再跑
> - M28×M29 二次实证教训：登记会自锁 `check`（别把 check 链进自己命令）；共享 gradle daemon 会被对方 `--stop` 误杀（测试执行器莫名 FAILED）——权威全量回归建议 `git worktree` 独立目录 + `--no-daemon`（沙盒随 build 目录一并完全隔离）
> - **`expected_end` 不是活性信号，判活要查进程**（2026-09-20 实证）：`T-GifRec-MCP` 登记 `expected_end=02:19`，到 15:50 仍在跑——`check` 只报「存在活跃任务」不报真死假死。要判某条登记是否已成残留，查进程命令行而非时钟：`powershell Get-CimInstance Win32_Process -Filter "Name='java.exe'"` 找 `idea-sandbox`/`-javaagent:…\build\MPSV-…`/对方 checkout 的 `gradlew`。
> - **录制会话活跃时禁开新 runIde 沙盒**：新 IDE 窗口会抢前台，录制脚本的坐标点击与窗口 Z 序都会被打偏（录制管线本身要求「录制中系统空闲时优先」）——真机走查要么等对方注销，要么用独立沙盒且不抢焦点（难以保证，实际按前者）。
> - **构建并发资源定例（2026-09-23 双树对照实测，T-BuildConcurrency O-65）**：构建并发上限 **2 路**——瓶颈是内存提交量不是 CPU（双路 Commit 峰值 66.9/上限 74.7 GB、free 最低 2.8 GB；单路 CPU 均值仅 49.8%，双路加速比 1.52）。日常验证走 `testFast`（可双路，94~155s），全量 `testShards` 3 片只在单路收口跑；**禁止降片（`-PtestShardCount` 调小）换并行或提速**（双路 2 片实测慢一倍且 free 跌到 0.3 GB）。跑全量前先 `timeout 10 docker info` 验 daemon 活性（引擎半活态 `DialectDockerVerificationTest` 会无限挂起且不产失败读数）。`~/.gradle` 实体已迁 `F:\gradle-home`（`C:\Users\USER\.gradle` 为 junction），拆联接只用 `rmdir`/`Remove-Item`、**禁 Git Bash `rm -rf`**。详版＝`docs/经验总结/20260923-1055-多工作树并行构建资源实测与定例-经验总结.md`
> - **env 车道禁合回（T-BranchHygiene3 O-62 登记）**：`origin/env/cloud`、`origin/env/no-proxy` 为构建环境车道（本机构建环境调参专用），**禁合回 master/dev**，本地无需建分支，治理波次不必清理
> - **`testDatabase` 门禁 10 绿的含义（T-BranchHygiene3 O-62 落档，销 t-testdb-driver 裁决）**：该任务只覆盖 DB 集成小集合（5 类 10 例＝驱动管线 `DbDriverPipelineTest` 硬断言 + DBN 四个集成类）；2026-09-18 驱动管线打通后四类首次真跑暴露 7 项断言失败，判定为测试侧平台行为假设（沙盒缺真实 IDE 项目/窗口/VFS 夹具）非产品缺陷，经 T-Fix-TestDb（`627fd13` 稳定工程目录）真实转绿——**非 skip/豁免掩盖**；HeavyNative B 路径（`LocalDataSource.getModel()` 是否带内省结果）本环境 `roots=0` 无法真跑，在真机走查清单在册。详见 `docs/调研报告/20260918-testDatabase驱动管线打通-记录.md`
