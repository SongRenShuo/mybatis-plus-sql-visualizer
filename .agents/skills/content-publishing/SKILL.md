# content-publishing 多平台内容发布作业法

权威文档两处：`docs/内容营销/多平台发布手册.md`（平台入口、编辑器规则、配图规范）与 `docs/内容营销/已发布内容清单.md`（发过什么、链接、数据）。本 skill 是它们的执行版，只管「怎么把稿子变成三个平台上的线上文章」；冲突时以两份文档为准。

对外发布属 AGENTS.md 第 9 条的「外发内容」，**必须用户明确授权**才动手。发布用的浏览器会话、账号登录态都在用户手里，助手只做「打开编辑器、灌内容、设设置、点发布」这段机械动作。

占位符：`{标题}`＝文章标题；`{md}`＝平台版 markdown 的仓库相对路径；`{图片目录}`＝`docs/内容营销/img-<日期>/upload/`；`{平台ID}`＝CSDN 171493618 / 知乎 2109663091604694014 / 掘金 7712657463330603059 这类文章 id。

## 0. 先定三件事

1. **发哪几个平台**。默认组合：知乎专栏（首选，AI 检索权重高）、掘金（技术社区）、CSDN（中文 AI 引用权重最高）。博客园 / 腾讯云 / 阿里云用 CSDN 版复用。
2. **51CTO 永远跳过**——它对推广零容忍，首版被拒过（见 §5）。
3. **今天是否已发过知乎**。同日多条自荐内容会叠加判罚风险，一天最多 1 篇带产品名的文章。

## 1. 拆稿：一篇文章拆成三版

同一素材、三套开合，避免整篇重复（重复内容对 SEO 无益，平台也可能判洗稿）：

| 平台 | 结构 | 语气 | 必备差异 |
|---|---|---|---|
| 知乎专栏 | H3 分层，6 节左右 | 第一人称、读者提问视角 | 文末原创声明；创作声明「包含 AI 辅助创作」 |
| 掘金 | H2，6 节 | 动作 / 工程视角 | 一段可复制的 `curl + jq`；列表化结论 |
| CSDN | H2 + H3，7 节 | 教程向 | 开头「这篇适合谁」；结尾可执行检查清单；摘要手填 |

**表格一律压到 4 列**。手机端 5~6 列会被压成两行字，读不成表。版本号、日期、下载量这类次要列挪进正文写成一句话。

拆稿产物放 `docs/内容营销/拆稿-<日期>/`，同时写一份 `README-发布清单.md`：三版差异、发布顺序与设置、五张图放在哪节、发布后回填字段。

## 2. 配图：先解决「地址从哪来」

平台编辑器不认本地路径。三条来源，按可靠性排序：

| 来源 | 可用性 | 说明 |
|---|---|---|
| **Gitee raw** | ✅ 首选 | `https://gitee.com/<账号>/<仓>/raw/master/docs/<中文路径 URL 编码>`。国内快，CSDN/知乎都能抓 |
| jsDelivr | ❌ 本仓不可用 | 单包上限 50MB，本仓超了；只有早前被缓存过的图能取，新图 403 |
| CSDN 图床 | ❌ 不能跨站 | 带 `Referer: juejin.cn` 请求返回 403（防盗链实测） |

**各平台对图片的处理不一样，必须分别对待**：

- **CSDN**：自动抓取外链 → 转存 `i-blog.csdnimg.cn`。
- **知乎**：自动抓取外链 → 转存 `pic-private.zhihu.com`。
- **掘金**：**不转存**，原样保留外链。必须手动重新上传（§3.3）。

上传版统一压到 1200px 宽放 `{图片目录}`，2x 原图留在同级目录备查。压图脚本见 `.local/cdp/shrink-figs.py` 一类（PIL LANCZOS + optimize）。

## 3. 机器发布：三套 recipe

### 3.0 浏览器会话怎么搭

用独立 profile 起一个调试用 Edge，**不要关用户正在用的浏览器**（可能开着几十个标签）：

```
msedge.exe --remote-debugging-port=9222 \
  --user-data-dir=<repo>/.local/edge-pub-profile \
  --no-first-run --no-default-browser-check --window-size=1440,1000
```

启动要用后台任务常驻（`run_in_background: true`），`Start-Process` 起的进程会随命令结束被沙箱收走。登录态靠 Cookie 文件复制不可行——运行中的 Edge 对 `Cookies` 持独占锁，`FileShare.ReadWrite` 也打不开；**要么让用户在调试窗口里扫码登录一次，要么关掉主浏览器**（后者要用户点头）。

通用脚本 `.local/cdp/`（gitignored，本 skill 的 `scripts/cdp.js` 是同一套的精简版）：`run.js` 在指定 tab 里求值一段 snippet，`goto.js` 导航，`shot.js` 截图，`login-check.js` 看三平台登录态。

### 3.1 CSDN（CKEditor 4）

1. 打开 `https://mp.csdn.net/mp_blog/creation/editor`，等 `CKEDITOR.instances.editor` 出现。
2. md → HTML：表格 `<table>`、代码块 `<pre><code>`、图片 `<img>`、行内 `**x**` → `<strong>`。
3. 灌入：`CKEDITOR.instances.editor.setData(html)` + `fire('change')`；标题走 `#txtTitle`（原生 setter + `input` 事件）。
4. 摘要走 `#txtSammary`（原生 setter + `input`）。
5. 标签是受控组件：**先用真实鼠标点开「添加文章标签」**（该元素在视口外，要先 `scrollIntoView`），再用 CDP 发 Enter；JS 合成 `KeyboardEvent` 不生效。
6. 点「发布博客」→ URL 变 `/mp_blog/creation/success/<id>` 即成功（页面提示「正在审核中」不等于没发出去）。

### 3.2 知乎（Draft.js）

**正文用「导入文档」，不要用剪贴板粘贴。** Ctrl+V 会被图片分支吃掉，只落进一张图。

1. 打开 `https://zhuanlan.zhihu.com/write`。
2. 点工具栏「导入」→ 菜单项「导入文档 MD/Doc」。菜单项文字带零宽字符 `\u200b`，匹配前要剥掉。
3. `input[type=file][accept*=".md"]` **有两个**，取最后一个（前一个是「直答知识库」上传器，会永久卡在「上传中」）。用 `DOM.setFileInputFiles` 喂 `.md`。
4. 导入后核对：正文 >4000 字符、图片数对、表格在。知乎会丢一些小表（本次丢了 build 前缀表），正文里有等价文字就没事。
5. 标题走 `textarea[placeholder*="请输入标题"]`；封面 file input 的 accept 含 `.jpeg`。
6. 发布设置：话题按正文自动识别（通常已填）；创作声明在下拉里选「包含 AI 辅助创作 作者对内容负责」；勾「发布到专栏」再选专栏。
7. 点「发布」→ 创作中心显示「发布于刚刚」即成功。**不要 reload 编辑器验证**，会把内容刷掉。

### 3.3 掘金（bytemd + CodeMirror 实例）

1. 打开 `https://juejin.cn/editor/drafts/new`。
2. 正文：`document.querySelector('.CodeMirror').CodeMirror.setValue(md)`；标题 `input.title-input`。
3. 发布面板：分类点「后端」（选中态是 `item active`）。
4. 标签是 `byte-select`，`input[type=text]` 选不中：点 `.byte-select__input` 并**确认 `document.activeElement` 就是它**，再 `Input.insertText` 输入 `MyBatis`，然后点 `.byte-select__dropdown` 里的同名选项。焦点没落对时 Ctrl+A 会把 CodeMirror 全文选中。
5. 封面走 `input.file-input`。
6. 「确定并发布」要点**可见实例**（隐藏模板按钮 `getBoundingClientRect()` 为 0，点它没反应）。
7. **图片必须重新上传**：工具栏图片按钮在 CDP 下点不开（`Page.setInterceptFileChooserDialog` 收不到 `fileChooserOpened`，点击还会阻塞渲染线程），两个 file input 也都不吃文件。唯一跑通的是剪贴板粘贴：
   - `Set-Clipboard -Path <本地图>` → 编辑器光标落到正文末尾 → CDP 发 Ctrl+V
   - 掘金自己上传并插入 markdown，地址是 `p0-xtjj-private.juejin.cn`，线上渲染成 `p3-xtjj-sign.byteimg.com`
   - 取到 URL 后把正文里的外链替换掉，再「更新 → 确定并更新」

## 4. 发布后核验

| 平台 | 成功判据 | 别拿什么当判据 |
|---|---|---|
| CSDN | URL 变 `/mp_blog/creation/success/<id>`；创作中心列表可见 | 页面文案「正在审核中」 |
| 知乎 | 创作中心「发布于刚刚」+ 阅读数 ≥1 | 编辑器是否跳转（可能停在 `/edit`） |
| 掘金 | 跳 `/published` 且标题回显 | 发布面板是否关闭 |

核验线上页要看三样：标题、正文长度、图片 `naturalWidth`（不是 `img` 个数，图标也算）。

**缓存**：掘金与知乎更新后立刻查会看到旧内容，加 `?t=<timestamp>` 破除才看到新版本。知乎「更新」点了之后按钮显示「发布中…」，大约 30 秒才落地，别当失败重试。

**审核口径**：计数 +1 但列表搜不到 = 审核队列，不是失败，**不要删了重发**。

## 5. 推广红线：比发布本身更重要

| 平台 | 容忍度 | 实证 |
|---|---|---|
| 51CTO | **零容忍** | 首版被判「含广告信息」（文末同时有官网外链 + 「插件市场搜 XXX」安装引导 + 免费开源）。删掉全部外链与推广节、只留一句产品名 → 过审 |
| 知乎 | **已收紧** | 2026-11-26 系统通知账号「多次发布含有垃圾信息与违规营销的内容」，要求自查删除。**被标记的文章没有外链**——触发结构是「竞品逐一列名 + 对比表 + 文末卖点清单 + 自证清白式辩解」 |
| 掘金 / CSDN / 博客园 | 宽松 | 带产品名与功能说明未出事；博客园必须勾「内容由AI生成」 |

**规则**：

1. 文末只用一句「作者说明」——谁维护的 + 方法不依赖它。**不列卖点**（免费开源/版本要求/专属能力这些是 Marketplace 页面的事）。
2. 竞品对比文降权：把对比写成**读者能自查的方法**（区间怎么读、去哪查、退版怎么退），不写「谁家宽谁家窄」的榜单。
3. 已收到营销警告的账号，7 天内不发新的自荐内容；旧内容里带安装引导的段落按通知要求清理。

## 6. 回填（发布完立刻做）

1. `docs/内容营销/已发布内容清单.md`：概览表篇数 +1；在对应平台段落追加明细（链接、发布日期、摘要、字数、图数、标签、是否进专栏、状态）。
2. 拆稿目录的 `README-发布清单.md`：把状态改成「已发布」并列出三个链接；本次跑通的新手法补进「机器发布路径」节。
3. 若发现平台判罚、平台改规则、或某种做法失效，同步 `docs/内容营销/多平台发布手册.md` 对应章节（尤其 §3.5 推广容忍度、§4 配图规范）。
4. 提交按仓规走：显式路径 `git add`，信息写文件 `git commit -F`（Git Bash 里反引号会被命令替换吃掉）。

## 7. 已知坑速查

| 现象 | 根因 | 处置 |
|---|---|---|
| 剪贴板粘贴进知乎只剩一张图 | Draft.js 的粘贴分支先吃图片 | 改用「导入文档 MD/Doc」 |
| 知乎导入卡「上传中」 | 打到了「直答知识库」的上传 input | 取 `querySelectorAll(...).pop()` |
| 知乎工具栏「导入」匹配不到 | 菜单文字含 `\u200b` | 匹配前 strip 零宽字符 |
| 掘金 Ctrl+A 全选正文 | 焦点没落在 `byte-select__input` | 先校验 `document.activeElement` |
| 掘金点「确定并发布」没反应 | 点到了隐藏模板按钮 | 过滤 `getBoundingClientRect().width > 0` |
| 掘金图片还是外链 | 掘金不转存 | 剪贴板粘贴重新上传 |
| 更新完线上还是旧内容 | 页面/CDN 缓存 | 加 `?t=` |
| 知乎标题行残留 `### ` | 在该块里直接打 `###` 不会转标题 | 打成 `###` + 空格触发 markdown 快捷转换，或事后删掉残留字符 |
| jsDelivr 403 | 仓库超 50MB 单包上限 | 换 Gitee raw |
| CSDN 图床图在掘金 403 | 防盗链 | 掘金必须自传 |
| Bash 里 `Set-Clipboard`/`git commit -m` 内容被吃掉 | 反引号命令替换 | 路径与文案写文件，或用 `-F` |

## 8. 交付前自查

- [ ] 三版是否只有开合不同、事实一致（数字、日期、区间口径必须一致）
- [ ] 表格是否都 ≤4 列
- [ ] 图片地址是否 200（逐张 curl 验证，别只看页面渲染）
- [ ] 该平台是否需要重新上传图（掘金必须）
- [ ] 文末是否只剩一句作者说明，没有卖点清单
- [ ] 发布后是否核到「标题 + 正文长度 + 图片 naturalWidth」三样
- [ ] 清单与 README 是否回填
